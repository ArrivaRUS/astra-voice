# Связка релизных ключей

`release.gpg` — связка ключей, по которой `astra_voice.security.verify` проверяет
подпись `SHA256SUMS.asc` у релизов и `.deb` «из файла». Файл попадает в пакет как
`/usr/share/astra-voice/keys/release.gpg`, root-owned, и отпечатки в коде
(`PINNED_FINGERPRINTS`) едут в том же пакете — подменить одно без другого нельзя
(`docs/threat-model.md` §4.2 «б»).

## Текущее содержимое — ВРЕМЕННОЕ

| Ключ | Отпечаток | Статус |
|---|---|---|
| `Astra Voice Spike s1` | `CB95 1AD7 9440 7972 A0B1  A5BB AFA8 7398 C495 3A71` | **тестовый**, до генерации мастера заказчиком (срок — до 25.09) |

Это ключ спайка S2 (`spikes/s2_polkit_helper/keys/test-release.gpg`), сгенерированный
для проверки цепочки `gpgv` → пин отпечатка. Закрытая часть лежит только в
`~/.cache/astra-voice-spike/gpg/` на машине разработки и в репозиторий не копируется.
**Ни один публичный релиз этим ключом не подписывается.**

## Что здесь будет после генерации мастера

По `docs/SECURITY.md` §4: `release.gpg` = публичная часть офлайн-мастера + подписывающие
подключи `S1` (в GitHub Environment `release`) и `S2` (резерв, закрытая часть офлайн).
Пин по отпечатку **мастера** позволяет плановую ротацию `S1 → S2` без правки кода.

Порядок замены (одним коммитом, иначе гейт `verify` разъедется):

1. заказчик генерирует мастер и подключи по `docs/SECURITY.md` §4;
2. `gpg --export <master-fpr> > data/keys/release.gpg`;
3. в `src/astra_voice/security/verify.py` заменить `PINNED_FINGERPRINTS` на отпечаток
   мастера (TODO там же), тестовый ключ убрать;
4. отпечаток мастера — в `README.md` и `packaging/INSTALL-ADMIN.md`.
