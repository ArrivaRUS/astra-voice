## 1. Фон и цели

### 1.1 Почему сейчас
На машинах заказчика голосовой ввод — переделанный Handy (Tauri + React + Rust, форк `ArrivaRUS/handy-gigaam`).
Распознаёт отлично (GigaAM v3, фраза 6 с → ~130 мс, пунктуация, «ё»), но это чужой форк: тяжёлая сборка,
которую `tauri build` не собирает, deb перепаковывается руками, английский UI с недопереводом, чужая
айдентика, ярлык автозапуска переписывается при каждом старте (на машине живут два ярлыка), раздел
LLM-постобработки с API-ключами, который в корпоративную сборку нельзя. Заказчик 2026-09-07 попросил
**свою утилиту с нуля под ALSE** с пятью конкретными требованиями (см. `PROJECT.md`). Решение G0 — GO,
Discovery только техническое.

### 1.4 Проверка гипотезы (обязательный блок)
- **Гипотеза.** Своя утилита на Python + PyQt5 (apt) + `onnx-asr` даёт тот же пользовательский опыт, что Handy + GigaAM, при на порядок более дешёвой сборке и честном русском UI, и её можно довести до корпоративных ALSE (ЗПС, офлайн).
- **Ожидаемый эффект.** Заказчик пользуется Astra Voice ежедневно вместо Handy ≥ 14 дней без возврата; корпоративный пилот (если будет) не упирается в сеть/права/ЗПС.
- **Метрики и способ замера.** (а) p95 задержки ≤ 0,5 с (локальная статистика; достигнуто на M4 15.09 — p95 291 мс, удержать до срока проверки); (б) откатов на Handy за 14 дней = 0 (слово заказчика); (в) дефектов P0/P1 после v1.0 за 14 дней ≤ 2 (issues репо); (г) сборка deb — одна команда ≤ 5 мин (Ц7).
- **Срок проверки.** **2026-11-15** (14 дней после плановой даты v1.0). ProductManager возвращается к блоку в срок (P25), Юрка ставит напоминание.
- **Решение при недоборе (названо заранее).** (а) не достигнуто → менять рантайм (`sherpa-onnx` вместо `onnx-asr`) и/или дефолт на e2e_ctc — **развивать**; (б) > 0 откатов → разбор причин, откат на Handy до фикса, повторная проверка через 14 дней — **менять**; (г) не достигнуто → пересмотр упаковки в v1.1 — **менять**; если (а)+(б) провалены одновременно → **убрать**: проект парковать, Handy остаётся.

### F1. Установка и первый запуск (онбординг) — P0
**Описание.** Один deb-пакет; первый запуск проводит через 5 коротких экранов, каждый — один вопрос.
**Story.** Как П1, я хочу за несколько минут получить работающую диктовку, чтобы не читать инструкции.
**Бизнес-правила.**
1. Пакет `astra-voice_X.Y.Z_amd64.deb` ставится штатно (`apt install ./…`); зависимости — только из репозиториев Astra 1.8 плюс вендоренные python-пакеты внутри пакета; `postinst` **не выходит в сеть** и не запускает GUI.
2. Модели в пакет не входят. Пакет без моделей ≤ 80 МБ (допущение, проверить прототипом).
3. Онбординг показывается, если нет ни одной установленной модели **или** не завершён флаг `onboarding_done`. Возврат — из настроек «Пройти настройку заново».
4. Экраны: **(1) Приветствие и сеть** — язык интерфейса (ru/en, авто по `LANG`) и два тумблера «Проверять обновления утилиты» / «Проверять обновления моделей» (подпись: не чаще раза в сутки; хосты huggingface.co, github.com). **Оба тумблера пусты по умолчанию во всех профилях** — пользователь включает сам; пока не включил — утилита в сеть не выходит (кроме явного «Скачать» на экране 2). Требования заказчика №1/№4 (проверка при запуске) действуют после явного включения. Если `policy.conf` задаёт `offline=true`/`profile=secure`, тумблеры показаны заблокированными («Задано администратором»). **(2) Модель** — рекомендованная карточка сверху (GigaAM v3 RNN-T), остальные по размеру; кнопки «Скачать» (показывает хост и объём) и «Установить из файла/папки…»; шаг нельзя пропустить без модели. **(3) Горячая клавиша** — предзаполнена **`Ctrl+Space`, режим «удерживать» (push-to-talk)**; если на машине обнаружен Astra Cowork (F17.2) — вторая строка **«Команда помощнику»** со своей клавишей (предзаполнена **одиночная Win** — решение заказчика 2026-09-15, `decisions/log.md`; под строкой обязательная подпись простым языком: «Пока Astra Voice работает, клавиша Win не открывает меню приложений — она нужна для команды помощнику. Можно выбрать другую клавишу» и кнопка «Выбрать другую» (F17.10 (д)); переход дальше = согласие; `Ctrl+Alt+Space` от 14.09 не используется — на KDE заказчика занята и при остановленном Handy, пробник 15.09), обе проходят пробник и не могут совпадать (F17.4), без Cowork строки нет; поле захвата другой комбинации, переключатель «удерживать / нажать-нажать»; занятость проверяется живым `XGrabKey`-пробником **до** сохранения (F2.2): конфликт с шорткатом KDE — предупреждение с именем действия, не запрет; `BadAccess` от другой программы — сообщение и выбор из свободных комбинаций по F2-исключениям. **(3a) «Astra Voice заменяет Handy»** — показывается перед (3) только если обнаружен запущенный Handy (процесс `handy` или юнит `app-Handy@autostart.service`): объясняет, что обе утилиты держат `Ctrl+Space`, даёт инструкцию отключить хоткей в Handy или его автозапуск (ярлыки `handy.desktop`/`Handy.desktop` в `~/.config/autostart`), кнопки «Проверить снова» (повторный пробник) и «Пропустить»; в Handy утилита **ничего не меняет сама** — P1 (Should v0.1, Must v0.2; US-1.9). Текст экрана — простым языком, без путей и имён служб («отключите автозапуск Handy в его настройках или закройте Handy»); пути — в документации. Факт 2026-09-15: после перезагрузки Handy стартует раньше Astra Voice и снова держит `Ctrl+Space` — экран этого не лечит, лечит перезахват F2.11 (US-2.11): как только Handy закрыт, клавиша захватывается без перезапуска. **(4) Проверка микрофона** — выбор устройства, живой индикатор уровня, кнопка «Сказать тестовую фразу» → распознанный текст на экране (без вставки). **(5) Автозапуск** — тумблер (по умолчанию включён; без технических пояснений о ярлыках — решение заказчика 2026-09-09) и «Готово».
5. Каждый экран, кроме (2), можно пропустить; пропущенное доступно в настройках.
6. По завершении — окно сворачивается в трей, показывается системное уведомление «Astra Voice готов: зажмите <хоткей> и говорите».
**Исключения.** Нет сети на шаге 2 → карточки «Скачать» неактивны с текстом «Нет доступа к <хост>», активен «Установить из файла»; обрыв загрузки → докачка (F7); микрофон не найден → F6; ЗПС блокирует запуск воркера → текст «Часть компонентов не подписана для ЗПС — обратитесь к администратору (инструкция)».

### F2. Захват речи и горячие клавиши — P0
**Описание.** Глобальный хоткей в X11 (XGrabKey через `python3-xlib`), два режима: push-to-talk (удержание) и toggle (нажал — говоришь — нажал).
**Story.** Как П1, я хочу зажать клавишу и говорить, чтобы текст появился без мыши и переключения окон.
**Бизнес-правила.**
1. Режим по умолчанию — push-to-talk; toggle — второй режим (отдельная комбинация или переключатель режима в настройках).
2. Комбинация по умолчанию — **`Ctrl+Space`** для push-to-talk (как в Handy заказчика; решение 2026-09-07); toggle — второй режим на отдельной комбинации (по умолчанию не назначена, задаётся в настройках); занятость проверяется **реальным `XGrabKey`-пробником до записи настройки**: `kglobalshortcutsrc`/`kglobalaccel` видят только действия KDE и слепы к захватам X-клиентов (Handy, ibus/fcitx, Electron) — файл годится лишь на подсказку имени действия; альтернативы предлагаются из живого скана свободных комбинаций (каждый кандидат проверен тем же пробником, не по файлу; на машине заказчика по живым пробникам 2026-09-09 и 2026-09-15 (KDE, Handy остановлен) свободны `Ctrl+Shift+Space`, `Win+Space`, `Ctrl+Alt+D`, `Ctrl+Alt+V`; заняты `Ctrl+Alt+Space` (владелец — не Handy и не мы: в чистой X свободна, в конфигах KDE/Fly записи нет, кандидаты — демоны Fly в KDE-сеансе) и `Alt+Space` (KRunner); одиночная `Super_L` захватывается). Дефолт из-за Handy не меняется — Astra Voice его замещает (решение 2026-09-09). Ревизии 7–8: при обнаруженном Astra Cowork регистрируется **вторая** клавиша — режим «Команда помощнику» (F17; по умолчанию одиночная Win, F17.10); пробник, живой скан, исключения и повторный захват (п. 11) применяются к каждой клавише отдельно, пара дополнительно проверяется на несовпадение (F17.4).
3. Захват работает поверх любого X11-окна, не требует root и группы `input`; `evdev` — опциональный «надёжный режим» (P2).
4. Запись короче **0,3 с** игнорируется молча (случайное нажатие): без вставки, без ошибки, пилюля не показывается дольше 150 мс.
5. Лимит одной записи — **120 с** (настройка 30–300 с); по достижении — автостоп + распознавание + подсказка в пилюле «Достигнут лимит записи».
6. Фразы до 20 с распознаются одним куском; длиннее — сегментация по паузам (VAD) с сохранением порядка; лимит окна модели (24 с у GigaAM) не должен резать слова.
7. Аудиоустройство открывается **только при нажатии хоткея**, не при старте (гонка WirePlumber, F6). Опция «держать микрофон открытым 30 с после записи» — P1.
8. Отмена записи: `Esc` во время записи (пока хоткей зажат) или «×» в пилюле, или «Отмена» в трее — аудио отбрасывается, вставки нет.
9. Повторное нажатие хоткея во время распознавания — новая запись становится в очередь (максимум 1); вставка идёт в порядке записи.
10. Пока идёт распознавание, хоткей не блокируется; пока GUI-окно настроек в фокусе, хоткей работает так же (вставка пойдёт в поле настроек — допустимо).
11. **Повторный захват (ревизия 8).** Если при старте или после смены настройки клавиша занята (`BadAccess`), программа не останавливается на сообщении: повторяет попытку захвата **по таймеру** (раз в 30 с, пока трей в `nokey`; одна попытка `XGrabKey` укладывается в «CPU в покое» §8) и **по действию пользователя** (кнопка «Повторить» в уведомлении, пункт трея «Повторить захват клавиши», кнопка в «Общих»). Успех → трей «готов», одно уведомление «Горячая клавиша снова работает: <клавиша>»; неудача по таймеру — молча (без повторных уведомлений), неудача по действию — «Клавиша всё ещё занята другой программой». Тексты — простым языком, без имён служб и путей. Правило действует для каждой клавиши (F17.4) отдельно. Факт 2026-09-15: после перезагрузки Handy стартует раньше Astra Voice и держит `Ctrl+Space`; программа сообщила «занята» один раз и больше не пробовала — требовался перезапуск (US-2.11, S1-A9).
**Исключения.** Комбинацию не удалось захватить (`BadAccess`) → трей в состоянии `nokey` («Горячая клавиша не захвачена», иконка-кольцо — `design/spec.md` §9.1) + уведомление «Комбинация занята другой программой (возможно Handy или переключатель ввода)» с кнопками «Повторить» (п. 11) и «Выбрать другую» → список свободных комбинаций по живому скану (если занята действием KDE — с его именем); потеря X-соединения → перезахват при восстановлении; клавиша отпущена раньше, чем открылся микрофон → см. п. 4.

### F3. Индикация: пилюля, трей, звук — P0
**Описание.** Три канала: пилюля-оверлей с живым уровнем (по умолчанию включена, отключаемая), иконка трея с состояниями, опциональные звуки.
**Story.** Как П1, я хочу видеть, что микрофон меня слышит, чтобы не диктовать в пустоту.
**Бизнес-правила.**
1. Пилюля появляется ≤ 100 мс после нажатия, у нижнего края экрана по центру (настройка: снизу / сверху / выключена), поверх всех окон, **не забирает фокус** и не появляется в панели задач/Alt+Tab.
2. Состояния пилюли: «слушаю» (бирюза `#12B3A0`, столбики уровня), «распознаю» (нейтральный, пульс), «готово» (краткое подтверждение 500 мс — решение G2 2026-09-08, затем скрытие), «ничего не распознано» (1 с), «ошибка» (красный + короткий текст, 3 с, клик открывает подробности). Точные размеры/анимация — дизайн-спека. В режиме «Команда помощнику» подписи состояний другие («Слушаю команду…», «Отправляю помощнику…», «Передано помощнику», «Помощник недоступен — текст в буфере» — F17.6); режим различается подписью и значком, цветовой акцент — на усмотрение дизайн-спеки, но не единственный признак (§8 «Доступность»).
3. В пилюле есть «×» — отмена записи.
4. Иконка трея (SNI/`QSystemTrayIcon`): 4 состояния — «готов», «слушаю» (бирюза), «распознаю», «ошибка/микрофон недоступен» (красный). Тема иконки — по теме панели (светлая/тёмная). В панели Fly — SNI, если поддерживается, иначе XEmbed: перекраска под тему не требуется, состояние читается формой значка и подсказкой (S17-A3). Регистрация в трее с ретраем до 30 с после старта (гонка с панелью — KDE и Fly).
5. Звуки «начало/конец записи» — настройка, по умолчанию **выключены**; при отключении пилюли утилита один раз предлагает включить звук («Вы отключили индикатор — включить звуковой сигнал?»).
6. Отключение пилюли **не** отключает индикацию в трее: иконка «слушаю» обязательна всегда (запрет скрытой записи, §9.5).
7. Тема пилюли и окна — в KDE из `~/.config/kdeglobals` (не из палитры Qt), во Fly — из настроек темы Fly без `kdeglobals` (S17-A7; при невозможности определить — светлая + настройка «Тема: авто / светлая / тёмная»), применяется до первой отрисовки (без «вспышки светлой темы»).
**Исключения.** Композитор не даёт «поверх всех» → пилюля всё равно показывается (может быть перекрыта); трей недоступен > 30 с → окно настроек открывается само с баннером «Системный трей недоступен, приложение работает; закрыть окно = свернуть».

### F4. Распознавание (движок, воркер, модель) — P0
**Описание.** Инференс в отдельном процессе-воркере (`onnx-asr`), модель держится в памяти, GUI не блокируется и не падает вместе с ORT.
**Story.** Как П2, я хочу ту же скорость и качество, что в Handy с GigaAM, чтобы замена не была шагом назад.
**Бизнес-правила.**
1. Воркер — отдельный процесс; крах воркера не роняет GUI: автоперезапуск (до 3 раз за 10 мин), пользователю — ошибка в пилюле/трее.
2. Модель по умолчанию — GigaAM v3 e2e_rnnt int8. Активная модель загружается в память при старте в фоне (после готовности трея) и **держится в памяти постоянно** (решение заказчика 2026-09-07); выгрузка по простою — опция «выгружать после: 5 / 15 / 60 мин / никогда», по умолчанию «никогда».
3. Целевая задержка: «отпустил → текст» p95 ≤ 0,5 с (6-с фраза, эталонная машина, модель в памяти); холодный старт модели ≤ 5 с с индикацией «Загружаю модель…» в пилюле.
4. Потоки ORT — по умолчанию `min(4, физических ядер)`; настройка в «Продвинутых».
5. Результат — текст UTF-8 как выдала модель; единственная обработка: обрезка пробелов по краям, опция «пробел в конце» (по умолчанию вкл — допущение), опция «первая буква заглавной» для моделей без пунктуации (P1). Никакой LLM-постобработки. **Санитизация всегда:** `\r\n`/`\r`/`\n` → пробел, остальные управляющие символы (C0/C1, кроме табуляции → пробел) вырезаются до вставки; текст воркера ограничен 32 КиБ (T1 M4).
6. Пустой результат → «ничего не распознано», вставки нет.
7. Каждое распознавание пишет в локальную статистику `(model_id, audio_ms, t_ms, ts)`; первый прогон после загрузки помечается «холодным» и в медиану не входит.
8. После первого прогона каждой модели снимается `VmHWM` воркера → карточка получает «ОЗУ: N МБ (замерено на этом компьютере)».
9. **Самопроверка при загрузке модели — fail-closed (ревизия 8, P0 v0.1, M5).** После каждой загрузки модели в воркер (старт, смена модели, обновление ревизии, установка из сети или из файла) воркер распознаёт вшитый в пакет эталонный фрагмент (русская фраза ≤ 2 с, ожидаемые слова известны) **до того**, как модель объявляется готовой. Текст пустой или без ожидаемых слов → модель **не** становится активной для диктовки, трей «ошибка», уведомление простым языком: «Распознавание на этом компьютере не работает. Обратитесь к администратору» с кнопкой «Подробности» (в «Отладке»: тип процессора, версия движка, код проверки) — без слова «повреждена», если sha256 файлов сходится (это не порча файлов, а движок на этом процессоре); хоткей не начинает запись, пилюля при нажатии — «Модель не загружена». Бюджет: ≤ 1 с сверх времени загрузки на эталонной машине; результат — в локальной статистике `model_selfcheck` (§10). Контекст: на Intel Xeon с AMX движок onnxruntime 1.24.4 возвращает пустой текст молча (`research/tech-amx-int8.md`; три образца в CI 14.09) — проверка страхует от таких дефектов ядер, но **не заменяет** починку движка (спайки S6-a/S6-b, решение до R2). Смоук установщика (M5, О2: скачать → sha256 → эталонный wav → `current.json`) — тот же механизм на этапе установки; после обновления ревизии — F8.4.
**Исключения.** Модель не загрузилась (битый файл, несовпадение входов ONNX) → карточка «Повреждена — переустановить», активной становится предыдущая рабочая модель, если есть; самопроверка (п. 9) не прошла при сходящемся sha256 → «Распознавание на этом компьютере не работает», предыдущая рабочая модель остаётся активной, если была; нехватка ОЗУ (`MemoryError`/OOM) → ошибка «Недостаточно памяти для модели X (нужно ~N МБ)» и предложение более лёгкой модели из каталога.

### F5. Вставка текста в активное окно — P0
**Описание.** Через буфер обмена: сохранить буфер → положить `text/plain` → послать комбинацию вставки → восстановить буфер.
**Story.** Как П1, я хочу, чтобы текст оказался там, где курсор, в терминале, браузере и LibreOffice, а мой буфер обмена остался нетронутым.
**Бизнес-правила.**
1. В буфер кладётся **только `text/plain`** (без форматирования — LibreOffice вставит чистый текст без диалога). Клавиша Enter **никогда не синтезируется** (нет «авто-Enter» в v1); вставляется только санитизированный текст (F4.5).
2. Комбинация вставки — настройка: `Ctrl+V` (по умолчанию) / `Ctrl+Shift+V` / `Shift+Insert` / «не вставлять, только в буфер».
3. Задержка перед вставкой — настройка, по умолчанию 50 мс; после вставки через 100 мс восстанавливается исходное содержимое буфера (если оно было текстом; нетекстовое содержимое не восстанавливается — допущение, §12). Гарантия — **текст и типы `text/*`**, не побайтовая копия: менеджер буфера (Klipper) после смены владельца пересобирает набор прочих MIME-типов (S4 §2.8).
4. Автоопределение терминалов по `WM_CLASS`, метод вставки — по классу окна: VTE/konsole-подобные (`konsole`, `yakuake`, `fly-term`, `alacritty`; список редактируемый) → `Ctrl+Shift+V`; `xterm`, `rxvt` и неопознанные терминалы → `Shift+Insert` с текстом в PRIMARY (xterm не знает `Ctrl+Shift+V` — S4 §2.3; PRIMARY сохраняется и восстанавливается так же, как CLIPBOARD) — P1.
5. `xdotool type` (посимвольный ввод) — только как явно помеченный аварийный вариант в «Продвинутых» (кириллица ненадёжна) — P2.
6. Приватность буфера: опция «Не оставлять распознанный текст в истории буфера (Klipper)» — P1, реализация через `x-kde-passwordManagerHint`; до неё — честное предупреждение в настройках. Во Fly-сессии Klipper отсутствует — опция неактивна с подписью «нет менеджера истории буфера», обращений к Klipper нет (S17-A8).
7. Последний распознанный текст хранится **только в памяти** до выхода; «Скопировать последний текст» в трее; на диск не пишется (история — вне v1).
8. Перед показом пилюли запоминается активное окно (`_NET_ACTIVE_WINDOW`); вставка идёт в него, если оно ещё существует, иначе — в текущее активное. Пилюля никогда не активируется.
**Исключения.** Активного окна нет (рабочий стол) → текст только в буфере + пилюля «Скопировано в буфер»; окно не приняло вставку — утилита не может это узнать, поэтому текст остаётся в буфере 100 мс до восстановления; опция «оставлять текст в буфере» (не восстанавливать) — настройка.

### F6. Ошибки микрофона и аудио — P0
**Описание.** Микрофон открывается лениво; каждая ошибка ведёт к действию, а не в тупик; известная гонка WirePlumber диагностируется явно.
**Story.** Как П1, я хочу понять, почему меня не слышно, и починить это одной кнопкой.
**Бизнес-правила.**
1. Устройство ввода — настройка «Микрофон: системный по умолчанию / конкретное»; список — из PipeWire/ALSA.
2. Ошибки и тексты (русский, путь ALSE/KDE):
   - нет устройств: «Микрофон не найден. Подключите микрофон или гарнитуру и попробуйте снова» + кнопка «Обновить список»;
   - устройство занято/ошибка открытия: «Микрофон недоступен (код). Повторить» — ретрай 3 раза по 300 мс автоматически;
   - **тишина**: если за 2 с записи пик уровня < −60 дБ (порог настраиваемый) → пилюля «Микрофон молчит» и уведомление с кнопкой **«Перезапустить звуковую службу»** (`systemctl --user restart wireplumber`, без root) и ссылкой «Что это» (гонка при загрузке, профиль карты). После перезапуска — автоматическая повторная проверка уровня.
3. Первая запись после входа в систему при автозапуске: если открытие устройства не удалось — повторить через 1 с (до 3 раз) до показа ошибки.
4. Утилита никогда не пишет аудио на диск (ни временных wav); буфер записи живёт в памяти и очищается после распознавания или отмены.
5. **Смена микрофона во время записи (ревизия 8, Must v0.1, ИБ T2).** Программа замечает, что устройство записи сменилось **во время записи** (звуковая служба молча перевела поток на другое устройство: отключилась гарнитура или USB-микрофон, сменилось системное умолчание), не позднее чем через 1 с: запись **останавливается**, звук с нового устройства не используется; записанное до смены (если ≥ 0,3 с) распознаётся и вставляется как обычно; пилюля «Микрофон сменился» (3 с) и уведомление «Микрофон сменился. Сейчас используется: <название устройства, как его показывает система>» с кнопкой «Выбрать микрофон» (открывает «Общие»). Если в настройках выбрано конкретное устройство и оно пропало — то же поведение с текстом «Микрофон отключился», тихого перехода на другое устройство нет. Смена устройства **между** записями допустима, но перед первой записью с нового устройства один раз показывается уведомление «Микрофон: <название>». Тексты — без технических имён устройств и служб. Факт 2026-09-15 (T-56, живьём): при отключении устройства PipeWire перевёл поток на встроенный микрофон, запись продолжилась 4,2 с без ошибки и без уведомления, результат — пусто. ИБ: расширение У44/У45 (`docs/threat-model.md`) — триггер T2 `security-gate` для security-analyst; способ обнаружения (подпись устройства потока, события звуковой службы) — архитектор (A18).
**Исключения.** `wireplumber` не установлен/не отвечает → кнопка неактивна, текст «Обратитесь к администратору: служба звука не отвечает»; уровень есть, но результат пустой → «ничего не распознано» (это не ошибка микрофона); на PipeWire ошибка «нет устройства» при отключении микрофона практически не приходит (служба сама подменяет устройство) — обнаружение смены (п. 5) не должно опираться на ошибку открытия.

### F7. Каталог моделей — P1 (минимум для v0.1: одна встроенная модель по умолчанию)
**Описание.** Экран «Модели»: секции «Установленные» и «Доступные», карточки с честными цифрами, скачивание с докачкой и проверкой sha256, удаление, выбор активной.
**Story.** Как П2, я хочу видеть размер, память, качество и скорость каждой модели, чтобы выбрать под свою машину, а не гадать.
**Бизнес-правила — карточка (обязательные поля).**
| Поле | Правило |
|---|---|
| Имя и производитель | «GigaAM v3 RNN-T · Сбер»; чужие знаки — только как имена моделей |
| Назначение | одна фраза: «Русская диктовка с пунктуацией — по умолчанию» |
| Бейджи | «Рекомендуем», «Активна», «Новое» (появилась в каталоге ≤ 30 дней), «Обновление доступно» |
| Размер на диске | из манифеста, МБ (десятичные, одна единица во всём UI) |
| ОЗУ в работе | **три уровня достоверности**: «замерено на этом компьютере» (жирным; VmHWM воркера после первого прогона, дополнительно PSS из `smaps_rollup`), «заявлено автором» (обычным, со ссылкой), «оценка ~N» (серым; ориентир ×1,85 от int8-весов по единственной точке, реальный разброс 1,5–3× по Researcher #2 — поэтому только с «~»); до замера — справочное |
| Полоска «качество» | из WER на **одном наборе для всех** (Russian LibriSpeech, бенчмарк onnx-asr), `quality = clamp((30 % − WER) / 25 %, 0, 1)` — WER ≤ 5 % = полная полоска, ≥ 30 % = пустая, пороги показаны в «Как мы считаем»; подпись источника по клику; отдельный значок «пунктуация: да/нет» — качество и пунктуация не смешиваются |
| Полоска «скорость» | из RTFx: замеренная медиана по ≥ 5 прогонам на этой машине (жирным) либо бенчмарк x64 int8, пересчитанный коэффициентом машины (серым); шкала логарифмическая, RTFx 1 = 0 %, 60 = 100 %; текст «≈20× быстрее речи: фраза 6 с → 0,3 с». Нет int8-бенчмарка → подпись «по бенчмарку fp32»; нет данных по протоколу → полоска не рисуется, подпись «нет данных по протоколу» (до собственного замера, US-5.4) |
| Язык(и) | «Только русский» / «ru + kk/ky/uz/en» / «Многоязычная» |
| Лицензия | SPDX + правообладатель; CC-BY — значок «требует указания авторства» |
| Происхождение | «отечественная / зарубежная» — **по юрлицу правообладателя** (решение 2026-09-08, контекст Указа № 166); подпись может уточнять: «зарубежная · команда из России» (Vosk); используется фильтром «только отечественные», §9.4 |
| Статус | не скачана / скачивается (прогресс, скорость, «Отмена») / проверяется (sha256) / установлена / активна / обновление доступно / повреждена |
| Действия | Скачать · Установить из файла · Выбрать · Удалить · Обновить (если доступно) · «Подробнее» (ссылка на карточку HF, протокол замера) |
**Бизнес-правила — поведение.**
1. Загрузка во временный `.part` с докачкой по `Range` (продолжать только при 206 с корректным `Content-Range`; на 200 — сначала); URL закреплён на `/resolve/{revision}/…`, не на `main`; после завершения — размер и sha256 против манифеста, `fsync`, атомарный `os.replace`; модель хранится в каталоге `<ревизия>/`, активная ревизия — указатель `current.json` (откат = смена указателя); несовпадение → удалить и показать ошибку, не «доклеивать».
2. Источники по очереди: HF → GitHub Releases (наше зеркало) → корпоративный URL; переход к следующему при ошибке сети/429/404; отображается, откуда качаем. Запись каталога привязана к рантайму (`engine`): экспорт под `onnx-asr` (istupakov) и под `sherpa-onnx` (csukuangfj) — разные записи, не взаимозаменяемые.
3. Установка из файла/папки: те же файлы, та же проверка sha256 по манифесту; неизвестный набор файлов (нет в манифесте) → «Своя модель» без полосок, P2.
4. Удаление активной модели запрещено, пока не выбрана другая; удаление освобождает диск и снимает «замерено».
5. Выбор модели — переключение воркера с индикацией «Переключаю…»; пока идёт — хоткей работает на старой модели.
6. Перед скачиванием проверяется свободное место (размер × 1,2); недостаточно → ошибка с цифрами.
7. Проверка на минимальную ОЗУ машины: если `MemTotal` < `min_ram_mb` модели — предупреждение, не запрет.
8. Фильтр по языку (P2) и переключатель «только отечественные» (P1, автоматически в защищённом профиле).
9. Каталог всегда работает офлайн: встроенный манифест из пакета + последний скачанный; «нет сети» = состояние секции «Доступные» с кнопкой «Установить из файла», а не пустой список.
**Состав каталога v1** — §7.2. **Формат манифеста** — §7.3.
**Исключения.** Манифест с URL не прошёл подпись/схему → используется предыдущий, в статусной строке «Каталог не обновлён: <причина>»; диск заполнился во время загрузки → пауза, ошибка с кнопкой «Повторить» после освобождения места.

### F8. Проверка обновлений моделей при старте — P1
**Описание.** Раз в сутки, в фоне, не блокируя работу: (A) новая ревизия закреплённой модели; (B) обновлённый манифест каталога с новыми моделями; (C) сигнал «у автора вышла близкая модель».
**Story.** Как П2, я хочу узнавать при запуске, что вышла новая ревизия моей модели или близкая модель, чтобы не следить за HF вручную.
**Бизнес-правила.**
1. Работает только при включённом пользователем тумблере «Проверять обновления моделей» (по умолчанию выключен; онбординг, экран 1); в офлайн-режиме, при `policy.conf: offline` или `HF_HUB_OFFLINE=1` в окружении — никогда.
2. Не чаще **1 раза в 24 ч**, запуск через случайную задержку 0–30 мин после готовности GUI, общий таймаут 3 с, ≤ 1 повтор; при 429 — не повторять до конца окна; кэш `~/.local/state/astra-voice/update-cache.json`. User-Agent `astra-voice/X.Y.Z (+repo URL)`. Прокси — из окружения. В состоянии хранятся **раздельно** `last_attempt_at` («последняя попытка») и `last_success_at` («последний успех»); подсказка строки статуса показывает возраст последнего успеха («каталог проверен 12 дней назад») — freeze-атака (подмена сети, вечное «нет обновлений») остаётся остаточным риском, видимым пользователю (T1 У41/П2).
3. **(A) Новая ревизия.** Для активной и всех установленных моделей сравнивается коммит **нужной ветки** (`sha` из `GET /api/models/{repo}/revision/{branch}`, `targetCommit` из `/refs` или `X-Repo-Commit` в HEAD; для `ai-sage/GigaAM-v3` варианты = ветки, `main` не показатель) с `pinned_revision`. Отличие → бейдж «Обновление доступно» на карточке + строка внизу «Обновление модели: GigaAM v3 RNN-T» (нейтральный цвет) + одно системное уведомление. **Ничего не скачивается само.**
4. Установка обновления модели: по кнопке → скачать в staging → sha256 → **смоук-распознавание** вшитого тестового wav (ожидаемые слова) → атомарная подмена → старая ревизия хранится до следующего успешного запуска (откат кнопкой «Вернуть предыдущую», P2) ; провал смоука → откат автоматически + ошибка «Новая ревизия не прошла проверку, оставлена текущая».
5. **(B) Манифест.** Обновляется с `catalog_url` (наш GitHub raw/Release или корпоративный) по той же частоте; новые записи получают «Новое», удалённые из манифеста — остаются у пользователя, если установлены, с пометкой «снята с каталога». Новый манифест применяется только по правилу анти-отката §7.3 (`(trust_epoch, serial)` больше применённого); ревизии/модели из `revoked[]` нельзя активировать и на них нельзя откатиться — карточка «отозвана», предлагается обновление.
6. **(C) Близкая модель (P2).** Запросы `GET /api/models?author=<автор>&sort=lastModified&direction=-1` по белому списку авторов из манифеста (`update_watch.authors`: `ai-sage`, `csukuangfj`, `istupakov`; поиск по `author=salute-developers` **не** находит `ai-sage/GigaAM-v3` — Researcher #2); GitHub `salute-developers/GigaAM` без Releases и тегов — не источник. Новый репозиторий того же семейства (`giga-am`/`gigaam`), которого нет в манифесте → информационный баннер в «Моделях»: «У Сбера вышла новая модель: GigaAM-Multilingual (14.07.2026). В каталог Astra Voice ещё не добавлена» + ссылка. **Не устанавливается** из UI до появления в манифесте (веса могут иметь другие входы ONNX).
7. «Пропустить эту ревизию» — не напоминать про конкретный sha.
**Исключения.** Нет сети/DNS/таймаут → тихий пропуск, ничего не меняется в UI (кроме `last_attempt_at`; `last_success_at` не сдвигается — возраст успеха растёт и виден в подсказке); 429/403 → пропуск с backoff; ответ HF без `x-repo-commit` → считать «неизвестно», не считать обновлением.

### F9. Проверка и установка обновлений утилиты — P1 (трек без ЗПС), P2 (трек ЗПС)
**Описание.** Строка внизу окна (как у Handy) с тремя состояниями; установка — **только по явному действию** пользователя; два трека по среде; «обновить из файла» для офлайн.
**Story.** Как П2, я хочу увидеть внизу «Доступна версия X» и поставить её из утилиты; как П1 в контуре с ЗПС — скачать пакет и передать администратору.
**Бизнес-правила.**
1. Источник — GitHub Releases API `releases/latest` (или `latest.json` с корпоративного URL); `tag_name` нормализуется (один префикс `v`) и сравнивается как SemVer с `__version__` пакета; `ETag`/`If-None-Match`, лимит анонима GitHub 60 запросов/час на IP. Только при включённом пользователем тумблере «Проверять обновления утилиты» (по умолчанию выключен); ≤ 1 раза в 24 ч; при старте — сначала показывается **кэшированный** результат, свежая проверка — в фоне с задержкой 0–10 мин; ручная кнопка «Проверить сейчас» — без ограничения частоты, но с уважением 429. Никаких токенов в клиенте.
2. Состояния строки: «Проверяю обновления…» → «Установлена последняя версия» (только при ручной проверке, 3 с) / **«Доступна версия X.Y.Z»** (единственный цветовой акцент внизу) / «Проверка обновлений отключена» / **«Источник обновлений недоступен»** (не молчать) / «Загрузка… 42 %» / «Установка…» / «Перезапустить».
3. Клик по «Доступна версия» → панель: «Что нового» (из тела релиза), размер, и действия по треку:
   - **Трек A (без ЗПС, пользователь может пройти polkit):** «Скачать и установить» → скачать `.deb` + `SHA256SUMS` + подпись в `~/.cache/astra-voice/updates/` → проверить sha256 и подпись релиза (keyring вшит в пакет; `gpgv` — только `VALIDSIG` с пином fingerprint, §9.2) → **один** вызов root-помощника `/usr/libexec/astra-voice/update-helper` через `pkexec` с собственным polkit-действием (`auth_admin`, одно окно пароля агента polkit текущей сессии — KDE или Fly); помощник копирует пакет в root-staging, **повторно** проверяет подпись/sha256/имя пакета/архитектуру/повышение версии и выполняет `apt-get install --no-remove ./astra-voice_X.Y.Z_amd64.deb` → «Установлено. Перезапустить сейчас / позже». Если агент polkit не запущен — «Не найден агент авторизации (KDE: polkit-kde-authentication-agent-1; Fly: агент polkit Fly)» + подсказка «Обновить вручную: sudo apt install ./…»; первая установка — штатным apt (помощник появляется с первым пакетом).
   - **Трек B (ЗПС включена, или нет прав администратора, или `policy.conf: updates=admin`):** «Скачать пакет для администратора» → те же файлы + `INSTALL-ADMIN.md` (инструкция: проверка подписи релиза, `apt install`; при включённой ЗПС — подпись ELF/`.so` по процедуре заказчика; в v1 артефакты **не** подписаны ГОСТ-ключом на сборке — это v1.1) → «Открыть папку» + текст «Установку выполняет администратор. Подпись пакета проверена». Кнопки «Установить» **нет**.
   - Всегда: «Пропустить эту версию», «Напомнить позже».
4. Определение трека: ЗПС = `DIGSIG_ELF_MODE ≠ 0` (если файл конфигурации читаем) **или** `policy.conf: zps=on`; при невозможности определить — вопрос пользователю «На этом компьютере включена замкнутая программная среда? Да / Нет / Не знаю (→ трек B)». Права = членство в `astra-admin`/`sudo`.
5. **Никогда**: тихая установка, установка без проверки подписи, установка при несовпадении sha256 (файл удаляется, ошибка «Пакет не прошёл проверку»), запуск `dpkg -i` (только `apt-get install ./файл`), привязка polkit-действия напрямую к `/usr/bin/apt` (произвольные аргументы), `auth_admin_keep`, JS-правила в `/etc/polkit-1/rules.d`. Также никогда: `apt-get --allow-unauthenticated`, принятие подписи по `GOODSIG`/коду возврата без `VALIDSIG` и пина fingerprint (§9.2).
6. «Обновить из файла…» (меню строки и «О программе»): выбрать `.deb` (+ рядом `.sig`/`SHA256SUMS`) → та же проверка → трек A/B. Без валидной подписи GUI **отказывает** и подсказывает штатный `apt` администратору.
7. После установки автоперезапуск не делаем без согласия: кнопка «Перезапустить».

### F17. Режимы диктовки: «Текст» и «Команда помощнику» — P1 (беклог; запрос заказчика 2026-09-14; релиз — **v1.0**, досрочно v0.2 при зафиксированном контракте Cowork — §12.1 В2; клавиша «Команда» = **одиночная Win, жёсткий перехват** — решение заказчика 2026-09-15, п. 10; спайк S7 и ИБ T2 до реализации)
**Описание.** Две горячие клавиши — два адресата распознанного текста. Режим **«Текст»** — как сейчас (F2–F5): вставка в активное окно. Режим **«Команда помощнику»** — распознанная фраза уходит помощнику Astra Cowork одной командой и **в активное окно не вставляется**. Второй режим существует только на машинах, где обнаружен Astra Cowork («артефакты Agentic OS»). Astra Voice остаётся «микрофоном»: текст не толкует и не исполняет (§11), ответ помощника показывает сам Cowork.
**Story.** Как П2 с установленным Astra Cowork, я хочу зажать вторую комбинацию и произнести команду помощнику, чтобы она ушла ему сразу — без открытия окна Cowork и без вставки в чужое поле.
**Бизнес-правила.**
1. **Режимы и адресаты.** Каждая комбинация привязана к режиму: «Текст» → вставка (F5); «Команда помощнику» → доставка помощнику (п. 5). Способ захвата (удерживать / нажать-нажать) — общая настройка F2.1 для обеих комбинаций; отдельная toggle-комбинация F2.2 остаётся необязательной третьей. Захват речи, VAD, лимиты, отмена (`Esc`/«×»/трей), очередь — F2.4–F2.10 без изменений в обоих режимах.
2. **Обнаружение Astra Cowork.** «Установлен» — есть хотя бы один артефакт: исполняемый файл `astra-cowork` в `PATH` пользователя, ярлык `astra-cowork.desktop` (системный или в `~/.config/autostart/`), пользовательский юнит `astra-cowork-daemon.service` (допущение A13). «Доступен» — помощник запущен и отвечает по своему локальному контракту; точный механизм (D-Bus-объект помощника или локальный REST/сокет; в памяти проекта Astra Cowork — локальный шлюз `127.0.0.1:8765` и единое окно ввода) — **решают архитекторы обоих проектов**, PRD фиксирует только требования п. 5–8. Проверка «установлен» — при старте и при открытии настроек/онбординга; «доступен» — при каждом нажатии командной комбинации (ответ ≤ 300 мс, иначе «недоступен»). Фоновых опросов помощника в простое нет (§8 «CPU в покое»).
3. **Без Cowork — без второго режима.** Если Cowork не установлен: вторая комбинация **не регистрируется** (`XGrabKey` не вызывается), строка настроек «Команда помощнику» показана неактивной с подписью «Astra Cowork не установлен», экран онбординга (3) вторую строку не показывает. Появление Cowork после установки подхватывается при следующем старте или по кнопке «Проверить снова» в настройках.
4. **Две комбинации.** Обе проходят живой `XGrabKey`-пробник до сохранения (F2.2, US-1.5b); совпадающие комбинации запрещены («Уже используется для режима «Текст»»); при `BadAccess` любой из них — сообщение и выбор из живого скана; отказ одной не мешает другой (трей `nokey` называет режим). Значения по умолчанию: «Текст» — **`Ctrl+Space`** (без изменений, решение 2026-09-14); «Команда помощнику» — **одиночная клавиша Win** (решение заказчика 2026-09-15, `decisions/log.md`; рекомендация Юрки `Win+Space` отклонена — «безо всяких Win+Space»; правила перехвата — п. 10). Дефолт 14.09 `Ctrl+Alt+Space` **снят**: живой пробник 2026-09-15 на KDE заказчика при остановленном Handy — занята (владелец — не Handy и не мы: в чистой X свободна, в `kglobalshortcutsrc`/`kglobalaccel`/`keyshortcutrc` записи нет; кандидаты — демоны Fly в KDE-сеансе). Тем же пробником: `Alt+Space` — KRunner; `Ctrl+Shift+Space`, `Win+Space`, `Ctrl+Alt+D`, `Ctrl+Alt+V` — свободны; одиночная `Super_L` захватывается. Занятость Win при старте → повторные попытки захвата по F2.11. Рассмотренные и отвергнутые варианты, факты — §12.1 В1.
5. **Доставка команды.** Команда — распознанный и санитизированный текст (F4.5) **целиком одной строкой** (VAD-сегменты склеены по порядку, переводов строки нет), с меткой источника «Astra Voice»; отправляется **после** окончания записи и распознавания, не по частям. Команда должна появиться в Astra Cowork так, как если бы пользователь ввёл её в окно ввода помощника (видна в его чате/задачах; подтверждения и исполнение — по правилам Cowork, Astra Voice их не обходит и своих не добавляет). В активное окно текст **не вставляется**, буфер обмена при успешной доставке **не трогается**. Ответ помощника Astra Voice не ждёт и не показывает.
6. **Индикация.** Пилюля и трей различают режимы **подписью и значком**, а не только цветом (§8 «Доступность»): «Слушаю команду…» (столбики уровня как в «Текст»), «Распознаю…», «Отправляю помощнику…», «Передано помощнику» (подтверждение доставки, 800 мс), «Помощник недоступен — текст в буфере» (3 с, клик — подробности). Подсказка трея во время записи — «Слушаю команду». Цветовой акцент режима — дизайн-спека (UXAnalyst), не единственный признак.
7. **Недоступность помощника.** Cowork установлен, но не отвечает (не запущен, таймаут, ошибка контракта) → распознанный текст кладётся в буфер обмена (`text/plain`, прежнее содержимое не восстанавливается — как «только буфер» F5.2), пилюля «Помощник недоступен — текст в буфере», уведомление с кнопками «Открыть Astra Cowork» (запуск ярлыка) и «Что случилось». Вставки в активное окно нет ни при каком исходе командного режима.
8. **Приватность.** Команда не логируется (F14.6, §8 «Приватность»): в логах — длина, тайминги, код результата; в статистике — `dictation` с `mode=command` без текста (§10). Передача — только локальному процессу на этой машине по локальному транспорту; ни один сетевой хост не добавляется (Ц4, F14.1). Дальнейшая судьба команды (модель, облако, журнал) — зона ответственности Astra Cowork и его политики; в «Приватность» утилиты — одна фраза об этом. Новая локальная IPC-поверхность к агенту, который исполняет действия в ОС, — триггер T2 `security-gate` при проектировании.
9. **Настройки.** «Общие»: строка «Команда помощнику» — клавиша + состояние («Astra Cowork найден · доступен» / «найден · не запущен» / «не установлен»), кнопка «Проверить снова»; под строкой — та же подпись о Win и кнопка «Выбрать другую», что в онбординге (п. 10 (д)). Опция «Показывать команду перед отправкой» (пилюля с текстом 3 с, `Esc` — отмена) — **P2**, по умолчанию выключена (заказчик просит скорость).
10. **Одиночная Win — жёсткий перехват (ревизия 8; решение заказчика 2026-09-15).**
   (а) Пока программа работает и Cowork найден, клавиша Win (левая, `Super_L`; правая — по выбору в настройках) принадлежит Astra Voice **безусловно**: тап по Win **не открывает** меню приложений KDE (KWin, «только модификатор») и старт-меню Fly (`fly-wm`); никакого «умного» пропуска тапа в систему нет. После выхода из программы — штатного или аварийного — меню возвращается; восстановление обязательно и при крахе (сторож как у У47).
   (б) Удержание Win ≥ 0,3 с = запись команды (push-to-talk); тап < 0,3 с игнорируется по F2.4 — ни записи, ни меню; в режиме «нажать-нажать» тап начинает и завершает запись.
   (в) `Win+<клавиша>` (`Win+D`, `Win+V`, `Win+E`, `Win+Tab` и прочие сочетания KDE/Fly): **во время записи команды не срабатывают** как системные действия и не попадают в чужие окна; **вне записи** работают как без нас (сочетание, нажатое в первые 0,3 с после Win, — системное, без записи; A17) — механизм подтверждает спайк S7.
   (г) Win нельзя захватить (`BadAccess`) → как для любой клавиши (п. 4, F2.11): повторные попытки, замена по живому скану, «Текст» работает независимо.
   (д) Онбординг (экран 3) и «Общие» **объясняют** последствие простым языком («Пока Astra Voice работает, клавиша Win не открывает меню приложений — она нужна для команды помощнику») и дают **сменить клавишу одним действием** («Выбрать другую»: живой скан, первыми в списке `Win+Space` и `Ctrl+Shift+Space`); продолжение онбординга = согласие, повторных вопросов нет; смена применяется без перезапуска (F11.7).
   (е) Без Cowork Win не захватывается вовсе (п. 3) — на машинах парка без помощника меню по Win не меняется.
   (ж) ИБ: перехват системной клавиши — триггер T2 `security-gate` при проектировании (блокировка/подмена системных сочетаний, залипший захват при зависании программы, восстановление после `kill -9`).
   (з) **Спайк S7** (`arch/spikes/S7.md`; до реализации F17; не путать со сценарием S7 §6): 1) KDE — подавляет ли наш захват `Super_L` меню KWin «только модификатор» (KWin следит за модификатором сам, не через захват); если нет — на время работы программы отключать эту настройку KWin с возвратом при выходе, с согласия пользователя в онбординге; 2) Fly — то же для старт-меню `fly-wm`; 3) поведение `Win+<клавиша>` при удержании Win (в); 4) возврат меню после `kill -9` и зависания.
**Исключения.** Cowork установлен, но нет `~/.config/astra-cowork/` (не настроен) → считается «не запущен» (п. 7); Win занята другой программой при старте → п. 10 (г); пользователь выбрал под «Команду» сочетание с Win (`Win+Space`) → обычная комбинация по п. 4, ограничения п. 10 (а)/(в) не действуют, меню по тапу Win работает; команда пустая или запись короче 0,3 с → как F2.4, помощнику ничего не уходит; отмена во время «Отправляю…» — если запрос уже ушёл, команда доставляется (пилюля не обещает отмену после отправки); обе комбинации нажаты одновременно → приоритет у первой нажатой, вторая игнорируется до отпускания; контракт помощника изменился (ошибка версии) → «Помощник недоступен» + код в лог.

### S18. Режим «Команда помощнику» (F17, F2, F3; запрос заказчика 2026-09-14; релиз v1.0 / досрочно v0.2 — §12.1 В2)
Клавиши по умолчанию: «<Текст>» = `Ctrl+Space`, «<Команда>» = **одиночная Win** (решение заказчика 2026-09-15; `Ctrl+Alt+Space` от 14.09 снята — занята на KDE заказчика и при остановленном Handy); в acceptance — обозначения ролей, чтобы сценарий не зависел от переназначения пользователем. - **A1 (Cowork есть).** Given на машине установлен и запущен Astra Cowork, утилита в трее, курсор в поле Kate, When зажимаю <Команда>, говорю «Открой папку загрузки» и отпускаю, Then пилюля ≤ 100 мс «Слушаю команду…» (столбики + подпись режима), затем «Распознаю…» → «Отправляю помощнику…» → «Передано помощнику» (800 мс); в Kate ничего не вставлено; буфер обмена не изменён; в Astra Cowork команда видна как введённая пользователем с источником «Astra Voice»; событие `dictation{mode=command, result=delivered}`; в логах текста команды нет.
- **A2 (Cowork нет).** Given Astra Cowork не установлен (нет `astra-cowork` в `PATH`, ярлыка `astra-cowork.desktop` и юнита `astra-cowork-daemon.service`), When утилита стартует и открываю «Общие», Then вторая комбинация не захвачена (`XGrabKey` не вызывался — проверка в изолированном X), строка «Команда помощнику» неактивна с подписью «Astra Cowork не установлен», в онбординге экран 3 показывает одну комбинацию; нажатие бывшей <Команда> уходит в систему как обычная клавиша (тап по Win открывает меню приложений, как без нас).
- **A3 (недоступен).** Given Cowork установлен, но `astra-cowork-daemon.service` остановлен, When диктую команду по <Команда>, Then ≤ 300 мс после распознавания пилюля «Помощник недоступен — текст в буфере» (3 с), текст в буфере обмена, уведомление с «Открыть Astra Cowork»; в активное окно не вставлено; `dictation{mode=command, result=undelivered}`.
- **A4 (режимы по хоткеям).** Given обе комбинации захвачены, When диктую одну фразу по <Текст>, затем другую по <Команда>, Then первая вставлена в активное окно и в Cowork не ушла, вторая ушла в Cowork и не вставлена; пилюля в первом случае «Слушаю», во втором «Слушаю команду…»; подсказка трея соответствует режиму.
- **A5 (две комбинации через пробник).** Given экран 3 онбординга или «Общие», When ввожу для <Команда> ту же комбинацию, что у <Текст>, Then сохранение запрещено с текстом «Уже используется для режима «Текст»»; When ввожу комбинацию, занятую другой программой, Then `BadAccess` до сохранения и живой скан — как S1-A4, для каждой комбинации отдельно; When <Команда> не удалось захватить при старте, Then <Текст> работает, трей `nokey` называет режим, уведомление «Выбрать другую» относится к нему (US-11.2).

- **A7 (приватность и сеть).** Given `tcpdump` за сессию с 20 командами, Then исходящих соединений процесса нет (локальный транспорт); в `~/.local/state/astra-voice/` и логах — ни одной строки с текстом команды.
- **A8 (Fly).** Given Fly-сессия, Then A1–A6 и A10–A12 повторяются с теми же ожиданиями (S17-A1); Win проходит тот же живой пробник, старт-меню Fly по Win во время работы программы не открывается и возвращается после выхода (F17.10 (а), спайк S7; `keyshortcutrc` использует Mod4 только с F5 и Shift+</> — A15); если пользователь выбрал `Alt+Space`, пробник показывает конфликт с `FLYWM_POPUP_MENU` по имени действия из `keyshortcutrc` (US-1.5b, F2.2).

- **A3.** Given настройка, требующая перезапуска (например, язык интерфейса, если архитектор не сделает живую смену), When меняю её, Then значение сохранено сразу, под контролом подпись «Вступит в силу после перезапуска» и кнопка «Перезапустить».

- **A5 (регресс на факт 15.09).** Given любой контрол каждого раздела окна, When меняю его и перечитываю файл, Then значение в файле совпадает с контролом — автотест обходит все контролы (переключатель индикатора не записывал `pill_enabled`).

### S20. Самопроверка модели при загрузке (F4.9; контекст `research/tech-amx-int8.md`)
- **A1 (штатно).** Given машина заказчика (Core Ultra 7), When модель загружается (старт, смена, обновление, установка), Then до объявления готовности воркер распознал эталонный фрагмент из пакета, ожидаемые слова найдены, готовность объявлена не позже чем на 1 с позже, чем без проверки; `model_selfcheck{result=ok}`.
- **A2 (дефектный движок на этом процессоре).** Given процессор, на котором движок возвращает пустой текст (Intel Xeon с AMX, onnxruntime 1.24.4 — три образца в CI 14.09), When модель загружается, Then текст эталона пуст → модель **не активна** для диктовки, трей «ошибка», уведомление «Распознавание на этом компьютере не работает. Обратитесь к администратору» с «Подробности» (тип процессора, версия движка, код проверки) — без слова «повреждена»; нажатие хоткея не начинает запись, пилюля «Модель не загружена»; `model_selfcheck{result=fail}`; sha256 файлов при этом сходится.
- **A3 (смоук установщика, M5 О2).** Given установка или обновление модели, When файлы скачаны и sha256 сошёлся, Then та же проверка выполняется до записи указателя активной ревизии; провал → модель помечена «не прошла проверку на этом компьютере», прежняя активная остаётся (F8.4).
- **A4 (предыдущая модель).** Given была рабочая активная модель, When новая не прошла самопроверку, Then прежняя остаётся активной и диктовка работает без перезапуска.

**Версионирование и отзыв (T1 §4.3, У5/У33).** `serial` (целое, монотонное) и `trust_epoch` — **обязательные** поля подписанного манифеста; `generated_at` остаётся для UI и обязан не убывать. Правило применения: новый манифест принимается только при `(trust_epoch, serial)` **строго больше** применённого; равный — только с тем же sha256 файла (no-op); меньший — отказ «каталог старее текущего» в строке статуса (и в логе). Встроенный в пакет манифест и скачанный сравниваются тем же правилом — берётся больший. Массив `revoked[]` — ревизии/модели, которые **нельзя активировать и на которые нельзя откатиться** (проверяется при выборе модели, при «Вернуть предыдущую» и при старте); отзыв доставляется манифестом и `trust.json` (§9.2). Состояние применённого манифеста — `~/.local/state/astra-voice/catalog-state.json` (`trust_epoch`, `serial`, `sha256`, `last_attempt_at`, `last_success_at`), **не** в очищаемом `~/.cache`. Expiry манифеста не вводится (офлайн-инсталляции и трек B живут месяцами; freeze-атака — принятый остаточный риск, F8.2). Дубли ключей JSON, повторы `id`/`path`, `..`/абсолютные пути/NUL в `files[].path` → отказ манифеста целиком.

## 9. Безопасность и комплаенс

### 9.1 Целостность моделей
Каждый файл — sha256 из манифеста (для HF — `lfs.oid`), проверка до `rename`; закреплённые ревизии (`pinned_revision`); смоук-тест после обновления ревизии с автоматическим откатом; манифест подписан (наш ключ вшит; корпоративный — из `policy.conf`). Runtime-загрузка модели трактуется как supply-chain-изменение, а не «данные». Ревизии из `revoked[]` манифеста/`trust.json` не активируются и не восстанавливаются откатом; манифест — с анти-откатом по `(trust_epoch, serial)` (§7.3). Перед `InferenceSession` — проверка ONNX-protobuf: `external_data.location` только внутри каталога ревизии и ⊆ `files[]`, лишние файлы в каталоге ревизии → отказ загрузки (T1 M2).

### 9.2 Подпись релизов и проверка перед установкой
**Инструмент — GPG (Ed25519), проверка `gpgv --status-fd 1 --keyring <абсолютный путь>`**: успех **только** при строке `VALIDSIG <fpr> … <fpr_primary>`, где fingerprint подключа ∈ `PINNED_FINGERPRINTS` ∧ ∉ `REVOKED_FINGERPRINTS` **и** fingerprint первичного (мастер-) ключа ∈ `PINNED`; `GOODSIG` и код возврата — недостаточно. `gpgv` **не проверяет expiry и отзыв ключей** (`man gpgv` 2.2.40) → отзыв реализуется списком в коде (`REVOKED_FINGERPRINTS`) **и** файлом `trust.json`. Один модуль проверки (`security/verify.py`, `Verifier(purpose)`) для релиза, deb «из файла», манифеста каталога и корпоративного `catalog_pubkey`; keyring и списки fingerprint — в одном пакете, root-owned. **Схема ключей:** офлайн-**мастер** (cert-only) у заказчика; подключ подписи **S1** (expiry 12 мес) — в GitHub Environment `release` (required reviewer, только job по тегу `v*`); keyring в пакете = мастер-pub + S1 + **заранее сгенерированный S2** (закрытая часть офлайн, не в CI) → плановая ротация без внешнего канала (релиз N+1 подписан S2, keyring N+1 = мастер + S2 + S3). **`trust.json`** `{trust_epoch, allowed[], revoked[]}` (fingerprint'ы) подписан **офлайн-мастером** (fingerprint мастера — константа в коде), проверяется тем же `gpgv`, `trust_epoch` монотонен; хранится в `/var/lib/astra-voice/trust/` (root, пишет помощник) и `~/.local/state/astra-voice/` (GUI); поставляется в `.deb` **и** принимается «из файла» администратором («Сеть и обновления → Доверенные ключи → Импортировать trust.json») — отзыв доставляется без установки пакета. Компрометация S1: `trust.json` с новым epoch и `revoked=[S1]`, релиз, подписанный S2, с keyring без S1, `REVOKED_FINGERPRINTS += S1`, каталог переподписан S2, объявление с fingerprint в README/Release; окно уязвимости до установки этого релиза — принято, смягчение — трек B с ручной проверкой fingerprint администратором. `SHA256SUMS.asc` подписывает файл сумм; имя `.deb` в нём должно совпадать с ожидаемой версией. Проверка обязательна и для «обновить из файла»; **ровно один привилегированный шаг**: собственное polkit-действие (`auth_admin`, без `_keep`) привязано к root-помощнику `/usr/libexec/astra-voice/update-helper`, а не к `/usr/bin/apt`; помощник повторно проверяет подпись/sha256/имя/архитектуру/версию на копии в root-staging (`O_NOFOLLOW`, `O_EXCL` + `flock`) и выполняет `apt-get install --no-remove` **без** `--allow-unauthenticated`; политика ставится из deb в `/usr/share/polkit-1/actions/`, JS-правила в `rules.d` не поставляются; никакого `dpkg -i`; первая установка — штатным apt. **`docs/SECURITY.md` — обязательный артефакт каждого релиза** (в репо и в пакете): владелец мастера, календарь ротации, действия при компрометации, канал сообщений об уязвимостях и срок реакции — закрывает ФСТЭК № 239 п. 29.3.3.

### 9.3 Трек ЗПС
**В v1.0 (заказчик 2026-09-07):** детект `DIGSIG_ELF_MODE`/`policy.conf: zps`, трек B «скачать пакет и передать администратору» (S10), документ для администратора; собственные ELF/`.so` (onnxruntime/движок, помощник обновления — ориентировочно 2–5 объектов, A11) в v1 **не подписаны** ГОСТ-ключом на сборке — на машине с ЗПС их подписывает интегратор/администратор заказчика по своей процедуре (`INSTALL-ADMIN.md`). **После v1.0 (v1.1, Ц5):** подпись всех собственных ELF/`.so` на сборке (`bsign-integrator`, ключ организации), открытый ключ и регистрация админом, `postinst` ничего не подписывает на месте, прогон на ВМ с ЗПС (P21½). Минимизировать число собственных ELF (Python поверх системного Qt) — действует с v0.1.

### 9.4 Профиль «защищённый контур» (приказы ФСТЭК № 117/239, Указ № 166)
`profile=secure`: тумблеры проверок заблокированы в выключенном состоянии (во всех профилях они выключены, пока пользователь не включил), установка — только администратором, офлайн-путь для моделей и утилиты, `domestic_only=true` (зарубежные по юрлицу правообладателя модели скрыты из каталога: Whisper, FastConformer и обе версии Vosk — Alpha Cephei Inc., США), закреплённые ревизии, документ «Влияние на среду функционирования ALSE» для администратора ИБ (tech-writer, до пилота). Установка обновления **всегда** по явному действию пользователя/администратора — тихой автоустановки не существует ни в одном профиле.

### 9.5 Запреты функциональности (явно, L8/L9 из `research/legal.md`)
Утилита **не содержит и не будет содержать в v1**: диаризацию и распознавание говорящего; «профиль голоса», голосовую аутентификацию/разблокировку; wake-word, привязанный к сотруднику; хранение аудио, аудио-сниппетов и эмбеддингов голоса; телеметрию, crash-dumps, «отправить отчёт» на любой сервер, собственный сервер обновлений с логами; скрытую запись микрофона (запись только по хоткею, всегда с индикацией в трее); автозапуск без видимого UI/иконки; эксфильтрацию текста/аудио; обход СЗИ. Появление любого из этого = новое правовое заключение (разработчик становится оператором ПДн).

### 11.1 Известные ограничения выпуска v0.1 (ревизия 8; обязательны в заметках к выпуску, `changelog-writer`)
- **Серверные Intel Xeon с AMX пока не поддерживаются** (Sapphire/Emerald/Granite Rapids — Xeon Platinum 8573C, Xeon 6973P-C и подобные): движок onnxruntime 1.24.4 возвращает пустой текст (`research/tech-amx-int8.md`; `decisions/log.md` 2026-09-14, три записи). С F4.9 программа сообщает об этом понятной ошибкой при загрузке модели вместо тихой пустоты.
