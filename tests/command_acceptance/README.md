# Независимая приёмка Voice Command1

Источник требований: `docs/contracts/astra-cowork-command1.md` 1.7,
JSON-вектора и PRD F17/US-2.10. Эта зона добавлена независимым tester;
реализация находится вне её области изменений.

Приоритетные сценарии, отсутствовавшие на базе `a23095f`:

| Риск | Наблюдаемое доказательство |
|---|---|
| Незаметный сетевой адрес после unix | Проверяется каждый адрес; смешанный список отклонён |
| Переполнение времени после долгого uptime | Настоящий D-Bus получает положительные временные поля `x` |
| Таймаут принятой команды ошибочно объявлен отказом | `unknown`, один Submit, поздний ответ не даёт второй исход |
| Самозванец выдаёт ошибку после эффекта | Только полные имена allowlist означают отказ; `Failed`/чужой NoReply неизвестны |
| Неверный ответ подтверждает чужую команду | Эхо request_id и карта ответа проверены |
| Discovery отнимает бюджет доставки | Единственный срок 300 мс, до Submit учитывается очередь |
| Блокировка до/после отправки | Нет публикации и UI; текст сохранён только в памяти |
| Сон и поздний accepted после resume | Поздний callback отброшен, автоматического повтора нет |
| Ручная/отозванная модель | Нет Submit; текст остаётся доступен пользователю |
| Успех загрязняет буфер/отказ вставляет текст в окно | Accepted не вызывает publish; fallback только буфер |
| Ошибка буфера теряет фразу | clipboard_failed и ручное восстановление из памяти |
| Разовый Unlock ошибочно открывает публикацию | Нужен подтверждённый снимок unlocked |
| Нормализация расходится по Unicode/Python | Явные запрещённые диапазоны 15.1 и осмысленный текст |
| Скрытый запуск службы/опрос Status | Шина без service activation; Submit не вызывает Status |
| Секрет из reason/error утёк в журнал | Контрольная фраза отсутствует в DEBUG и статистике |

Старый ключ политики `command_hotkey` отменён в 1.7. Эти проверки не
требуют его наличия и не возвращают администраторское управление клавишей.
Дедуп Cowork — серверная ответственность; клиент обязан не повторять Submit.
Тесты SHA контрактных копий уже существуют и здесь не дублируются.

Private bus сценарии используют `tests/helpers/private_bus.py`:
`dbus-run-session` с конфигурацией без путей активации служб и offscreen,
без DISPLAY, без пользовательской шины. После каждого сценария проверяется
отсутствие оставшихся процессов его группы. Фейковый сервер сохраняет только
типы, сроки и счётчики; распознанный текст в trace не записывается.

Живые микрофон, X11-хоткеи, KDE/Fly, блокировка экрана, реальная installed dev5,
история Klipper и производительность ASR этим набором не проверяются.

Запуск обоими штатными способами (одинаковая test-only настройка импортов):

```sh
QT_QPA_PLATFORM=offscreen DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent \
  /home/astra/.cache/astra-voice-dev/venv-a/bin/pytest tests/command_acceptance -m unit
MYPYPATH=src /home/astra/.cache/astra-voice-dev/venv-a/bin/mypy tests/command_acceptance
/home/astra/.cache/astra-voice-dev/venv-a/bin/ruff check tests/command_acceptance
```

Для собственного unix socket песочнице нужен доступ к сокетам. Private-bus
helper всё равно убирает DISPLAY и адрес пользовательской шины.
Типизированный login1 wire peer использует необязательные `dbus-python` и `gi`;
при их отсутствии только этот сценарий явно пропускается, остальные работают
на имеющемся Qt5. Ни peer, ни клиент сценария не используют системную шину.

Оркестрация и runtime используют существующие фейковые hardware factories
из `tests/unit/test_dictation.py` и `test_runtime.py`, с независимыми сценариями
и проверками результата. `start_command_mode` в runtime QA не вызывается.
Новый набор не проверяет настоящий сервер Cowork/Qt6: command peer — искусственный.

## Дополнение 08.10: потеря командной клавиши

`test_mapping_loss.py` проводит 18 независимых сценариев через настоящий
`HotkeyManager`, публичные события `MappingEvent`/`HotkeyEvent`, runtime и
фейковые порты клавиатуры/воркера. Проверяется команда немедленной отмены
записи, а не только визуальный индикатор. Покрыты потеря захвата при busy,
успешная смена физического keycode и пропавшее отпускание, ожидание 300 мс,
хвост записи после отпускания, поздний результат распознавания, повторный busy,
восстановление по таймеру до 30 с, конфликт с ролью «Текст» и запоздалые
события после блокировки. Неизменившаяся карта не прерывает запись;
потеря командной роли не отменяет независимую текстовую диктовку.

Сохранённый `snapshot.json` — **исторический снимок приёмки 07.10** базы
`a23095f`; он не доказывает состояние последующих коммитов. Новый результат
08.10 хранится отдельно в `snapshot-2026-10-08.json` и
`VERIFICATION-2026-10-08.md` после финального прогона.

Изоляция при новых прогонах включает обе переменные адресов:
`DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent` и
`DBUS_SYSTEM_BUS_ADDRESS=unix:path=/nonexistent`; DISPLAY/Wayland удаляются,
Qt использует `offscreen`. Сценарии настоящего IPC самостоятельно создают
закрытую шину без активации служб.
