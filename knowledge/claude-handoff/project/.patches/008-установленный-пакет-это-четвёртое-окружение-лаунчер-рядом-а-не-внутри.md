# 008 — Установленный пакет — четвёртое окружение: лаунчер «рядом, а не внутри» ломает импорт (2026-09-14)

## Что случилось
Заказчик поставил `0.1.0~m4.1` и не увидел «Загружаю модель…». В журнале: «Не удалось запустить диктовку, приложение
продолжит работу без неё» — без traceback (`except Exception: log.warning(...)`). Импорт из установленного дерева:
`worker/supervisor.py:17 from astra_voice import bootstrap` → `ImportError: cannot import name 'bootstrap'`.
Причина: `packaging/debian/rules` **нарочно** переносит `bootstrap.py` из пакета в `/usr/lib/astra-voice/bootstrap.py`
(«лежит РЯДОМ, не внутри» — чтобы запускать `python3 -I bootstrap.py app`), а супервизор с M2 (`f371959`, 11.09) берёт из
модуля путь к лаунчеру для argv воркера. В dev-дереве `src/astra_voice/bootstrap.py` внутри пакета — 2218 unit, стенды,
`--debug-transcribe` в venv зелёные. Проверка установки в CI (job `deb`) ограничивалась `--version`, который до
`runtime`/`supervisor` не доходит. Так пакет M2/M3/M4 три дня был неработоспособен незаметно.

## Почему это грабли
1. Урок 005 говорил о трёх окружениях CI; **установленный пакет — четвёртое**, и оно единственное, которое видит заказчик.
2. «Зелёные тесты» проверяют dev-раскладку; раскладка пакета описана в `rules` и нигде не проверяется импортом.
3. `except Exception: log.warning("…продолжит работу без неё")` без `exc_info` превратил дефект в загадку: журнал есть,
   причины нет.

## Правило на будущее
1. Смоук установленного пакета в CI (job `deb`) и в `build-deb.sh`: **импорт всех модулей пакета** из распакованного
   `dist/` дерева (`pkgutil.walk_packages`, offscreen) + запуск лаунчера; `--version` — не смоук.
2. Всё, что `rules` перекладывает/переименовывает относительно `src/`, — с тестом на импортируемость из итоговой раскладки
   (или не перекладывать: лаунчер — тонкая обёртка над модулем внутри пакета).
3. Любой `except Exception` с «продолжаем без …» пишет traceback в журнал (`exc_info=True`); текст пользователю — простой,
   журнал — полный (без пользовательских данных).
4. Перед выдачей пакета заказчику — прогон **из распакованного пакета** на изолированном стенде, не из `src/`.

## Дополнение (тот же день): второй дефект того же класса — ресурсы, не только импорты
Разработчик при починке нашёл: `rules` удаляет `$(SHAREDIR)/data/icons`, а `ui/tray_icons.py` для сеанса Fly намеренно
обходит `QIcon.fromTheme` и читает SVG из `data_dir_static()/icons/hicolor/…` — в пакете каталога нет → во Fly трей из
установленного пакета не поднялся бы никогда (в KDE спасает тема). Импорт-смоук этого не ловит.
5. Смоук установленного пакета проверяет и **ресурсы**, к которым код обращается по путям (значки, QML, модели VAD, ключи):
   существование файлов по тем же функциям поиска, что использует код, — из распакованного `dist/` дерева.
