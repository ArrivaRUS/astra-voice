# 012 · `git add -A` при работающих зонах: чужие файлы на середине правки и временные снимки уехали в коммит журналов

**Дата:** 2026-09-16 · **Веха:** M5 (цикл 3 фиксов)

## Что случилось

Три зоны `developer-codex` писали код в общем рабочем дереве. Я в это время фиксировал
документы (спецификацию, журнал решений, план тестов, HEARTBEAT) — и делал это через
`git add -A`, как привык, когда дерево принадлежит одному процессу. Три коммита подряд
(`46cd44f`, `afc7bc4`, `e6867d2`) захватили:

- **8 файлов трёх зон на середине правки** (`net/http.py`, `test_net_http.py`, `CaptureField.qml`,
  `dictation.py`, `bridges.py`, `worker/ipc.py`, `worker/state.py`, `test_onboarding.py`) — под
  сообщением «Спека §3.2…», без валидации, в состоянии, которого ни одна зона не сдавала;
- **временные каталоги `design/refs/impl/.pill-<случайные>/`** — их создают тесты пилюли на время
  прогона рядом с эталонами; один коммит их добавил, следующий удалил, третий добавил снова.

Заметила это зона A в своём отчёте: «мой незакоммиченный фикс лежит внутри чужого коммита».
Публичный `main` переписывать нельзя, дефект зафиксирован как есть и закрывается следующим
коммитом цикла, который проходит полную валидацию.

## Правило на будущее

- **Пока в дереве работает хотя бы одна зона, `git add -A` запрещён.** Журналы и документы
  фиксировать только явными путями: `git add HEARTBEAT.md decisions/log.md docs/… design/spec.md`.
  Коммит кода — один на цикл, после того как все зоны сдались и полная валидация зелёная.
- Перед любым коммитом смотреть `git status --short` глазами: файлы вне списка того, что
  собирался коммитить, — стоп.
- **Временные артефакты тестов не живут рядом с эталонами.** Каталоги вида `.pill-*` под
  `design/refs/impl/` — в `.gitignore`; правильнее вообще писать их в `tmp_path`
  (штатный путь из урока 011 — `ASTRA_VOICE_SNAPSHOT_DIR`).
- Параллельные зоны в одном дереве — источник этой гонки. Когда возможно, зонам давать
  собственные worktree (для этой сессии `Agent` с `isolation: worktree` был недоступен из
  не-git папки — worktree создавать вручную, как для ветки движка).
