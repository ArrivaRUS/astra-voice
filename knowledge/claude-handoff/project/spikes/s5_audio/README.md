# S5 — спайк «захват звука» (M0)

> Проверяет развилку Р1 синтез-плана (захват живёт **в воркере**, PCM не покидает процесс),
> контракт И4 (`audio.close` → `audio.ready`) и требование модели угроз У39
> (`docs/threat-model.md`: имена `*.monitor` — источник записи экрана/чужого звука).
>
> **Этап 1 (сделано, 2026-09-09): код + прогон на виртуальном источнике.**
> **Этап 2 (ждёт «ок» заказчика): рестарт `wireplumber` и уведомление с кнопкой в живом KDE.**
> **Этап 3: Fly (после перелогина).**

## Файлы

| Файл | Что это | Куда переедет |
|---|---|---|
| `audio_probe.py` | `Pulse` (ctypes над `libpulse-simple.so.0`, все функции с `argtypes`/`restype`), `PulseSimpleSource` (открыть по имени → читать 20 мс → закрыть), `Capture` (поток чтения, кольцевой буфер в ОЗУ, RMS/пик в дБFS, «тишина», лимит), `assert_device_exists`, `run_asr` (PCM → `np.float32` → `onnx_asr`, без файлов) | `src/astra_voice/worker/audio.py` (+ `run_asr` — уже часть `worker/engine.py` из S3) |
| `virtual_mic.sh` | `up`/`down`/`check`: null-sink `av_test` + remap-source `av_test_src` от его монитора, снимок и возврат устройств по умолчанию | `scripts/e2e/virtual_mic.sh` (M3, Validation в `docs/plans.md`) |
| `out/` | Артефакты прогона: JSON-отчёты и логи по кейсам, логи подъёма/выгрузки виртуального микрофона | — |

Формат зафиксирован константами в начале `audio_probe.py` и совпадает с `docs/plans.md` M3:
`RATE=16000`, `CHANNELS=1`, s16le, `CHUNK_MS=20` → `CHUNK_BYTES=640`, `SILENCE_DBFS=-60.0`,
`SILENCE_HOLD_S=2.0`, `LIMIT_S_DEFAULT=120.0`, `OPEN_RETRIES=3` × `OPEN_RETRY_MS=300`.

## Правила безопасности прогона

1. **Микрофон заказчика не открываем.** Все кейсы, кроме намеренного негативного (`enodev`),
   идут на виртуальный источник `av_test_src`. Проверка имени (`--strict-device`) включена
   **по умолчанию**; чтобы воспроизвести молчаливую подмену устройства, нужен явный
   `--no-strict-device`.
2. **Устройства по умолчанию не трогаем.** `virtual_mic.sh up` снимает `pactl get-default-sink`
   / `get-default-source` **до** загрузки модулей и возвращает их обратно, если сервер переключил
   на наш `av_test`; `wpctl get-volume` снимается до и после, mute чужих устройств не меняется.
   Размучивается только собственный sink `av_test`.
3. **`systemctl --user restart wireplumber` в спайке НЕ выполнялся** — это звуковая подсистема
   заказчика, у которой известна гонка профиля `sof-hda-dsp` при старте сессии. Сценарий описан
   ниже как «требует живого прогона со явным ок».
4. **На диск ничего не пишется.** PCM живёт в `deque` внутри процесса и умирает вместе с ним;
   в отчёты попадают только уровни и текст распознавания.

### Список источников (У39)

`--list-devices` печатает `pactl list short sources` с явной пометкой мониторов
(`out/silence.log`): всего **8** источников, из них **5 с суффиксом `.monitor`**
(4 системных монитора выходов + наш `av_test.monitor`). Мониторы — это звук, который слышат
колонки (чужие созвоны, видео), поэтому в списке выбора устройства (US-11.1) они обязаны быть
помечены и не могут попадать в автовыбор. Полный листинг устройств заказчика в отчёт не выносится.

## Грабли этапа 1

1. **`restype` обязателен.** У `pa_simple_new` возвращаемый `pa_simple*` без
   `restype = ctypes.c_void_p` усекается до 32 бит → SIGSEGV на первом же `pa_simple_read`
   (тот же класс граблей, что в S1 с `Display*`). В `audio_probe.py` подписаны **все**
   используемые функции, включая `pa_simple_get_latency` (`restype = c_uint64`) и
   `pa_strerror` (`restype = c_char_p`).
2. **PipeWire поднимает свежий `module-null-sink` с выключенным звуком.**
   `pactl get-sink-mute av_test` → «да», из-за чего `av_test.monitor` отдавал ровную тишину и
   захват «не ловил» `paplay`. Лечение в `virtual_mic.sh`: `pactl set-sink-mute av_test 0`
   сразу после загрузки модуля (размучивается только собственный sink).
3. **`pa_simple` не умеет сказать, что открылось на самом деле.** `pa_stream_get_device_name`
   есть только в асинхронном API, поэтому подмену устройства (кейс D) обнаружить постфактум
   нечем — отсюда обязательная проверка имени **до** открытия.
4. **Порядок выгрузки модулей.** `virtual_mic.sh` пишет id в файл состояния в обратном порядке
   (remap-source, затем null-sink) — иначе выгрузка мастера оставляет висячий remap.
5. **Буфер PulseAudio.** В `pa_buffer_attr` осмысленно задаётся только `fragsize = CHUNK_BYTES`
   (640 Б = 20 мс), остальные поля — `(uint32)-1` (сервер по умолчанию). Латентность на записи
   получалась 28–54 мкс.

## Что НЕ проверено этапом 1

| Пункт | Почему | Что нужно |
|---|---|---|
| `systemctl --user restart wireplumber` → открытие со 2-й попытки ≤ 1 с (И4 `audio.close`/`audio.ready`) | рестарт трогает звуковую подсистему заказчика; у него известна гонка профиля `sof-hda-dsp` при старте сессии (два WirePlumber: `linger astra` + greeter `fly-dm`), после которой микрофон может «замолчать» | явное «ок» человека, затем прогон в его сессии; страховка — `systemctl --user status wireplumber` и `pactl list short sources` до/после |
| Уведомление «Перезапустить звуковую службу» с кнопкой (`GetCapabilities`, `ActionInvoked`) | требует пользовательской шины и живой Plasma; в спайке шина заказчика не трогалась (урок `.patches/002`) | живой KDE, затем `fly-notifications` во Fly |
| Fly целиком (имена источников, поведение после перелогина, гонка greeter) | нужен перелогин заказчика | этап 3 |
| Реальный микрофон как штатный источник (уровень, АРУ, шумодав) | сознательно вне спайка — кейс D открыл его на 0,9 с только как негативную проверку | живой прогон вместе с рестартом WirePlumber |

### Про кейс D — что произошло с этими 0,9 с

При снятой проверке имени процесс прочитал **0,9 с звука с реального микрофона** в ОЗУ.
Данные никуда не писались (кейс G), распознавание на этом буфере не запускалось, процесс
завершился сразу после отчёта; в `out/enodev.json` попали только уровни (пик/медиана в дБFS).
Именно этот прогон и есть доказательство находки — но повторять его не нужно: поведение
воспроизводится и без открытия микрофона, по факту `device_check.exists = false`.

# Живой KDE: рестарт WirePlumber (этап 2) — 2026-09-09

Допуск получен от заказчика через Юрку (`decisions/log.md`, «Допуски на живые прогоны M0»):
один `systemctl --user restart wireplumber` с принятым риском гонки профиля `sof-hda-dsp`.
Прогон: `~/.cache/astra-voice-spikes/s5_live_reopen.py` (scratch, вне репо) на venv из S3;
артефакты — `out/live_kde_wireplumber.json|log`. Устройство — **реальный микрофон заказчика**

| Шаг | Факт |
|---|---|
| Снимок «до» | default source `…Mic1__source`, default sink `…Speaker__sink`, источников 6, `wireplumber` active |

само открытие** (иначе он тихо ждёт внутри libpulse).
