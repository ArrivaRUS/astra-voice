**Handy** (голосовой ввод, github.com/cjpais/Handy, Tauri+Rust) — кастомная сборка в `~/Документы/Установка Хенди/`: `work/Handy` (клон 0.8.3 + правки), `work/transcribe-rs` (форк с движком `gigaam_rnnt` в `src/onnx/gigaam_rnnt/`, подключён через `[patch.crates-io]`), `work/.toolchain` (rustup/cargo — задавать `RUSTUP_HOME`/`CARGO_HOME` на него). Данные приложения: `~/.local/share/com.pais.handy/` (settings_store.json, logs/handy.log — время в UTC, models/, recordings/ — 16 кГц моно wav).

**2026-09-01: Whisper medium заменён на GigaAM v3 RNN-T** (Сбер, русский, пунктуация/нормализация; ONNX int8 экспорт sherpa-onnx от csukuangfj, HF `csukuangfj/sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16`). Причина: whisper-medium-q4_1 на CPU всегда обсчитывает 30-сек окно → ~14 с на любую фразу (Core Ultra 7 255U). GigaAM: **та же фраза 6 с → 120–130 мс (~110×), загрузка модели 450 мс**, качество на живых записях идентично/лучше (ё, пунктуация). Модель: `models/gigaam-v3-rnnt-int8/` (encoder.int8.onnx + decoder.onnx + joiner.onnx + vocab.txt=tokens.txt, ~230 МБ; `<blk>`=1024). В settings `selected_model: "gigaam-v3-rnnt"`.

**Июньская интеграция не работала, т.к. её ни разу не запускали**: у реального экспорта входы джойнера `enc`/`dec`, а движок слал `encoder_outputs`/`decoder_outputs` → «Invalid input name». Исправлено в форке (mod.rs run_joiner). Энкодер: `audio_signal`[B,64,T]+`length`→`encoded`[B,768,T']; декодер позиционно [x, unused_x_len.1, h.1, c.1]→[dec, unused_x_len, h, c].

**Грабли сборки:**
- ort тянет prebuilt onnxruntime под новую glibc → undefined `__isoc23_strto*` на glibc 2.36. В Handy решено шимом `src-tauri/isoc23_shim.c` (build.rs линкует в бинари); для сборки примеров transcribe-rs: `RUSTFLAGS="-C link-arg=<shim.o>"`.
- **`cargo build --release` БЕЗ `--features tauri/custom-protocol` даёт dev-бинарь**, который грузит devUrl localhost:1420 → окно «Could not connect to localhost», webview-фронтенд не работает (Enigo и глобальные шорткаты не инициализируются — их вызывает фронтенд после onboarding). Продовая сборка: `cargo build --release --features tauri/custom-protocol` (или tauri CLI).
- tauri CLI (`node_modules/.bin/tauri build`) жёстко падает на version mismatch tauri 2.10.2 vs @tauri-apps/api 2.11.0. Обход: фронт `npm run build` (bun в системе нет), бинарь cargo с фичей, deb перепаковать dpkg-deb -R/-b из старого.
- Vulkan для whisper отключён на Астре (старые заголовки), whisper на CPU; GigaAM идёт через ORT — не затронут.

**Как тестировать STT без микрофона/рук:** Handy слушает SIGUSR2 = тумблер записи binding «transcribe» (SIGUSR1 = с постобработкой). Виртуальный мик: `pactl load-module module-null-sink sink_name=vmic_sink` + `module-remap-source master=vmic_sink.monitor source_name=vmic` + `set-default-source vmic`, затем `kill -USR2 <pid>` → `paplay --device=vmic_sink файл.wav` → `kill -USR2`. Монитор auto_null НЕ отдаёт звук (тишина). Результат смотреть в logs/handy.log (`Transcription completed`, `Transcription result`).

**Инцидент 2026-09-02 «звук с микрофона не поступает»:** Handy получал 0 сэмплов, потому что у карты `sof-hda-dsp` (ThinkPad T14 Gen6) в пользовательском PipeWire был профиль `off`, а HiFi вообще пропал из списка (UCM при этом исправен: `alsaucm -c sof-hda-dsp list _verbs` показывает HiFi) — первая гипотеза «PCM не готовы» НЕ подтвердилась (см. ниже), реальная причина — гонка с greeter-стеком. Началось с перезагрузки 2026-09-01 15:34, не связано с правками Handy. **Лечение:** `systemctl --user restart wireplumber` (перепробирование) → HiFi активен, Mic1 = встроенный Digital Microphone (Mic2 — гарнитурный). На машине два аудиостека: пользовательский (`/run/user/1000z0_0_0x0_0x0`, к нему подключены все приложения) и greeter-стек fly-dm (uid 102, недоступен для чтения). **Ловушка при тестах:** в рекордере Handy стоит VAD — тишина даёт «sample count: 0», это НЕ признак поломки; честный тест микрофона — `paplay` записи через динамик при записи по SIGUSR2 (акустический loopback). `pactl set-default-source` сохраняется WirePlumber'ом в `~/.local/state/wireplumber/default-nodes` — после тестов с виртуальным миком чистить. **Причина подтверждена по журналу загрузки 2026-09-02 16:58:** PCM карты готовы на 9-й с, оба WirePlumber (astra через linger и greeter fly-dm uid 102) стартуют на 16,8-й с в одну секунду; пока greeter прощупывает карту, наш получает EBUSY → HiFi выброшен, профиль off. Ожидание только PCM НЕ помогло. **Постоянное лечение (drop-in v2, с согласия пользователя):** `~/.config/systemd/user/wireplumber.service.d/wait-sof.conf` — ExecStartPre (timeout 45, с «-») ждёт PCM, затем `sleep 3`, затем пока `pgrep -u fly-dm -x wireplumber` проживёт ≥8 с (прощупывание greeter'а закончено). Проверено на restart (3 с), на реальной загрузке — ждёт проверки. Запасной root-вариант: маскировать pipewire/wireplumber у пользователя fly-dm (`/var/lib/fly-dm/.config/systemd/user/*.{socket,service}` → /dev/null). Если микрофон снова «молчит» — `systemctl --user restart wireplumber`. Ловушка при акустическом тесте: динамик может быть в mute на уровне PipeWire-узла/маршрута (`wpctl get-volume <id>` → `[MUTED]`, `pw-dump` Props mute/softMute), при этом `pactl get-sink-mute` врёт «нет» — проверять именно wpctl. 2026-09-02 такой mute появился сам после `systemctl --user restart wireplumber` (пользователь не выключал) — после перезапуска WirePlumber проверять `wpctl get-volume @DEFAULT_AUDIO_SINK@` и при `[MUTED]` включать `wpctl set-mute @DEFAULT_AUDIO_SINK@ 0`.

**Ловушка с бинарём (2026-09-02):** пользователь НЕ ставил перепакованный deb, `/usr/bin/handy` остался июньским (сломанный GigaAM-джойнер); автозапуск `~/.config/autostart/Handy.desktop` Handy переписывает сам на путь запущенного exe, а ярлык меню `/usr/share/applications/Handy.desktop` = `/usr/bin/handy` — любой запуск старого бинаря возвращает автозапуск на него. Пока deb не установлен, рабочая сборка = `work/Handy/src-tauri/target/release/handy`, запуск `systemd-run --user --unit=handy-test <bin>`. Deb: `Установка Хенди/Handy_0.8.3_gigaam_amd64.deb`.

**Запуск руками на Astra:** нужен полный env сессии — `XDG_RUNTIME_DIR=/run/user/1000z0_0_0x0_0x0` (мандатный суффикс!) и соответствующий `DBUS_SESSION_BUS_ADDRESS`, иначе webview/DBus не поднимутся. Надёжнее `systemd-run --user`.
