## Как пользоваться на другой машине

Скажите моему собрату там: «склонируй `ArrivaRUS/handy-gigaam` и выполни `install.sh`». Или руками:

```bash
git clone https://github.com/ArrivaRUS/handy-gigaam.git && cd handy-gigaam && ./install.sh
```

Один прогон делает всё: зависимости, модель, сборку, пакет, установку, проверку. Нужен Debian или производная (Astra Linux, Ubuntu), 10–20 минут и права sudo. В корне лежит `CLAUDE.md` — инструкция агенту, включая то, чего делать **нельзя**: не собирать через tauri CLI, не забыть флаг production-сборки, не обновлять форк движка из upstream.

Код обоих форков лежит целиком, а не патчами, так что сборка не сломается при изменениях upstream. Модель в git не хранится: закреплена ревизия на Hugging Face и контрольные суммы, скачивается ровно та же версия, что работает здесь.

## Что дала живая проверка

Прогон вскрыл три вещи, которые чтением кода не находятся:

- **`npm ci` падал**: postinstall-хук вызывает `bun`, которого в системе нет. Обошёл.
- **Моя же проверка ложно падала**: `strings` на 45-мегабайтном бинаре в паре с `grep -q` рвёт конвейер, строгий режим считает это ошибкой. Теперь считаю иначе.
- **Проверка была слабой**: наличие строки с именем модели есть и в сломанной июньской сборке. Заменил на побайтовое сравнение установленного бинаря с собранным плюс реальное распознавание тестовой фразы.

## На этой машине осталось одно действие

Проверка честно показала: у вас до сих пор установлен **старый пакет** от 3 июня, а работает бинарь из папки сборки, который я запускаю вручную. После перезагрузки может снова подхватиться старый. Ставится одной командой:

```bash
cd ~/Документы/handy-gigaam && ./install.sh 50
```

Она поставит только что собранный пакет и пропишет модель в настройках. После этого все пути — меню, автозапуск, `/usr/bin/handy` — ведут на одну рабочую сборку.
