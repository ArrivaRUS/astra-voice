# Обновления программы — UX-target M7 / action 2b

Статус: target для реализации и отдельного design review; не приёмка продукта.
База: `codex/program-updates`, HEAD `39b0d91b7c43a053c26323fe9c40359b516e515a`,
исходное дерево чистое. Назначение координатора от 2026-10-09 разрешает этот шаг
после AppImage; исторические сроки/запрет продолжения сегодня в памяти не являются
текущим брифом. Ownership: только этот файл и [mockup.html](mockup.html).

Основа: `design/spec.md` §1–2, §4.1, §6, `qml/Theme.qml`, `Network.qml`,
`UpdatePanel.qml`, `StatusBar.qml`, `PRD.md` F9, `docs/plans.md` M7 action 2b,
`docs/test-plan.md` T-16/19/36/116, `arch/appimage.md` §6 и урок `.patches/030`.
Новые требования брифа к AppImage уточняют старую формулировку «один запуск»:
после проверки — явное «Установить и перезапустить», без тихой установки.

## 1. Объём и размещение

Существующий раздел «Сеть и обновления»: панель результата наверху, затем группы
«Сетевые проверки» и «Вручную». Сохраняются ручная проверка при выключенном
тумблере, skip/remind/release page и существующая строка-статус. Автопроверка
не включает автозагрузку: **каждая загрузка начинается отдельным нажатием**.
Нового раздела/мастера/диалога подтверждения загрузки нет. Модели, доверенные
ключи, импорт файла, root/helper/polkit, откат MA-2 и ВКС вне этого target.

Без моста или без результата (`idle`, `disabled`) панель отсутствует. Проверка
и скачать недоступны без моста; объяснение — «Проверка пока недоступна».
Ручная проверка открывает существующее `checking`. Для найденного кандидата
bounded-проверка подписанных metadata входит в эту фазу с допуском
`check_app` / `check_app_manual`; `available` разрешён только после успешной
проверки metadata (T178). Пакет при этом не скачивается. Успешный check —
`uptodate` или доверенный `available`; недоступный источник — `unavailable`,
отказ подписи metadata — ошибка проверки, без предложения скачать.
Ошибка до доверенного `available`: «Не удалось проверить сведения об
обновлении» + «Повторить проверку» (checkNow), без версии кандидата, notes,
размера и download/install. Последняя успешная дата не меняется. Эти состояния сохраняют
текущие тексты и семантику. «Последняя версия» возможна лишь после успешной
проверки; сетевая ошибка не обновляет дату успешной проверки.

В панель `available` добавляется главное действие: `.deb` «Скачать пакет»,
AppImage «Скачать новую версию». «Страница выпуска» становится secondary;
она открывается только по явному нажатию, с учётом NetworkGate. При отсутствии
совместимого проверенного в metadata артефакта главное действие disabled с пояснением
«Для этой сборки файл обновления недоступен»; ссылка допустима лишь если есть
проверенный разрешённый адрес. UI не выбирает трек по наличию папок на диске.

## 2. Геометрия и токены

Проверять окно **1024×620** и штатный минимум **900×588**, sidebar 184 px,
контент с отступами 22 px; фактическая ширина панели соответственно 796 и
672 px (`sizeContentColMax`). Дополнительный stress: колонка 480 px, 150% font.
HTML использует точно эту оболочку; нарисованная верхняя полоса представляет
рамку ОС только для снимка, не элемент будущего QML.

- Панель: `bgSurface`, radius 10, border 1, padding Y14 / X16 внутри границы.
  Заголовок 16/500, межстрочный 1.3; метаданные 12/1.4 `fgMuted`.
- Заголовок и версия переносятся, без elide; badge «Новая» только `available`.
  Версия в моноширинном шрифте; её отдельный длинный токен переносится в любом
  месте. Badge переходит на следующую строку, если не помещается.
- «Что нового»: 13/bold `fgSecondary`; список 12.5/1.6 `fgSecondary`, висячий
  отступ 17 px, gap перед списком 6 px. Пустые notes: «Описание изменений не
  предоставлено». Список остаётся на месте при загрузке и ошибке; вся секция
  прокручивается штатным Flickable, второго scroll area нет.
- После notes gap 12. Операционный блок: `bgSurface2`, radius 7, padding 10/12,
  status 13/1.45, пояснение 12/1.4, progress 6 px. Минимальная высота блока
  **120 px для AppImage, 190 px для deb** для фаз
  available → metadata → downloading → verifying → ready;
  Место deb-инструкции резервируется до ready, чтобы кнопки не съезжали.
  Длинные пояснения/путь увеличивают высоту только при stress-контенте. Пустые позиции progress и counter
  резервируются, невидимы и не доступны screen reader.
- Действия ниже блока gap 12. Ряд A: главный слот **264 px**, gap 8, слот
  secondary «Отмена» **92 px**, далее «Страница выпуска». Ряд B с gap сверху 8:
  «Пропустить эту версию» secondary, gap 8, «Напомнить позже» ghost. Button
  height 34, font 13/500, padding 6/12, radius по `Theme.buttonRadius`.
  Ширины слотов обеспечивают одинаковый левый край/место primary и cancel во
  всех фазах. Если полный ряд не помещается, **только страницу выпуска**
  перенести на следующую строку; при ширине тела <364 px ряд A превращается
  в вертикальную колонку. Текст кнопок никогда не обрезается; при увеличенном
  шрифте размеры растут от implicitWidth. Общий AvButton не менять ради панели.
- В available cancel-слот пустой; в busy он видим. В ready не занимать его
  другой важной командой. Skip/remind в busy disabled и остаются на месте.
  После ready/error они доступны. В error primary остаётся на своём месте.
- Border primary для available/busy/ready, border dangerInk для error,
  border обычный для idle/checking/offline/policy. Никакой мигающей рамки.
  Цвет сообщает то же, что явный текст/иконка, без единственной цветовой подсказки.
- Theme UI/mono font stacks и все цвета из `Theme.qml`. Focus ring 2 px,
  offset 2. Не добавлять новые шрифты/цвета/маркетинг. StatusBar остаётся 36 px.

## 3. Состояния и точные тексты

Текущие состояния проверок (`checking`, `uptodate`, `unavailable`, `skipped`)
не переименовывать в bridge ради макета. Ниже `metadata` означает новую фазу
**повторной локальной проверки metadata после нажатия скачать**,
не первичную проверку metadata: та уже выполнена внутри `checking`.

| Фаза | Текст операционного блока | Primary / secondary в ряду A |
|---|---|---|
| available | «Скачивание начнётся по вашему нажатию.»; deb: «Установку выполняет администратор.»; AppImage: «Установка и перезапуск — отдельным нажатием после проверки.» | Скачать пакет / Скачать новую версию; cancel пустой |
| metadata | «Проверяю сведения перед скачиванием…»; «Размер подтверждён подписью. Повторно проверяю сведения о файле.» | disabled прежнее Скачать…; Отмена |
| downloading | «Скачиваю обновление…»; «42 % · 42 МБ из 100 МБ» (пример); determinate bar | disabled прежнее Скачать…; Отмена |
| verifying | «Проверяю подпись и целостность…»; «Файл скачан. Пока проверка не закончена, использовать его нельзя.» | disabled прежнее Скачать…; Отмена |
| readydeb | «Пакет готов. Подпись и целостность проверены.»; «Установку выполняет администратор. Передайте ему пакет и файлы проверки из этой папки.» | Открыть папку; cancel пустой |
| readyappimage | «Новая версия готова. Подпись и целостность проверены.»; «Установка заменит текущую копию программы в домашней папке. Модели и настройки сохранятся. Программа закроется для запуска новой версии. Если она не откроется, запустите Astra Voice из меню.» | Установить и перезапустить; cancel пустой |
| error | Заголовок по таблице ниже; конкретная причина и следующий шаг | Повторить скачивание / Повторить установку; cancel пустой |
| cancelled | «Скачивание отменено. Обновление не установлено.» | прежнее Скачать…; cancel пустой |
| installing (AppImage) | «Устанавливаю новую версию…»; «Программа закроется для запуска новой версии. Если она не откроется, запустите Astra Voice из меню. Ошибка после закрытия будет показана при следующем запуске.» | disabled Установить и перезапустить; cancel пустой |

В повторной metadata-фазе progress indeterminate, без процента/скорости;
ранее проверенный размер сохраняется. Размер появляется **только из прошедших
проверку подписанных metadata**, уже в `available`. В `checking` до проверки
размер не показывается. Отсутствие signed size — не 0 МБ; `available`/загрузка
не разрешены, показать ошибку сведений. В скачивании
процент вычисляется от trusted total; 100% не означает ready. В verifying нет
процента загрузки; indeterminate. В ready progress скрыт, остаётся reserved slot.
Не придумывать ETA, скорость или точный таймаут, если их нет в bridge.

В readydeb: путь папки — selectable plain text моно 12 с переносом. Ниже внутри
операционного блока — «Администратору: в этой папке выполните» и selectable
`sudo apt install ./astra-voice_0.2.1_amd64.deb` **только с безопасным реальным
basename из проверенного результата**; пример здесь не действительная версия.
Команда — инструкция, не кнопка, UI не запускает shell/root. Если безопасная
команда недоступна, оставить человеческую инструкцию и путь; не подставлять
сетевой/недоверенный текст в команду. «Открыть папку» не запускает пакет.

Для неподдерживаемой локальной установки AppImage пояснение «Эту копию нельзя
обновить автоматически. Откройте папку с проверенным файлом и запустите его
вручную» + «Открыть папку», без ложной доступности install. Backend возвращает
capability/reason; UI не обходит отказ. На время записи/обработки local install
disabled: «Завершите диктовку, чтобы установить обновление». Это существующий
lifecycle barrier, не новый микрофонный сценарий. Install меняет фазу только
после принятия запроса мостом; успешный `Popen` означает лишь передачу
управления новой копии, не установленную новую версию. UI не сообщает «Обновление установлено» по успешному Popen. Ошибка до закрытия остаётся в работающей панели. Ошибка после закрытия показывается при следующем запуске программы; неподтверждённая попытка тоже не считается успехом.

## 4. Ошибки и допуски

| Причина | Heading / пояснение | Повтор |
|---|---|---|
| download/network | «Не удалось скачать обновление» / «Проверьте соединение и повторите скачивание.» | ручной download с повторной валидацией локальных metadata |
| metadata/signature/hash | «Не удалось проверить обновление» / «Подпись или целостность не подтверждены. Этот файл нельзя использовать.» | новая загрузка; нет install/folder для непроверенного файла |
| no-space | «Не хватает места для обновления» / «Освободите место на диске и повторите скачивание.» | новая загрузка |
| permission/write | «Не удалось сохранить обновление» / «Папка обновлений недоступна для записи.» | новая загрузка после исправления |
| stale/missing ready file | «Проверенный файл больше недоступен» / «Скачайте обновление ещё раз.» | download; install/folder сразу disabled |
| install/restart | «Не удалось установить обновление» / безопасная конкретная причина от backend; нельзя заявлять, что установлено/перезапущено | только если bridge подтверждает повторяемость, повтор local install с повторной валидацией; иначе download |
| clock | «Не удалось проверить обновление» / «Системные часы отстают. Проверьте дату и время и повторите скачивание.» | download; проверку подписи не обходить |

Безопасная причина в PlainText; никаких сырого HTML/stack trace/URL-токенов.
Нет fake-ready даже на отмене и позднем событии старой операции.

Offline banner: «Включён офлайн-режим» / «Проверка и скачивание обновлений
недоступны. Диктовка работает без сети». Сохраняется доступная cached версия
и notes; это не свежий успешный check. Main download/check/release page disabled,
skip/remind допустимы. Если офлайн включил пользователь, действие поясняется
строкой существующего тумблера; автоматически отключать офлайн нельзя.

Policy banner: «Обновления ограничены администратором» + фактическая безопасная
причина. Не обещать возможность снять блокировку UI. `updates=admin` запрещает
AppImage install; если gate допускает deb download, оставить «Скачать пакет»
и администраторский финал. При полном сетевом запрете download/check/release
page disabled. Возможности check/download/install/openFolder задаёт backend;
UI не выводит их из единственного bool и не расширяет `updates=admin`.

Если запрет/офлайн возникает в metadata/downloading: отмена операции,
блокировка новых запросов, пояснение «Скачивание остановлено: включён
офлайн-режим» либо причина политики. После снятия допуска только ручной retry,
не продолжать автоматически. В verifying/ready сетевой офлайн сам по себе
не запрещает **локальную** проверку/«Открыть папку»; local AppImage install
доступен только при актуальной разрешающей политике. Для готового файла сетевой
баннер не должен скрывать сведения о его проверке. Backend обязан снова
проверить допуск/файл перед выполнением действия.

## 5. Переходы и нижняя строка

`idle → check → checking (discovery + bounded signed metadata) → available/uptodate/unavailable/error`.
`available` только с доверенными metadata; HTTP discovery сам по себе не даёт
предложения обновления.
`available → manual download → metadata (повторная локальная проверка) → downloading → verifying → readydeb/readyappimage`.
Любая из трёх busy-фаз → Отмена → cancelled (без установки) → manual download.
Любая ошибка → error → manual retry (повторная проверка metadata).
`readyappimage → explicit install → installing → успешный перезапуск / error`.
`available/ready/error → skip → skipped`; очистка skip возвращает version details,
проверенное ready сохраняется лишь если backend повторно подтверждает файл.
`remind` убирает акцент в StatusBar, не начинает и не отменяет загрузку; в busy
эта кнопка недоступна. Повторные нажатия primary не создают вторую операцию.

StatusBar отображает текущую фазу, а клик/Enter/Space **открывает раздел и панель**,
не начинает download/install. Тексты: metadata «Проверяю сведения об обновлении…»;
downloading «Скачиваю обновление · 42 %»; verifying «Проверяю обновление…»;
readydeb «Пакет проверен · Открыть обновления»; readyappimage «Обновление готово
· Открыть обновления»; installing «Устанавливаю обновление…»; error
«Обновление не выполнено · Подробнее». Version details полностью в панели;
в строке допустим elide и доступное полное имя. При дефиците ширины левой
модели оставить место справа для обновления, без пересечения; размер модели
можно сократить текущим elide. Не добавлять вторую DownloadStrip для программы:
существующая полоса загрузки моделей остаётся независимой.

## 6. Фокус, клавиатура, недоверенный текст

Tab/Shift+Tab штатные, порядок панели: primary → cancel (только busy) → release
page → skip → remind → существующие toggles → check. Disabled и пустые слоты
пропускаются. Enter/Space выполняют только сфокусированную кнопку. Esc отменяет
busy **только при фокусе внутри панели**, без глобального перехвата на запись/
другие разделы; отмена не требует диалога. Esc вне busy не ставит обновление.
Смена состояния не переносит фокус автоматически на install: после завершения
загрузки фокус с исчезнувшей cancel переносится на нейтральный заголовок панели
(`Accessible.role` heading, programmatic focus), следующий Tab — primary.
Когда нажата download и primary disabled, фокус переводится на cancel. После
manual cancellation фокус возвращается на download; при error — на heading,
не активировать retry автоматически. Заголовок/весь focused control виден
в штатной прокрутке; ring не обрезан viewport. Устойчивый объект slot сохраняет
положение кнопки; не заменять кнопку под удерживаемой клавишей на install.

Все версии/notes/пути/причины `Text.PlainText`, HTML `textContent` в макете,
без rich/auto text, inline links, remote image или загрузки по тексту notes.
Поддержать длинный токен и многопараграфный note. Версия, path и инструкция
доступны для копирования штатным selectable text. Screen reader: имя действия,
фаза, текущий процент и ошибка доступны; progress announce без спама на каждый
байт (целые проценты/смена фаз), status polite, ошибка alert. Недоступное
действие имеет видимое объяснение, не только tooltip/цвет.

## 7. Матрица независимой UX-проверки

1. В обеих темах, 1024×620 и 900×588: idle, metadata, downloading, verifying,
   readydeb, readyappimage, error и offline. Снимок **всего окна** и увеличенный
   crop панели. Дополнительно available/checking/uptodate/skipped/cancelled/policy,
   installing и capability refusal AppImage. Макет предоставляет stand controls;
   эти controls не входят в продукт.
2. Long version/notes/path, malicious note `<img src="https://invalid.example/x">`,
   пустые notes, 480px column и 150% font: полный текст, нет горизонтального
   overflow/пересечения/обрезки, все actions достижимы прокруткой и Tab.
3. Primary/cancel остаются на своих местах metadata→download→verify→ready.
   Загрузка не начинается при открытии панели/check/remind/release page.
   Download 100% не даёт success до проверки; signature error не даёт folder/
   install. Cancel и поздний старый progress не восстанавливают ready.
4. Без моста, поздний bridge, network/policy refusal before/during operation,
   отключение auto-check во время download: точные допуски и сохранённые настройки,
   нет silent restart/resume. Ready invalidated after external file changes.
5. Tab/Shift+Tab/Enter/Space/Esc, смена фаз с фокусом cancel, переход из StatusBar,
   смена раздела и возврат во время операции: focus виден, install никогда не
   запускается автоматически или остаточным Enter от download.
6. Deb: folder показывает только проверенный результат, инструкция соответствует
   реальному basename, никакого root-вызова. AppImage: explicit install после
   verify, занятость диктовки/политика/ошибка не маскируются success.
7. Проверка actual QML отдельным design_reviewer против frozen HTML/spec и
   фактических снимков; точные hashes target/actual в заключении. HTML-проверка
   сама по себе не доказывает actual QML, клавиатуру Qt, KDE/Fly или установленную
   сборку. Unit/Xvfb не означают живую проверку микрофона/перезапуска.

Target фиксируется SHA256 обоих файлов в отчёте координатору после создания.
Любое изменение target после передачи требует новой фиксации и сверки actual.

### R1. Заголовок без «обводки»

Диагноз. Обводка — кольцо фокуса заголовка панели (`UpdatePanel.qml:224–234`, `visible: heading.activeFocus`).
Фокус на заголовок ставит `focusHeading()` (`UpdatePanel.qml:137`) **всегда с `Qt.TabFocusReason`**:
клик **мышью** по «Доступна версия X · Подробнее» в строке состояния (`Main.qml:350–358` → `Network.qml:23`),
а также конец скачивания (`UpdatePanel.qml:149`: фокус был на «Отмене», куда его после щелчка мышью по «Скачать»
перевела строка 422 — тоже с `TabFocusReason`, отчего и «Отмена» получает кольцо). Странно выглядит, потому что:
кольцо (а) появляется после щелчка мышью — во всём остальном приложении кольцо только для клавиатуры (§1.3, PR #51);
(б) охватывает `Flow` во всю ширину панели (762 px при 1024), а не текст — справа пустая рамка на ~500 px;
(в) прижато к буквам на 2 px по вертикали; (г) бирюзовое (`stateFocusRing`) внутри тёмно-синей рамки панели
(`primary`) — две рамки разного цвета в 11 px друг от друга. PR #51 (`ringOutset`) не причина: он менял только
клип области прокрутки; кольцо заголовка нарисовано внутри панели и существует с `f08d1bc`, было и в 0.1.2.

Target:
- Заголовок без рамки, бейджа-обводки и подложки: «Доступна версия» 16/500 lh 21 `fg`, gap 9, версия моно 16 `fg`,
  gap 9, badge «Новая» (`badgeHeight` 21.3, `badgePaddingX` 7, `badgeRadius` 5, 11.5/500 `primary` на `primaryBg`).
  Без изменений, кроме фокуса.
- Программный фокус на заголовке остаётся (для порядка Tab и экранного диктора), **кольцо — только если путь
  начат с клавиатуры**: Enter/Space/AT-press на строке состояния; смена фазы, когда до неё фокус в панели был
  клавиатурным (`visualFocus`). Щелчок мышью → фокус без кольца.
- То же для внутренних переносов фокуса: после щелчка мышью по «Скачать» фокус на «Отмену» ставится с
  `Qt.OtherFocusReason` (кольца нет); после Enter/Space — с `Qt.TabFocusReason` (кольцо есть).
- Геометрия кольца, когда оно видно: охватывает **содержимое строки** (заголовок + версия + бейдж; при переносе —
  ограничивающий прямоугольник строк), а не всю ширину панели; отступ `focusOffset` 2 + толщина `focusWidth` 2 со всех
  сторон, `focusRadius` 8, цвет `stateFocusRing`. Итого при 1024: ≈ 264 × 29 px вместо 770 × 29.

### R2. «Что нового»

Вид без изменений (13/bold `fgSecondary`, список 12.5/1.6, висячий отступ 17). Содержимое — по новому правилу
заметок к выпуску (владелец 13.10, текст пишет changelog-writer): 1–3 пункта ключевых возможностей простым языком,
затем одна обобщающая строка («Улучшения интерфейса», «Исправления ошибок»), без мелких деталей. В тело выпуска
не кладём: строку-заголовок «Astra Voice X.Y.Z» (дублирует заголовок панели), сведения для скачивающих с GitHub
(Telegram-архив, файлы проверки, отпечаток ключа — они есть в `INSTALL-ADMIN.md` и README), номера замечаний.
Ориентир — не больше 5 строк списка при 1024 px. Пример формы:
«- Обновление программы прямо из неё: проверка, скачивание и установка в два нажатия / - Улучшения интерфейса».

### R3. Блок-статус: остаётся, компактный, только когда несёт смысл

Блок (`bgSurface2` → `successBg` после проверки → `dangerBg` при ошибке) остаётся. Изменения:

1. **В `available` без операции блока нет.** Текст «Скачивание начнётся по вашему нажатию.» и подписи
   «Установка и перезапуск — отдельным нажатием после проверки.» / deb «Установку выполняет администратор.»
   удаляются: ни ИБ, ни PRD этого текста не требуют (см. отчёт: требуется явное действие — им и является кнопка;
   строка тумблера «Раз в сутки. Скачивание — по вашему нажатию.» остаётся). Блок появляется при нажатии
   «Скачать» (фаза `metadata`) и остаётся в `downloading → verifying → ready*/installing/error/cancelled`.
2. Исключение — `available` с недоступным скачиванием (`!canDownload` или `networkRefusal`): блок виден и объясняет
   причину. Заголовок блока во всех таких случаях — «Скачивание недоступно» (сейчас без офлайна там ошибочно
   «Скачивание начнётся по вашему нажатию.» рядом с «файл недоступен»); пояснение — прежнее по причине
   (`downloadRetryText`, если бэкенд задал срок повтора).
3. **Высота — по содержимому, без резерва под будущий текст.** Причина лишней высоты сейчас:
   `UpdatePanel.qml:358` — `max(120, высота текста перезапуска + 78)` для AppImage и **жёстко 190 для deb**, плюс
   отдельный пустой ряд счётчика 17 px (`:387–390`) и прозрачная полоса прогресса 6 px с отступами 6+6 (`:391–400`),
   которые резервируются во всех фазах, включая `available`. При 1024 в `available` полезного текста ~44 px из 120.

   Новая сетка блока (токены спеки §2 — padding 10/12, status 13/1.45 = lh 19, пояснение 12/1.4 = lh 17):

   | Ряд | Значение | Когда |
   |---|---|---|
   | padding top | 10 | всегда |
   | статус | 13/500, lh 19 | всегда |
   | gap | 4 | всегда |
   | деталь | 12/1.4, lh 17 × строк — пояснение **или** счётчик «42 % · 42 МБ из 100 МБ» (один слот, без отдельного ряда) | всегда |
   | gap + progress | 8 + 6 | только `metadata`, `downloading`, `verifying`, `installing` |
   | путь / инструкция администратора | как в §3 (gap 7, моно 12) | только `readydeb` |
   | padding bottom | 10 | всегда |

   Итоговые высоты: busy-фазы **74**; одна строка детали **60**; две строки **77**.
   **Минимальная высота после нажатия «Скачать» — 77** (metadata…ready, error, cancelled): ряд кнопок не сдвигается
   между фазами AppImage. Блок-объяснение в `available` (п. 2) — по содержимому, обычно 60.
   Растёт только при длинном тексте/узкой колонке/150 % шрифта. Резерв deb 190 и `reservedReadyText` удаляются;
   в `readydeb` ряд кнопок опускается один раз (≈ на 45 px) — допустимо: главное действие там «Открыть папку»,
   кнопки установки нет.
4. Текст `readyappimage` сокращается до двух строк при 900 px (иначе 3 строки и сдвиг 17 px):
   «Программа закроется и откроется уже новой версией. Модели и настройки сохранятся. Если она не откроется,
   запустите Astra Voice из меню.» Остальные тексты фаз — как в §3/§4.

### R4. Один ряд кнопок

Убираются «Напомнить позже» (`updateRemindLater`) и «Страница выпуска» (`updateReleasePage`) во всех фазах.
Второй ряд (`deferrals`) удаляется. Ряд действий (`updateActionRow`), gap сверху 12 от блока (или от «Что нового»,
если блока нет), `Flow` слева направо, spacing 8 по обеим осям:

| Слот | Кнопка | Ширина |
|---|---|---|
| 1 | primary: «Скачать новую версию» / deb «Скачать пакет»; далее по фазе — «Установить и перезапустить», «Открыть папку», «Повторить скачивание», «Повторить установку» | **слот = ширина самой длинной подписи своего трека** + 2 × `buttonPaddingX` 12 (по TextMetrics шрифта кнопки 13/500, не магическое 264); подпись по центру слота (padding = max(12, (слот − текст)/2)) |
| 2 | secondary «Пропустить эту версию» | `implicitWidth` |
| 3 | secondary «Отмена» | `implicitWidth`; **существует только в busy-фазах**, стоит последней |

Кнопки: высота `buttonHeight` 33.5, шрифт 13/500, radius 7 (AvButton как есть). Primary всегда x = 0;
«Пропустить» не двигается ни в одной фазе (слот 1 фиксирован); «Отмена» появляется справа и исчезает, ничего
не сдвигая, — на её месте после ready не оказывается другой команды. В busy «Пропустить» видна и disabled.

Помещается ли при 900 × 588: ширина тела панели 672 − 2 × (16 + 1) = **638 px**. Замер (запасной шрифт стенда,
шире PT Astra Sans): слот AppImage 221 + 8 + «Пропустить» 186 + 8 + «Отмена» 76 = **499 px** — один ряд с запасом 139;
150 % шрифта при 900: ≈ 320 + 8 + 267 = 595 (без «Отмены») — один ряд; с «Отменой» 705 → «Отмена» уходит на
вторую строку. Правило: при 100 % шрифта и ширине окна ≥ 900 — **всегда один ряд** (проверяется тестом);
перенос разрешён только целыми кнопками (stress: колонка 480, 150 %), текст кнопок не обрезается и не переносится
внутри кнопки. Спец-случай «вертикальная колонка при теле < 364» удаляется — Flow делает это сам.

Кнопки по фазам:

| Фаза | Слот 1 (primary) | Слот 2 | Слот 3 |
|---|---|---|---|
| available | Скачать новую версию / Скачать пакет | Пропустить эту версию | — |

### R5. Пользователь ничего не нажал

> **Решение владельца 13.10: вариант Б.** Неявного «напомнить позже» нет: выделение «Доступна версия X» держится, пока не нажаты «Скачать» или «Пропустить». Рекомендация ниже — история, не реализуется.

Панель встроена в раздел, «закрыть» её — уйти из раздела «Сеть и обновления» или скрыть окно. Поведение по
умолчанию (рекомендация, без изменения `checker.py`): **посмотрел = «напомнить позже» неявно.** Если панель была
показана в `available` с `downloadPhase === "idle"` и пользователь ушёл из раздела или скрыл окно, ничего не нажав,
QML вызывает существующий `updates.remindLater()` (`checker.remind_later()` → `remind_until = now + REMIND_LATER_S`,
24 ч). Эффект: строка «Доступна версия X» внизу остаётся (кликабельна), но без акцента 24 ч (`updateSnoozed`
уже поддержан в `StatusBar.qml:94`); затем акцент возвращается. Скачанное/проверенное ready это не трогает
(`remindLater` в busy/ready не вызывается). Повторно не вызывать, если `updates.snoozed` уже true.
Запасной вариант, если неявное откладывание отклонят: ничего не делать — акцент держится до «Скачать»/«Пропустить».

### R6. Что не меняется

Тексты ошибок §4, офлайн/политика (баннер), фаза `checking`/`uptodate`/`skipped`/`unavailable` и их кнопки,
StatusBar (кроме флага клавиатуры у сигнала активации), защита Enter (`enterArmed`), PlainText для недоверенного
текста. Мост (`updates_bridge.py`) не меняется: `remindLater` используется неявно, `openReleasePage` /
`releasePageAvailable` остаются в API без кнопки (удаление — отдельной задачей, если решат).
