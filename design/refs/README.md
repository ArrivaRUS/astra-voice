# Референсы экранов — как они сняты

PNG в этой папке — **источник истины по внешнему виду** для разработки и `design-reviewer`.
У каждого экрана две версии: светлая `NN-имя.png` и тёмная `NN-имя-dark.png`.
Исходник каждого снимка — одноимённый `.html` в `design/mockups/final/`
(генерируется `python3 design/mockups/final/_build.py`).

## Метод съёмки

Снимаем **headless-chromium, без дисплея** — `:0` не трогаем, живой сеанс пользователя не нужен.

```bash
chromium --headless=new --no-sandbox --disable-gpu --hide-scrollbars \
         --force-device-scale-factor=1 --virtual-time-budget=5000 \
         --window-size=<W>,6000 \
         --screenshot=/tmp/shot.png \
         "file:///home/astra/Документы/astra-voice/design/mockups/final/<экран>.html"
```

- **Ширина `W`: 951 для светлой темы, 923 для тёмной.** Ширина влияет на переносы текста
  в подписях и легенде — менять её нельзя, иначе снимки перестанут сравниваться между собой.
- `--window-size` по высоте берём заведомо больше страницы (6000) и потом обрезаем;
  проверяем, что снизу осталось пустое поле — иначе страница не поместилась и высоту надо поднять.
- `--force-device-scale-factor=1` обязателен: **снимок 1 : 1, без масштабирования.**
  Прежние снимки (до 2026-09-09) снимались другим инструментом, который ужимал высокие
  страницы под предел 1506 px — из-за этого пиксели «плыли». Сейчас масштабирования нет.

**2026-09-16 набор переснят целиком**, все 48 кадров — одним прогоном по этой инструкции.
Кадров, снятых старым инструментом, в папке не осталось: признаки таких кадров — высота
ровно 1506 px (обрез под предел) и ширина 931 px вместо 951 (было у `09-pill`, `09-tray`).
Если такое снова появится — кадр снят не тем инструментом, переснимайте.

## Кроп

Обрезаем по «чернилам» — прямоугольнику непустых пикселей (фон определяем по пикселю `(2, 2)`):

- сверху — **12 px** над первой непустой строкой,
- снизу — **11 px** под последней непустой строкой,
- по ширине — вся ширина кадра (`W`), без обрезки.

Высота получается разной у разных экранов — это нормально: она равна высоте страницы.
Светлая и тёмная версии одного экрана отличаются по высоте на 1–2 строки: тёмный кадр уже
(923 px), и легенда переносится на строку больше.

## Когда пересматривать

**Правка в общем CSS — переснимаем весь набор, все 48.** Это `VARS_LIGHT`/`VARS_DARK` и `CSS`
в `design/mockups/directions/_base.py` и `CSS_FINAL` в `design/mockups/final/_shell.py`.
Прежнее правило «только затронутые экраны» подводит: на глаз не видно, где именно всплывёт
переменная, и 2026-09-16 ревизия нашла **18 протухших кадров из 48** — их не переснимали
после правок 2026-09-08/09, и дизайн-ревью три круга ловило расхождения макета, а не кода.
Съёмка всего набора занимает около 11 секунд в 4 потока — экономить тут не на чем.

Правка только в разметке одного экрана (`_p1.py`/`_p2.py`/`_p3.py`) — можно переснять его одного.

## Проверка механизма (обязательна перед заменой кадров)

Прежде чем класть новые PNG в папку, докажите, что снимаете тем же инструментом и в том же
масштабе. Снимите **версию HTML из `HEAD`** (до своих правок) и сравните с лежащим в репо PNG:

```bash
git show HEAD:design/mockups/final/<экран>.html > /tmp/head/<экран>.html
# снять /tmp/head/<экран>.html по инструкции выше -> /tmp/ctrl/<экран>.png
python3 -c "from PIL import Image,ImageChops; \
a=Image.open('design/refs/<экран>.png').convert('RGB'); \
b=Image.open('/tmp/ctrl/<экран>.png').convert('RGB'); \
print(a.size==b.size and ImageChops.difference(a,b).getbbox() is None)"
```

Хотя бы на нескольких непротухших экранах должно выйти `True` — **побайтовое** совпадение.
Если `False` — расходятся chromium, шрифты или масштаб, и снимать нельзя: ревью получит
ложные Δ. Дальше сравнивайте свои новые кадры с этим контролем, а не со старым PNG, — тогда
видно ровно то, что изменила ваша правка.

Кроп в коде: фон берём `im.getpixel((2,2))`, прямоугольник «чернил» —
`ImageChops.difference(im, Image.new("RGB", im.size, bg)).getbbox()`, затем срез
`(0, y0-12, W, y1+11)`. Проверяйте, что `y1` заметно меньше 6000, иначе страница не поместилась.
