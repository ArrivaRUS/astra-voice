## Тексты

Для одиночной Win показывать точное пояснение проверенного поведения:

> Win используется для записи вместо меню приложений. Сочетания с Win работают до начала записи; во время записи с удерживаемой Win они недоступны. Рекомендуем «Удерживать».

Системное сочетание Win + клавиша сохраняется, если вторая клавиша нажата до начала записи (порог удержания 300 мс). После подтверждения удержания и старта записи сочетания с удерживаемой Win недоступны. Это уточнение подтверждено координатором после интеграции проверенного Win broker; оно не обещает восстановление меню во всех аварийных случаях.

Следующая строка (в том же блоке, отдельная ссылка): **«Режим клавиатуры: Удерживать. Изменить в «Общих»»**. Для toggle: **«Режим клавиатуры: Нажать-нажать. Изменить в «Общих»»**. Ссылка открывает General и прокручивает/фокусирует существующий selector режима. Ничего не переключает. Для иной клавиши Win-предупреждение заменить: **«Эта клавиша запускает голосовую команду в Astra Cowork.»**; строка режима остаётся. Не утверждать возврат меню Win при выходе/переназначении, пока backend не доказал это отдельно.

Мышь2, выключена: **«Если включить, средняя кнопка будет занята голосовыми командами во всех приложениях. Вставка выделенного текста и другие действия средней кнопки станут недоступны.»**

## Выбор мыши и доступность кнопок

В selector три удобных варианта: **«Средняя кнопка»** (логическая2), **«Дополнительная кнопка 1»** (8), **«Дополнительная кнопка 2»** (9). Для захваченной иной поддерживаемой дополнительной кнопки показать **«Кнопка мыши N»** и добавить её как текущий пункт. Selector нужен также пользователю, который выбирает настройку только клавиатурой. Он показывает назначение, а не гарантирует физическое наличие кнопки. В справке: **«Дополнительные кнопки обычно находятся сбоку. При изменённой раскладке мыши используйте «Выбрать другую».»** Не называть8/9 безусловно «Назад/Вперёд».

Допустимы2 и дополнительные>=8 в подтверждённом архитектурой/реализацией диапазоне. Не ограничивать capture только8/9. Основные логические1/3 запрещены, чтобы не отнять выбор элементов и контекстное меню;4–7 запрещены как прокрутка/наклон колеса. При неподдерживаемом событии: **«Эта кнопка не подходит. Выберите среднюю или дополнительную кнопку; прокрутка, основная и контекстная кнопки недоступны.»** Поле остаётся открытым; настройки не меняются. Перенастройку ОС/драйвера интерфейс не делает. Нижняя/верхняя граница дополнительных номеров — контракт backend, не ввод произвольного числа в UI.

Техническое основание: Xorg описывает переставляемое соответствие физических и логических кнопок и ZAxisMapping для колеса; это не позволяет гарантировать расположение8/9 на конкретной мыши. [Mouse support, Xorg](https://www.x.org/archive/X11R6.8.2/PDF/mouse.pdf). Совпадающий grab может закончиться BadAccess, а активный grab направляет события клиенту захвата: [Xlib, XGrabButton/XUngrabPointer](https://xorg.freedesktop.org/archive/X11R7.5/doc/libX11/libX11.html). Эти источники объясняют ограничения; доступность2/8/9 на KDE/Fly здесь не проверялась. Набор удобных вариантов и исключение основных кнопок — UX-решение, не утверждение Xlib о «безопасности» любых боковых кнопок.

### Безопасное назначение мыши

`idle → capturing → pressed → candidate-check → candidate-ready → apply → success`.

1. «Выбрать другую» открывает inline поле **«Нажмите среднюю или дополнительную кнопку»**, под ним **«Внутри этого поля. Esc — отмена»**, кнопка **«Отмена»**. Фокус на поле, оба command triggers временно приостановлены для назначения. Текстовая диктовка не должна случайно стартовать при выборе: детали единого capture gate согласовывает архитектор.
2. Начальный click/release, которым открыли поле, полностью закончился до arming. Capture реагирует только на допустимое новое нажатие внутри поля, а не на кнопку, уже удерживаемую в момент входа. Событие употреблено как настройка, без обычного действия кнопки и без звука/Submit.
3. При нажатии показывать **«Средняя кнопка — отпустите её»** (или выбранное имя). Только соответствующее release завершает пробу. Зажатая кнопка не запускает ни запись, ни отправку. Отпускание вне поля тоже закрывает press-пару; потеря окна отменяет всю пробу.
4. После release проверить кандидат без отправки; **«Проверяю кнопку…»**. При успехе показать **«Выбрана: Дополнительная кнопка 1»** и **«Назначение ещё не сохранено»**, кнопки **«Использовать эту кнопку»** и **«Отмена»**. Первая применяет; без неё старое назначение сохраняется. Для выбора из selector такое же применение безопасно после полного окончания selecting gesture, без нового диалога.
5. После успеха **«Кнопка назначена»**; on/off preference не изменяется назначением. Если было on, новая кнопка применяется атомарно; если новое назначение не удалось, прежнее остаётся. Восстановление command admission только после завершения всех нажатий настройки; хвост release нельзя интерпретировать как конец записи.
6. Esc, «Отмена», закрытие/сворачивание/деактивация окна, смена раздела, исчезновение Cowork, сон/блокировка, истечение существующего capture deadline → отмена без сохранения и без Submit. Никаких stuck grabs. После возврата фокус на вызвавшей кнопке, на позднее сообщение фокус не перескакивает.
7. Во время записи/распознавания команды capture/переназначение/новое включение недоступно: **«Дождитесь окончания команды»**. Главный switch off и cancel записи остаются доступными. Выключение во время удержания отменяет текущую команду, снимает захват и не отправляет по последующему release.

### Запись через мышь

Удержание выбранной кнопки запускает тот же command path, что клавиатура: те же микрофон/модель, индикация «Слушаю команду…», распознавание, предпросмотр, отмена, доставка и fallback. Единственное отличие — mouse всегда hold/PTT, даже при keyboard toggle. Сохранить существующий порог PTT короткого нажатия (сейчас0.3с), если архитектор не изменит его отдельно. Короткий tap не даёт команды и при включённом глобальном захвате не обещает обычного middle click.

Одновременные keyboard+mouse не создают вторую запись; источник владельца записи определяется первым допущенным нажатием, отпускание другого источника не завершает её. Любой выход/сон/lock/Cowork-disallow снимает захват и отменяет незавершённую команду; после разблокировки требуется новое нажатие. Архитектурная проверка этих условий нужна до реализации. UX target не даёт разрешения запускать живые диктовки или менять настройки ОС.

## Клавиатура и доступность

Tab order: keyboard «Выбрать другую» → Левая Win → Правая Win → Проверить снова → голосовые команды → mouse toggle → mouse selector → mouse «Выбрать другую» → preview toggle. При появлении capture его controls входят сразу после своей вызывающей кнопки; autofocus только по явному действию пользователя. Shift+Tab в обратном порядке. В selector стрелки меняют выбор, Enter подтверждает, Esc закрывает popup без назначения. Space/Enter действуют на buttons/toggles, Esc сначала отменяет capture/popup, затем штатную страницу. Не ловить Tab глобальным Shortcut; использовать штатный Qt focus traversal и прокрутку к focused элементу.

Accessible names: «Клавиша команды, Левая Win»; кнопки «Выбрать клавишу команды» и «Выбрать кнопку мыши для команды» (видимый текст одинаковый, accessible различается); «Команда кнопкой мыши, выключено/включено»; «Кнопка мыши, Средняя кнопка»; «Показывать команду перед отправкой». Selector/button/capture имеют правильные роли. Поле описывает допустимые кнопки и Esc. Сообщения готовности/ошибки объявлять через доступное текстовое состояние; цвет/иконка не единственный сигнал. Не терять текст причины из-за elide. Disabled opacity=1, fgDisabled; пояснение причины visible. Focus ring2px+offset2 из Theme. Warning и error используют текущие NoteBanner и Theme, не новую цветовую систему. Доступность screen reader подтверждается отдельной проверкой реального QML, SVG её не доказывает.

## Критерии независимой UX-проверки

- На900/1035 вся группа только в Advanced; General без Cowork; wizard сохранён. Колонки672/796, inset15, text/capture/actions на одной линии, нет двойных padding.
- Сравнить полные actual-карточки с `states.svg`: default mouse off; on/button2; absent; custom keyboard; keyboard capturing; keyboard conflict; mouse capturing; mouse candidate-ready; mouse conflict. Дополнительно pressed, loading, failed-save, command-off, policy-disabled, late bridge, button9 и иной>=8, длинные названия/ошибки; light/dark.
- Снимок actual viewport900×620 и1035×620: короткая страница и длинный конфликт, прокрутка до последнего toggle, фокус внизу; нет частичной карточки в evidence, нет наложений на header после прокрутки/смены раздела.
- Mouse default выключен и никак не забирает middle click. Переключение keyboard mode не меняет mouse PTT. Общее command-off снимает оба захвата, сохранённые preferences не исчезают. Настройка мыши никогда не включает её сама.
- При назначении и всех выходах из capture счётчики record/Submit равны0. Opening gesture, release candidate, Space/Enter «Использовать», отказ/отмена, escape, window-deactivate и deadline не отправляют команду. Held-before-arming не принимается.
- Main/context/scroll нельзя назначить; другие дополнительные в поддерживаемом диапазоне можно. Не обещать busy-owner имя, наличие физической side button или штатный paste при on.
- Для mouse on реальная PTT запись/отмена/preview/delivery/fallback и keyboard+mouse arbitration — отдельные функциональные/security проверки. Живые KDE/Fly, микрофон/мышь, блокировка и screen reader требуют отдельного разрешённого опыта; макет и SVG render не являются их PASS.

Обязательных продуктовых вопросов пользователю по брифу нет. Архитектор должен до implementation зафиксировать backend диапазон дополнительных кнопок, единый capture gate и поведение admission при потере активного grab; это технические контракты, а не новая настройка для пользователя. Новая функция идёт отдельным этапом после пакета dev7.
