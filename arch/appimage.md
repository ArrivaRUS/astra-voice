## Итог

1. **`.AppImage` — носитель и установщик, работает всегда установленная копия.** Первый запуск файла копирует программу
   в `~/.local/share/astra-voice/app/<версия>-<build_id>/`, переключает симлинк `app/current`, регистрирует меню, значок и
   автозапуск, дальше запускается сам из копии. Меню и автозапуск указывают только на `app/current/AppRun` — никогда на
   `$APPIMAGE` (файл в «Загрузках» удалят) и никогда на FUSE (в 2 раза медленнее, под `nochmodx` не исполняется).
2. **Логика установки живёт в Python (`platform/userinstall.py`), `AppRun` — тонкий sh.** Один код для самоустановки
   (0.2), `--uninstall` (0.2) и самообновления (v1.0: та же функция `install_from_dir()` + переключение `current`).
   Блокировка — `fcntl.flock`, не `mkdir` с 30-секундным ожиданием.
3. **Сосуществование с `.deb` — «последняя явно установленная пользователем копия владеет меню и автозапуском»**, общий
   lock одного экземпляра и общие данные уже есть; в «О программе» видно, какая копия работает, и одна кнопка возвращает
   системную версию. Администратор может запретить трек ключом `appimage=deny` (совещательно, не техническое средство).
   **T1/MJ-4:** в треке AppImage программа, keyring и пины лежат во владении пользователя — защита слабее, чем у `.deb`
   (инвариант §5); заказчик разрешил трек и при `profile=secure`, автоматического отказа нет, решение — за администратором.
4. **`latest.json` версии 2 с блоком `artifacts` (`deb`, `appimage`: имя, sha256, размер)**; код выбирает артефакт по
   `paths.install_kind()`; действие «Доступна версия X» для AppImage = скачать → проверить подпись `Verifier("release")` →
   «Установить и перезапустить». Самообновление v1.0 — тот же путь без участия пользователя.
5. **OpenSSL 1.1.1k остаётся в 0.2 как принятый риск** (это сборка AlmaLinux 8 с бэкпортами, только TLS-клиент к
   allowlist-хостам, CA — хостовые, `gpgv` — хостовый). В v1.0 база Python переезжает на пакеты Debian 12 (тот же
   интерпретатор, что в `.deb`, OpenSSL 3 с хоста). Сборки `manylinux_2_34` у python-appimage нет (проверено 28.09) —
   вариант B закрыт; решение заказчика В2: принятый риск П16.
6. **CI: workflow вызывает только скрипты репозитория**; включение AppImage в выпуск — файл-флаг `packaging/appimage/ENABLED`.
   Одна правка `.github/workflows/ci.yml` заказчиком 05–06.10 (список §9.4).
7. **T1 (28.09) — строить можно, четыре условия внесены:** отказ установки из небезопасной временной папки — в коде
   `userinstall`, не в `AppRun` (BL-1, §1); путь автозапуска и меню — только из `app/current` с проверкой `is_relative_to`
   (MJ-1, §3–§4); имя ассета обновления строится из версии, `latest.json` читается только после сверки с подписанными
   суммами (MJ-2, §6); от root трек не работает, снятие чужого профиля — `runuser` (MJ-3, §1/§4); MJ-4 — инвариант §5.
   Minor MN-1…MN-9 — по разделам; проверки T-175…T-182 (T1 §7).

Оценка всего пакета 0.2: **≈ 11 дней потока** (ревизия 1 — ≈ 10; +≈ 1 по требованиям T1; вилка 9,5–12; без переезда OpenSSL).

## 1. Раскладка установки в `$HOME`

**Решение.**

```
~/.local/share/astra-voice/                 # = paths.data_dir(), 0700, уже есть (models/, logs/, measurements.json)
  app/                                      # только копии программы; ничего пользовательского здесь нет
    0.2.0-1c866c1789f7/                     # <версия>-<build_id> (KEY из .astra-voice-build, как в спайке)
      AppRun  opt/  usr/  .astra-voice-build  .installed-ok
    0.1.0-8f0e…/                            # предыдущая версия (откат)
    current -> 0.2.0-1c866c1789f7           # стабильная точка входа: меню, автозапуск, «О программе»
    previous -> 0.1.0-8f0e…                 # необязательный; переключается вместе с current
    .install.lock                           # flock
```

- **Стабильная точка входа — симлинк `app/current`**, а не лаунчер в `~/.local/bin`: без лишнего исполняемого файла в
  `$HOME`, без зависимости от `PATH` сеанса (каталог `~/.local/bin`, созданный после входа, в `PATH` не попадает до
  перелогина), переключение атомарное (`os.symlink(tmp)` + `os.replace(tmp, current)`), запущенный процесс не замечает смены:
  он живёт в своём `<KEY>/` (`sys.executable` внутри копии, воркер стартует через него — `worker/supervisor.py`).
  Команда `astra-voice` в терминале для AppImage-пользователей не требование; при желании — v1.0.
- **Правило старых версий:** хранятся ровно `current` и `previous`; всё остальное в `app/`, что подходит под маску
  `^\d+\.\d+\.\d+(~[A-Za-z0-9.]+)?-[0-9a-f]{12}$`, плюс `.tmp-*`, удаляется **при установке новой версии** (не при
  старте). Ничего другого чистка не трогает: модели (`../models`), журналы, `settings.json` лежат вне `app/`, а маска и
  запрет следовать по симлинкам защищают от случайного `rm -rf`. Работающую копию защищает файл
  `runtime_dir()/running-key` (пишет `app.py` при старте): версия из него не удаляется, даже если уже не `current`/`previous`.
  Цена: 2 × 267 МБ ≈ 0,55 ГБ (решение заказчика В1 28.09 — две копии).
- **Блокировка самоустановки:** `fcntl.flock(app/.install.lock, LOCK_EX)` с ожиданием ≤ 180 с (в `userinstall.py`);
  блокировка исчезает вместе с процессом, зависших `.lock-<KEY>` не бывает. После получения замка — повторная проверка
  «уже установлено». Свободное место: `os.statvfs(app)` ≥ 350 МБ, иначе «Недостаточно места в домашней папке: нужно ещё N МБ».
- **T1/BL-1 (У101) — проверка каталога-источника до копирования, в коде, а не только в `AppRun`.**
  `userinstall.install_from_dir()` в режиме В (extract-and-run) отказывает, если `HERE` или любой его родитель до
  `$TMPDIR` (по умолчанию `/tmp`; сам `$TMPDIR` не проверяется — он 1777 по замыслу) либо до `$HOME` — что встретится
  раньше — по `os.lstat` фактического пути: символьная ссылка, не каталог, владелец не текущий uid или запись разрешена
  группе/миру (`mode & 0o022`). **30.09 (BL-1a):** это гигиена, не контроль У101 — см. §8 «Решение 30.09 (б)». Сообщение: «Небезопасная временная папка. Запустите так:
  `TMPDIR="$HOME/.cache" ./….AppImage --appimage-extract-and-run`», код выхода 4, `app/` не создаётся. В режиме Б источник
  обязан быть корнем монтирования типа `fuse*` с `ro,nosuid,nodev` по `/proc/self/mountinfo` (точка монтирования —
  приватный `mkdtemp`, T1 B20); иначе тот же отказ. Документированная команда с `TMPDIR` (§8) — подстраховка, не барьер.
- **T1/MJ-3 (У104) — от root не работаем.** `AppRun` (`id -u` = 0) и `bootstrap.main()` в бандле (`os.geteuid() == 0`,
  любая команда: `app`, `selfinstall`, `--uninstall`, даже `--version`) завершаются с сообщением «Версия AppImage не
  запускается от имени root. Управляйте ею под учётной записью пользователя» и кодом 3, не меняя ни одного файла.
  Трек `.deb` не затронут.
- **T1/MN-1 (У106) — одна грамматика KEY.** Маска `^\d+\.\d+\.\d+(~[A-Za-z0-9.]+)?-[0-9a-f]{12}$` живёт в
  `userinstall.KEY_RE`; `AppRun` проверяет KEY тем же правилом из `packaging/appimage/keylib.sh` (функция `key_ok`:
  `case`-шаблон, отказ на `/`, `..`, пробелы и управляющие символы); общий набор векторов `tests/fixtures/appimage/keys.txt`
  прогоняется обоими (T-181). Чистка в sh не делается вовсе — только в Python.
- **T1/MN-8 (У111):** `running-key` сравнивается как строка KEY с именами каталогов `app/`; путь из содержимого файла
  не строится.
- **Порядок установки** (`userinstall.install_from_dir(src)`, так в коде с 28.09): отказ от root (MJ-3) → **проверка
  источника (BL-1) — до замка и до создания `app/`**, чтобы отказ не оставлял следов (T-175) → чтение `.astra-voice-build`
  → место ≥ 350 МБ (при первой установке — до создания `app/`) → `flock` → повторная проверка «уже установлено» → уборка
  своих брошенных `app/.tmp-*` и проверка места под замком → `cp` в `app/.tmp-<KEY>.XXXX` (Python
  `shutil.copytree(symlinks=True)`, режимы файлов сохраняются) → маркер `.installed-ok` → `syncfs` тома (данные копии на
  диске до `rename`) → **смоук новой копии** `<tmp>/AppRun --version` == ожидаемая версия → `os.rename(tmp, app/<KEY>)`
  → `previous := current` (если был и ≠ KEY) → `current := KEY` (атомарно) → чистка по правилу выше → регистрация (§4).
  Смоук перед переключением — это и есть «атомарная замена» для самообновления v1.0: сломанная сборка не становится `current`.
- **Запуск файла всегда делает его версию текущей.** Повторный запуск того же `.AppImage` — быстрый путь (`installed_ok`
  → `exec app/<KEY>/AppRun`, ≈ 20 мс + Python); запуск старого файла — откат (переустановка старой версии как `current`).
- **Не устанавливать** — только явно: `ASTRA_VOICE_PORTABLE=1` (замена `ASTRA_VOICE_SELFINSTALL` спайка, инвертированная):
  запуск из монтирования без записи в `$HOME` (для проверок и администраторов). Служебные флаги `--version`, `--help`,
  `--stats`, `--selfinstall-status` тоже не устанавливают (закрывает спайк §7.10).

**Альтернативы (одной строкой).** Лаунчер `~/.local/bin/astra-voice` — лишний исполняемый файл и зависимость от `PATH`
сеанса; `current` как настоящий каталог с переименованием — работающий процесс потерял бы свой путь; только `current` без
`previous` — дешевле по диску, но чистка удалит работающую версию при обновлении из GUI и нет отката для v1.0.

**Оценка.** 1,75 дня (`userinstall.py` + `bootstrap selfinstall` + тонкий `AppRun` + юнит-тесты; +0,25 по T1: проверка
источника, отказ от root, общая грамматика KEY).

**Тест.** T-164 (unit, временный `HOME`): установка → `current`/`previous`/чистка по маске; повторная установка того же KEY
не копирует; параллельный запуск двух установок — вторая ждёт flock и берёт готовую копию; нехватка места → сообщение и
ничего не создано; `app/` — симлинк → отказ; смоук новой копии провален → `current` не переключён, `.tmp` убран;
`running-key` защищает работающую версию. T-170 (smoke.sh): `--version` из `--appimage-extract-and-run` не создаёт `app/`.
**T1:** T-175 (I) — источник в режиме В с чужим владельцем / правами 0775 / родителем-ссылкой → отказ до копирования,
`app/` нет; 0700 под своим uid → установка; T-179 (U/M) — `AppRun`/`bootstrap` при `euid==0` → отказ, файлы не тронуты;
T-181 (U) — `key_ok` (sh) и `KEY_RE` (Python) дают одинаковый вердикт на общем наборе имён.

## 2. Сосуществование с `.deb`

**Факты (В).** Один desktop ID `astra-voice.desktop`: `~/.local/share/applications` перекрывает `/usr/share/applications`;
один файл автозапуска `~/.config/autostart/astra-voice.desktop`; общий lock `$XDG_RUNTIME_DIR/astra-voice/lock`
(`app.py:816`, `QLockFile`) — второй экземпляр любого трека шлёт `--show` первому и выходит; общие `~/.config/astra-voice`,
`~/.local/share/astra-voice/models`, `~/.local/state/astra-voice`. `Settings` держит незнакомые ключи в `extra`
(`core/settings.py:91–101`) — версии переживают друг друга в обе стороны.

**Решение — правило (б) «пользователь выбрал — пользователь владеет», с явным обратным ходом.**

| Ситуация | Меню | Автозапуск | Что видит пользователь |
|---|---|---|---|
| Только `.deb` | системная запись | своя запись `Exec=/usr/bin/astra-voice --hidden` (как в v0.1) | «Установка: пакет (администратором)» |
| Только AppImage | `~/.local/share/applications/astra-voice.desktop` → `app/current/AppRun` | своя запись → `app/current/AppRun --hidden` | «Установка: в домашнюю папку (AppImage)» |
| Стоят оба, AppImage установлен позже | пользовательская запись перекрывает системную → AppImage | своя запись перенацелена на `app/current/AppRun` (только если запись **наша**, чужую не трогаем) | «Установка: AppImage. Есть и системная версия X — [Использовать системную версию]» |
| Стоят оба, `.deb` поставлен позже | без изменений: меню и автозапуск продолжают запускать AppImage | без изменений | то же; если системная новее — «Системная версия новее (X)» + та же кнопка |
| Пользователь нажал «Использовать системную версию» | пользовательская запись удалена → системная | своя запись перенацелена на `/usr/bin/astra-voice` | «Установка: пакет»; копии в `app/` можно удалить второй кнопкой |

- Почему не (а) «при наличии `/usr/bin/astra-voice` AppImage не регистрируется без согласия»: для этого нужен диалог до
  запуска Qt (в sh его нет), а типовой сценарий трека — пользователь без прав администратора, который сам решил поставить
  программу; воля администратора выражается политикой (§5), а не тихим отказом.
- Как программа узнаёт, какая копия работает: `paths.install_kind()` → `InstallKind.DEB | APPIMAGE | SOURCE` по
  `ASTRA_VOICE_APPIMAGE_DIR` (ставит `AppRun`) с запасной проверкой маркера `.astra-voice-build` вверх от `bootstrap.py`
  и `here.is_relative_to(INSTALL_LIB_DIR)` (как сейчас в `resource_root()`); в «О программе» (`qml/sections/About.qml`,
  `AppInfo` в `app.py:364`) — строка «Способ установки» и версия; версию системной копии AppImage узнаёт чтением
  `/usr/lib/astra-voice/astra_voice/_version.py` (без `dpkg-query`, без дочернего процесса; **T1/MN-7 (У108):** открытие с
  `O_NOFOLLOW`, только обычный файл, лимит 4 КиБ, версия — строго по регулярному выражению, иначе «неизвестна»).
- **T1/MJ-4:** в «О программе» для трека AppImage — строка простым языком: «Программа и ключи проверки обновлений лежат в
  вашей домашней папке, поэтому защищены слабее, чем при установке администратором (пакет .deb)»; та же мысль — в
  `INSTALL-ADMIN.md` (§5).
- Понижение версии (AppImage 0.2 после `.deb` 0.3) не запрещаем, но `catalog-state.json` (анти-откат каталога) и
  `settings.extra` переживают его; в «О программе» — та же подсказка «Системная версия новее».

**Альтернативы.** (а) приоритет администратора — см. выше; отдельные каталоги данных для AppImage — дублирование моделей
(226 МБ) и разъезд настроек, отвергнуто (ресёрч §7, практика Krita).

**Оценка.** 1 день (детект трека, «О программе», две кнопки, перенацеливание записи).

**Тест.** T-163 (unit): `install_kind()` по env/маркеру/пути. T-166 (unit, временный `HOME` + фиктивный
`/usr/bin/astra-voice` через параметр): регистрация при стоящем `.deb` перенацеливает **только** нашу запись; чужая запись
(`Exec=sh -c "sleep 8; …"`) — байт в байт; «Использовать системную версию» возвращает `Exec=/usr/bin/astra-voice`, без
`.deb` — удаляет запись; модели и `settings.json` в фикстуре нетронуты. T-173 (integration): экземпляр с lock из одного
трека + запуск другого → `--show`, второй процесс не стартует. Руками (М): оба стоят → меню запускает AppImage, после
кнопки — пакет.

## 3. Автозапуск

**Решение.**
- Запись AppImage-трека: `Exec="<XDG_DATA_HOME>/astra-voice/app/current/AppRun" --hidden`, `TryExec=<тот же путь>`,
  `X-KDE-autostart-after=panel`, `X-AstraVoice-Managed=true`, `NoDisplay=true`, `Icon=astravoice` — те же строки, что в
  `_ENTRY` (`platform/autostart.py:17–28`), меняется только исполняемый файл. Путь в `Exec` экранируется по спецификации
  Desktop Entry (кавычки); `TryExec` пишется, если в пути нет пробелов и кавычек (иначе опускается — запись автозапускается
  без проверки; на ALSE логины POSIX, случай теоретический). Не `$APPIMAGE`: файл переедет или будет удалён, а
  запуск через FUSE вдвое медленнее и не работает под `nochmodx`. `TryExec` даёт тихий пропуск, если пользователь снёс `app/`.
- `autostart.py`: константа `EXECUTABLE` → функция `executable() -> str` из `core/paths.py`: `DEB`/`SOURCE` →
  `/usr/bin/astra-voice`; `APPIMAGE` → `str(paths.appimage_current_apprun())` (= родитель `ASTRA_VOICE_APPIMAGE_DIR` / `current/AppRun`);
  портативный режим (§1, не установлен) → переключатель автозапуска заблокирован с подсказкой «Автозапуск доступен после
  установки»: запись на `$APPIMAGE`, точку монтирования или распаковку не пишется никогда (T1/MJ-1). `_ENTRY` становится
  `entry_bytes()`.
- **Сверка при смене трека — только при регистрации, не при старте.** Правило v0.1 «при старте файлы автозапуска не
  пишутся» (`INSTALL-ADMIN.md` §6, У27, PRD F10.1) сохраняется. Новая функция `autostart.retarget()` вызывается из
  `userinstall.register()`/`unregister()`: если пользовательская запись **наша** (`X-AstraVoice-Managed=true`) — заменяет
  только строки `Exec`/`TryExec`, сохраняя `Hidden=true`, порядок строк, права; чужую запись не трогает (как сейчас — только
  `Hidden`). При старте — только чтение: `AutostartState` получает поле `target: "ours-this" | "ours-other" | "foreign" | "system" | "none"`,
  и «О программе»/«Общие» показывают подсказку «Автозапуск запускает другую копию» (без записи в файл).
- `ensure_autostart_after_onboarding` (`ui/bridges.py:467`) и `set_enabled` не меняются: они уже берут содержимое записи
  из модуля, а тот — из `executable()`.
- **T1/MJ-1 (У102) — инвариант с проверкой, а не намерение.** `register()` и `retarget()` строят `Exec`/`TryExec` **только**
  из `paths.appimage_current_apprun()` и отклоняют регистрацию, если путь не `is_relative_to(data_dir() / "app")`,
  `current` — не наш симлинк или его цель вне `app/` (так будет, если `ASTRA_VOICE_APPIMAGE_DIR` указывает в
  `/tmp/.mount_*` или в распаковку — например, при вызове регистрации до самоустановки). Отказ — в журнал, файлы не
  меняются; самоустановка всегда предшествует регистрации (`--register` только после `exec app/<KEY>/AppRun`).
  **T1/MN-2 (У109):** при формировании `Exec` символ `%` удваивается (`%%`), путь с управляющими символами (< 0x20, 0x7F)
  или переводом строки → отказ; то же правило у `retarget()` для нашей записи (чужая — по-прежнему только `Hidden`).

**Альтернативы.** Сверять и переписывать при каждом старте — нарушает У27/PRD F10.1 и правило заказчика про чужую запись;
`Exec=astra-voice` через лаунчер в `~/.local/bin` — зависимость от `PATH` сеанса (§1).

**Тест.** T-165 (unit): содержимое записи по треку; экранирование пути с пробелом; `retarget()` сохраняет `Hidden=true`,

## 5. Политика администратора

**Факт.** `core/policy.py` читает абсолютный `/etc/astra-voice/policy.conf` (`POLICY_PATH`) — из AppImage это тот же
файл хоста, тем же кодом; M7-ядро добавит проверку владельца/прав (У16/У37) — одинаково для обоих треков.

**Решение.** Новый ключ `appimage = allow | deny` (по умолчанию `allow`), действует в 0.2 минимально:
- `app.py` сразу после `policy_mod.load()` (`app.py:828`): `deny` → журнал, уведомление/stderr «Администратор запретил
  версию, установленную в домашнюю папку. Программу на этом компьютере устанавливает администратор (пакет .deb)», код выхода 3;
  самоустановка (`bootstrap selfinstall`) при `deny` не копирует ничего.
- `AppRun` — быстрый предварительный отказ до копирования 267 МБ: `grep -Eiq '^[[:space:]]*appimage[[:space:]]*=[[:space:]]*(deny|no|false|0)'`
  по файлу, если он читаем; окончательное слово — за Python.
- Невалидный файл (`invalid`): для сети остаётся fail-closed (У37), для `appimage` — как `allow` (запуск не сетевая
  операция; пользователь на машине с испорченной политикой не должен остаться без программы); в журнал.
- `INSTALL-ADMIN.md` §5: ключ, и честно — **это совещательный запрет**: владелец копии может её изменить; технический
  запрет пользовательских исполняемых файлов — средства ОС (ЗПС, `astra-nochmodx-lock`, `noexec` на `/home`), при которых
  AppImage не работает по определению.

- **T1/MJ-4 (У105/П15) — инвариант; решение заказчика 28.09: «разрешить оба».** В треке AppImage корень доверия к
  обновлениям (keyring `data/keys/release.gpg`, `PINNED_FINGERPRINTS`), код чтения `policy.conf` и сама программа лежат в
  `app/<KEY>/` во владении пользователя (граница B22): процесс того же uid может изменить их до применения. Поэтому
  политика администратора и пины в этом треке — **не техническое средство** против процесса того же uid; техническое
  средство — только `.deb` под root с ЗПС/`astra-nochmodx-lock`. Заказчик разрешил трек и при `profile=secure`:
  **автоматического отказа при `secure` не делаем**, решение — за администратором через `appimage=deny`, и этот ключ
  совещательный. Сказать это простым языком обязательно в двух местах — `INSTALL-ADMIN.md` (раздел про AppImage и §5
  «Политика») и «О программе» для трека AppImage: «Программа и ключи проверки обновлений лежат в вашей домашней папке,
  поэтому защищены слабее, чем при установке администратором. Если на вашем компьютере действуют требования безопасности,
  попросите администратора установить пакет .deb». Принятый риск — П15 (`decisions/log.md`, строки T1 §8).

Надо ли в 0.2: да — 0,25 дня, а без ключа у администратора парка нет документированного ответа «как запретить». Ключи
`updates=admin`/`offline` (PRD F14) начнут действовать на самообновление в v1.0 (MA-2).

**Альтернативы.** Отказ при `profile=secure` автоматически — отвергнут заказчиком (MJ-4, «разрешить оба») и неожидан для
существующих политик; ничего не делать в 0.2 —
дешевле на 0,25 дня, но вопрос от администраторов неизбежен.

**Оценка.** 0,25 дня.

**Тест.** T-167 (unit): `policy.conf` с `appimage=deny` → `main()` возвращает 3 до создания `QApplication` в треке
APPIMAGE и ничего не делает в треке DEB; `invalid` → запуск разрешён; smoke.sh: `AppRun` под запретом не создаёт `app/`
(решение 29.09: своего разбора политики в `AppRun` нет, решает только `core/policy.py`; при стоящем `.deb` установленная
копия передаёт запуск в `/usr/bin/astra-voice`, снятие регистрации запретом не блокируется — `decisions/log.md` 29.09). **T1:** T-180 (U) — `profile=secure` без

трек DEB — без изменений; `invalid` → запуск разрешён, сеть закрыта.

**`latest.json` версии 2** (`scripts/release_latest_json.py`; потребителей у версии 1 нет, `tools/validate release` правится):

```json
{
  "schema": 2,

  "published_at": "2026-10-15T09:00:00Z",
  "min_astra": "1.8",
  "release_url": "https://github.com/ArrivaRUS/astra-voice/releases/tag/v0.2.0",
  "artifacts": {
    "deb":      {"name": "astra-voice_0.2.0_amd64.deb",          "sha256": "…", "size": 15728640},
    "appimage": {"name": "Astra_Voice-0.2.0-x86_64.AppImage",     "sha256": "…", "size": 81226232}
  }
}
```

`artifacts.appimage` присутствует только при `packaging/appimage/ENABLED`; `SHA256SUMS(.asc)` покрывает оба файла и оба SBOM
(`sbom.cdx.json`, `sbom-appimage.cdx.json`) — модель доверия одна: подпись `SHA256SUMS.asc` подключом мастера
`5F1F7718559F8F57FFE1178055BB1162F17A5CB0` (`security/verify.py:PINNED_FINGERPRINTS`), sha256 из подписанного файла.

**Как код отличает трек:** `paths.install_kind()` → `updates/checker.py` (M7-ядро) берёт `artifacts["appimage"]` или
`artifacts["deb"]`; `SOURCE` → `deb`. Источник версии — GitHub `releases/latest` (PRD F9.1) → `latest.json` из ассетов тега.

**T1/MJ-2 (У103) — `latest.json` только указатель; имена и версии — под подписью.** Порядок в `updates/checker.py`:
GitHub `releases/latest` → тег → из ассетов тега скачать `SHA256SUMS`, `SHA256SUMS.asc`, `latest.json` → `verify_detached`
(пин мастера) → `verify_sha256sums(SHA256SUMS, latest.json)` (`latest.json` входит в подписанный список — `ci.yml:333`) →
только теперь читать `latest.json`: `version` обязан совпасть с тегом и быть строго больше установленной (SemVer).
**Имя ассета продукт строит сам из версии** — `Astra_Voice-<version>-x86_64.AppImage` / `astra-voice_<version>_amd64.deb` —
и требует его в `SHA256SUMS` (`verify_sha256sums` ищет точное имя: `verify.py:246–263`); из `latest.json` берутся только
`size` (после сверки — доверенный) и `release_url`. Старый подлинно подписанный набор под новым `latest.json` так не
пройдёт: неподписанный `latest.json` не проходит сверку сумм, а подписанный старый даёт версию не больше текущей.
**T1/MN-6 (У113):** до скачивания — `os.statvfs(cache_dir())` ≥ `size` + 64 МиБ, иначе «Недостаточно места»; чтение
обрывается на `size+1` байт (как У20/У23 у моделей), недокачанный `.part` удаляется.

**Куда ведёт «Доступна версия X» (действие 2b плана, без помощника):**
- `.deb`: «Скачать пакет» → `~/.cache/astra-voice/updates/<версия>/` (0700): deb + `SHA256SUMS` + `.asc` →
  `Verifier("release").verify_detached` → `verify_sha256sums` → «Открыть папку» + «Установку выполняет администратор:
  `sudo apt install ./…`».
- AppImage: «Скачать новую версию» → файл с именем, построенным из версии (MJ-2), + те же `SHA256SUMS`/`.asc` → та же
  проверка → `chmod 0755` **только после** проверки →
  «Установить и перезапустить»: `Popen([файл], start_new_session=True, env=clean_env())` → `app.quit()`. Новый процесс сам
  устанавливает версию, переключает `current`, регистрируется и стартует (§1). Если lock ещё занят (гонка с выходом) —
  новый процесс шлёт `--show` старому и выходит, но `current` уже переключён: следующий запуск из меню — новая версия;
  для пользователя всегда доступна и ссылка `release_url`.
- Понижение версии не предлагается (SemVer > текущей), `T-116` (часы) — общая для треков; `policy: offline`/`invalid` — сеть
  запрещена, как сейчас (`net/gate.py`).

**Задел под самообновление v1.0 (MA-2)** — новые части не нужны, только связка существующих:
1. загрузка в `app/.tmp-download/` (тот же том, что `app/` → атомарный `rename`), проверка `Verifier` (gpgv хостовый,

## 7. OpenSSL в бандловом Python

**Факты (проверено на машине заказчика, только чтение).** В AppDir спайка `usr/lib/libssl.so.1.1` и `libcrypto.so.1.1` —

## 8. PARSEC / `nochmodx`: что говорим и нужен ли установщик

**Факты.** У заказчика `parsec.enable_exec_on_fuse=N`, `/parsecfs/nochmodx=0` — запуск из FUSE работает (спайк §4).
При включённом `astra-nochmodx-lock` (или параметре ядра): runtime монтирует образ, `execv AppRun` падает, в терминал —
`execv error: …`, по двойному щелчку — ничего; `AppRun` управления не получает. Кроме того, под `nochmodx` пользователь
**не может поставить бит исполнения на скачанный файл** — то есть не запустит и `--appimage-extract-and-run`; выдержит ли
распаковка/копирование режимов файлов сам запрет — **данных нет (Н)**, стоковой ВМ у заказчика нет (ответ 28.09).
`noexec` на `/home` и ЗПС — не работает ничего (ресёрч §4).

**Решение.**
- **Отдельный скрипт-установщик не нужен:** установщик — сам `.AppImage` (режим В `appimage_extracted_*` → самоустановка,
  временная распаковка удаляется, спайк §9.4). Достаточно одной документированной команды на случай «FUSE запрещён, но
  бит исполнения ставить можно»:
  ```sh
  chmod +x Astra_Voice-0.2.0-x86_64.AppImage
  TMPDIR="$HOME/.cache" ./Astra_Voice-0.2.0-x86_64.AppImage --appimage-extract-and-run
  ```
  `TMPDIR` в домашней папке — на случай `noexec` на `/tmp` и против подсадки предсказуемого `/tmp/appimage_extracted_<md5>`
  другим пользователем. **T1/BL-1:** это подстраховка, а барьер — отказ `userinstall` от небезопасного источника (§1); когда
  новый файл запускает сама программа (§6), она ставит `TMPDIR` внутри `cache_dir()` и снимает `APPIMAGE_EXTRACT_AND_RUN`
  (§10.4). После установки последующие запуски FUSE не используют.
- **Текст пользователю** (страница выпуска, README, уведомление не показать — программа не стартует): «Если после
  двойного щелчка ничего не происходит, откройте терминал в папке с файлом и выполните две команды выше. Если и это не
  помогло — на компьютере включён режим защиты, и установить программу может только администратор (пакет .deb)». Ни в
  одной инструкции для пользователя нет `sudo` (T1/MN-4).
- **Текст администратору** (`INSTALL-ADMIN.md`, новый раздел «Установка без прав администратора (AppImage)»): где трек
  не работает — ЗПС, `astra-interpreters-lock`/`astra-nochmodx-lock`, `noexec` на `/home`, `parsec.enable_exec_on_fuse=0`
  (при нём — команда выше); что программа кладёт в `$HOME` (§1) и как это снять (§4); ключ `appimage=deny` (§5);
  «на системе с запретом запуска из FUSE не проверено» — так и пишем в заметках к выпуску (решение 28.09).
- В `AppRun` при неудаче самоустановки в режиме Б (нет места и т. п.) — запуск из монтирования с уведомлением
  «Программа работает без установки»; в режиме В — только сообщение и выход.

**Решение 30.09 (б) — BL-1a/У101** (`decisions/log.md` 2026-09-30 «BL-1a (У101): решение заказчика — вариант (б)»;
`docs/security/2026-09-30-t1t2-appimage.md` §3.1). Абзацы выше о «барьере в `userinstall`» замещены: закреплённый
type2-runtime переиспользует чужой `$TMPDIR/appimage_extracted_<md5 содержимого>` и исполняет его `AppRun` раньше любой
нашей проверки, поэтому контроль — вне бандла. Запуск без FUSE с распаковкой в общий `TMPDIR` (`/tmp`) **не
поддерживается**; штатный первый запуск — через FUSE (libfuse на ALSE есть); если FUSE недоступен — только с личным
временным каталогом: `TMPDIR="$HOME/.cache" ./Astra_Voice-<версия>-x86_64.AppImage --appimage-extract-and-run`.
Runtime уважает `TMPDIR` (проверено `smoke.sh` шаг 2b), распаковка ложится в `~/.cache/appimage_extracted_<…>` под своим
uid, `AppRun` видит режим В, самоустановка идёт как из FUSE, распаковка удаляется. `--appimage-extract` (в `squashfs-root`
текущей папки) не выбран: из такой папки `AppRun` работает в режиме Г без самоустановки (нет меню и автозапуска), а
распаковка остаётся на диске. `check_source` остаётся гигиеной, без ярлыка «контроль У101». Та же формулировка — README,
`INSTALL-ADMIN.md` §3, `docs/threat-model.md` У101, `docs/plans.md` §MA. Вариант (а) — доверенный runtime с приватной
распаковкой (upstream-фикс или наша сборка с патчем, подписанная ключом выпуска) — **кандидат v1.x**. Тест — T-197.

**Альтернативы.** Патчить runtime, чтобы сам падал в extract-and-run, — чужой бинарь, теряем пин по sha256; `install.sh`
рядом с файлом — ещё один файл без бита исполнения под тем же запретом.

**Оценка.** 0,5 дня (тексты; tech-writer) + 0,25 (ветка отказа в `AppRun`).

**Тест.** T-175 (BL-1, см. §1). T-170 (smoke.sh): режим В во временном `HOME` с `TMPDIR` внутри него → установка, распаковка удалена; отказ по
месту → в режиме Б `exec` из монтирования (эмуляция: `ASTRA_VOICE_TEST_NO_SPACE=1`). Руками (М): «двойной щелчок»
в Dolphin и во Fly-FM (чеклист 12.10 — запускает ли Fly-FM `.AppImage` вообще).

**Проверено на ALSE — В:**

- Python-пакеты установлены в версии `3.11.2-6+deb12u6.astra6`; доступный кандидат из локального apt-кэша метаданных уже другой. Поэтому `apt-cache policy/show` не подменяет фиксацию конкретного входа.

**Манифест хоста (29.09, реализация R3).** Всё, что ELF бандла берут вне AppDir, перечислено в `packaging/appimage.lock` записями `# host-lib: <SONAME> <пакет>` — 44 SONAME: glibc, C++-рантайм, восемь библиотек интерпретатора выше, `libssl.so.3`/`libcrypto.so.3` и прежний графический/шинный контракт Qt. Статус каждого — **origin=host, not-bundled**, как у OpenSSL; так же они отражаются в SBOM. `check_bundle.py` валит сборку, если DT_NEEDED вне AppDir не из манифеста, если запись манифеста не нужна ни одному ELF или отсутствует на машине проверки.

**Удаляем до расчёта зависимостей:**

- `readline*.so`, `_gdbm*.so`, `_dbm*.so`, ненужные DBM-обёртки;
- `libreadline*`, `libgdbm*`, `libgdbm_compat*`, `libdb-*.so*`;
- `_tkinter`, Tcl/Tk, `tkinter`, IDLE, тестовые расширения и уже удаляемый сборщиком мусор;
- при отсутствии потребителей — `_curses`, `_curses_panel`, `nis`, вслед за ними ненужные ncurses/panel/tinfo и NIS/RPC-зависимости;
- `pip`, `ensurepip`, инструменты разработки из итогового дерева;
- **`sitecustomize.py`, ведущий на хост**, и прочие абсолютные/выходящие из AppDir симлинки.

Не копировать транзитивный список `apt Depends` целиком: он включает возможности stdlib, которые продукт не использует. Одновременно нельзя удалить библиотеку, оставив зависящий от неё `.so`: гейт проверяет обе стороны.

**Относительность Python — главный технический спайк.** Локальные `site.py` и `sysconfig.py` подтверждают Debian-поведение: вне venv используются `dist-packages`, схема установки по умолчанию — `posix_local`; обычный `site-packages` автоматически не добавляется. `-I` отключает пользовательские Python-пути, но не является запретом глобального `site` и `sitecustomize`.

На хосте `/usr/lib/python3.11/sitecustomize.py` — абсолютная ссылка на `/etc/python3.11/sitecustomize.py`; этот файл пытается подключить apport. Перенос такой ссылки создал бы зависимость от кода хоста ещё до `bootstrap`.

Предлагаемое решение:

1. Перенести интерпретатор вместе с полным необходимым деревом stdlib под `opt/python3.11`, сохранив ориентиры поиска stdlib, включая `os.py` и `encodings`.
2. Удалить хостовый `sitecustomize`; не создавать venv, привязанный к `/usr`.
3. Добавить указанный относительный адаптер `dist-packages`.
4. Ставить колёса **сборочным Python 3.11 контейнера** через `pip --target <SITE> --no-index --no-deps --require-hashes`; pip внутри Debian-бандла отсутствует и не нужен.
5. Сохранить запуск `-I`. `PYTHONHOME`/`PYTHONPATH` не использовать как исправление: при `-I` они игнорируются.
6. Подтвердить самостоятельный поиск префикса во всех режимах T-183. Если он не проходит, не маскировать это переписыванием `sys.prefix` после старта; исправление механизма запуска входит в установленный срок спайка.

**С:** корректно перенесённый префикс должен удержать производные пути внутри AppDir. Без запуска точного Debian-интерпретатора это пока не доказано.

`AppRun`, `userinstall.REQUIRED_FILES`, `EXECUTABLE_FILES` и запуск воркера через `sys.executable -I ... bootstrap.py worker` сохраняются. В `wt-ma` копирование уже использует `symlinks=True`; относительные ссылки поддерживаются. Повторно проверить запуск из временной установленной копии до `rename`.

Для ELF — адресные относительные `RUNPATH`, вычисленные от положения файла; без глобального `LD_LIBRARY_PATH`. `RUNPATH` не транзитивен: собственные зависимости каждой переносимой библиотеки проверяются отдельно. Состояние унаследованного `LD_LIBRARY_PATH` учитывать в тестах: существующий `AppRun` его не задаёт, но это ещё не означает, что он отсутствует.

**Qt и TLS.** В main и `wt-ma` найдены `QLocalSocket`/`QLocalServer`; `QSslSocket`, `QNetworkAccessManager` и QML `XMLHttpRequest` в просмотренном коде не найдены. Поэтому **QtNetwork оставляем** для IPC. В локальных Qt/PyQt-колёсах нет файлов `libssl`/`libcrypto`. В `libQt5Network.so.5` нет соответствующих `DT_NEEDED`, но есть диагностическая строка несовместимости сборки с OpenSSL 1.x и runtime ≥3.x.

Вывод **С:** Qt TLS с хостовым OpenSSL 3 считать неработоспособным; текущему приложению он не нужен, HTTPS выполняет Python. Не добавлять OpenSSL 1.1 ради Qt. Новое использование Qt HTTPS потребует отдельного решения. Отсутствие прямого `DT_NEEDED` само по себе не исключает `dlopen`.

### R3.3. Цепочка доверия и lock

**Выбираем Debian 12, не смесь Debian и Astra.** Это соответствует контейнеру CI и снимает показанную выше зависимость Astra Python от OpenSSL 3.4. Публичная доступность точных Debian-входов и исходников должна быть проверена при разрешённом получении пакетов — сейчас **Н**.

Порядок происхождения:

```text
доверенный Debian archive keyring
  → подпись InRelease либо Release.gpg + Release
  → SHA256 и размер Packages/Sources
  → SHA256 и размер конкретного .deb / .dsc
  → .dsc: точные orig/debian tar и их SHA256
```

`deb.debian.org` — источник актуального набора; `snapshot.debian.org` — закреплённый адрес архивного набора. Для security-пакетов учитывать отдельный архив. Точный timestamp snapshot, suite, component и пути выбираются по фактически найденным объектам. «Постоянный URL» означает неизменяемую адресацию, а не гарантию доступности сервиса: кэш и архив исходников в Release остаются необходимыми.

`apt-get download package=version` в Debian 12 удобен для получения бинарника. Он не заменяет сохранение подписанных индексов, проверку связи с ними и сверку SHA256 по lock. Не использовать незакреплённые `apt install`/`apt download` как источник содержимого AppDir.

**Предлагаемое расширение `packaging/appimage.lock`:** pip-строки сохраняются; машинные записи о Debian и исходниках остаются комментариями для pip. Например, однострочные JSON-записи:

```text
# base: debian12
# openssl-origin: host
# openssl-major: 3
# max-glibc: 2.36
# expect-elf: <измеренное N>

# archive: {"id":"<id>","keyring":"<путь в репозитории>","signer":"<проверенный fingerprint>","release":"<URL>","sha256":"<SHA256>"}
# index: {"id":"<id>","archive":"<id>","kind":"Packages","file":"<имя>","size":<число>,"sha256":"<SHA256>","url":"<URL>"}
# deb: {"package":"python3.11-minimal","version":"<полная версия>","arch":"amd64","file":"<имя.deb>","size":<число>,"sha256":"<SHA256>","url":"<snapshot URL>","index":"<id>","source":"python3.11","source_version":"<версия исходника>","dsc":"<id исходника>"}
# source: {"id":"<id>","file":"<имя.dsc или tar>","size":<число>,"sha256":"<SHA256>","url":"<точный URL>","index":"<Sources id, если применимо>"}
```

Это **схема, не готовый lock**: угловые скобки не допускаются в выпуске. У исходного и бинарного пакета версии могут различаться, например из-за binNMU; читать поле `Source`, а не выводить исходную версию из имени файла.

Изменения реализации:

- `lockfile.py`: убрать безусловные `TOOL_COUNT=4` и обязательный `python_tool`; для Debian-базы оставить runtime, его подпись и appimagetool. Добавить строгий разбор новых записей, ссылочную целостность, запрет дублей и неполных пинов.
- Проверять одинаковую версию трёх Python-пакетов, архитектуру, source version и соответствие метаданным `.deb`.
- Один разбор lock использовать в сборщике, SBOM и выпуске; сейчас `sbom.py` отдельно разбирает строки инструментов.
- Кэш: `downloads/`, `wheels/`, `debs/`, `sources/`, `metadata/`. Все входы — под существующим каталогом кэша; ключ по `appimage.lock` остаётся достаточным, если все пины в нём.
- Подписи, индексы и хэши проверять также при **офлайн-сборке из кэша**, до распаковки/исполнения. Сейчас подпись runtime проверяется только в `--fetch`; одного кэш-попадания недостаточно.
- Для исторического snapshot: проверять подпись и закреплённый timestamp; исключение по `Valid-Until`, если необходимо, ограничить этим архивным набором. Не отключать проверку подлинности и срока индексов глобально.

**Реализация 29.09:** закреплён ключ «Debian Archive Automatic Signing Key (12/bookworm)» B8B80B5B623EAB6AD8775C45B7C5D7D6350947F8 (из `debian-archive-keyring` ALSE 1.8, отпечаток сверен с ftp-master.debian.org/keys.html), `packaging/appimage/keys/debian-archive-bookworm-automatic.gpg`. **Срок ключа — 2031-01-19 UTC**: до него снимок и ключ перепинить. Codename/Suite InRelease закреплены в lock.

Ключ Debian архивов — отдельный корень доверия к поставщику, не ключ подписи выпуска Astra Voice. Его происхождение и допустимые подписанты закрепляются в репозитории; скачивание ключа вместе с проверяемым пакетом без независимого основания доверия не подходит.

**Архив в Release — принимаем как способ исполнения, а не факультативное украшение.** Предлагаемый ассет: `astra-voice-<version>-sources.tar.xz`; при слишком большом результате — заранее определённые части и единый манифест. Размер не назначать до измерения.

Предлагаемый `scripts/release_sources.sh`:

- режим получения вызывается из существующего сетевого этапа и наполняет `sources/metadata`;
- офлайн-режим сверяет все хэши, комплектность, соответствие source mapping и собирает архив из кэша плюс исходники текущего коммита;
- включает манифест версий/происхождения, лицензии, оригинальные исходные архивы, патчи и инструкции;
- нормализует порядок, владельцев и время; не захватывает `.git`, секреты, рабочие сборки и посторонние файлы.

`release_build.sh` проверяет этот результат до подписи. `release_assets.sh` явно добавляет архив в `files`, `SHA256SUMS` и `assets.txt`; `release.sh` показывает его в предрелизном списке. Схема `latest.json.artifacts` остаётся для установочных артефактов `deb`/`appimage`.

`tools/validate release` расширить для нового набора, сохранив проверку старых выпусков: обязательное наличие архива для 0.2 AppImage, подписанное покрытие, манифест, соответствие версий и комплектность. **В:** текущий лимит обычного ассета — 16 МиБ, установочного — 512 МиБ; архив исходников нельзя молча обрабатывать как небольшой документ. Нужны отдельный обоснованный предел и потоковое хэширование; не загружать весь большой архив в память и не распаковывать непроверенные пути.

**Сеть:** получение недостающих `.deb`, подписанных индексов и исходников, проверка доступности ссылок и публикация Release требуют сети. Проверка подписей/хэшей, сборка из заполненного кэша, локальные HTTPS-тесты, лицензии, SBOM, архив и суммы работают без внешней сети. Сборка при неполном кэше должна завершаться ошибкой, а не скачивать скрыто.

Подпись официального образа и сборочные SHA256 Qt сохраняются. **Проверки целостности Qt при запуске установленной/распакованной пользовательской копии не добавлять.** BUILD_ID — идентификатор сборки; он не должен превращаться в запрет изменённого Qt.

### R3.9. Откат (г)

Откат — прежний закреплённый python-appimage и pip-Qt, с удалением readline/gdbm и связанных возможностей, **не** выключение всех лицензионных гейтов.

1. Вернуть прежнюю базу из её точного lock; не скачивать автоматически «последнюю».
2. Удалить `readline`, `_gdbm`, `_dbm`, `libreadline*`, `libgdbm*`, `libgdbm_compat*`; проверить отсутствие libdb и потребителей удалённых библиотек.
3. Повторно измерить `expect-elf`; сохранить гейт 2.28 лишь после подтверждения.
4. Гейт ожидает именно разрешённую ветку OpenSSL 1.1, SBOM явно называет её и происхождение. Не делать проверку «принимается любая версия».
5. В `decisions/log.md` записать причину отката, артефакт, срок устранения и остающийся лицензионный/ИБ-риск; П16 сохраняется.
6. Выполнить весь общий комплаенс R3.6, включая исходники новой фактической поставки.

Цена технического переключения — **0,5–1 день, С**, при сохранённых входах и доступных исходниках. Собрать и проверить откат до пакета workflow; не поддерживать оба backend в продукте ради одного выпуска.

**Удаление readline/gdbm не устраняет конфликт OpenSSL 1.1 с нашим GPL-кодом и PyQt5**, указанный legal-analyst. Это уменьшение состава при принятом риске, а не заключение о совместимости. Правообладатель нашего кода не может самостоятельно изменить условия Riverbank.

Если отсутствуют обязательные исходники прежнего Qt/runtime, (г) не считается зелёным. При общем красном рубеже 06.10 действует перенос AppImage в v1.0, `.deb` остаётся выпуском 15.10.
