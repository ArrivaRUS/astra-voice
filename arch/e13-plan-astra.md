## 2. Компоненты и границы процессов

```text
GUI-процесс PyQt5/QML
│
├─ MeetingService
│  ├─ пользовательское включение, политика, действия интерфейса
│  ├─ список встреч, карточка, прогресс, участники
│  └─ страж индикации, lease захвата
│
├─ MeetingStore — файловые операции вне GUI-потока
├─ MeetingScheduler + ResourceGate
├─ RecorderSupervisor ── приватный IPC ── Recorder
│                                         ├─ собственный SessionGuard
│                                         ├─ libpulse-контекст и два захвата
│                                         ├─ ограниченные очереди PCM
│                                         └─ сегменты аудио + временная шкала
│
├─ MeetingJobSupervisor ─ приватный IPC ── Processor
│                                         ├─ ASR-черновик
│                                         ├─ диаризация 20 мин + RAM-связывание
│                                         └─ ASR уточняемых реплик
│                                      [фазы — последовательные поколения]
│
├─ существующий WorkerSupervisor ─ v4 ── Worker диктовки
│
└─ SummaryProvider — интерфейс; по умолчанию DisabledProvider

Файлы встречи ← Recorder: только аудио и журнал захвата
Файлы встречи ← MeetingStore: метаданные, задания, текст, экспорт
Processor → только чтение аудио и ограниченные результаты через IPC
```

### Ответственность компонентов

| Компонент | Предлагаемая область файлов | Ответственность |
|---|---|---|
| `MeetingService` | `src/astra_voice/meetings/service.py` | Единственная прикладная точка действий встреч; автомат состояний, гейты, координация |
| `MeetingPolicy` | `meetings/policy.py` | Типизированная эффективная конфигурация, ограничения администратора |
| `MeetingStore` | `meetings/store.py`, `schema.py`, `retention.py` | Безопасные файловые операции, версии данных, восстановление, удаление |
| Планировщик | `meetings/scheduler.py`, `resources.py` | Очередь, память, приоритет диктовки, отмена и восстановление |
| Протокол и супервизоры | `meetings/ipc.py`, `supervisor.py` | Корреляция, поколения, таймауты, выход процессов |
| Recorder | `meetings/recorder/*` | Захват, часы, смена устройств, лимиты, физическое закрытие |
| Processor | `meetings/processing/*` | Выравнивание, VAD/ASR, диаризация, связывание, уточнение реплик |
| UI | мост встреч и `qml/meetings/*` | Реализация принятого G3 |
| Шаблоны | `meetings/templates.py`, `export.py` | Детерминированные представления и безопасный экспорт |
| ИИ-контракт | `meetings/summary_contract.py` | Типы запроса, результата и допуска; без обязательного сетевого клиента |

Названия новых файлов — предложение для реализации.

**Почему не расширяем `transcribe.file` воркера v4.** В базе эта команда использует служебный ID `"file"`, возвращает склеенный текст и не является долговечной очередью. Автомат диктовки рассчитан на короткие PCM-буферы, а подтверждения привязаны к `utterance_id` и типу команды. Простое увеличение лимита времени нарушит изоляцию записи, отмены и диктовки.

Переиспользуются низкоуровневые адаптеры движка, VAD, проверки моделей и подход к запуску дочерних процессов. Не переиспользуются автомат фразы, маршрут вставки текста и владение микрофоном диктовки.

### Потоки и жизненный цикл

- В GUI нет файлового ввода-вывода, инференса или синхронного ожидания процесса.
- Recorder имеет неблокирующий управляющий цикл; аудиоколбэки и запись на диск не задерживают обработку lock/stop.
- Processor имеет управляющий цикл и вычислительный поток. Невозможность прервать нативный вызов закрывается завершением **его собственного** процесса.
- Между ASR и диаризацией процесс завершается. Новая фаза запускается после подтверждённого выхода: это освобождает модели и память нативных аллокаторов.
- Одновременно допускаются одна запись и одно фоновое задание обработки. Новая запись может сосуществовать с обработкой предыдущей встречи, если разрешает бюджет ресурсов.
- Работа встреч включается в общую проверку занятости перед выходом, заменой AppImage и операциями над используемыми моделями.

## 3. Данные и файлы на диске

### Структура

Корень: `${XDG_DATA_HOME:-~/.local/share}/astra-voice/meetings/`.

```text
meetings/                                      0700
└─ 20261201T103000Z-<random-id>/                 0700
   ├─ meeting.json                             0600
   ├─ capture.json                             0600
   ├─ timeline.jsonl                           0600
   ├─ audio/                                   0700
   │  ├─ mic-000001.pcm                         0600
   │  ├─ far-000001.pcm                         0600
   │  └─ ...
   ├─ jobs/                                    0700
   │  ├─ state.json                            0600
   │  ├─ asr.jsonl                             0600
   │  └─ turns.jsonl                           0600
   ├─ results/                                 0700
   │  ├─ transcript-<revision>.json             0600
   │  ├─ transcript-<revision>.md               0600
   │  └─ summary-<revision>.json                0600  [если появится ИИ]
   └─ .delete-intent                           0600  [только при удалении]
```

Имя каталога создаёт программа. Название встречи, имя участника и имя программы ВКС не используются в пути. Все временные файлы с содержимым встречи создаются внутри этого каталога.

Центральная база данных для v1.1 не нужна. Список восстанавливается по небольшим `meeting.json`; чтение выполняется вне GUI-потока. Это упрощает удаление встречи целиком и исключение данных из диагностики.

### Схемы

| Объект | Основные поля |
|---|---|
| `meeting.json` | `schema_version`, случайный `meeting_id`, `revision`, название, время начала с часовым поясом, режим захвата, длительности, состояние, отметки сетевой ФС/аудиослужбы, настройки обработки, ссылка на опубликованный результат, сроки хранения, текстовая таблица имён и объединений |
| `capture.json` | Формат PCM; состояние захвата; список сегментов, дорожек и эпох; подтверждённые смещения файлов; предел записанного времени; финальная причина остановки |
| `timeline.jsonl` | Привязки счётчиков отсчётов ко времени, паузы, пропуски, смены эпох и устройств, границы сегментов |
| `jobs/state.json` | `job_id`, поколение попытки, фаза, `cancelled`, checkpoint, версии алгоритмов/моделей, отпечаток входов, причина ожидания/ошибки |
| `asr.jsonl` | ID окна, дорожка, начало/конец, текст, provisional-метка, версия результата |
| `turns.jsonl` | Начало/конец, анонимная метка говорящего, признак неопределённости; **без признаков голоса** |
| Итоговая реплика | Стабильный `segment_id`, временной интервал, текст, `speaker_label`, дорожка, отметки качества/перекрытия |

Checkpoint связывается с точными ревизиями моделей, алгоритма и входных аудиосегментов. При несовпадении переиспользование запрещено либо ограничено доказанно совместимыми окнами.

**Не сохраняются:** embeddings, центроиды, матрицы расстояний, спектральные признаки, кэш идентификации людей. Числовые таймкоды, анонимные метки и текст не являются заменой такого кэша.

### Аудиоформат и устойчивость

- Две независимые дорожки: PCM S16LE, mono, 16 кГц.
- Логический файл — до пяти минут; пауза и смена эпохи могут завершить его раньше.
- Используется raw PCM с описанием в манифесте: восстановление не зависит от корректно закрытого WAV-заголовка.
- Каждые не более пяти секунд writer фиксирует аудиоданные и устойчивую границу восстановления. Сначала `fdatasync` аудио, затем атомарная запись checkpoint и синхронизация каталога.
- Максимальный возраст подтверждённой границы контролируется. При зависшем диске захват прекращается до нарушения бюджета потери ≤10 секунд.
- После аварии читается только подтверждённый диапазон; недописанный хвост отбрасывается либо восстанавливается после проверки. Пропуск явно отмечается.

Объём двух дорожек:

- 64 000 байт/с;
- около **460,8 МБ за два часа**;
- около **921,6 МБ за четыре часа**, без служебных данных.

Использование PCM делает размер предсказуемым и не добавляет кодек в критический путь захвата.

### Владение файлами и публикация

Recorder пишет только аудио, `capture.json` и `timeline.jsonl`. `MeetingStore` — единственный писатель остальных файлов. Processor получает проверенные дескрипторы аудио только для чтения; пути из входного IPC не открывает произвольно.

Результат публикуется так:

1. Записать новую ревизию структурированного текста и `.md`.
2. Синхронизировать файлы.
3. Атомарно обновить указатель опубликованной ревизии в `meeting.json`.
4. Зафиксировать завершение задания.
5. После выхода процесса с голосовыми признаками открыть редактирование имён.
6. Начать удаление аудио по политике хранения.

До шага 3 прежний результат остаётся действующим. Частичный файл не становится «Готово».

### Удаление и сроки

- По умолчанию аудио удаляется после успешного завершения выбранного конвейера, включая диаризацию, если она включена.
- Отмена, нехватка памяти, отсутствие модели и ошибка обработки аудио не удаляют.
- Сохраняются предусмотренные F18 варианты хранения 7/30 дней и административное значение 0–365 дней. Срок аудио предлагается считать **от успешного завершения обработки**.
- Возраст встречи для удаления целиком — от `started_at`; «Никогда» остаётся значением по умолчанию.
- Автоочистка выполняется при запуске и раз в сутки. Активные задания не удаляются гонкой с таймером.
- Удаление встречи: устойчивый `.delete-intent` → запрет новых работ → отмена и ожидание процессов/операций → удаление каталога. После перезапуска intent завершается до планирования заданий.
- Поздний результат не имеет права воссоздать удалённую встречу.
- Удаление обычное, без обещания гарантированного стирания на SSD. Экспортированные копии программа не контролирует.

### Миграция настроек

В базе `Settings.SCHEMA_VERSION=2`; для E13 резервируется следующая свободная версия, предварительно **3**.

Новые пользовательские настройки:

- `meetings_enabled=false`;
- `meeting_prompt_enabled=false`;
- версия принятого экрана ответственности;
- `meeting_transcribe_immediately=true`;
- `meeting_diarization=true`;
- `meeting_audio_retention_days=0`;
- срок удаления встреч — «Никогда»;
- подпись «Я», текст уведомления и приглашения.

Миграция **никогда не выставляет включение встреч или детектора** по наличию политики, старых экспериментальных ключей либо установленных моделей. Повторное включение после пользовательского выключения снова требует экрана ответственности.

Секрет ИИ не помещается в `settings.json`. Неизвестная более новая схема встречи открывается ограниченно, без разрушительной миграции и автоматического удаления аудио. Downgrade не переписывает её в старый формат.

## 4. IPC/контракты

### Отдельная версия

Диктовка сохраняет `protocol=4`. Для встреч вводится отдельное семейство, например:

```json
{
  "family": "astra-voice.meetings",
  "protocol": 1,
  "role": "recorder",
  "build": "<build-id>"
}
```

Транспорт — унаследованные приватные `socketpair`; публичного сокета, D-Bus-метода или CLI-команды начала записи нет. Запуск служебного процесса с дескриптором не разрешает захват без команды из текущего GUI-сеанса.

Кадрирование — длина + JSON, максимум 64 КиБ. Большие результаты передаются порциями; PCM через GUI не проходит.

### Общий конверт

```json
{
  "type": "capture.pause",
  "request_id": "<unique-id>",
  "meeting_id": "<id>",
  "capture_id": "<id>",
  "reason": "user"
}
```

Для заданий вместо `capture_id` используются `job_id` и `attempt_id`. Ответ содержит собственный `request_type`, установленный получателем.

Поколение определяется соединением и локальным контекстом супервизора. Поле из пришедшего JSON не может объявить старое соединение новым.

### Основные сообщения

| Запрос/событие | Значение подтверждения |
|---|---|
| `capture.prepare` → `prepared` | Проверены ресурсы, формат и возможности; аудиопотоков ещё нет |
| `capture.start` → `accepted` | Команда допущена; не доказательство открытого или закрытого захвата |
| `capture.started` | Разрешённые дорожки действительно открыты; указаны эпохи и начало |
| `capture.keepalive` | Lease от GUI, сведения о доступности индикаторов; не продлевает пользовательский лимит записи |
| `capture.pause` → `capture.paused` | Все требуемые потоки физически закрыты |
| `capture.resume` → `capture.started` | Новый захват той же встречи после повторных гейтов |
| `capture.extend` → `limit.changed` | Лимит увеличен ровно на час, максимум до четырёх часов |
| `capture.stop` → `capture.closed` | Физическое закрытие всех потоков |
| `capture.finalized` | Аудиоманифест и последняя подтверждённая граница устойчиво сохранены |
| `capture.track_lost` | Потеря конкретной дорожки; остальные не считаются закрытыми |
| `job.start` → `accepted` | Задание принято в память исполнителя |
| `job.progress` | Стадия, обработанное время, счётчики; не подтверждение сохранения |
| `job.result_batch` → `job.batch_committed` | Порция текста устойчиво записана `MeetingStore` |
| `job.cancel` → `job.cancelled` | Вычисление остановлено; новых результатов этой попытки не будет |
| `job.done` | Исполнитель закончил фазу; публикация результата остаётся обязанностью Store |
| `status` → `state` | Снимок состояния для разрешения потерянного ответа в том же поколении |

**Закрытие захвата, отмена вычисления и сохранение файла — три разных факта.** Уведомление о прогрессе не заменяет ни один из них.

### Повторы и ограничение очередей

- В пределах поколения повтор того же `request_id` с тем же содержимым возвращает прежний исход. Другое содержимое с тем же ID — ошибка.
- После рестарта команды `start`, `resume`, `extend` автоматически не воспроизводятся.
- Порции текста имеют последовательный номер и ID окна; повтор после потерянного ACK не создаёт дубликат.
- Очередь результатов ограничена, предварительно 1 МиБ; прогресс объединяется до последнего значения. Накопление полной стенограммы в очереди запрещено.
- Управляющий канал обслуживается независимо от заполненного канала результатов: `cancel` не ждёт освобождения очереди текста.
- При остановленном потребителе processor ждёт или прекращает работу, сохраняя последний подтверждённый checkpoint.

### Таймауты

Предлагаемые начальные значения, уточняемые в M1/M3:

| Операция | Срок и реакция |
|---|---|
| `hello` | 3 с; несовместимость версии делает поколение терминальным |
| Приём обычной команды | 1 с; отсутствие ACK не означает отсутствие действия |
| Открытие записи | Пользовательская цель ≤1 с; разрешён прогрев только контекста без аудиопотоков |
| Stop/pause/lock | Физическое закрытие ≤1 с; при отказе — эскалация завершением recorder |
| Lease GUI | Отправка раз в 1 с; отсутствие 5 с → recorder сам закрывает захват |
| Heartbeat processor | Раз в 1 с; отсутствие 5 с → проверка зависания и отмена |
| Отмена processor | Кооперативно до 1 с, затем завершение процесса |
| Инференс ASR-окна | Отдельный предел, предварительно 60 с |
| Диаризация блока | Отдельный предел, предварительно 15 мин на 20-минутный блок |
| Корпоративный ИИ | 180 с, без автоматического повтора |

Длинная задача **не получает таймаут 120 секунд от диктовки**. Heartbeat показывает живость управления; продвижение стадии — отдельно контролируемый факт. Одних heartbeat недостаточно, чтобы бесконечно продлевать зависший инференс.

### Перезапуск двухчасовой задачи

1. Зафиксировать отказ попытки и прекратить принимать её новые результаты.
2. Остановить процесс и подтвердить выход через `wait/poll`.
3. Только после этого создать новое поколение.
4. Для ASR повторить незавершённое окно; подтверждённые совместимые окна переиспользовать.
5. Для прерванной диаризации заново обработать **всю дорожку**, включая связывание.
6. Старые provisional-метки не используются для восстановления голосового состояния.
7. Автоматически повторить один раз только вероятный временный сбой процесса. Повторяющийся сбой, повреждённая модель и несовместимость протокола требуют действия пользователя.
8. Явно отменённые и удаляемые задания не возобновлять.

Отправка SIGKILL сама по себе не доказывает выход. Пока процесс жив, не запускается его замена и не снимается владение ресурсами. Это сохраняет принцип действующего [ACK-протокола v4](/home/yurka/VibeCoding2/astra-voice-wt-v10a/docs/ipc-ack-protocol.md).

## 5. Захват звука

### Источники

Основной путь — асинхронный libpulse:

- микрофон — выбранный физический source;
- собеседники — monitor конкретного sink-input через `pa_stream_set_monitor_stream`;
- «Весь звук компьютера» — явно выбранный monitor выхода;
- «Встреча в комнате» — только микрофон.

Первый кандидат проверяется и на PulseAudio, и на pipewire-pulse. Если необходимый захват недоступен, интерфейс **до старта** показывает честный вариант полного выхода. Во время записи исчезновение цели никогда не вызывает молчаливого перехода на весь звук компьютера.

Нативный PipeWire backend остаётся резервом M1. Его включение требует подтверждения timestamps, запрета автоматического перенаправления, контроля дочернего процесса и состава AppImage. Null-sink, `move-sink-input` и системный echo-cancel в базовую архитектуру не входят.

### Идентичность цели

Привязка включает:

- экземпляр звукового сервера;
- стабильный идентификатор объекта в пределах этого экземпляра;
- подтверждённый экземпляр приложения;
- разрешённый набор его потоков.

Числового индекса или `application.name` недостаточно. При появлении дополнительных потоков приложения их принадлежность перепроверяется. Неоднозначность означает паузу дорожки и понятное сообщение, а не захват более широкого источника.

Для браузера охват — звук браузера, включая другие вкладки. Это показывается до нажатия. Детектор является эвристикой предложения и не служит границей авторизации.

### Общая временная шкала

Для каждой дорожки сохраняются:

```text
epoch_id
sample_index
server_timestamp / server_latency observation
monotonic_timestamp
discontinuity / dropped_samples
```

Внутри непрерывной эпохи оценивается отображение:

```text
t_common(n) = offset + n / estimated_sample_rate
```

Оценка строится по серверным временным данным и длинному окну наблюдения. Время прихода Python-буфера не принимается за точное время записи.

После остановки `AlignedAudioReader` выдаёт обе дорожки на общей сетке 16 кГц:

- компенсирует стартовое смещение;
- выполняет плавный ресемплинг по оценённой скорости;
- сохраняет разрывы как разрывы;
- не растягивает звук через паузу или смену устройства;
- не использует сходство двух разных разговорных сигналов как основной источник времени.

Коррекция выполняется потоково в памяти, без второй полной копии аудио на диске. Сырые дорожки остаются неизменными до удаления.

**Критерий:** после коррекции остаточное взаимное смещение ≤50 мс на часовом контрольном сигнале; таймкоды реплик ±1 с. Если используемый backend не даёт достаточных временных данных, этот критерий закрывается другим backend до приёмки записи.

Время разделяется на:

- `elapsed` — шкалу встречи с паузами;
- `recorded` — время активной записи для лимита 2/4 часа;
- `speech` — длительность речи для статистики.

Изменение системных часов не меняет таймкоды и лимит. Паузы отображаются на шкале встречи, но не расходуют записанный лимит.

### Устройства, блокировка, сон

- Пропал или сменился микрофон — закрывается только микрофонная дорожка; собеседники продолжают записываться. Новое устройство включается только нажатием.
- Сменился выход — захват той же программы продолжается после проверки цели. В режиме полного выхода допустимо следование за новым выходом, как требует F18.
- Программа ВКС закрылась — far-дорожка завершается; микрофон может продолжаться, с явным сообщением.
- Пользовательская пауза закрывает потоки обеих дорожек. Пауза 60 минут завершает встречу.
- Lock, неподтверждённый Lock или неизвестное состояние — закрытие ≤1 с, продолжение только нажатием.
- Сон и смена сеанса — остановка с сохранением. Для штатного сна используется проверенный механизм `PrepareForSleep` и delay-inhibitor на время завершения записи; после пробуждения захват не восстанавливается.
- Recorder имеет собственную подписку на состояние сеанса. GUI lease в пять секунд не заменяет требование lock≤1 с.
- `platform/session.py` определяет оболочку. Для допуска записи нужен отдельный адаптер состояния сеанса; `SessionMonitor.snapshot.allowed`, содержащий ограничения Cowork во Fly, напрямую не используется.
- Во Fly без достоверного источника блокировки — отказ старта с принятым текстом. Запрет не снимается эвристикой «окно локера сейчас не видно».

### Индикация и эхо

Плашка и трей не читают `pill_enabled`. Потеря обоих индикаторов более секунды либо GUI lease вызывает паузу.

Для восстановления индикации предлагается сохранить специальное поведение принятого G3: автоматическое продолжение только в том же живом сеансе записи, если единственная причина паузы — индикация/зависание GUI. Lock, ручная пауза, смена микрофона и сбой имеют более сильный запрет. Расхождение общей формулировки BL-2 и этого исключения вынесено в §12.

Эхоподавление выполняется только над уже записанными дорожками. Гейт должен пройти проверку double-talk; нельзя удалять собственную речь только потому, что одновременно говорит far-дорожка. До подтверждения качества — подсказка о гарнитуре и явное ограничение качества, без обещания отсутствия дублей.

## 6. Расшифровка и диаризация блоками

### Конвейер

```text
RECORDED
  → QUEUED
  → WAIT_MODEL / WAIT_MEMORY
  → ASR_DRAFT
  → DIARIZATION [если включена]
  → ASR_RECONCILE [если появились границы говорящих внутри ASR-реплик]
  → FINALIZING
  → READY
```

`CANCELLED`, `FAILED`, `INTERRUPTED`, `DELETING` — отдельные состояния. Состояние записи и состояние обработки хранятся раздельно.

### ASR-черновик

- Только GigaAM v3 e2e RNN-T, русский язык.
- Модель загружается через существующую доверенную цепочку каталога, ревизий и самопроверки.
- Чтение аудио ограниченными окнами; вся встреча в массив не загружается.
- Silero VAD делит речь по паузам в пределах окна движка, с контекстом на стыках и устранением дублей.
- Для звонка черновые подписи — «Я» и «Собеседники». Для комнаты — «Участники».
- Каждая законченная порция сохраняется до показа в UI.
- Карточка показывает обработанное время и предупреждение, что подписи говорящих уточняются.

### Диаризация

Начальный размер блока — **20 минут**. 30 минут — допустимая конфигурация только после измерений памяти и качества.

- Диаризируется far-дорожка; в режиме комнаты — единственная микрофонная дорожка.
- Микрофон участника звонка не используется как голосовой профиль: «Я» определяется дорожкой.
- Начальное перекрытие блоков — 10 секунд, с последующей калибровкой. Это контекст вычисления, а не двойное включение реплик в результат.
- Локальные кластеры связываются с ограниченным набором представлений **всех ранее встреченных спикеров этой встречи**. Ограничение только предыдущим блоком неприемлемо: человек может вернуться через 40 минут.
- Сопоставление — с порогом уверенности и ограничениями совместимости. При сомнении создаётся новая анонимная метка; принудительно объединять людей нельзя.
- Центроиды и признаки живут только в RAM процесса диаризации. Число кластеров, объём признаков и матриц ограничены.
- При превышении лимита — явная ошибка диаризации с сохранением аудио и чернового текста. Нельзя молча объединить всех оставшихся людей.
- После завершения голосовые признаки уничтожаются выходом процесса. В файлах остаются только интервалы и анонимные метки.
- Финальная нумерация — по первому появлению. Ручное последующее объединение не перенумеровывает остальных.

Рабочий движок — sherpa-onnx в блочном режиме. `diar_v2` не рассматривается. Выбор конкретного эмбеддера и порога закрывается измерениями и лицензиями; значение θ≈1,05 из спайка не становится дефолтом автоматически.

### Согласование текста и говорящих

Одна VAD-реплика может содержать речь нескольких людей. Нельзя назначить всему её тексту спикера с наибольшей длительностью.

Поэтому после диаризации:

1. Найти черновые ASR-сегменты, пересечённые границами говорящих.
2. Повторно распознать их части по уточнённым интервалам с небольшим акустическим контекстом.
3. Атомарно заменить соответствующие provisional-реплики.
4. Проверить отсутствие потерь и дублей на стыках.

Это не требует неподтверждённых пословных timestamps выбранной модели. При перекрывающейся речи сохраняется явная неопределённость; повторное ASR само её не устраняет.

**В худшем случае повториться может почти весь ASR.** Ограничены размер операции и память, но не суммарный объём повторной работы. Полный проход включается в измерение цели ≤10 минут на час.

### Память и приоритет

- Тяжёлые фазы встреч выполняются последовательно; ASR и sherpa не загружаются одновременно в одном поколении.
- Плановый hard limit processor — около **3 ГиБ адресного пространства**, после проверки совместимости библиотек. Это отдельно от RSS.
- Цель PRD сохраняется: прирост памяти обработки относительно покоя ≤1,5 ГБ.
- Дополнительно измеряется совокупная память GUI, диктовки, recorder и processor, включая переходы фаз. Нельзя объявить бюджет выполненным по одному PID.
- Допуск вычисления: измеренная оставшаяся потребность стадии + резерв диктовки + 200 МБ должны помещаться в доступную память.
- Сначала ограничиваются вычислительные потоки и применяется пониженный приоритет. Если p95 диктовки >0,8 с, фоновая работа уступает ресурсы.
- ASR уступает на границе короткой операции. Диаризация может быть приостановлена в RAM; если требуется освободить память, её процесс завершается, а следующий запуск повторяет диаризацию целиком.
- Холодная загрузка/смена модели диктовки сначала вытесняет processor. Встреча переходит в «Ждёт памяти», а не ломает диктовку.

### Восстановление и прогресс

После перезапуска незавершённая разрешённая обработка возобновляется автоматически. При этом:

- ASR переиспользует только совместимые подтверждённые окна;
- диаризация восстанавливается полным повтором;
- provisional-метки прошлой попытки инвалидируются;
- имена недоступны до окончательного завершения;
- повторное разделение уже готовой встречи требует сохранённого аудио и предупреждения о сбросе имён.

Прогресс состоит из стадии, обработанного аудиовремени и приблизительного процента. Он не достигает 100% до устойчивой публикации. После рестарта стадия диаризации честно начинается заново; прежний процент не изображает выполненную работу.

## 7. Шаблоны/саммари и корпоративный ИИ

### Локальная часть

Без сети и языковой модели:

| Представление | Правило |
|---|---|
| Стенограмма | Реплики по времени, таймкоды, подписи; соседние совместимые реплики одного говорящего объединяются |
| Я и собеседники | Группировка по дорожкам; для комнаты отдельного «Я» нет |
| Только текст | Абзацы без подписей и таймкодов |
| Статистика встречи | Длительность, число реплик, время речи и доли участников |

Доли считаются относительно суммы длительностей речи участников и нормализуются до 100%. При одновременной речи сумма speaker-time может превышать длительность встречи; интерфейс не должен представлять эти величины как одно и то же.

Форматы v1.1 — `.md` и `.txt`. Экспорт строится из структурированных данных с экранированием Markdown, без активного HTML, внешних изображений и автоматических ссылок.

«Сохранить как…» — собственный шаг D4, затем системный диалог. Экспорт создаётся с 0600, в том числе при замене существующего файла; символические ссылки и неоднозначные цели не обходят проверки. Копия вне программы не участвует в retention.

**Смысловое краткое содержание без языковой модели не обещается.** Локальные шаблоны оформляют имеющийся текст; summary требует отдельного провайдера, в том числе локального сервера на loopback.

### Контракт `SummaryProvider`

```text
SummaryRequest:
  meeting_id
  transcript_revision
  template_id
  template_version
  model_id
  anonymize_labels
  endpoint_policy_snapshot
  consent_snapshot

SummaryResult:
  safe_document
  provider_kind
  transcript_revision
  request_outcome
  transmission_may_have_started
```

Для текущего локального объёма — `DisabledProvider`. Сетевой адаптер не является зависимостью записи, ASR, диаризации или экспорта.

Корпоративный адаптер при будущей реализации обязан:

- работать только по явному нажатию;
- фиксировать адрес, модель, политику, текстовую ревизию и шаблон для одной отправки;
- передавать только стенограмму и фиксированную инструкцию, без аудио, tools и других встреч;
- использовать отдельный сетевой scope, не правила скачивания моделей;
- классифицировать все адреса DNS по явным CIDR и закреплять их за соединением;
- внутренние/loopback адреса соединять напрямую, игнорируя proxy env;
- проверять TLS; запрещать редиректы и автоматические повторы;
- ограничивать ответ, предварительно 4 МиБ, и время 180 секундами;
- до возможной отправки тела устойчиво фиксировать попытку: после сбоя честно сообщать «мог быть получен»;
- преобразовывать ответ в безопасную структуру до сохранения, удаляя HTML, адреса, ссылки и изображения;
- показывать метку «Сделано сервисом ИИ по тексту встречи — проверьте по стенограмме».

Секрет привязан к получателю, очищается при смене endpoint, не передаётся в argv/env. Secret Service/KWallet — основной путь. Файл 0600 допустим только при отсутствии службы; отмена, заблокированное хранилище или временная ошибка не разрешают тихое сохранение на диск.

`meeting_ai_allow_external=false` в существующем PRD означает **предупреждение**, а не полный запрет внешней отправки. Нельзя использовать этот ключ как несуществующую корпоративную allowlist. Расширение на пользовательские внешние сервисы находится за пределами запрошенного здесь корпоративного контракта.

### Политика

Обрабатываются семь ключей:

`meeting_record`, `meeting_diarization`, `meeting_ai_endpoint`, `meeting_ai_allow_external`, `meeting_ai_allow_plaintext`, `meeting_audio_retention_days`, `meeting_notice_text`.

- `meeting_record=prompt` разрешает возможности, но не включает пользовательские флаги.
- `off` запрещает новые записи и расшифровки; просмотр, экспорт и удаление сохранённых встреч остаются.
- Неразобранная политика или небезопасные права дают закрытый набор для `meeting_*`.
- Ошибка отдельного meeting-ключа ограничивает этот ключ, а не превращает весь файл в «отсутствующий».
- Булевы разрешения разбираются строго; `yes` не становится `true`.
- Политика применяется в сервисе и исполнителях, а не только через disabled-контролы.
- Изменение политики, запрещающее текущую операцию, останавливает её; дальнейшее снятие запрета не запускает захват.

Существующий `core/policy.py` предупреждает о небезопасных правах, но это не готовая реализация meeting fail-closed. Нужен отдельный resolver; глобальное изменение поведения остальных ключей не включается в E13 автоматически.

В UI — серые недоступные строки и одно общее пояснение. Подписи-замки у каждой строки остаются v1.2.

### Защита файлов и процессов

- Явные 0700/0600 независимо от umask.
- Операции относительно проверенного directory FD; запрет следования ссылкам, проверка владельца и типа файла.
- `RLIMIT_CORE=0`, `PR_SET_DUMPABLE=0`, ограничение ресурсов и parent-death protection до доступа к данным. Отказ обязательного hardening блокирует соответствующую работу.
- Чужие исключения и native stderr не пишутся в журнал целиком.
- Сбор диагностики использует список разрешённых файлов; `meetings/`, checkpoints и ключи исключены.
- Модели не скачиваются при инференсе. Недостающая модель вызывает состояние «Нужна модель» и отдельное пользовательское действие установки.
- Секреты, названия, имена, текст уведомления и экспортные пути отсутствуют в логах. Для plaintext-запроса не записываются также host/IP/port.

Своп и гибернация остаются принятым риском ОС. Формулировка: **программа не сериализует голосовые признаки**; защита от записи RAM средствами ОС требует шифрования диска/свопа. Обещание «признаки никогда не могут попасть на диск» неверно.

Материалы T1 и юридический ресёрч здесь используются как входные требования, без нового правового заключения: [T1](/home/yurka/VibeCoding2/astra-voice/docs/security/T1-meetings-2026-10-12.md), [второе мнение](/home/yurka/VibeCoding2/astra-voice/docs/security/T1-meetings-2026-10-12-astra.md), [правовые условия](/home/yurka/VibeCoding2/astra-voice/research/legal-meetings.md).

## 9. Отказы и инварианты

| Событие | Обязательная реакция | Инвариант |
|---|---|---|
| Экран заблокирован между нажатием и открытием | Отклонить устаревшее разрешение | Подготовка не разрешает поздний старт |
| Lock/unknown во время записи | Закрыть обе дорожки ≤1 с, сохранить паузу | Возврат индикации не снимает lock |
| GUI завис | Recorder закрывает потоки по lease | Живой recorder не означает разрешённую запись |
| Recorder аварийно завершился | «Прервана», восстановить подтверждённые сегменты | Автовозобновления захвата нет |
| Не удалось закрыть поток | Эскалация, ожидание выхода; состояние закрытия неизвестно | Таймаут/SIGKILL не выдаются за ACK |
| Потерян микрофон | Пауза mic, far продолжается | Новый микрофон не выбирается молча |
| Потеряна цель приложения | Закрыть far, отметить пропуск | Нет fallback на весь выход |
| Перезапущен звуковой сервер | Инвалидировать эпохи и идентификаторы; пауза/завершение | Старый индекс не авторизует новую цель |
| Мало места до старта | Отказ при <600 МБ на целевой ФС | Потоков и пустой встречи нет |
| Место стало <200 МБ, EDQUOT/ENOSPC | Остановить захват, сохранить доступное | Не продолжать писать до исчерпания диска |
| Диск завис | Ограничить очередь, прекратить захват | RAM не растёт без предела |
| Достигнуты 2/3/4 часа | Остановить без нового пользовательского продления | Потолок четыре часа неизменяем |
| Сон/смена сеанса | Завершить запись; после пробуждения уведомить | Захват сам не возвращается |
| Не хватает памяти | «Ждёт памяти», освободить processor | Диктовка имеет приоритет |
| Сбой ASR | Повторить незавершённое окно | Подтверждённый текст не дублируется |
| Сбой диаризации | Повторить всю дорожку; текст сохранить | Голосовое состояние с диска не восстанавливается |
| Модель изменена/отозвана | Остановить допуск, сохранить аудио | Старый checkpoint не обход доверия модели |
| Отмена | Зафиксировать отмену до снятия UI-состояния | После restart отменённое не запускается |
| Удаление при обработке | Intent → остановка → ожидание → удаление | Поздний результат не воссоздаёт каталог |
| Публикация завершилась, очистка аудио — нет | Повторить очистку при запуске | READY не теряет опубликованный текст |
| Повреждён отдельный сегмент | Отметить диапазон; сохранить остальное | Повреждение не превращается в незаметную тишину |
| ИИ принял тело, ответ потерян | «Текст мог быть получен», без автоповтора | Ошибка ответа не означает отсутствие передачи |

## 10. Milestones M1…M10, оценки и зависимости

Оценки — **человеко-дни**, включая обычные локальные проверки и исправления одного цикла ревью. Это новая оценка по выявленным рискам, а не прежние 16,5+11 дней из беклога.

**Целевой объём: 32–47 человеко-дней**, плюс резерв примерно 20% на аппаратные и качественные риски. Календарный поток может быть короче при параллельной работе над UI, обработкой и проверками, но захват, связывание и живые испытания не распараллеливаются без ограничений.

Формальное Must-ядро без M6/M8/M9 — ориентировочно **24–35 человеко-дней**, до резерва. Выпуск без диаризации не считается исполнением всего целевого сценария этой задачи; такое сокращение требует решения владельца.

### Что обязательно для v1.1 Must

- Пользовательское включение и политика.
- Ручная запись, видимая индикация, уведомление участников.
- Две дорожки, устойчивость к аварии, лимиты и безопасная реакция на lock/sleep.
- Офлайн-ASR с частичным показом, очередью и восстановлением.
- Стенограмма, хранение/удаление, права и отсутствие содержимого в журналах.
- Документ администратора и PRIVACY.
- BL-1…BL-5 и относящиеся к этим поверхностям Major T1.
- Проверенная установленная поставка, а не только запуск из исходников.

Разработчик отвечает за реализацию назначенной области; независимые reviewer и tester проверяют конкретный commit. Security review требуется на дифы захвата, IPC, хранения, доверия моделям, упаковки и сетевого контракта. Пересекающиеся правки `runtime.py`, policy и UI-мостов интегрируются последовательно.

US-2.13, хотя присутствует в более позднем плане v1.1, в оценку E13 не включена.

## 11. Тест-стратегия

Проверки ниже — план, **не выполненные результаты**. Для E13 вводятся отдельные идентификаторы `E13-U-*`, `E13-I-*`, `E13-L-*`: T-200…T-234 в базе уже заняты обновлениями моделей.

### Unit и компонентные

- Миграция: новые установки и обновления остаются с выключенными встречами/детектором.
- Политика: все значения, неверные типы, права, INVALID≠ABSENT, строгие bool, независимость ключей.
- Автоматы: комбинации ручной паузы, lock, потери индикации, микрофона и GUI.
- Часы: ppm обоих знаков, стартовое смещение, джиттер, гэпы, смена эпох, скачок wall clock.
- Файлы: umask 000, symlink/FIFO, подмена каталога, короткие записи, ENOSPC/EDQUOT, оборванный JSONL.
- Recovery: аварии на каждом шаге публикации и удаления; потерянные ACK; отсутствие повторной автозаписи.
- Очередь: restart, cancellation, invalid checkpoint, удаление при позднем результате.
- Диаризация: возвращение спикера через пропущенный блок, неизвестный спикер, неоднозначная связь, перекрытие и границы.
- ASR: слова на стыках окон, смена говорящего внутри VAD-сегмента, атомарная замена чернового текста.
- Шаблоны: экранирование, расчёт долей, отсутствие активного содержимого.
- Логи: маркеры в тексте, именах, названиях, исключениях, stderr, экспорте и диагностическом архиве.

### Настоящая IPC-цепочка

Использовать реальные Service → Supervisor → Recorder/Processor state machine. Подменять ОС, аудиосервер, часы и тяжёлый движок, а не весь путь подтверждений.

Обязательные сценарии:

- поздний ответ другого поколения;
- `closed` до `finalized`;
- отсутствие ACK при уже выполненной операции;
- SIGKILL отправлен, процесс ещё жив;
- заполненная очередь результатов при `cancel`;
- неправильная версия протокола;
- GUI SIGSTOP на 60 секунд;
- lock во время зависшего GUI;
- удаление встречи между результатом и его commit.

### Engine и производительность

На корпусах с подтверждёнными правами:

- два и четыре часа плотной речи;
- частые смены говорящих и double-talk;
- реальные разные голоса, а не только Piper;
- 20- и 30-минутные блоки с рабочими параметрами;
- DER, число спикеров, ошибки связывания и точность таймкодов;
- полный RTF **с повторным ASR**, пиковая и совокупная память;
- диктовка под нагрузкой: p95 ≤0,8 с, отдельно от чистого baseline;
- остановка потребителя: рост RSS ≤20 MiB за 60 секунд;
- отсутствие записей признаков: анализ схем и трассировка файловых операций, `pwrite/writev/mmap`, детей и открытых удалённых файлов.

Нельзя копировать старый T-209 буквально: link-local должен считаться внешним, а пользовательский HTTP вне loopback отклоняться. Проверка BL-3 не ограничивается поиском оставшихся файлов после завершения.

### QML/xvfb и дизайн

Проверять реальные метаобъекты мостов и макеты G3:

- 1024×620 и 900×588;
- breakpoint контента 760 px;
- панель участников 232 px и выезжающая 300 px;
- колонки 76/124/остаток;
- W2 высотой 36 px и шириной 340–524 px, перенос дополнительных действий во второй ряд;
- обе темы, длинные имена, крупный DPI, шрифты Fly;
- Tab/Esc, возврат фокуса, все действия через трей;
- окно закрыто, но плашка и запись продолжаются;
- отсутствие привязки индикации к `pill_enabled`.

Глифы `rec/stop/play/more` получают явный режим заливки в описании иконок, без глобального изменения рендера остальных значков.

### Живые проверки

Отдельно на KDE и Fly, в установленном `.deb` и AppImage:

- PulseAudio/PipeWire на заявленных версиях;
- настоящий звонок DION, затем Jazz/браузер по подтверждённой поддержке;
- посторонний звук одновременно с per-app записью;
- USB/BT и смена выхода;
- lock/unlock, неизвестное состояние, сон, смена сеанса;
- два часа записи и отдельный четырёхчасовой soak;
- диктовка во время записи/обработки;
- реальные акустические дубли и потери собственного голоса;
- фактическое отсутствие сетевых соединений конвейера встреч.

Для сетевого контроля фиксируется окружение: автоматические проверки обновлений приложения и принятый пользователем сетевой аудиосервер не должны ошибочно считаться сетью ASR.

Используются штатные `make lint`, `make test`, `make test-engine`, `make test-xvfb` с `VENV` из Makefile и профильная цель `tools/validate` после её добавления. Qt/X11-проверки — в изолированном окружении CI; живой `:0` и звуковая служба пользователя не используются автоматическими тестами.

### Упаковка

- Чистый Python 3.11 и целевая glibc.
- Все новые необходимые бинарные зависимости внутри AppImage; зависимости от наличия `pw-record`, `ffmpeg` или GI на хосте не допускаются.
- CPU-провайдер указан явно.
- Инвентарь ELF/ORT, SBOM, NOTICE и лицензии **конкретных весов**.
- Проверка `external_data.location` ONNX; неизвестная лицензия блокирует включение модели.
- Smoke импортов и полный сценарий из распакованного/установленного артефакта.

Источником геометрии остаётся [принятая спецификация встреч](/home/yurka/VibeCoding2/astra-voice/design/meetings/spec.md:661).

Ниже каждый пункт требует одного решения. Уже принятые default off, отсутствие предзаписи, блокировка→пауза, направление A и предупреждение для сетевого хранения повторно не открываются.

| № | Вопрос | Рекомендация |
|---|---|---|
| **Q1** | Считать ли диаризацию условием самого выпуска v1.1, хотя US-13.8 формально Should? | Планировать её в целевом выпуске; при провале качества переносить дату или явно согласовывать выпуск только «Я/Собеседники», без тихого сокращения |
| **Q2** | Как зафиксировать конфликт BL-2 и автоматического продолжения после возврата индикации? | Сохранить конкретное поведение G3/BL-4 как узкое исключение: только тот же capture-сеанс, только причина `indicator/gui-stall`, без lock/manual/device/crash; уточнить общую формулировку до кода |
| **Q3** | Разрешать ли внутренний HTTP в `profile=secure` вопреки итоговому T1? | Сохранить решение Д46: вне loopback HTTP в secure запрещён; привести PRD к итоговому T1 |
| **Q4** | Что делать, если эхогейт не проходит double-talk? | Выпускать проверенный режим с гарнитурой и честным предупреждением для колонок; не включать агрессивное удаление собственной речи и не менять системный граф без отдельного решения |
| **Q5** | Какой абсолютный порог качества диаризации считать достаточным? | В M1 зафиксировать размеченный корпус и DER, отдельно оценить связывание между блоками; число говорящих ±1 само по себе недостаточно |
| **Q6** | При превышении ≤10 мин/час сохранять ли дату ценой более медленной диаризации? | Сначала измерить полный конвейер на ноутбуке; любое изменение цели принять явно, включая дополнительный ASR-проход |
| **Q7** | От какой даты считать хранение звука и как удалять старые незавершённые встречи? | Аудио 7/30 дней — от успешной обработки; возраст встречи — от начала. Незавершённые записи не удалять как «успешно обработанные»; автоматическое удаление целиком должно иметь явно описанный охват |
| **Q8** | Ограничить ли первый ИИ-адаптер только адресом из административной политики? | Да, для запрошенного корпоративного контракта; пользовательские внешние endpoint из расширенного PRD оставить отдельным решением |
| **Q9** | Когда должна быть завершена очная юридическая проверка? | Архитектуру готовить сейчас; сроки правовой проверки зафиксировать до реализации соответствующей поверхности и обязательно до выпуска. Документы сейчас расходятся между «до кода» и «до G5» |
| **Q10** | Какой резерв календаря допустим при незакрытых аппаратных гейтах? | Закладывать 20% к оценке и подтвердить дату после M1; прежние оценки спайков и 27,5 дня историй не считать достаточной гарантией |

Технические решения, не требующие нового продуктового выбора, закрывает команда: конкретный эмбеддер по качеству и лицензии, backend по матрице поддержки, параметры ресемплинга, внутренние размеры очередей. Их доказательства прикладываются к M1 и соответствующим commit.

Основные риски критического пути: достоверная блокировка во Fly, timestamp-aware захват, качество связывания реальных голосов, стоимость повторного ASR, AppImage с дополнительным ORT. Ни один из них не закрыт одними результатами VPS.

## 13. Что НЕ делаем в v1.1

- Предзапись, автоматическое начало записи, фоновый захват до нажатия.
- Публичное API начала/продолжения записи, управление записью через Cowork.
- Запись под блокировкой экрана или при неизвестном состоянии сеанса.
- Голосовые профили, узнавание личности, перенос имён между встречами.
- Сохранение embeddings, центроидов и других признаков для восстановления.
- Диаризацию двух часов целиком и реализацию `diar_v2`.
- Одновременную обработку нескольких встреч и неограниченное число процессов.
- Обязательную транскрибацию во время продолжающейся записи.
- Новую локальную LLM, автоматическую саммаризацию или отправку текста после ASR.
- Пользовательские внешние ИИ-сервисы как часть обязательной локальной поставки.
- Системное перенаправление аудиографа и автоматическое включение echo-cancel.
- Автоматическую остановку микрофонной дорожки по mute внутри ВКС.
- Шифрование хранилища средствами Astra Voice и гарантированное стирание на SSD.
- DOCX/ODT, произвольный шаблонный язык, плеер и собственные шаблоны как обязательный объём.
- Подписи-замки у каждой настройки, ГОСТ/ЗПС и остальные задачи корпоративного контура v1.2.
- Обещание поддержки конкретной ВКС, качества диаризации или времени обработки без проверки на целевой установленной сборке.
