# E13 «Запись встреч» — синтез двух архитектур (суд Юрки, 2026-10-21)

> Вход: план #1 — `arch/e13-plan-claude.md` (Fable 5.1 @max), план #2 — `arch/e13-plan-astra.md` (GPT-6 Astra @high).
> Статус: **синтез до проверки Astra** (гейт «проверка синтеза»). После проверки — execution-pack (`docs/plans.md` R5, `docs/status.md`, `docs/test-plan.md` T-300…).
> Принцип суда: где планы согласны — принято без обсуждения; где расходятся — выбран вариант с меньшим риском для инвариантов T1 (BL-1…BL-5, MJ-*), при равном риске — более простой.

## 0. Итог одной строкой
**База — план Fable целиком** (три процесса `meeting-capture` / `meeting-transcribe` / дочерний `meeting-diar`, B′ монитор-поток libpulse, timeline без ресемплинга, блоки 20 мин + связывание со всеми глобальными дикторами + консолидация, IPC с `req`/поколениями, M0…M10). **Из плана Astra принято 8 поправок (Д1–Д8)**, отклонено 3 (О1–О3). Оценка после поправок: **Must ≈ 25,5 дн. + Should ≈ 12,5 = 38 дн.; с резервом 20 % (Astra) ≈ 45 дн.**

## 1. В чём планы согласны (принято без обсуждения)
- Отдельные процессы захвата и обработки; воркер диктовки и протокол v4 не меняются; публичного API/D-Bus/CLI старта записи нет; транспорт — приватные `socketpair`.
- Захват: libpulse async, far = монитор конкретного sink-input (`pa_stream_set_monitor_stream`), цель привязана к (index, object.serial, проверенный pid, сервер); исчезновение цели → дорожка `ended`, **никакого** тихого перехода на «весь звук»; `pw-record` — резерв; null-sink / `move-sink-input` / echo-cancel графа — не делаем.
- Блокировка/неизвестное состояние → закрытие потоков ≤ 1 с, продолжение только нажатием; сон/смена сеанса → стоп; **Fly без достоверного сигнала блокировки → отказ старта** принятым текстом, эвристика «окно локера» запрещена.
- Аренда GUI → захват: keepalive 1 с, 5 с тишины → самопауза; авто-продолжение — только узкое исключение G3 (та же сессия захвата, причина только индикация/зависание GUI).
- Диск: отказ старта < 600 МБ, стоп записи < 200 МБ / ENOSPC / EDQUOT; потеря при `kill -9` ≤ 10 с.
- Диаризация: sherpa-onnx блоками **20 мин** (30 — только после замеров), диаризуется far (в «комнате» — mic), «Я» — по дорожке, связывание **со всеми ранее виденными дикторами встречи**, признаки только в ОЗУ процесса разделения, на диске — интервалы и анонимные метки; крах разделения → текст сохранён, повтор с нуля; `diar_v2` не рассматривается.
- Память: тяжёлые фазы последовательно, «Ждёт памяти» вместо поломки диктовки, диктовка в приоритете; чекпойнт — только текст и числа; ASR резюмируется с чекпойнта, разделение — заново.
- ИИ-шаблоны: только контракт, адрес — из политики администратора, вне loopback в `secure` запрещён (Д46), таймаут 180 с без автоповтора; локальные шаблоны без сети.
- Не делаем в v1.1: предзапись, авторестарт захвата, профили голосов, хранение embeddings, шифрование/затирание, DOCX/ODT, замки у настроек, ЗПС новых ELF.

## 3. Принятые поправки к плану Fable (Д1–Д8)
- **Д1. Семейство протокола.** `hello` ролей встреч несёт `family="astra-voice.meetings"`, `protocol=1`; константа диктовки остаётся 4 и не меняется выпусками встреч. Кадрирование, `req`, поколения, `bad-field`/`unknown-message` — из `worker/ipc.py` (§4.1 Fable).
- **Д2. Идемпотентность.** В пределах поколения повтор `req` с тем же содержимым возвращает прежний исход, с другим — `error{code: req-conflict}`; после рестарта роли GUI не воспроизводит `open/resume/extend` сам; порции реплик нумеруются (`seq`), повтор после потерянного ACK не даёт дубликата. Закрытие захвата, отмена вычисления и сохранение файла — три разных подтверждения; SIGKILL без `wait/poll` не считается закрытием (состояние `closing-unknown` до подтверждённого выхода).
- **Д3. Собственная подписка захватчика на сеанс.** `meeting-capture` подписан на login1 (`LockedHint`/`Lock`, `PrepareForSleep`, `Active`) тем же кодом `SessionMonitor` и сам закрывает потоки ≤ 1 с по блокировке; GUI остаётся первичным (`pause{lock}`), второе закрытие — no-op. Во Fly без сигнала старт запрещён уже в GUI (D24). +0,5 дн. к M2.
- **Д4. Один движок в памяти.** Перед фазой разделения `meeting-transcribe` делает `model.unload` (ASR), запускает `meeting-diar`; для Д5 модель загружается заново. Формула допуска «Ждёт памяти» Fable (§6.1) сохраняется; тест: пик RSS transcribe+diar не превышает max(ASR, diar) + 150 МБ.
- **Д5. Согласование реплик с границами говорящих (ограниченное).** После `labels{final}`: реплика, пересечённая границей так, что обе части ≥ 1 с, распознаётся заново по частям (контекст 0,3 с), результат атомарно заменяет provisional-реплику; **предел — 15 % речевой длительности встречи**; сверх предела — метка по максимальному перекрытию и отметка «реплика с несколькими говорящими». Перекрывающаяся речь не разрешается. Входит в M7 (+1 дн.), резюм: этап после чекпойнта `diar: done`.
- **Д6. Сроки хранения.** Срок звука (7/30 дн.) — от успешного завершения обработки; возраст встречи — от начала записи; незавершённые/прерванные записи никогда не удаляются как «обработанные» и не попадают под авто-удаление звука; охват авто-удаления описан в документе и PRIVACY.
- **Д7. Эхо-гейт по данным.** Реализуется в M4 с защитой двойного разговора (+6 дБ, Fable §6.1); **значение по умолчанию выбирает M0**: блок F (5 мин настоящего звука) с double-talk — потеря «Я» ≤ 2 % речи → включён; иначе выключен + подсказка «в гарнитуре чище» и честная строка о дублях. Вопрос владельцу снимается.
- **Д8. Таймауты и резерв.** Таблица Astra как абсолютные потолки: инференс окна ASR 60 с, блок разделения `min(15 мин, max(120 с, 3×блок×RTF))`, `hello` 3 с, отмена кооперативно 1 с → SIGKILL группы, ИИ 180 с. Оценка: Must 21,5 + Д3 0,5 + релиз 2,5 = **24,5**; Should 11,5 + Д5 1 = **12,5**; итого ≈ 37; **резерв 20 %** на аппаратные и качественные риски → ≈ 44–45 дн. Порядок выноса при нехватке: M9 (ИИ) → odt/docx → M8 (детектор) → консолидация и Д5 в M7.

## 4. Отклонено (О1–О3)
- **О1.** Ресемплинг на общую сетку — нет требования, которое он закрывает; CPU/память на 2 ч float32; остаётся резервом за интерфейсом `timeline.py`.
- **О2.** M1 Astra «закрыть развилки 3–5 дн. до контрактов» — спайки M0 идут параллельно M1 Fable; от их исхода зависят константы (θ, τ, θ_echo, B′/C), не границы компонентов.
- **О3.** Один Processor ≈ 3 ГиБ AS — заменён на 2 + 1,5 с Д4; диаризация без путей записи проверяется `strace -f` на маленьком процессе.

## 5. Что решает Юрка (закрыто здесь)
- Эмбеддер: **3D-Speaker CAM++** (Apache-2.0); калибровка на блоке F; при DER хуже WeSpeaker CAM++ LM более чем на 2 п.п. — WeSpeaker + NOTICE (CC-BY-4.0).
- `oom_score_adj` захватчика 300 (ниже 500 из T1) — вопрос T2 с обоснованием «запись важнее, RSS ≤ 60 МБ».
- Нумерация тестов T-300…T-340 (T-2xx заняты M7-моделями); CI-гейты: ELF 3 → 7, импорт-гейты ролей, lint логгера, схема чекпойнта (нет массивов > 16 чисел).
- Альтернатива C (разделение в процессе ASR) — только при положительной пробе на VPS и флагом сборки; по умолчанию — дочерний процесс.
- Второй поток Codex на M7/M8 параллельно M5/M6.

## 8. Проверка синтеза Astra (2026-10-22 ~09:50 МСК) — вердикт «СОВМЕСТИМ С ПРАВКАМИ», суд Юрки
