## 0. Итог

**Рекомендация.** `pa_simple` заменить собственным потоком `pa_stream`. Цикл `pa_mainloop` однопоточный,
им владеет поток захвата. Запись подключается с флагом **`PA_STREAM_DONT_MOVE`**. С этим флагом ни PulseAudio,
ни pipewire-pulse не могут молча перевести запись на другое устройство: если устройство пропало, поток убивается
или остаётся без источника. Воркер узнаёт об этом по тому же соединению. Сигналов три: поток перешёл в FAILED с
кодом KILLED, пришло событие подписки REMOVE для нашего источника, сработал запасной колбэк `moved`. Решение
принимается только по идентичности нашего устройства (индекс или имя), без таймеров. Поэтому ложные срабатывания
класса BL-3 невозможны. Дальше воркер действует так же, как при `record.limit`: сам останавливает запись, отрезает
последние 100 мс и определяет исход `switched` или `device-lost`. Подпись он берёт из уже существующего очищенного
списка устройств и отправляет `audio.device.changed`. GUI распознаёт записанное до смены, если его набралось
не меньше 0,3 с, и показывает пилюлю и уведомление.
Цикл ждёт через `prepare/poll` с таймаутом 50 мс, так что вечно висящего чтения больше нет. `pa_simple` остаётся
запасным бэкендом на один выпуск.

**Оценка:** ≈ **3 дня потока** (2,5–3,5). Если контракт с GUI и источник делать двумя параллельными линиями,
календарно выходит ≈ 2 дня. Отдельно, по итогам проверки заказчика, может понадобиться необязательный уровень 2
(переключение порта внутри одного источника): +0,5 дня. В `plan-v0.2.md` на S5-A5 заложено 1,5 дня. Разница
+1,5 дня, её покрывает резерв потока 3 (03–04.10).

## 1. Что есть сейчас и почему прошлая попытка ошибалась

- Поток всегда открывается по имени: `pa_simple_new(dev=<имя>)`. В режиме «по умолчанию» воркер сам узнаёт
  умолчание через `pactl get-default-source` (У44) и сверяет имя со списком устройств до libpulse (S5-R1:
  «fail closed», иначе отказ). Флагов потока `pa_simple` не принимает: внутри всегда
  `INTERPOLATE_TIMING|ADJUST_LATENCY|AUTO_TIMING_UPDATE`. Наружу он не отдаёт ни `pa_stream`, ни событий.
- `audio.ready{device, changed}` появляется только в момент открытия (`AudioCapture._run`). Смену устройства
  внутри записи он не видит по построению.
- **BL-3** (ревью 15–16.09). GUI останавливал запись, если `audio.ready{changed}` приходил раньше `_t0 + 0,3 с`.
  На гонке WirePlumber при первом открытии (повторные попытки) это давало ложный стоп. Настоящую смену (T-56)
  такая проверка не ловила вовсе, а тест для неё строился на невозможных данных (урок 007). Ветку сняли 16.09.
  Вывод: судить о смене устройства по времени событий нельзя, только по идентичности устройства.
- **T-56** (15.09, машина заказчика). Виртуальный источник выгрузили посреди записи. PipeWire молча перевёл поток
  на встроенный микрофон, запись шла 4,2 с, результат пустой, ошибок 0. **S5-R1** (09.09): `pa_simple_new` с
  несуществующим именем молча открывает умолчание, то есть подмену цели сервер делает и на старте.
- `pa_simple_read` блокирует, пока не придут данные. Если поток «осиротел» (цели нет, подменить нечем, например
  на ПК с одним USB-микрофоном), чтение висит. Выход тогда один: сторож 5 с, `CaptureStopTimeout` и фатальный
  выход воркера.
- **Среда.** На машине заказчика стоят PipeWire 1.4.9, pipewire-pulse и WirePlumber 0.5.12 (backport). Пакет
  pulseaudio 16.1 тоже установлен, и на машинах парка сервером вполне может быть он. Поэтому решение опирается на
  семантику протокола PulseAudio, которую реализуют оба сервера.

## 3. Рекомендуемая схема

### 3.1 Источник `PulseStreamSource` (новый модуль `src/astra_voice/worker/pulse_stream.py`)

**Два слоя.**
- `_PulseAsync`: тонкие ctypes-привязки к `libpulse.so.0` (`libpulse-simple` больше не нужна). Все argtypes и
  restype объявлены явно, указатели идут как `c_void_p` (урок про SIGSEGV из-за усечённого указателя). На каждый
  вызов по одному методу-обёртке без логики. Здесь же константы и типы колбэков.
- `PulseStreamSource`: вся логика. Реализует прежний протокол `AudioSource` плюс `selected_device`,
  `device_label` и новое свойство `device_change`. Тестируется на фейковом `_PulseAsync`, без звука.

**Инварианты.**
1. Libpulse вызывается **только из потока захвата**. Другие потоки лишь снимают `running`. `pa_mainloop_wakeup`
   из чужого потока не используем. Остановку поток замечает не позже чем через 50 мс (таймаут опроса), а при
   идущих данных (порции по 20 мс) быстрее.
2. Соединение (mainloop + context + stream) живёт ровно одну запись: open → close в `_run`. Инвариант T-43
   «между записями микрофон закрыт» сохраняется. Фонового слежения за устройствами нет.
3. Колбэки (подписка и `moved`) только записывают факт вместе со значением `pa_stream_readable_size()` на момент
   события. В очередь попадают только SOURCE REMOVE и `moved`; SOURCE NEW/CHANGE отбрасываются, SERVER CHANGE —
   флаг. Очередь без вытеснения, лимит 64: при переполнении — флаг `_overflow` с точкой обрезки и сверка по
   устройству потока и списку устройств (как в ветке KILLED). Своё устройство неизвестно по точному индексу
   (`index_exact`) — любой REMOVE источника ведёт к той же сверке. *(Ревью 29.09: `deque(maxlen=64)` вытеснял наш
   REMOVE при шторме чужих событий — на pipewire-pulse запись молча висела.)* Исключения внутри колбэка ловятся.
   Объекты `CFUNCTYPE` живут на экземпляре. Перед `unref` колбэки обнуляются.
4. Никаких решений по времени: только по идентичности нашего устройства и состоянию потока.

**Открытие (порядок важен).**
1. Устройство выбирается как сейчас: кэш 2 с, `list_devices`, `default_device`, `resolve_device`, проверки У44 и
   S5-R1 до libpulse. Этот код вынести в общую функцию для обоих источников.
2. `pa_mainloop_new` → `pa_context_new(api, "astra-voice")` → `pa_context_set_subscribe_callback` →
   `pa_context_connect(ctx, NULL, PA_CONTEXT_NOAUTOSPAWN, NULL)`. Итерации идут до READY с `_OpenDeadline`
   и проверкой `running`.
3. `pa_context_subscribe(ctx, SOURCE|SERVER, NULL, NULL)` и освобождение операции. Подписываемся **до** создания
   потока, чтобы не пропустить REMOVE.
4. `pa_stream_new(ctx, "dictation", s16le/16000/1, NULL)` → `pa_stream_set_moved_callback` →
   `pa_stream_connect_record(s, <имя>, attr{-1,-1,-1,-1, fragsize=640}, INTERPOLATE_TIMING|ADJUST_LATENCY|AUTO_TIMING_UPDATE|DONT_MOVE)`.
   Это флаги `pa_simple` плюс `DONT_MOVE`, так что поведение с данными остаётся прежним. Итерации до READY или FAILED.
5. Если FAILED, смотрим `pa_context_errno`: BUSY или ACCESS → `audio-busy`; NOENTITY → `audio-no-device`;
   остальное → `audio-failed`. Все ресурсы освобождаются, повторы `3 × 300 мс` как сейчас.
6. **Базовая линия.** `idx = pa_stream_get_device_index(s)`, `name = pa_stream_get_device_name(s)` (копировать
   сразу). Индекс для сверки событий: `idx`, если он валиден, иначе `selected.index` из списка устройств. В
   pipewire-pulse индексы равны `object.serial` и совпадают у pactl и событий; уверенность средняя. Если `name`
   известно и не совпадает с выбранным, это смена `mismatch` до первого звука. `AudioCapture` тогда **не шлёт**
   `audio.ready`, а сразу сообщает о смене, чтобы не было двух уведомлений подряд.

**Чтение `read_chunk()`.**
- Отдаёт ровно `CHUNK_BYTES` (640 Б = 20 мс) из внутреннего буфера. Если в буфере меньше, делает одну итерацию
  `pa_mainloop_prepare(m, 50_000)` → `pa_mainloop_poll` → `pa_mainloop_dispatch` и затем забирает все фрагменты
  через `pa_stream_peek`/`pa_stream_drop` (дыру пропускает через drop без данных). Фрагменты любой длины
  склеиваются в порции.
- Данных нет → возвращает **`b""`**. Это новое значение протокола: «пока пусто, спроси ещё». `AudioCapture._read`
  на нём только проверяет `running` и дедлайн, сторожей тишины и нулей не трогает.
- Смена зафиксирована → байты после точки обрезки не выдаются, возвращается `None`, `device_change` заполнено.
- Поток FAILED и `pa_context_errno == PA_ERR_KILLED` → до 250 мс итераций в ожидании REMOVE нашего источника
  (PulseAudio шлёт REMOVE с отсрочкой, уже после убийства). Если REMOVE пришёл, это смена `killed`. Если нет,
  проверяем имя в свежем списке устройств (общий бюджет §3.3): имени нет → `killed`; имя есть (поток убили из
  микшера) → обычный сбой, то есть `None` без смены и прежнее `audio-failed «Запись звука прервалась»`.
- Контекст FAILED или TERMINATED (упала служба) → обычный сбой, как сейчас.

### 3.2 Что считается сменой

| Сигнал | Условие | Причина |
|---|---|---|
| событие `REMOVE` с объектом `SOURCE` | `idx` совпадает с индексом сверки | `removed` |
| поток FAILED + `PA_ERR_KILLED` | за 250 мс пришёл REMOVE нашего источника или имени нет в списке | `killed` |
| `moved` | базовый индекс известен и новый от него отличается; **или** базовый неизвестен, а новое имя не совпадает с выбранным | `moved` |
| `moved` | базовый неизвестен, новое имя совпадает с выбранным | **принять**: это не смена, базовая линия запоминается |
| сразу после READY | имя известно и не совпадает с выбранным | `mismatch` |
| `SOURCE NEW/CHANGE`, `SERVER CHANGE`, события с чужими индексами | — | не смена; `SERVER CHANGE` только отмечается для §3.3 |

**Точка обрезки.** Это `len(внутренний буфер) + pa_stream_readable_size()` в момент колбэка. Кроме того,
`WorkerState` отрезает последние **100 мс** уже переданного звука. Это страховка от рассинхрона каналов данных и
команд: у PulseAudio данные идут по общей памяти (srbchannel), а команды по сокету. Для `DONT_MOVE`/`killed`
чужого звука быть не может; запас нужен только для `moved`, но правило одно для всех: ради фразы, которую и так
оборвали, 100 мс не жалко.

### 3.3 Классификация и подпись (`classify_change` — чистая функция в `audio.py`)

Режим: **явный**, если `record.start` пришёл с полем `device`; **умолчание**, если без него (источник знает режим
из `open(None)`). В режиме умолчания при `removed`/`killed` источник ещё до 200 мс ждёт `SERVER CHANGE` (новое
умолчание), если он не пришёл раньше. Затем `AudioCapture` в пределах общего **бюджета 0,7 с** вызывает
`list_devices()` и, только для умолчания, `default_device()`. Это существующие очищенные пути: удаление Cc/Cf,
не больше 120 символов, «(null)», запасной pw-dump, У44 (монитор по умолчанию считается ошибкой, `AudioError`
превращается в «умолчания нет»).

| Причина | Режим | Итог |
|---|---|---|
| `removed` / `killed` | явный | `device-lost` |
| `removed` / `killed` | умолчание | `switched(label = новое умолчание)`, если оно есть, не монитор и не исходное устройство; иначе `device-lost` |
| `moved` / `mismatch` | любой | `switched(label = куда перевели)`, если это устройство есть в списке, не монитор и (режим умолчания **или** исходное устройство ещё существует); иначе `device-lost` |
| бюджет подписи истёк | любой | `device-lost` без подписи |

Монитор никогда не называется устройством, которое «сейчас используется» (У44).

| 6 | WirePlumber перезапустился сам посреди записи | Узлы устройств пересоздаются | REMOVE | Стоп. Это истинное срабатывание: устройство действительно пропадало. Наша кнопка «Перезапустить звуковую службу» идёт после `audio.close` (И4), записи в этот момент нет |
| 7 | Перезапуск pipewire-pulse или pulseaudio | — | Контекст FAILED | прежнее «Запись звука прервалась» (это не смена устройства) |
| 8 | Смена профиля карты, BT A2DP ↔ HFP | Узел пересоздан | REMOVE | Стоп (истинное) |
| 9 | Гарнитура 3,5 мм в комбо-разъёме | (а) отдельный узел (UCM; у T14 с sof-hda-dsp это вероятно, но не проверено): как 1/2, либо узел остаётся с недоступным портом и идёт тишина. (б) порт того же источника (HDA без UCM): запись тихо продолжается с встроенного микрофона того же источника | (а) REMOVE, либо ничего. (б) ничего (уровень 1) | (а) как 1/2, либо «Микрофон молчит» через 2–3 с от существующих сторожей. (б) нужен **уровень 2**, необязательный, §6 F |
| 10 | Устройство пропало между проверкой имени и подключением (остаток S5-R1) | Сервер подставляет умолчание | `mismatch` после READY (если pipewire-pulse отдаёт фактическое имя) или `moved` при первом подключении | Стоп до первого звука, `audio_ms = 0`. Какое поведение у pipewire-pulse на самом деле, покажет спайк C1 |

### 3.5 Почему нет ложных срабатываний

- Таймеров нет. Стоп случается только при событии, привязанном к **нашему** устройству: REMOVE нашего индекса,
  KILLED с подтверждением пропажи, `moved` на **известное другое** устройство, `mismatch` по известному имени.
- Первый `moved` при подключении к тому же устройству принимается (правило «принять»). Это ровно тот старт-кейс,
  на котором ошибался BL-3.
- Смена умолчания, громкость, mute, SOURCE CHANGE и события чужих устройств на стоп не влияют.
- Внешний рестарт WirePlumber и смена профиля дают стоп, но это истинные срабатывания: наш источник действительно
  исчезал. Сама кнопка И4 закрывает звук до рестарта.
- Проверки И4 и «Общие» (уровень) каждый раз открывают новый поток со своей базовой линией.

## 4. Контракт воркер → GUI

```json
{"type": "audio.device.changed", "utterance_id": "<id>", "kind": "switched", "label": "Встроенный микрофон", "audio_ms": 2140}
```

- **Схема (`ipc.py`).** Обязательные поля: `utterance_id` (прежний regex) и `kind` ∈ {`switched`, `device-lost`}.
  Необязательные: `label` (строка, только при `switched`, формирует `AudioDevice.label`: не больше 120 символов,
  без Cc/Cf) и `audio_ms` (int ≥ 0, `bool` отвергается). **`PROTOCOL_VERSION` 2 → 3**: старый GUI не должен
  получить неизвестный тип.
- **Гарантии воркера.**
  - Событие приходит не чаще одного раза за запись.
  - После него запись в воркере остановлена (как при `record.limit`). PCM до смены за вычетом 100 мс хранится как
    после `record.stop` (TTL 300 с), и GUI обязан прислать `recognize` или `record.cancel`.
  - Звук после точки обрезки в буфер не попадает никогда.
  - Если GUI уже прислал `record.stop` (человек отпустил клавишу в момент смены), событие всё равно приходит, а
    запись не трогается. Если был `record.cancel`, событие не приходит.
  - В `_read` ветку `device_change` проверять **до** выхода по `running`: смена, случившаяся одновременно с
    отпусканием клавиши, всё равно должна быть сообщена.
  - При `switched` воркер не переоткрывает устройство и `audio.ready` не шлёт.
- **Журнал воркера (info).** Пишутся причина, `kind`, время от обнаружения до отправки в мс, `audio_ms` и подпись.
  Подпись — это описание устройства, его писать можно. Распознанного текста нет никогда. Технические имена
  устройств только на уровне debug.

**Реакции GUI (`DictationController`).**

| Фаза | Что делает |
|---|---|
| RECORDING | Пилюля ERROR «Микрофон сменился» или «Микрофон отключился» на 3 с (`STATE_DURATION_MS[ERROR]`). Уведомление. `mic_error{kind=device-changed\|device-lost, recovered_by=none}`. Для `switched`: `_announced_selected_device = _resolved_device = label` и `on_device_resolved`, чтобы следующая запись не объявила «Микрофон: X» ещё раз. Если `audio_ms ≥ 300`, дальше путь `record.limit`: `_stop(recording_stopped=True)`, затем `recognize` и вставка. Иначе `record.cancel` без пилюли «Отменено». Пока висит эта пилюля, её **не перебивают** PROCESSING, DONE, EMPTY и CANCELLED; CLIPBOARD_ONLY и ошибки распознавания перебивают (это важнее). Трей: `switched` → IDLE, `device-lost` → ERROR. Хоткей ведёт себя как после `record.limit` (T-56: не залипает) |
| PROCESSING (клавишу уже отпустили) | Пилюля, уведомление и статистика. Распознавание не трогаем |
| Проверка уровня («Общие», мастер) | `_end_level(…)`: «Микрофон отключился. Подключите его или выберите другой.» / «Микрофон сменился. Выберите микрофон в списке.» |
| Проверка тестовой фразой | `_finish_test(error, message=…)` с теми же текстами |
| IDLE, чужой id, `_cancel_pending` | Игнорировать (debug) |

**Уведомления (`ui/notify.py`).**
- `switched` → `notify_microphone_changed(label)`: «Микрофон сменился», «Сейчас используется: <label>. Выбрать
  другой можно в настройках.», кнопка «Выбрать микрофон».
- `device-lost` → `notify_microphone_lost()` **плюс кнопка «Выбрать микрофон»** (сейчас её там нет).
- Подпись в теле уведомления экранировать через `html.escape(label, quote=False)`: Plasma отображает разметку
  в теле (см. §5).

**Смена между диктовками (A6).** Если в `_audio_ready` пришло другое имя, звать `on_device_selected`
(«Микрофон: X»), а не `on_device_changed`. Тогда «Микрофон сменился» остаётся только для смены посреди записи.
Абзац в `docs/ui-bridge.md` §3.2 поправить соответственно.

## 5. Безопасность: вход для T2 (одним проходом с остальными дифами v0.2)

- **Что нового видит воркер.**
  - На время записи он подписан на SOURCE|SERVER: видит номера источников, факт их появления, исчезновения и
    изменения, смену умолчания. Имён по событиям не запрашивает; имена и описания всех источников он и так
    читает через `list_devices` при каждом открытии, теперь ещё и при классификации.
  - SINK_INPUT, SOURCE_OUTPUT, CLIENT и CARD сознательно **не** подписываются: активность чужих программ (кто
    пишет микрофон) воркеру не нужна.
  - Кроме того, он узнаёт индекс и имя своего потока (`pa_stream_get_device_*`).
  - Фонового соединения нет: связь со службой есть только во время записи или проверки.
- **Новые меры защиты.**
  - `DONT_MOVE`: сервер не может перевести запись на чужое устройство. Это касается и монитора колонок при пропаже
    последнего микрофона на PulseAudio (вариант У44 посреди записи). Человек тоже не может перенести поток
    микшером; выбор устройства остаётся в настройках программы (У39).
  - `PA_CONTEXT_NOAUTOSPAWN` прямо на контексте. Раньше был только обход через `PULSE_CLIENTCONFIG`, он остаётся
    для pactl.
  - Чтение без бесконечной блокировки: сценарий «висим в libpulse → фатальный выход» для нового источника
    практически исчезает.
- **У44.** Монитор никогда не называется «используемым»: классификация даёт `device-lost`. Если умолчанием
  следующей записи стал монитор, это прежняя ошибка ещё до libpulse.
- **У45.** Событие несёт `utterance_id`. Чужие и поздние id отбрасываются. PCM после события лежит в `stopped` с
  TTL, как после `record.limit`. `record.cancel` не подавляется.
- **У39/T-41.** Подпись берётся только из `AudioDevice.label`. В пилюлю она не попадает никогда (там только
  тексты из реестра `ERROR_REASONS`), в QML выводится как PlainText (ИБ-12, сделано раньше).
  **Найден пробел:** `notify_microphone_changed` кладёт имя в *тело* уведомления без экранирования. Plasma
  поддерживает разметку тела, а имя приходит из строки USB-устройства. Экранировать в этом же дифе; тест ниже (T-e).
- **Нативный код.** Около 30 функций с явным ABI; указатели через `c_void_p`. Колбэки хранятся на экземпляре и
  обнуляются до `unref`. Все вызовы идут из одного потока, `pa_mainloop_wakeup` из чужого потока не вызывается.
  Структуры libpulse (`pa_source_info`, `pa_server_info`) не разбираются: подписи берутся из существующего
  списка устройств.
- **IPC.** Новый тип сообщения, `kind` — перечисление, `label` не длиннее 120 символов, `audio_ms` — int, версия
  протокола 3.
- **Журнал.** Причина, `kind`, тайминги, подпись. Текста нет. Чужие устройства в журнал не пишутся.
- **Отказ в обслуживании.** Шторм событий от неисправного USB-устройства упирается в ограниченную очередь; действие
  выполняется только по нашему индексу. Каждая запись останавливается не больше одного раза, поэтому на диктовку
  приходится не больше одного уведомления.
- **Откат.** `ASTRA_VOICE_AUDIO_BACKEND=simple` возвращает `pa_simple` без `DONT_MOVE`. Это переменная окружения
  того же пользователя, то есть вне модели угроз. Пользователям не документировать, только в «Отладке» и для
  администратора.
- **Кандидаты в строки test-plan** (номера даст tech-writer):
  - **T-a** (U): фейк KILLED + REMOVE нашего индекса → `device-lost`; `audio_ms` без последних 100 мс; байтов
    после точки обрезки в буфере нет.
  - **T-b** (U): REMOVE чужого индекса, SERVER CHANGE и SOURCE CHANGE → стопа нет.
  - **T-c** (U): первый `moved` на то же имя при неизвестном индексе → принять, стопа нет; `moved` на другое имя
    → `switched`, стоп.
  - **T-d** (U): режим умолчания, новое умолчание — монитор → `device-lost`, без подписи.
  - **T-e** (U): подпись `<img src="http://127.0.0.1:P/x">` → в теле уведомления экранирована; заголовок не изменился.
  - **T-f** (U): `audio.device.changed` с `kind="other"`, `audio_ms=True` или `label=123` → `BAD_FIELD`;
    `hello` с `protocol=2` → mismatch.
  - **T-g** (I, стенд): выгрузка `av_test_src` посреди записи → событие не позже 1 с от выгрузки; PCM после
    выгрузки не распознан; `pactl list source-outputs` пуст.

## 7. Тесты (без настоящего звука)

- **Фейк `_PulseAsync`** со сценарием по шагам: каждый `dispatch` продвигает сценарий на один шаг и вызывает
  сохранённые колбэки. Сценарий задаёт состояния контекста и потока, фрагменты данных (в том числе дыры),
  события подписки и `moved`, а также `errno`. Нативный код в тестах не вызывается. ABI проверяется отдельно,
  через `FakeLibrary`.
- **Контрактные тесты захвата** параметризуются по двум источникам (B10) и остаются на месте, пока жив `pa_simple`.
- **IPC** (A1), **автомат** (A2), **классификация** (A3, таблица), **захват** (A4 на `ControlledSource`),
  **GUI** (D2–D5 на фейковых портах пилюли, трея, уведомлений и статистики).
- Отдельный тест: остановка после `request_stop` замечается не позже чем за 100 мс по часам фейка, и ни один вызов
  `_PulseAsync` не идёт из чужого потока. Проверять по `threading.get_ident()` внутри фейка.

## 8. Ручная проверка заказчиком (5–10 мин)

Подготовка: запущенная 0.2-rc. Для каждого пункта: зажать хоткей, начать фразу, выполнить действие, договорить.

1. **USB- или BT-гарнитура выбрана в «Общих» явно**, посреди фразы её отключить. Ожидается: не позже чем через
   ~1 с пилюля «Микрофон отключился» и уведомление с кнопкой «Выбрать микрофон»; начало фразы вставлено.
   Следующая диктовка без гарнитуры: «Микрофон отключился». Гарнитуру вернуть: диктовка работает.
2. **Та же гарнитура как системная по умолчанию** («Системный по умолчанию»), посреди фразы отключить. Ожидается:
   «Микрофон сменился», в уведомлении «Сейчас используется: <встроенный>», начало фразы вставлено. Следующая
   диктовка идёт со встроенного **без** лишнего «Микрофон: …».
3. **Проводная гарнитура 3,5 мм** в режиме умолчания, отключить посреди фразы. Отметить, что произошло:
   «сменился» или «отключился» (значит, отдельное устройство), «Микрофон молчит» или ничего (значит, порт
   того же источника). От этого зависит, нужен ли уровень 2.
4. **Bluetooth-гарнитура**, если есть: выключить посреди фразы. Ожидается как в п. 1 или 2.
5. **Сменить микрофон по умолчанию в трее KDE посреди фразы.** Запись **не** должна останавливаться, фраза
   вставлена. На следующей диктовке один раз «Микрофон: <новый>».
6. **В настройках звука KDE (вкладка записи) попробовать перенести поток astra-voice на другой микрофон посреди
   фразы.** Ожидается: не переносится; если всё же перенёсся, запись останавливается с «Микрофон сменился».

## 10. Риски и где можно ошибиться

1. **Регресс главного пути захвата.** Это каждая диктовка. Меры: запасной бэкенд `simple` через окружение (до
   v1.0); контрактные тесты по обоим источникам; стенд и мини-Ц2 до того, как новый бэкенд станет основным.
2. **Семантика `DONT_MOVE` в pipewire-pulse** (KILLED, осиротевший поток или игнор) известна мне по памяти. Первые
   два исхода покрыты, третий ловится колбэком `moved` с обрезкой. Спайк C1 покажет, какой исход на самом деле.
3. **Первый `moved` или неизвестный индекс после READY в pipewire-pulse.** Это самый вероятный источник ложного
   стопа. Защита: правило «принять», решение только по известному другому устройству. Нужны отдельные тесты
   (T-c) и проверка в C1 п. 3.
4. **Ошибки ABI ctypes** (SIGSEGV). Меры: тест объявлений, `c_void_p` для указателей, колбэки держатся на
   экземпляре и обнуляются до `unref`, все вызовы из одного потока.
5. **Подпись при «по умолчанию» не успевает за бюджет** (WirePlumber медленно выбирает умолчание). Тогда
   показывается «Микрофон отключился» без имени: менее конкретно, но не ложно.
6. **Гарнитура 3,5 мм как порт того же источника** уровнем 1 не ловится. Утечки чужого звука здесь нет (тот же
   человек у встроенного микрофона). Закрывается уровнем 2 по факту E4.
7. **Перенос нашего потока в микшере больше невозможен** (`DONT_MOVE`). Это осознанное изменение поведения, одна
   строка в заметках к выпуску.
8. **Внешний рестарт WirePlumber посреди записи** остановит запись с «Микрофон отключился/сменился». Это
   истинное срабатывание, текст чуть неточный. Принимаем.
9. **Версия протокола 3.** При обновлении пакета без перезапуска срабатывает существующее «Программа обновлена —
   перезапустите её».
10. **Срок.** +1,5 дня к `plan-v0.2.md`. Если потоку 3 станет тесно, первым уходит уровень 2. A6 (D5) маленький,
    его оставить.
11. **Дублирующие уведомления о пропавшем явно выбранном микрофоне** на каждой следующей диктовке. Это прежнее
    поведение US-11.1, не часть этой задачи. Дедупликацию можно взять в беклог.

## 11. Открытые вопросы

1. **Юрке и заказчику (блокирует только C и E3):** разрешение на около 15 мин работы со стендом `virtual_mic`.
   Будут загружаться и выгружаться виртуальные модули, открываться записи. Это та же процедура, что T-56 15.09.
2. **PM, не блокирует:** в режиме умолчания с `DONT_MOVE` фраза «Сейчас используется: X» означает «дальше будет
   использоваться X» (с X не записано ни звука). Оставить текст PRD или уточнить? Туда же уточнение PRD F6.5:
   смена умолчания во время записи поток не переводит (§3.4 п. 4).
3. **Юрке, не блокирует:** уровень 2 в v0.2 или позже — решить по результату E4 п. 3.

**Константы** (уверенность высокая):
- `pa_context_state`: UNCONNECTED 0, CONNECTING 1, AUTHORIZING 2, SETTING_NAME 3, READY 4, FAILED 5, TERMINATED 6.
- `pa_stream_state`: UNCONNECTED 0, CREATING 1, READY 2, FAILED 3, TERMINATED 4.
- `pa_operation_state`: RUNNING 0, DONE 1, CANCELLED 2.
- `PA_CONTEXT_NOAUTOSPAWN` = 0x1.
- Флаги потока: `INTERPOLATE_TIMING` 0x2, `AUTO_TIMING_UPDATE` 0x8, `DONT_MOVE` 0x200, `ADJUST_LATENCY` 0x2000.
- Маски подписки: `SOURCE` 0x2, `SERVER` 0x80.
- Событие: объект `t & 0x0F` (SOURCE 0x1, SERVER 0x7), вид `t & 0x30` (NEW 0x00, CHANGE 0x10, REMOVE 0x20).
- Ошибки: ACCESS 1, NOENTITY 5, KILLED 12, BUSY 26. Коды 1, 5 и 26 уже есть в `audio.py`.
- `PA_INVALID_INDEX` = 0xFFFFFFFF.

**Поведение серверов** (по памяти, проверяется спайком C):
- **PulseAudio 16.** Поток с `DONT_MOVE` не спасается переносом при удалении источника, а убивается: клиент
  получает `RECORD_STREAM_KILLED`, поток переходит в FAILED, errno = KILLED. Событие REMOVE приходит с отсрочкой,
  уже после убийства. Уверенность высокая или средняя.
- **pipewire-pulse 1.4.** `DONT_MOVE` превращается в `node.dont-reconnect=true`. Косвенное подтверждение: штатное
  правило `pipewire-pulse.conf` снимает `DONT_MOVE` у захвата Firefox, потому что иначе поток «нельзя перенести
  в pavucontrol». WirePlumber 0.5 при потере цели уничтожает такой узел, и клиент получает KILLED. Если WirePlumber
  не работает, поток остаётся без цели, данных нет, REMOVE приходит. Уверенность средняя.
- **pipewire-pulse: индексы источников.** Равны `object.serial`, одинаковы у pactl и в событиях. Уверенность средняя.
- **pipewire-pulse: неизвестно.** Заполняет ли он имя и индекс устройства в ответе на создание потока и шлёт ли
  `moved` при первом подключении. На этот случай правило «принять» (§3.2) и проверка C п. 3–4.
