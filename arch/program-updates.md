# Обновления программы: контракт M7 / action 2b

Сводка координатора от 2026-10-09 по двум независимым архитектурным планам.
Статус: контракт реализации; не отчёт о готовности или выпуске. Основа —
`arch/appimage.md` §6, PRD F9, T-178. Этот документ уточняет прежний порядок
`Popen → quit`; исторические оценки сроков не являются текущим планом.

## Проверка и скачивание

GitHub discovery сохраняет исходный тег `X.Y.Z` либо `vX.Y.Z`. Проверка версии
включает ограниченные подписанные метаданные: подпись SHA256SUMS → хэш
latest.json → строгая схема2 → совпадение версии, трека, имени и суммы файла.
Только после этого публикуется `available`; сам пакет скачивается отдельно
по явному нажатию. Автоматическая проверка использует `check_app`, ручная —
`check_app_manual`; metadata-запрос не обходит существующую политику.

Лимиты метаданных: суммы1МиБ, подпись64КиБ, JSON64КиБ. Имя артефакта строится
из версии; адрес — только фиксированный репозиторий и исходный проверенный тег.
Raw JSON URL не является разрешением скачивания. Кэш API — лишь discovery;
сохранённые metadata повторно проверяются локально в worker до предложения
версии. Сериализованному verified-флагу доверять нельзя. `_compose` не ходит
в сеть и не нарушает интервал24ч. Skip/remind/manual сохраняются.

Временный транспортный отказ не уничтожает прежний годный подписанный кэш
того же raw tag/version/track и не обновляет время успешной проверки. Ошибка
подписи или несогласованности набора не маскируется старым успехом. Ограничение
сервера429/Retry-After действует также для ручной проверки и после рестарта.

Перед загрузкой повторно проверяются metadata, место size+64МиБ и допуск.
Файл создаётся exclusive0600 в собственном приватном каталоге0700; чтение
ограничено size+1, точный размер/хэш обязательны. Проверка symlink-компонентов
выполняется до создания каталогов/chmod. Отмена удаляет только собственные
незавершённые файлы. Готовый комплект публикуется атомарно и содержит пакет
и его metadata. AppImage получает0755 только после проверки.

Один worker `threading.Thread`, без QObject. Снимки неизменяемы, имеют operation_id;
устаревшие события не меняют текущую операцию. Закрытие запрещает callbacks,
отменяет операцию и подтверждает join; ссылка на незавершённый поток сохраняется.
Существующий долгий gpgv/show-keys требует отменяемого API до интеграции shutdown.

## Действие с готовым файлом

DEB: открыть папку и показать администратору текстовую инструкцию. Программа
не вызывает apt/dpkg/pkexec/root helper. SOURCE выбирает этот же трек.

AppImage: отдельное «Установить и перезапустить» после локальной перепроверки
файла, неизменности его идентичности и актуальных прав. Запись/обработка диктовки
не прерывается; пользователь сначала завершает её. `appimage=deny` запрещает
запуск. `updates=admin` трактуется консервативно: DEB можно передать администратору,
программный запуск установки AppImage недоступен. Это явное уточнение старого
задела MA-2; ручной запуск программы и политика моделей не изменяются.
Сетевой offline сам по себе не запрещает проверенный локальный файл.

## Перезапуск и сообщение об ошибке

До закрытия GUI готовится PendingRestart: проверенный файл, окружение, приватный
TMPDIR и ограниченная атомарная диагностическая запись попытки. В записи нет
argv, окружения или разрешения исполнения; её поля — schema, attempt_id, target
version, stage, закрытый error code и идентификатор комплекта. Данные записи
не исполняются. Ошибка подготовки остаётся в работающем GUI.

В интерфейсе заранее поясняется: «Программа закроется для запуска новой версии.
Если она не откроется, запустите Astra Voice из меню». Проверенный файл сохраняется.
Далее штатный shutdown: worker/resources подтверждённо остановлены, running-key
финализирован с явным успешным результатом, IPC и instance lock освобождены.
Только после этого запускается исходный проверенный файл:

```text
[absolute_appimage_path, "--appimage-extract-and-run"]
```

Без shell, с close_fds/start_new_session и `clean_env(private_tmp=True)`. Флаг
передаётся runtime файла AppImage, не установленному AppRun. Это штатный режим
самоустановки с распаковкой без зависимости от FUSE; noexec/нехватка места/отказ
политики остаются возможными ошибками. Новый install engine и откат не добавляются.

До Popen сохраняется `launch_requested`. OSError даёт `launch_failed`, закрытый
код, журнал и ненулевой выход. После успешного Popen старая копия запись больше
не меняет: новая уже может её читать. Popen не означает «обновление установлено».
При следующем обычном запуске bridge показывает неуспешную/неподтверждённую
попытку в панели; `--hidden` не открывает окно. Совпадение фактически запущенной
версии и трека позволяет убрать устаревшее предупреждение. Автоматического
отката/повторного запуска старого носителя/handshake в этом шаге нет.

## Приёмка

Независимые тесты и security review привязаны к точному дифу; реальные тестовые
GPG-подписи дополняют подмены транспорта. Отдельно проверяются429, отмена,
несовместимые наборы, чужие файлы, cache races, join/lock порядок и launch failure.
QML следует `design/program-updates` с уточнением post-shutdown сообщения выше;
нужен отдельный design review actual/target, обе темы/минимальная ширина/фокус.
Изолированная package QA должна проверить реальный запуск через private TMPDIR.
Unit/Xvfb не подтверждают KDE/Fly, микрофон или установку на машине пользователя.
Модели updates, M8/polkit, MA-2 rollback, ВКС и публичный выпуск вне этого шага.
