## 3. Решённые трактовки (Юрка)

1. **Выход из программы посреди повтора:** diar незавершён → при следующем запуске с начала; после `diar=done` — продолжение Д5 (бюджет не сбрасывается, Stop-and-Fix M7). Пересев рабочей пары с обнулением reconcile — **только до начала Д5**; если начатый Д5 нельзя восстановить с прежним бюджетом — повтор завершается отказом с прежним результатом (§6 И-2). Текст §Р.3 «начнётся с начала, 0 %» поправить на «продолжится; если разделение не успело — начнётся с начала» — правка UX, без изменения поведения для человека по смыслу.
2. **Повтор с частичным отказом Д5** (`diar=done`, `reconcile.failed`) — **успех повтора** (решение владельца 12.11, после челленджа Astra 6 / T1 Sol 9): публикуется как обычный успех (К3–К7, имена сброшены), `processing_status=partial` сохраняется как признак «есть реплики „несколько голосов“». **Хранение звука меняется и для первой расшифровки:** обычный срок хранения действует при `SUCCEEDED` **или** `PARTIAL ∧ diar_status=done` (partial только из-за `reconcile.failed`; другого источника `PARTIAL` в коде нет — `core/meeting_jobs.py:1656–1667`). Бессрочное удержание — только при `diar_status=failed` (до повтора или «Оставить так») и при активном `rediar`. Новое правило: `state==done ∧ not cancelled ∧ rediar is None ∧ (SUCCEEDED ∨ (PARTIAL ∧ diar_status=done))`; дата в подстроке карточки (`ui/meeting_card.py:631`) становится правдой. Отменяет Д6 плана M4/M5 «partial не запускает удаление звука» в части partial по Д5; нового интерфейса нет. Тесты: первая расшифровка и повтор с `reconcile.failed` при настройках 0/7/30 дней — звук удаляется в срок; `diar_status=failed` — не удаляется.
3. **Политика запретила запись/разделение** при незавершённом повторе → задание ждёт, звук удержан; при выключенном разделении к моменту допуска — повтор снимается как сбой (#1 §3.6).
4. **Старые сборки** не читают `meeting.json` с новыми ключами — допустимо (функция встреч не выпущена).
5. **Д5 поверх уже уточнённого текста** (#1 риск 3): сброс `multiple_speakers` при посеве; проверка на живой записи с двумя повторами подряд — в интеграционных; хранение исходного ASR — запасной ход (+0,5 дня), не делаем без доказанной деградации.
