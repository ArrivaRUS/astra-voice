## 1. Резюме контракта (10 строк)
1. Транспорт: **шина D-Bus сеанса пользователя** через QtDBus с обеих сторон (Voice — PyQt5 5.15.9/Qt 5.15.8, уже в `ui/notify.py`/`ui/tray.py`; Cowork — qtpy/PyQt6 6.7.1, уже в `core/notify.py`/`daemon/tray.py`); только **явно проверенный адрес `unix:`** (`tcp:`/`autolaunch:` — отказ; «шины нет» и «адрес не передан юниту» различаются), ноль новых зависимостей, ноль сети.
2. Имя `ru.astralinux.Cowork` (владеет демон Cowork: регистрирует после `CoworkDaemon.__init__`, снимает в `_quit`), объект `/ru/astralinux/Cowork`, интерфейс `ru.astralinux.Cowork.Command1` (цифра — мажорная версия; ломающее изменение = `Command2`). Реализация Cowork: `QDBusAbstractAdaptor` + `pyqtClassInfo("D-Bus Interface", …)` + `registerObject(…, ExportAdaptors)` — **только два метода, никаких `ExportAllSignals/Slots/Contents`**; в PyQt6 6.7.1 нет `QDBusContext`/`QDBusVirtualObject`, отправитель берётся из служебного аргумента `QDBusMessage` (`message.service()`).
3. Методы: `Status() → a{sv}` и `Submit(s text, a{sv} options) → a{sv}` (vardict — новые ключи не меняют сигнатуру; слоты `pyqtSlot(str, "QVariantMap", QDBusMessage, result="QVariantMap")`, словарь — map, не `QDBusVariant`). Интроспекция XML — канон в Cowork `docs/contracts/ru.astralinux.Cowork.Command1.xml`, зеркало с sha256 в Voice `docs/contracts/`.
4. `options` (обязательные): `source="astra-voice"`, `contract=1`, `request_id` (uuid4 hex, 32 символа), `sent_mono_ms` и `deadline_mono_ms` = `sent + 300` (оба `time.monotonic_ns() // 1_000_000`, CLOCK_MONOTONIC системный; целые в `i/u/x/t`, `bool`/`double`/строка — отказ); необязательные: `mode="submit"` (резерв `"draft"` — форма с префиллом, в v0.2 не включаем), `client_version`. Voice **нормализует** текст (`paste.normalize` + U+2028/2029/U+0085 → пробел, серии пробелов → один, `strip`), Cowork **проверяет и не исправляет** (§1а).
5. `reply.status`: `accepted` · `busy` (`shutting_down`/`rate_limited`/`locked`/`suspending`/`queue_full`) · `refused` (`invalid_options`/`invalid_text`/`unsupported_contract`/`bad_source`/`bad_mode`/`unverified_sender`/`request_conflict`/`policy_disabled`/`not_ready`) · `expired` (`deadline`/`suspended`). Закрытый машинный список, никакого текста исключений. У Voice **два класса исходов**: доказанное «не отправлено/отказано» (`ServiceUnknown`, `UnknownInterface/Method`, нет шины, любой не-`accepted` ответ) и «отправлено, достоверного ответа нет» = **`unknown`** (`NoReply`, обрыв соединения после отправки, повреждённый ответ, смена владельца имени во время вызова) — отдельная пилюля, повтора нет.
6. Тайминги: Voice — сырой асинхронный `QDBusMessage` (`setAutoStartService(False)`, `callWithCallback` с таймаутом **остаток бюджета 300 мс**; соединение/подписки — в рабочем потоке, как в `ui/tray.py`; `QDBusInterface` с интроспекцией не используется; `QDBusError.name()`/`type()` и признак «отправлено» сохраняются); **ровно один вызов, повтора нет** (at-most-once обеспечивает клиент). Cowork: формат ≤ 5 мс → UID отправителя **асинхронно в пределах deadline** (недоказанный UID = отказ) → допуск → **ответ до работы** (отложенный ответ `setDelayedReply` + `connection.send(createReply)`, без вложенного event loop) → работа `QTimer.singleShot(0)` под защитой shutdown.
7. Точка принятия: **`accepted` = запрос принят в память** — атомарно зарезервированы место среди незавершённых голосовых допусков (предел 3, поверх пула на 10) и запись дедупа (`request_id` + отпечаток текста sha256); долговечность до записи задачи не обещается. Работа: `TaskOrchestrator.submit(text, context={"source": "astra_voice", "hotkey": "astra_voice"})` (`request_id` в контекст **не** кладётся — живёт только в памяти приёмника, отдельно от `attention_request_id`); `FASTPATH_SOURCES += "astra_voice"` (иначе «Открой папку загрузки» уйдёт в облако). **Новая задача ≠ новый `dialog_id`**: локальная команда по вердикту роутера рождается в общей ветке «Операционные команды», просьба об откате — в диалоге предыдущего действия, облачная задача — в новом диалоге (как у виджета); окно не открывается (`_AUTOOPEN_SOURCES` без изменений), ответ — штатным уведомлением. Порядок в `submit`: проверка входа/допуска → побочные эффекты; для невалидной команды — ни отмены чужой задачи, ни диалога, ни записи.
8. Доступность: L0 «установлен» — статически (бинарь в PATH / `.desktop` / файл юнита / файл активации), без запуска systemd; L1 «запущен» — `NameHasOwner` + сигнал `NameOwnerChanged` (без опроса); L2 «готов» — сам `Submit`. `Status()` — только для «Проверить снова» и строки в «Общих». **Общий асинхронный источник «сеанс заблокирован / сон»** на обеих сторонах — `org.freedesktop.login1` (системная шина, только чтение: `LockedHint` + `PropertiesChanged`/`Lock`/`Unlock`, `PrepareForSleep`); **неизвестно = нет допуска** (Voice не отправляет, Cowork не принимает).
9. Безопасность: сервер принимает `Submit` только от **того же UID** (`GetConnectionUnixUser(message.service())` асинхронно, срок внутри deadline; ошибка/таймаут → `refused/unverified_sender`); текст 1…4000 символов, C0/C1, `\n`/`\r`/U+2028/U+2029/U+0085, пустота после `strip` — `invalid_text`; дедуп `request_id` в памяти (таблица до терминального исхода + 60 с, ёмкость 64 — вспомогательная защита; гарантию at-most-once даёт клиент); ≤ 1 принятого нового `Submit` за 500 мс (повтор принятого ID лимит не расходует); **текст команды и производные от него (превью, заголовок диалога, тела ответов/ошибок) не попадают в журналы и диагностику обеих сторон, статистику Voice, argv/env, публичные D-Bus-сигналы и ответы методов**; внутренние Qt-сигналы (`task_completed(task_id, reply_text)`), БД и уведомления Cowork — продукт (В-4); никакого shell/exec по строке; токен `auth.toml` Voice не трогает. **Предпосылка C0 (blocker): полная чистка утечек текста в Cowork** — три `preview` (`daemon/service.py:577`, `hermes/client.py:153`, `ui/fullscreen/main_window.py:642`), заголовки диалогов (`service.py:1255`, `:1271`), исключения на границах HTTP/SSE/decision (`hermes/client.py:238/248/255/271/313/316`, `stream_events`), pydantic `MessageReply.model_validate` (ValidationError включает вход), SQLAlchemy (параметры INSERT), `task_pool.py:850/1068/1211/1214`, `service.py:591` (`error=str(e)`, `exc_info=True`) — в журнал только тип исключения и разрешённый код/статус, без `str/repr(exc)`, тел и traceback; в `core/logging.py` — процессор structlog с чёрным списком приватных полей; проверка INFO **и** DEBUG контрольной фразой.
10. Отказы: любой не-`accepted` → **`publish_clipboard()` и пилюля по его результату** («Помощник недоступен — текст в буфере» при `True`; «…не удалось скопировать текст» при `False`), последняя фраза остаётся в памяти для повторного копирования (трей «Скопировать последнее», действие в подробностях пилюли) — действия восстановления доступны из пилюли/трея независимо от службы уведомлений; сохранность буфера ограничена временем жизни Voice и владением выделением (hint `secret` не даёт истории Klipper — так задумано); `unknown` → пилюля «Не удалось узнать, принята ли команда — текст в буфере»; действие **«Запустить Astra Cowork»** (`systemctl --user start` юнита / `gio launch` ярлыка) предлагается **только когда у имени нет владельца**, при прочих отказах — «Что случилось»; сеанс заблокирован/неизвестен в момент доставки → не отправлять и **не публиковать** (фраза только в памяти); сон (`PrepareForSleep`) → отмена командной диктовки/доставки, поздние ответы отсекаются; политика Voice `command_hotkey=`/`off`/неразбираемо/совпадает с «Текст»/**`PolicyStatus.INVALID`**/неверный тип → режим выключен (fail-closed), Win не подставляется; Cowork может выключить приём своей настройкой/политикой → `refused/policy_disabled`.

### 1а. Уточнения после челленджа (обязательны для реализации)

**Порядок допуска `Submit` на сервере (C1):**
1. Формат (синхронно, ≤ 5 мс): типы и диапазоны `options` → `refused/invalid_options`; правила текста → `refused/invalid_text`; `contract` > 1 → `unsupported_contract`; `source`/`mode` → `bad_source`/`bad_mode`. Ответ — сразу.
2. Отправитель: `GetConnectionUnixUser(message.service())` через `callWithCallback`, срок `min(100, deadline − now − 20)` мс; `uid ≠ os.getuid()`, ошибка или таймаут → `refused/unverified_sender`. (`Status()` без побочных эффектов — без проверки UID, ответ немедленно.)
3. Поиск принятого `request_id`: тот же ID и тот же отпечаток → `accepted` повторно (идемпотентно: без новой задачи, без расхода rate limit); тот же ID и другой отпечаток → `refused/request_conflict`.
4. Допуск нового ID, по порядку: `now > deadline_mono_ms − margin` (`margin = max(5 % бюджета, 30 мс)`, §1б п. 6) → `expired/deadline`; `sent_mono_ms ≤ sleep_start_mono` (отправлен до последнего сна) → `expired/suspended`; демон в `begin_shutdown` → `busy/shutting_down`; между `PrepareForSleep(true)` и `(false)` → `busy/suspending`; сеанс заблокирован или состояние неизвестно → `busy/locked`; принятый новый ID < 500 мс назад → `busy/rate_limited`; незавершённых голосовых допусков ≥ 3 → `busy/queue_full`; оркестратора нет → `refused/not_ready`; приём выключен настройкой/политикой Cowork → `refused/policy_disabled`.
5. Резервирование (запись дедупа + место) → ответ `accepted` → `singleShot(0)` с родителем-сервисом: при закрытом сервисе — освобождение и уведомление; в работе `TaskOrchestrator.submit` (или `form_router.open_form(FormRequest(source=FormSource.ASTRA_VOICE, prefill=text))` в `draft`); исключение → место освобождено, `tray.notify("Astra Cowork", "Не удалось принять голосовую команду")`, в журнале тип исключения; ошибка хранения **после** начала побочных эффектов (`_plan_undo` уже отменил задачу) — не «доказанный отказ без эффекта», а сбой после приёма, о нём сообщает Cowork. Терминальный исход задачи (по `task_id` из карты `request_id → task_id`) освобождает место; запись дедупа живёт ещё 60 с. Принятая до блокировки/сна команда исполняется — новых допусков нет.

**Клиент Voice (V1):** проверка шины до соединения (`DBUS_SESSION_BUS_ADDRESS` задан → только `unix:`; не задан → существует `$XDG_RUNTIME_DIR/bus`, иначе состояние `address_not_passed`) → `connectToBus(<явный unix-адрес>, "astra-voice-cowork")` в рабочем потоке → `NameHasOwner`/`NameOwnerChanged` → `Submit` с остатком бюджета. Гейты до отправки: сеанс не заблокирован и состояние известно; сон не начался. Исход `DeliveryOutcome{kind ∈ delivered|undelivered|unknown, reason (закрытый список), error_name}`. Перезапуск демона **до отправки** разрешает доставку новому владельцу (L1 обновился), во время вызова → `unknown`.

**Статистика Voice:** `dictation.result` += `delivered`, `undelivered`, `unknown`; поля `mode ∈ {text, command}`, `deliver_ms`, `deliver_reason` (закрытый список: `none|not_installed|no_bus|not_running|no_contract|busy|refused|expired|timeout|disconnected|bad_reply|locked|suspended|clipboard_failed`); `_FIELDS`/`_CHOICES`/`summary()` обновляются; текста и произвольных строк — нет.

**Захват клавиатуры на время записи команды (V2) — отменён ИБ T1 26.09 (У75, §1в п. 1): явного захвата при записи нет, под ним kscreenlocker не запирает экран.** Прежняя формулировка: отдельный примитив с собственным сроком `RECORD_LIMIT_S + 5` и сторожем-таймером в рантайме (не 30-секундный примитив поля настройки, чей срок снимается лишь при следующем обращении); снятие на **всех** исходах: остановка, отмена, ошибка, крах воркера, потеря индикаторов, сон, выход, смена клавиши. `XGrabKeyboard` не подавляет evdev-хоткеи Cowork (Ctrl+C+C, правые Ctrl×2/Alt×2) — матрица K5. Сравнение сочетаний двух ролей — по разобранным keycode+modifiers с учётом алиасов (`ctrl`/`control`, `win`/`super`), не по строке.

### 1б. После спайка S9 (2026-09-24, `arch/spikes/S9.md` — в `main` `d6f59d7`, PASS — go по формам QtDBus)
1. **PyQt6 6.7.1: `pyqtClassInfo` работает только как декоратор класса** — `@pyqtClassInfo("D-Bus Interface", "ru.astralinux.Cowork.Command1")`; вызов в теле класса (форма `Q_CLASSINFO` из PyQt5) classInfo не создаёт, и все вызовы получают `UnknownInterface` (прогон 1). Остальные формы п. 2/6 подтверждены межпроцессно: `ExportAdaptors`, служебный `QDBusMessage`, `setDelayedReply(True)` + `bus.send(message.createReply([dict]))` из callback асинхронного `GetConnectionUnixUser`; `a{sv}` в обе стороны, ровно один терминальный callback у клиента.
2. **Нет владельца имени при выключенной активации → шина отвечает `NameHasNoOwner`**, не `ServiceUnknown`; клиент относит оба к доказанному «не запущен» (`undelivered/not_running`).
3. **`sent_mono_ms`/`deadline_mono_ms` Voice шлёт явным типом `x` (int64)**: явный `i` при 2³¹+5 молча переполняется в отрицательное ещё на клиенте (сервер ответил `invalid_options`), обычный `int` уходит как `uint32` и за 2³² не проверен. Cowork принимает `i/u/x/t`, отрицательные отвергает (п. 4 без изменений).
4. **Сбой после приёма:** `app.quit()` не отменяет уже поставленный `singleShot(0)` — в C1 обязательна проверка флага остановки перед работой (в пробнике `WORK_SKIPPED_SHUTDOWN`); при смерти процесса сразу после `send` клиент получает `accepted`, работа не выполняется и следа нет — остаточный риск, записан в контракте явно (§1, §7 шаг 5); Voice после `accepted` не повторяет (уже так). Блокировка цикла 600 мс **до** ответа → `expired/deadline` на сервере и `NoReply` у клиента; 600 мс **после** `send` → `accepted` за ~1 мс.
5. **Замеры** (n=100, изолированная шина `dbus-run-session`, offscreen, машина заказчика): `Submit` p50 0,24 / p95 0,40 / max 1,06 мс; `Status` p95 0,12 мс; `GetConnectionUnixUser` p95 0,14 мс — бюджет 300 мс покрыт с запасом ~2,5 порядка; риск §4 «главный цикл занят» остаётся риском нагрузки демона, не транспорта.
6. **Margin дедлайна на сервере (Юрка, после S9):** отказ `expired/deadline` при `now > deadline_mono_ms − margin`, `margin = max(5 % бюджета, 30 мс)` (при 300 мс — новый ID не позже `sent + 270`): таймаут QtDBus у клиента срабатывает до 5 % раньше срока (`NoReply` за 286,7 мс), без запаса остаётся окно ~15 мс «сервер `accepted`, клиент `unknown`». §1а шаг 4 уточнён; вектора O-33 (теперь `expired`), O-46…O-49.
7. **`bus.send` = «поставлено в очередь», не «доставлено»:** `accepted` — приём в память + ответ в исходящей очереди соединения; при немедленной остановке процесса ответ может не уйти (клиент `unknown`) или уйти без работы (клиент `delivered`) — обе гонки остаточный риск; формулировка «без долговечности» в контракте уточнена (§1, §5.1, §7 шаг 5).
8. **Журнал приёмника — без производных от текста:** ни хэшей (sha8 короткой фразы перебирается по словарю), ни отпечатка дедупа — только длина в кодовых точках и `request_id` (контракт §7 шаг 3, §10).
9. **Детали реализации:** дедуп — ёмкость 64, срок «до исхода + 60 с»; таймеры допуска — объекты с родителем-сервисом, `deleteLater()` по завершении, при остановке незавершённые допуски → `busy/shutting_down`; клиент сопоставляет ошибки D-Bus по полному имени `org.freedesktop.DBus.Error.*` (не по суффиксу, не по `type()` в одиночку; вектор C-32); `callWithCallback` вернул `False` → `sent=False`, исход сразу «не отправлено» (`undelivered/no_bus` либо `refused`; C-31/C-33).

## 4. Риски
- Главный цикл Cowork занят > 300 мс → `expired` до принятия или `unknown` после; если доля > 5 % на приёмке — приёмник в отдельном D-Bus-соединении рабочего потока с передачей работы в GUI очередью сигналов (запасной путь внутри C1, эксперимент 4 в S9).
- Шина сеанса во Fly или у юнита не та/не передана → сначала чинится окружение запуска (drop-in `Environment=`/`import-environment`), не транспорт; если шины нет вовсе — запасной unix-сокет демона (замена внутри V1/C1, поля контракта те же).
- login1 недоступен (Fly без учёта сеансов logind) → «неизвестно = нет допуска» выключает режим; запасной источник — `org.freedesktop.ScreenSaver` на шине сеанса (решение по факту K5).
- Ослышанная команда исполняется как напечатанная (у заказчика подтверждения выключены) — вопрос В-1.
- Маршаллинг PyQt (`int → i/u/x`, `bool` отдельный тип) — сервер терпим к целочисленным типам, отказ `bool/double`; контрактный тест и S9.
- Имя шины закрепляется на K0 — после выпуска в парк менять дорого.
- Сбой после `accepted` (хранение, перезапуск) — команда может быть потеряна или исполнена без квитанции у Voice; сообщает Cowork; квитанции #2 — только если приёмка покажет > 1 % `unknown`.
- Утечки текста вне пути `Submit` (`daemon/form_routing.py:88/134/147` — текст уведомлений и заголовки чужих окон, `automations/cover_finder.py`, `cli/prompt_widget_preview.py`) — не голосовая команда, в C0 не входят; отдельная гигиена журналов Cowork после v0.2.

7. **major · граница `accepted`** — `accepted` = приём в память с атомарным резервированием места и записи дедупа; deadline ограничивает допуск нового запроса, принятый callback исполняется; callback с родителем и защитой shutdown, ошибки → уведомление Cowork; долговечность до записи не обещается; вложенного event loop нет (§1 п. 6–7; §1а шаг 5).
8. **major · реальный API `TaskOrchestrator.submit`** — назван фактический класс; порядок «проверка входа/допуска и подготовка → побочные эффекты»; невалидная команда не вызывает отмены, диалога, записи; ошибка хранения после начала эффектов — сбой после приёма, не «отказ без эффекта» (§1 п. 7; §1а шаг 5; C2).
9. **major · порядок и область дедупа** — формат/отправитель → поиск принятого ID (с отпечатком текста) → deadline/rate только для нового ID; ID резервируется до callback; повтор не расходует rate limit; конфликт ID → `refused/request_conflict`; LRU/TTL — вспомогательная защита, at-most-once — клиент (§1 п. 9; §1а шаги 3–4).
10. **major · лимит частоты ≠ лимит незавершённых** — предел незавершённых голосовых допусков (3) поверх пула, резервирование до `accepted`, освобождение на терминальном исходе; определено условие `queue_full` (§1 п. 7; §1а шаг 4; S9 эксперимент 3).
11. **major · fast-path и диалоги** — возвращена оговорка: локальная команда → ветка «Операционные команды», откат → предыдущий диалог, облачная → новый диалог; «новая задача ≠ новый `dialog_id`»; В-2 переформулирован (§1 п. 7; §5 В-2).
12. **minor · `Task.request_id` нет; статистика** — `request_id` живёт только в памяти приёмника (карта `request_id → task_id`), в контекст Hermes не идёт, отдельно от `attention_request_id`; статистика Voice: `result` += `delivered/undelivered/unknown`, `mode`, `deliver_ms`, `deliver_reason` (закрытый список), обновление `_FIELDS`/`_CHOICES`/`summary()` (§1 п. 7; §1а «Статистика Voice»).
13. **major · fail-closed политики** — `command_mode.resolve` отдельно обрабатывает `PolicyStatus.INVALID` (режим выключен, политика не «отсутствует»), неверный JSON-тип, сравнение сочетаний по keycode+modifiers с алиасами (§1 п. 10; §1а «Захват…»; V3).
14. **major · блокировка сеанса** — общий асинхронный источник login1 на обеих сторонах (C6/V7), неизвестно = нет допуска; проверка у Voice перед записью/отправкой, у Cowork при допуске; принятый callback после lock исполняется; при lock у Voice — не отправлять и не публиковать текст/уведомление, фраза только в памяти (§1 п. 8, 10; §1а).
15. **major · MONOTONIC и сон** — MONOTONIC сохранён; добавлены `sent_mono_ms`, `PrepareForSleep` на обеих сторонах: Voice отменяет командную диктовку/доставку и отсекает поздние ответы, Cowork отвечает `busy/suspending` в окне сна и `expired/suspended` запросам, отправленным до сна; сон — в эксперименте 5 (K5) (§1 п. 4, 10; §1а шаг 4).
16. **major · шина во Fly/юните** — только явно проверенный адрес `unix:` (без `tcp:`/`autolaunch:`), различение «шины нет»/«адрес не передан» (второе чинится окружением запуска); сверка одной шины у GUI и юнита — эксперимент 2 в K5 (§1 п. 1; §1а «Клиент Voice»; §4).
17. **major · CLIPBOARD** — пилюля по результату `publish_clipboard()`, последняя фраза в памяти для повторного копирования, действия восстановления в пилюле/трее независимо от службы уведомлений, сохранность ограничена временем жизни Voice/владением выделением (§1 п. 10; V4/V5; эксперимент 5).
18. **major · захват клавиатуры и evdev** — матрица K5 исправлена на реальные комбинации Cowork (Ctrl+C+C, правые Ctrl×2/Alt×2); отдельный сторож захвата на всё время записи (до 120 с + 5) со снятием на всех исходах; S7 проверяет evdev и сочетания блокировки экрана (§1а «Захват…»; V2; K5).
19. **minor · запрет текста в сигналах** — запрет ограничен публичными D-Bus-сигналами, ответами методов и диагностикой; адаптор экспортирует только контракт (`ExportAdaptors`, без `ExportAllSignals/Contents`); внутренние Qt-сигналы с текстом ответа допустимы (§1 п. 2, 9).
20. **minor · действие «Открыть»** — переименовано в «Запустить Astra Cowork», предлагается только когда у имени нет владельца; при прочих отказах — «Что случилось» (§1 п. 10).
