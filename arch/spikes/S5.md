## 1. Результаты

### 1.1 Формат и открытие по имени

`PulseSimpleSource.open()` открывает конкретный источник по имени, не трогая устройство по
умолчанию. Замеры открытия по всем прогонам: **10,6 / 10,8 / 12,9 / 13,8 / 14,8 мс**, всегда
с первой попытки (ретраи `3 × 300 мс` не понадобились), латентность записи 28–54 мкс.
Формат — ровно тот, что в плане M3: 16 кГц, mono, s16le, куски 20 мс = 640 Б.

### 1.2 Уровень, тишина, лимит

* Уровень: пик max **−5,9 дБFS** на живой фразе против **−120,0 дБFS** на пустом источнике —
  разделение однозначное, порог −60 дБFS лежит с большим запасом от обоих.
* Тишина: `silent` выставляется на **2,005–2,016 с** непрерывного пика < −60 дБFS.
* Лимит: кольцевой буфер держит ровно заданную длительность, сбрасывая старые куски; чтение
  при этом не прерывается (`chunks` растёт, `pcm_bytes` стоит) — то есть в M3 лимит 120 с
  реализуется без «обрыва записи», как и задумано.
* CPU потока чтения — **0,25–0,33 %** одного ядра (0,01 с на 3–4 с стены).

### 1.3 PCM не покидает процесс (Р1)

Распознавание сделано **прямо из ОЗУ**: `deque` байтов → `np.frombuffer(dtype='<i2')/32768.0`
→ `onnx_asr.recognize(wav, sample_rate=16000)` → `«Проверка связи.»`. Ни одного временного
файла (`out/no_audio_files.log` пуст). Развилка Р1 «захват в воркере» подтверждена целиком:
и захват, и инференс живут в одном процессе, наружу уходит только текст.

`load_ms` 725,8 и `infer_ms` 693,1 — **холодный** одиночный прогон варианта `int8` при
`--threads 4`; с p95 из S3 (228–253 мс на 10 тёплых прогонах) не сопоставимы и порогом Ц2
не являются.

### 1.4 Главная находка: `pa_simple_new` с неверным именем не падает

При снятой проверке (`--no-strict-device`) открытие несуществующего `av_no_such_source_42`
**прошло успешно** (10,8 мс) и дало 0,9 с звука с пиком −16,2 дБFS — сервер молча подставил
источник по умолчанию, то есть **реальный микрофон** (`…HiFi__Mic1__source`). Спросить
`pa_simple`, что открылось на самом деле, нечем: `pa_stream_get_device_name` есть только в
асинхронном API.

С включённой по умолчанию проверкой (`assert_device_exists` → `pactl list short sources`)
тот же вызов даёт **отказ до открытия**: `device_check {exists: false, known: 8}`, код 3,
`pa_simple_new` не вызывается вовсе.

**Требование к `worker/audio.py` (уточнение к плану M3):** имя устройства проверять **до**
`pa_simple_new` и отказываться, если его нет в списке источников (fail closed). Иначе опечатка
в конфиге или исчезнувшая гарнитура означают тихую запись с другого устройства — прямое
попадание в У39 (`*.monitor` = чужой звук с колонок) и в T-35.

## 3. Решение для `decisions/log.md`

> **Источник звука (Р1, M3):** захват в воркере через `libpulse-simple.so.0` по `ctypes`
> (`pa_simple_new` PA_STREAM_RECORD, s16le/16 кГц/mono, куски 20 мс) — **подтверждён фактом
> S5**: открытие по имени 10,6–14,8 мс, повторное открытие 15,2 мс, тишина на 2,0 с, CPU
> потока чтения 0,33 %, распознавание прямо из ОЗУ без единого файла на диске. Фолбэк
> `QAudioInput` (`python3-pyqt5.qtmultimedia`) и схема #2 (PCM через memfd) **не нужны**.
> Обязательное уточнение к M3: имя устройства проверяется до открытия (fail closed) — иначе
> PulseAudio молча подставляет микрофон по умолчанию (S5-R1).
