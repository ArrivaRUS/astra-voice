## 1. Замер задержки (риск для Ц2)

10 прогонов, `out/latency.tsv`:

| Что | Медиана | p95 |
|---|---:|---:|
| `paste.py` целиком (со стартом `QApplication`) | 420 мс | 446 мс |
| цепочка put→restore | **153 мс** | 154 мс |
| момент XTest от put | 56 мс | 57 мс |

10 из 10 вставок долетели. В продакшне старт `QApplication` вне цикла, значимая цифра —
**153 мс**, из которых **150 мс — наши собственные паузы** (50 мс до XTest + 100 мс до
восстановления). Это ≈ **30 % бюджета Ц2** (p95 «отпустил → текст» ≤ 0,5 с) ещё до инференса:
при p95 инференса у верхней границы 300 мс запас останется ≈ 50 мс.

**Кандидат на оптимизацию в M4:** сократить паузу восстановления или восстанавливать буфер по
событию `SelectionRequest`, а не по таймеру.

## 2. Находки для `platform/*`

### 2.1 Число масок считать, а не хардкодить (`platform/x11.py`)

План говорит «×8 масок Lock/Num/Scroll». На этой машине **Scroll Lock не привязан ни к одному
модификатору** (`xmodmap -pm`, `out/modmap_isolated.log`: `mod3` пуст), поэтому вариантов ровно
**4**. Хардкод «ровно 8» дал бы лишние grab-и и `BadValue`. Правило: число масок брать из
`get_modifier_mapping()` — тогда у пользователя со своим `xmodmap` их станет 8 автоматически.

### 2.2 Парсер `kglobalshortcutsrc`: `\t` экранирована (`platform/shortcuts_conflict.py`)

Несколько комбинаций одного действия разделены **двухсимвольной** последовательностью `\t`, а не
настоящим TAB (проверено `cat -A`):

```
_launch=Alt+Space\tAlt+F2\tSearch,Alt+Space\tAlt+F2\tSearch,Открыть строку поиска и запуска KRunner
```

Первая версия парсера резала по `"\t"` и **не находила `Alt+F2`**. Разбор обязан быть по
`re.split(r"\\t|\t", …)`. Файл заказчика открывается **только на чтение**.

### 2.3 xterm ломает правило «терминалы → `Ctrl+Shift+V`» (`platform/paste.py`)

`docs/plans.md` M4 перечисляет `konsole, fly-term, xterm, yakuake, alacritty → Ctrl+Shift+V`.
Штатный xterm этой машины комбинации **не знает**: приложению приходит литеральный байт `026`
(кейс G). Рабочий путь для xterm — `Shift+Insert`, но он вставляет **PRIMARY**, а не CLIPBOARD,
то есть потребует класть распознанный текст ещё и в первичное выделение — лишняя поверхность
утечки (P1/У11).

Предлагаемое разделение для `platform/paste.py`:
* **VTE/konsole-подобные** (`konsole`, `yakuake`, `fly-term`?, `alacritty`?) → `Ctrl+Shift+V`
  (для konsole подтверждено фактом);
* **остальные терминалы** (`xterm` и всё, что не опознано) → `Shift+Insert` + PRIMARY, с явным
  предупреждением о втором буфере, либо ручной выбор метода пользователем (US-3.4).

Решение — за Юркой; `fly-term` и `alacritty` в список по факту ещё никто не проверял.

### 2.4 `Ctrl+Shift` — это переключение раскладки у заказчика

`~/.config/kxkbrc` → `Options=grp:ctrl_shift_toggle`. С `Ctrl+Space` это не конфликтует, но
задевает саму вставку в терминалы: XTest-комбинация `Ctrl+Shift+V` может дёрнуть переключатель
группы. В изоляции переключателя нет — **проверить живьём** (после вставки в konsole активная
группа должна остаться прежней).

### 2.5 `Ctrl+Space` свободна в KDE, но есть оговорка

В `kglobalshortcutsrc` совпадений нет (`out/conflicts_kde.json`). Оговорки: комбинацию мог занять
модуль без записи в файл (проверяет только живой `XGrabKey`), и `Ctrl+Space` — классическая
комбинация переключателей ввода ibus/fcitx; на этой машине их нет, у корпоративного пользователя
могут быть.

### 2.6 Зависимость `python3-xlib` — открытый вопрос упаковки

```
$ apt-cache policy python3-xlib
  Установлен: (отсутствует)
  Кандидат:   0.33-2+b2        ← repository-EXTENDED (не main), приоритет 900
$ apt-cache show python3-xlib | grep Depends
  Depends: python3-six (>= 1.10.0), python3:any
```

Для прогона 0.33 положен в scratch (`~/.cache/astra-voice-spikes/s4-site`, `--no-deps`,
`six` системный) — система не менялась. Для `.deb` два пути:

| Вариант | Плюсы | Минусы |
|---|---|---|
| `Depends: python3-xlib` из `repository-extended` | ничего не вендорим, обновляется штатно | если у корпоративного заказчика подключён только `main`, зависимость не разрешится → пакет не поставится |
| Вендорить чистый Python `python-xlib` 0.33 (**LGPL-2.1+**, `License: LGPLv2+` в METADATA колеса) в `/usr/lib/astra-voice/vendor` | ставится в любом контуре, только `python3-six` из main | LGPL требует аккуратности в упаковке (текст лицензии, возможность замены модуля), свой апдейт-цикл |

Третий путь — как в S1: `ctypes` + `libX11` (`x11ewmh.py` уже так работает), но тогда `XGrabKey`
и XTest придётся писать руками. **Решение нужно от Юрки/человека до M4.**
