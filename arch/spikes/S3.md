### 2.4 Факты про раскладку, важные для манифеста и загрузчика (M2/M6)

- `onnx_asr.load_model(name, path)` **не требует `huggingface_hub`**, если каталог существует: `Resolver` при существующем `local_dir` включает `offline=True` (`onnx_asr/resolver.py`). То есть скачиванием управляем мы (`net/`), рантайм только читает файлы.
- Обязательный минимум файлов задаётся `_get_model_files()` в `onnx_asr/models/gigaam.py`. **`.yaml` в него не входит** — он не читается при офлайн-загрузке. `config.json` подхватывается, если лежит рядом (`_resolve_model_files`). Мы кладём `.yaml` в манифест для полноты и воспроизводимости, но при желании можно сократить манифест на 3 файла.
- Паттерны — glob: e2e_rnnt → `v3_e2e_rnnt_{encoder,decoder,joint}?int8.onnx` + `v3_e2e_rnnt_vocab.txt`; e2e_ctc → `v3_e2e_ctc?int8.onnx` + `v3_e2e_ctc_vocab.txt`; rnnt → `v?_rnnt_{encoder,decoder,joint}?int8.onnx` + `v?_vocab.txt`. `?` в паттерне — glob-джокер на один символ (точка перед `int8`).
  **Ловушка:** у не-e2e варианта паттерн `v?_…`, поэтому класть e2e- и не-e2e-файлы **в один каталог нельзя без риска** — а fp32 и int8 в одном каталоге дают `MoreThanOneModelFileFoundError` при `quantization=None`. Вывод для M6: **каталог на вариант**, как сделано здесь.
- `config.json` одинаков у всех трёх вариантов (135 Б, один sha256) — он и задаёт `version: v3` для препроцессора.

## 4. Замеры инференса (10 тёплых прогонов, `test-ru-6s.wav`)

Команда (для каждого варианта):
```sh
venv/bin/python scripts/measure_model.py \
  --model-dir ~/.cache/astra-voice-spike/gigaam-v3/<вариант> \
  --model <gigaam-v3-e2e-rnnt|gigaam-v3-e2e-ctc|gigaam-v3-rnnt> \
  --wav ~/.cache/astra-voice-spike/wav/test-ru-6s.wav \
```

## 5. Отмена инференса (Р4, контракт И1) — `RunOptions.terminate`

### 5.1 Пробрасывает ли onnx-asr `RunOptions`?

**Нет.** Ни один вызов в `onnx-asr` 0.12.0 не передаёт третий аргумент в `session.run(...)`:
```console
$ grep -rn "run_options\|RunOptions" venv/.../onnx_asr/
(пусто)
$ grep -rn "\.run(" venv/.../onnx_asr/models/gigaam.py
```

`load_model()` принимает `sess_options`, но `RunOptions` — объект **на прогон**, а не на сессию, и в публичном API его нет.

**Рекомендация в T1 У8 / M2:**
1. Оставить правило «`RLIMIT_AS` = `min_ram_mb × 3`, но не ниже **3 ГиБ**» — 3 072 МиБ выше всех измеренных порогов с запасом, включая худший (2 048 при 4 потоках).
2. Держать `intra_op_num_threads ≤ 2` (см. 4.3–4.4) — тогда порог 768 МиБ, то есть лимит 3 ГиБ даёт четырёхкратный запас.
3. Обязателен **сторожевой таймер** на загрузку модели в воркере (И1: `engine.load` с дедлайном), иначе зависание при неудачном лимите не отличить от долгой загрузки. Предлагаемый дедлайн — 10 с при норме 0,64–0,78 с.

### 7.1 Решения, которые S3 закрывает

1. **Дефолт остаётся `gigaam-v3-e2e-rnnt`** (`p95` 228–253 мс < 300 мс). Развилка «провал порога → e2e_ctc», «оба > 400 → `SherpaEngine`» **не активируется**; `SherpaEngine` в M2 не входит, второй адаптер не нужен. Риск R1 (Python-декодер RNN-T) снят: цена Python-цикла — ~52 мс на 6 с.
2. **Рантайм: `onnx-asr` 0.12.0 + `onnxruntime` 1.24.4** — подтверждено на этой машине (Р2, Р3, Н4 закрыты фактом, а не рассуждением).
3. **Отмена — вариант #2 из синтеза** (`RunOptions.terminate`), патч 28 строк к вендорной копии. `kill+reload` остаётся только аварийным путём.
4. **Новый параметр по умолчанию для M2: `intra_op_num_threads = 2` и `session.intra_op.allow_spinning = 0`.** Обоснование — 4.3 (CPU вдвое ниже без потери скорости), 4.4 (RSS в пороге), 6 (`RLIMIT_AS` 768 МиБ вместо 2 048). Это **уточнение к плану** — раньше число потоков не фиксировалось.
5. **`RLIMIT_AS` = 3 ГиБ** (пол из T1 У8) подтверждён как безопасный; обязателен дедлайн на `engine.load`.
6. **Каталог: строки 2 и 3 в `research/catalog-numbers.md` §1 указывают на sherpa-репозитории**, а не на `istupakov/gigaam-v3-onnx`, который использует наш рантайм. Для нашего манифеста верны цифры §2.2 и §2.3 (224 896 388 Б и 225 780 697 Б).

### 7.2 Что S3 НЕ закрывает (осознанно вне спайка)

- Замеры на **чистой ВМ ALSE 1.8** (Ц3, §14.5 плана #1) — машина заказчика мощная (Core Ultra 7, 14 потоков, 31,5 ГиБ). На слабом железе ориентир — колонка `intra_op=1` (p95 228–229 мс), она тоже в пороге, но проверять нужно отдельно.
- Реальное аудио с микрофона (это S5) — здесь синтетический wav из повторов эталонной фразы.
- WER на датасете — не задача спайка; цифры каталога берутся у автора `onnx-asr` по объявленному протоколу (`research/catalog-numbers.md` §0).
- Поведение под `RLIMIT_AS` при **смене модели** (два воркера, Р5) — отдельная проверка на M6.
