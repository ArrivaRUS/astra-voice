# Урок: тесты писали в настоящие каталоги пользователя; два агента в одном рабочем дереве

**Дата:** 2026-09-22 · **Веха:** M6

## Что случилось
1. Заказчик попросил запустить программу. Первый старт `0.1.0~m6.1` отверг встроенный каталог моделей:
   «Каталог отвергнут как устаревший: получено (1, 3), применено (1, 4)». В `~/.local/state/astra-voice/catalog-state.json`
   лежал serial 4 — из рабочего дерева, где блок 4 уже пересобрал каталог. Записал его прогон unit-тестов агента:
   `tests/conftest.py` изолировал только PulseAudio, а каталоги XDG (`config/data/state/cache`) брались настоящие.
   Раздел «Модели» у заказчика был бы пустым.
2. Параллельно в одном рабочем дереве работали два агента (блок 4 и отладчик вставки). Незакоммиченная правка
   одного роняла 35 тестов другого; `git stash`/`ruff format .` одного топчут файлы другого; мой коммит утянул строку
   из чужой заглушки (`installedCount` в фейке xvfb без свойства в мосте) → красный unit в CI.

## Правило на будущее
- `pytest_configure` в `tests/conftest.py` уводит `XDG_CONFIG_HOME/DATA_HOME/STATE_HOME/CACHE_HOME` во временный корень
  для всей сессии, до сбора тестов. Любой новый путь пользователя — только через `core/paths.py` и эти переменные.
- После установки новой сборки заказчику первым делом смотреть журнал старта на WARNING.
- Два агента, пишущих код одновременно, — только в разных `git worktree` (см. память «agent worktree needs repo cwd»),
  либо строго по очереди. Перед коммитом «чужих» файлов — `git diff` по каждому и проверка на чистом срезе
  (`git stash` недопустим при параллельном агенте; вместо этого `git worktree add` для проверки).
