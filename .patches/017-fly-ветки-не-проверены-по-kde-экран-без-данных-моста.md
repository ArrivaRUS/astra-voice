# 017 — Fly-ветки нельзя считать проверенными по KDE; экран, не читающий мост, молчит без ошибки
**Дата:** 2026-09-23 · **Фаза:** Разработка, M6 (снимки `2747803`, `3618e0c`, `6ce5aef`)

## Что сломалось
Три сигнала с машин заказчика на Fly за два дня, все — в коде, зелёном по тестам и живой проверке на KDE:
1. **Текст только в буфере.** `fly-wm` меняет `_NET_ACTIVE_WINDOW` при показе пилюли; проверка «активное окно то же»
   отказывала XTest, хотя фокус ввода оставался в Kate (`reason=active-changed`).
2. **«Не слышит» и один микрофон в списке.** Экран «Общие» с M1 никогда не читал `settings.devices` — рисовал заглушку
   «микрофон по умолчанию»; заметно стало только там, где умолчание системы — веб-камера.
3. **Значок трея не виден.** Во Fly значок грузится из файла с явным цветом, цвет брали по теме окон (заглушка — всегда
   светлая), а панель Fly в поставке Astra тёмная (`TaskbarColor = PrimaryDarkColor`); на KDE значок подставляет Plasma.

## Почему (настоящая причина)
- Ветки `if session == FLY` писались по чтению исходников и бинарей `fly-wm`, а **проверялись только на KDE** — где эти
  ветки не исполняются. Зелёный тест ветки с моком ≠ проверка на оболочке.
- Экран, который не привязан к данным моста, **не падает** — он показывает правдоподобную заглушку. Контракт
  `docs/ui-bridge.md` сверяет наличие членов, а не их использование экраном.
- Диагностика с чужой машины возможна только по журналу: пока в INFO-строке не появились `reason=`/`target=`/`wm_class=`,
  три отчёта заказчика были неразличимы.

## Правило на будущее
1. Каждая ветка `SessionKind.FLY` (и любая ветка «другая оболочка») получает пометку **«не проверено вживую»** в
   `docs/status.md`/HEARTBEAT до подтверждения с машины на Fly; в `docs/test-plan.md` — отдельная строка T-xx на Fly.
   Снимать пометку может только отчёт заказчика или прогон на Fly.
2. Для экранов настроек — тест «экран использует данные моста»: подать в заглушку 2+ элемента и проверить, что они
   попали в модель списка (как `test_settings_refresh_devices_lists_microphones` + xvfb-кейс). Заглушка по умолчанию
   в QML — только с явным комментарием «пока мост пуст».
3. Любой исход, зависящий от оболочки (вставка, трей, звук), пишет в журнал INFO **машиночитаемую строку без
   пользовательских данных** (`key=value`), чтобы отчёт с чужой машины разбирался без повторения.
4. Прежде чем отвечать «на той машине нужно X», сверить с фактами на своей: бинари `fly-wm`, темы в
   `/usr/share/fly-wm`, `~/.fly` — они есть на каждой Astra и отвечают на половину вопросов без заказчика.
