# 001 — Агенты пишут артефакт в конце → обрыв сессии теряет всю работу
**Дата:** 2026-09-09 · **Фаза:** Архитектура (P11)

## Что сломалось
Два архитектора (Fable ∥ GPT-6 Astra) работали ~30 минут; сессия Claude Code была перезапущена
(перезагрузка/перезапуск заказчиком). В `arch/` не оказалось ни одного файла — оба агента собирали
план в памяти и должны были записать его одним куском в конце. Ранее (2026-09-07/08) три других
агента тоже прерывались перезапуском, но их файлы уцелели, потому что они писали по ходу.

## Почему (настоящая причина)
Бриф Юрки говорил «запиши план в файл», не говорил «пиши частями». Codex exec буферизовал вывод
в stdout процесса, который умер вместе с сессией. Память проекта в git защищает только то, что
уже лежит на диске: правило §5.1 HANDOFF («память обязана быть в git») выполнялось, а «артефакт
обязан появляться на диске по мере готовности» — нет.

## Как починили
Возобновили обоих агентов с транскриптов (SendMessage) с указанием: план писать в файл
по разделам; вывод Codex — перенаправлением в файл сразу; монитор на завершение процесса.

## ПРАВИЛО НА БУДУЩЕЕ
1. В каждом брифе агенту с большим артефактом: **«пиши файл частями по мере готовности разделов»**
   (план, PRD, спека, отчёт ресёрча ≥ 100 строк).
2. Любой `codex exec` — с перенаправлением вывода в целевой файл **сразу** (`> arch/plan-codex.md`),
   а не «сохранить после».
3. После перезапуска сессии первое действие Юрки — `git status` + `ls` артефактов, потом резюме
   агентов; результат агента не считается сданным, пока файл не лежит на диске и не закоммичен.
