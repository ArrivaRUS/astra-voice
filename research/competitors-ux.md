# Конкуренты и UX-паттерны утилит голосового ввода (2025–2026)

> Researcher, 2026-09-07. Зона: **как устроены и как выглядят** лучшие dictation-утилиты —
> чтобы UX-аналитик и дизайнер не начинали с нуля. Рынок/спрос вне зоны (заказчик решил строить).
>
> **Метод.** Яндекс Search API не использован: доступ к файлу кредов (`tokens_and_keys.env`)
> в этой сессии **заблокирован политикой разрешений**, поэтому по правилу скилла — **fallback
> WebSearch + WebFetch**. Первичный источник — **локальные исходники Handy**
> (`/home/astra/Документы/handy-gigaam/vendor/Handy/`), это самая надёжная часть отчёта.
> Уверенность: `high` — код/официальный README; `med` — сайт или репо вендора; `low` —
> SEO-сравнялки (voibe/spokenly/getvoibe/openwhispr), которые сами продают конкурента.

## Итог

Категория за 2025–2026 сошлась на одном каноне: **хоткей (hold-to-talk по умолчанию) → маленькая
тёмная «пилюля» с живой аудио-визуализацией у края экрана → текст вставляется в активное окно →
приложение живёт в трее, а не в окне**. Окно настроек у лидеров — **левый сайдбар с 5–7 разделами
+ карточки-группы строк «заголовок · подсказка-tooltip · контрол справа»**, тёмная тема как
норма (Whispering с 2026 ставит dark по умолчанию), нижняя строка-статус с моделью слева и
обновлением справа.

Каталог моделей как **карточки с двумя полосками accuracy/speed** — это ровно паттерн Handy
(`ModelCard.tsx`), и он в категории скорее уникален, чем общепринят: остальные показывают модели
списком с размером. То есть требование заказчика №3 — не «как у всех», а **осознанное
заимствование сильной стороны Handy**, и его стоит усилить недостающей цифрой — **ОЗУ в работе**
(её нет ни у кого, включая Handy).

Главный вывод для ALSE: **все известные боли категории на Linux — не про красоту, а про хоткеи,
вставку текста и оверлей** (Handy issues #1239, #121, #429). Дизайн должен закладывать «честные»
состояния отказа для этих трёх мест, а не только счастливый путь.

## Разбор Handy по исходникам

Пути от `/home/astra/Документы/handy-gigaam/vendor/Handy/`. Всё в этом разделе — `high`
(прочитано в коде). Версия `0.8.3`, форк `ArrivaRUS/handy-gigaam`.

### Каркас окна — `src/App.tsx`
Три состояния: `accessibility` → `model` → `done`. Онбординг не показывается, если модели уже
есть (`hasAnyModelsAvailable()`), но **возвращающегося пользователя всё равно перекидывают на
экран разрешений**, если ОС отозвала доступ к микрофону. Основной экран — `h-screen flex
flex-col`: сверху сайдбар слева + прокручиваемый контент справа (`p-4 gap-4`), снизу
**фиксированный футер**. Тосты — `sonner`, `theme="system"`.

### Сайдбар — `src/components/Sidebar.tsx`
Ширина `w-40` (160 px), граница справа, сверху логотип `HandyTextLogo width={120}` и разделитель.
7 разделов, каждый — иконка 24×24 + подпись `text-sm font-medium truncate`; активный —
`bg-logo-primary/80`, неактивные — `opacity-85` + `hover:bg-mid-gray/20`, скругление `rounded-lg`.

Разделы (`SECTIONS_CONFIG`) с флагом `enabled(settings)` — **два раздела скрыты по умолчанию**:
| Раздел | Иконка | Видимость |
|---|---|---|
| Общие | HandyHand | всегда |
| Модели | Cpu | всегда |
| Продвинутые | Cog | всегда |
| История | History | всегда |
| Постобработка | Sparkles | только если `post_process_enabled` |
| Отладка | FlaskConical | только если `debug_mode` (включается **Ctrl+Shift+D**) |
| О программе | Info | всегда |

### Строка настройки — `ui/SettingsGroup.tsx` + `ui/SettingContainer.tsx`
Ключевой паттерн, который стоит унаследовать. `SettingsGroup` = заголовок группы
(`text-xs font-medium uppercase tracking-wide`, серый) над карточкой
`border rounded-lg` с `divide-y` между строками. `SettingContainer` = одна строка:
слева заголовок `text-sm font-medium` + **иконка «?» с тултипом** (`descriptionMode="tooltip"` —
описание не занимает место, а прячется в подсказку), справа контрол. Есть `layout="stacked"`
для длинных контролов и `disabled` с `opacity-50`.

Раскладка разделов:
- **Общие**: «горячие клавиши» (шорткат транскрибации, push-to-talk, шорткат отмены —
  *скрыт на Linux: комментарий в коде про «dynamic shortcut instability»*) → карточка настроек
  текущей модели (язык/перевод, **появляется только если модель это умеет**) → «Звук»
  (микрофон, глушить при записи, звуковой отклик, устройство вывода, громкость).
- **Продвинутые**: «Приложение» (запуск скрытым, **автозапуск**, иконка в трее, показывать
  оверлей, таймаут выгрузки модели, экспериментальные) · «Вывод» (метод вставки, инструмент
  ввода, работа с буфером, авто-Enter) · «Транскрипция» (свои слова, пробел в конце) ·
  «История» (лимит, срок хранения) · «Экспериментальные» — только по флагу.
- **О программе**: язык интерфейса, версия (`font-mono`), донаты, «исходный код», каталог
  данных, каталог логов, отдельная группа «Благодарности».

### Модели — `settings/models/ModelsSettings.tsx` + `onboarding/ModelCard.tsx`
Экран: `max-w-3xl` по центру, H1 + описание, затем **две секции — «Ваши модели» и «Доступные»**.
В шапке первой секции — фильтр по языку: кнопка-пилюля с глобусом → дропдаун `w-56` с **полем
поиска языка** (Enter выбирает первый, Escape закрывает), активный фильтр подсвечен.
Сортировка: активная модель первой, кастомные — вниз. Пусто → `«noModelsMatch»` по центру.

**Карточка модели** (`ModelCard.tsx`) — то самое:
- Верх: слева имя `text-base font-semibold` + бейджи («Рекомендуем» / «✓ Активна» / «Своя» /
  «Переключаем…» со спиннером) и описание `text-text/60 text-sm`.
- Справа — **две полоски**: подпись `text-xs` шириной `w-24` справа + трек `w-16 h-1.5`
  `rounded-full` с заливкой `width: score*100%`. Метки в i18n буквально `accuracy` / `speed`.
  Полоски **скрыты на узком экране** (`hidden sm:flex`) и не рисуются, если оба score = 0.
- `<hr>`, затем нижняя строка тегов высотой `h-5`: 🌐 «Только русский» / «Многоязычная»,
  🔤 «Может переводить на английский», а справа — **размер файла** (иконка загрузки +
  `formatModelSize`) либо кнопка «Удалить» для уже скачанных.
- Состояния (`ModelCardStatus`): `downloadable · downloading · verifying · extracting ·
  switching · active · available`. При загрузке — прогресс-полоска + «Загрузка 47 %» слева,
  **скорость `12.3 MB/s`** и «Отмена» справа; при проверке и распаковке — та же полоска
  `animate-pulse` на всю ширину + подпись.
- Рамки: активная `border-2 border-logo-primary/50 bg-logo-primary/10`, рекомендованная
  `/25` + `/5`, обычная `border-mid-gray/20`. Ховер `shadow-lg scale-[1.01]`, нажатие `[0.99]`.

**Чего в карточке нет: ОЗУ в работе.** Есть только размер на диске. Требование заказчика №3
про «сколько занимают памяти в работе» — это **добавка сверх Handy**, аналога в исходниках нет.

### Онбординг — `onboarding/Onboarding.tsx`
Полноэкранный (`p-6 gap-4`): логотип 200 px, подзаголовок «To get started, choose a
transcription model», ниже колонка `max-w-[600px]` — сначала **рекомендованные** карточки
(`variant="featured"`), затем остальные **по возрастанию размера**. Во время скачивания
прочие карточки `disabled`; переход дальше — только когда модель скачана + проверена +
распакована, после чего она автоматически выбирается. Отдельный шаг — разрешения (mac/Win).

### Обновления — `update-checker/UpdateChecker.tsx`
Именно то, что просил заказчик, — **не диалог, а строка в футере**. Одна кнопка-текст по
состояниям: `Проверка обновлений…` → `Не требует обновлений` (3 секунды и только при ручной
проверке) / `Доступно обновление` → клик → `Подготовка…` → `Загрузка… 42 %` → `Установка…` →
авто-`relaunch()`. Прогресс-бар рядом только на время загрузки. Выключено — текст `Проверка
обновлений отключена`, всё некликабельно. Стиль: `text-text/60`, а при наличии обновления
`text-logo-primary font-medium` — единственное цветовое пятно в футере; `tabular-nums`, чтобы
проценты не прыгали. Единственная модалка — для portable-установок: заголовок, объяснение,
«Закрыть» + «Открыть GitHub Releases».

Механика: Tauri updater, endpoint `.../releases/latest/download/latest.json`, подпись
**minisign** (`pubkey` в `tauri.conf.json`), `createUpdaterArtifacts: true`.

### Футер — `components/footer/Footer.tsx`
`border-t`, `text-xs`, `text-text/60`. Слева — `ModelSelector` (кнопка-статус с именем текущей
модели, по клику дропдаун + полоска прогресса), справа — `UpdateChecker` · `•` · `v0.8.3`.

### Оверлей — `overlay/RecordingOverlay.css` + `.tsx`
Отдельное Tauri-окно. Пилюля **172×36 px**, `border-radius: 18px`, фон `#000000cc`, grid в три
колонки `auto 1fr auto`, `padding: 6px`, появление `opacity 300ms`. Слева иконка микрофона или
транскрипции; в центре **9 столбиков** `width: 6px`, `gap: 3px`, цвет `#ffe5ee`, высота
`4…20 px` по формуле `4 + v^0.7 * 16` со сглаживанием `prev*0.7 + target*0.3` (прозрачность
тоже по уровню); справа круглая «×» 24×24, `hover: scale(1.05)`, `active: scale(0.95)`.
Состояния: `recording` (столбики) / `transcribing` / `processing` (пульсирующий текст `1.5s`).

### Трей — `src-tauri/src/tray.rs`
Иконка — **3 состояния** (Idle / Recording / Transcribing) × 3 темы (Dark/Light/Colored) =
9 PNG. Меню перестраивается на лету: версия (мёртвый пункт), подменю моделей (**label = имя

обновления» (**disabled, если проверки выключены**), «Выход» (`Ctrl+Q`); во время
записи/расшифровки вместо моделей появляется **«Отмена»**.

## Свод UX-паттернов (что считается «современным минималистичным» в 2026)

1. **Сайдбар, а не вкладки.** Handy — 160 px, 7 пунктов, иконка + текст. Whispering в 2026
   специально переехал на вертикальный сайдбар (схлопывающийся) и дал переключатель
   Sidebar ↔ Header. Одностраничник со скроллом остался у совсем простых утилит. `med`
2. **Прогрессивное раскрытие.** Разделы «Отладка» и «Постобработка» появляются только по
   флагу; продвинутые вещи спрятаны за «Экспериментальные». Настройка модели показывается
   только если модель её поддерживает. `high` (код Handy)
3. **Строка настройки = заголовок + «?» + контрол справа**, строки собраны в карточки с
   `divide-y` под маленьким СЕРЫМ CAPS-заголовком группы. Описания живут в тултипах, а не
   в тексте под каждой строкой — это и есть главный источник «минималистичности». `high`
4. **Карточка модели вместо строки списка**: имя + бейдж + описание слева, метрики справа,
   теги и размер внизу, прогресс — внутри той же карточки. Две полоски accuracy/speed — фича
   Handy; у Voxtype/VOXD/Speech Note модели показывают списком с размером. `high` / `med`
5. **Пилюля-оверлей у края экрана** с живой визуализацией уровня — консенсус всей категории,
   включая обе ОС: Win+H (панель сверху, микрофон + шестерёнка), macOS (иконка + анимированные
   полоски), Voxtype («floating waveform OSD»), Telly Spelly (live volume meter), плазмоид
   Dictee. Смысл — **доказать, что микрофон слышит**. И **отмена прямо из индикатора**: «×» в
   оверлее Handy, пункт «Отмена» в трее во время записи. `high`
6. **Трей — основной дом приложения.** Иконка меняет вид по состоянию, меню даёт переключение
   модели, настройки, обновления, выход. VOXD продаёт «tray mode» как отдельный режим. `high`
7. **Нижняя строка-статус**: слева «что за модель сейчас», справа «состояние обновления ·
   версия». Приглушённая, единственный цветовой акцент — когда есть обновление. Обновление —
   строка, а не модалка; модалка только там, где автообновление невозможно. `high`
8. **Онбординг = один вопрос.** «Выберите модель» + рекомендованная карточка сверху и
   сортировка остальных по размеру. Никаких многошаговых туров. `high`
9. **Микрокопия — состояние + следующий шаг.** Ошибка микрофона у Handy не «Error -3», а
   «Микрофон не найден» + «Подключите микрофон или гарнитуру и попробуйте снова», причём
   **инструкция разная под каждую ОС**. Ошибки — тосты, настройки при этом видны. `high`
10. **Тёмная тема — норма.** Handy следует `prefers-color-scheme`; Whispering в 2026 сделал
    dark дефолтом и отдельно чинил «вспышку светлой темы» — значит, **тему надо применять до
    первой отрисовки**. `high` / `med`
11. **Размер окна.** Handy тянется по вьюпорту, контент ограничен `max-w-3xl` (768 px) по
    центру, сайдбар 160 px → комфортная ширина ~950–1000 px; шрифт 15/24, радиусы 8–12 px,
    разделители на 20 % прозрачности. `high`
12. **Hold-to-talk по умолчанию, toggle — опцией.** Handy, Voxtype, Superwhisper (с 2026 —
    отдельные хоткеи на push-to-talk и toggle), macOS — сходятся. `high`

## Что критично именно для ALSE (без интернета, без root, ЗПС)

1. **Оверлей — под подозрением, а не «конечно, сделаем».** Целевая среда X11 + KDE 5.27, то есть
   большинство Wayland-граблей нас минует, но «кража фокуса» — ровно та проблема, из-за которой
   Handy выключил оверлей на Linux по умолчанию; в Astra Cowork она уже решалась (`StaysOnTop` +
   occlusion). **Нужен запасной вариант индикации** — иконка в трее (3 состояния) + звук.
2. **Каталог моделей должен работать офлайн и не выглядеть сломанным.** Handy без сети покажет
   пустой список «Доступные модели» и футер «Нет модели — требуется загрузка». Нам нужны
   **явные состояния «нет доступа к каталогу»** и путь «поставить модель из локального файла /
   с корпоративного зеркала», а не тупик.
3. **Обновления: строка в футере — да, автоскачивание — вопрос.** У Handy это Tauri-updater с
   minisign и GitHub-эндпоинтом. В закрытом контуре GitHub недоступен, а при включённом ЗПС
   подменённый на лету бинарь просто не запустится. Нужны явный статус «источник обновлений
   недоступен» (а не молчание, как у Handy) и **вариант «обновиться из файла»**. Без root deb
   не поставить — значит либо обновление в `~/.local`, либо «скачали → попросим админа».
4. **Автозапуск без root** — `~/.config/autostart/*.desktop` либо `systemd --user`. В UI один
   тумблер (у Handy — «Продвинутые → Приложение»), но текст должен честно писать, что делает.
5. **ОЗУ в работе — наша добавка к паттерну**, ни у кого из просмотренных этого нет. Для
   корпоративной машины (может быть 8 ГБ, а не 30 как у заказчика) цифра важнейшая. Куда класть:
   третья строка в блоке метрик или тег внизу рядом с размером. Рекомендация — **тег внизу**:
   две полоски остаются двумя полосками, а «222 МБ на диске · ~700 МБ ОЗУ» читается как факт.
6. **Русский UI — исходный язык, не перевод.** У Handy `ru` есть, но местами недопереведён.
   Инструкции в ошибках должны указывать на **реальные пути ALSE/KDE**, а не на «Системные
   настройки → Конфиденциальность». Особенно ошибки микрофона: в памяти проекта уже есть
   инцидент «микрофон молчит» (гонка двух WirePlumber, профиль sof-hda-dsp) — текст обязан
   вести к действию, а не в тупик.
7. **Никакой телеметрии и облачной постобработки.** Раздел «Post Process» с API-ключами
   (OpenAI-совместимый эндпоинт) из Handy в корпоративную сборку переносить нельзя.
8. **Тему брать из `kdeglobals`, а не у Qt/браузера** — записанный урок проекта; Handy
   полагается на `prefers-color-scheme`, у нас этот путь врёт.

## Находки / риски

- **Паттерн «две полоски» — не отраслевой стандарт, а именно Handy.** `high` (проверено в коде
  Handy; у Voxtype/VOXD/Speech Note модели показаны списком). Риск: если дизайнер решит, что
  это «как у всех», он потеряет то, чем карточка Handy реально хороша, — соседство
  бейджей, тегов и прогресса в одной коробке.
- **Ближайший живой конкурент под Linux — Voxtype** (Rust, MIT, deb+AppImage, 8 движков,
  Wayland-first, floating waveform OSD), и у него **нет нормального GUI настроек** — только
  TUI `voxtype configure` и опциональный Quickshell-OSD. `med`. Это наша прямая ниша: тот же
  уровень движка, но человеческий русский интерфейс. Полезная деталь: по умолчанию на GNOME/KDE
  он вешает **Scroll Lock** — свободных глобальных клавиш в KDE мало, дефолтный хоткей надо
  проверять на конфликты.
- **Цены облачных конкурентов расходятся между источниками** (VoiceInk $29 vs $39.99;
  Superwhisper lifetime $249.99 vs «freemium от $8.49»). Все источники — SEO-сравнялки,
  продающие свой продукт. `low`. В PRD эти цифры не тащить.
- **Скриншоты почти недоступны машинному сбору.** README Handy содержит только логотипы
  спонсоров, лендинг — webm-видео вместо картинок. `high`. Куда стоит сходить человеку глазами:
  [handy.computer](https://handy.computer) (видео),
  [tryvoiceink.com](https://tryvoiceink.com/), [voxtype.io](https://voxtype.io/),
  [epicenter.so/whispering](https://epicenter.so/whispering/),
  [store.kde.org/p/2351313](https://store.kde.org/p/2351313),
  [debugpoint.com про Speech Note](https://www.debugpoint.com/speech-note-text-to-speech/).
- **Риск метода:** Яндекс-бэкенд не использован (доступ к кредам заблокирован), выдача
  WebSearch по этой теме забита SEO-страницами конкурирующих приложений. Всё, что помечено
  `low`, стоит перепроверить, если оно станет основанием для решения.

## Противоречия

1. **Wispr Flow и Linux.** Одна SEO-страница обещает загрузку под Linux; ни один обзор
   Linux-опыт не описывает, другие сравнения перечисляют Mac/Windows/iOS/Android. Не сглаживаю:
   **Linux-поддержку считать неподтверждённой**. `low` Там же — цена VoiceInk: $29 vs $39.99
   в двух обзорах одной даты. `low`
2. **Оверлей на Linux**: README Handy говорит «выключен по умолчанию, крадёт фокус», но в коде
   `AdvancedSettings` тумблер `ShowOverlay` доступен всем платформам без предупреждения в UI.
   **Предупреждение живёт в README, а не там, где пользователь принимает решение** — это и
   находка, и готовое улучшение для нас. `high`
