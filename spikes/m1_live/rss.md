# RSS GUI-процесса в покое — замеры Optimizer (M1)

**Дата:** 2026-09-09 · **Зона:** av-opt · **Порог PRD A1 / DoD M1:** VmRSS ≤ 122 880 кБ (120 МБ)

## Методика (одинакова для всех вариантов)

Изолированный сеанс, реальный `:0` не затронут:

```
dbus-run-session -- kwin_wayland --virtual --width 1600 --height 1000 \
  --xwayland --no-global-shortcuts --socket=av-opt-201035 --exit-with-session=<скрипт>
```

Своя песочница XDG (`XDG_CONFIG_HOME`/`XDG_DATA_HOME`/`XDG_CACHE_HOME` в scratchpad,
`XDG_RUNTIME_DIR=/tmp/av-opt-201035/run` — короткий путь нужен из-за лимита 108 байт
на имя unix-сокета), `kdeglobals` — копия пользовательского. Запуск из репозитория:
`/usr/bin/python3 -I src/astra_voice/bootstrap.py app`, окно «Общие», воркера нет.
Через **5 с покоя** снимаются `/proc/<pid>/status`, `smaps_rollup`, `smaps`, `maps`.
Приложение — прямой ребёнок скрипта замера (иначе `/proc/<pid>/maps` недоступен).

**Грабли методики.** `bootstrap._harden()` ставит `prctl(PR_SET_DUMPABLE, 0)` (У9) —
у такого процесса `/proc/<pid>/maps|smaps|smaps_rollup` принадлежат root и не читаются.
`VmRSS`/`VmHWM` из `status` при этом видны. Поэтому разбор карт памяти делался
копией лаунчера без `prctl` (`diag_bootstrap.py`); RSS у неё совпадает с боевой
в пределах 2 % (170 604 против 167 832 кБ — разница от `sys.path` и отсутствия
`resource`-ограничения, на выводы не влияет).

| группа | RSS «как есть», кБ | RSS без GL, кБ | Pss «как есть», кБ |
|---|---:|---:|---:|
| **Mesa + LLVM** (`libgallium`, `libLLVM-16`) | **58 764** | 576 | 11 686 |
| анонимная память (heap, JS-куча QML, стеки) | 29 236 | 26 448 | 29 232 |
| библиотеки Qt5 | 24 712 | 24 520 | 4 113 |
| python3.11 + стандартная библиотека | 14 556 | 14 568 | 10 468 |
| KF5/Kirigami/breeze (тянет `QApplication`) | 8 752 | 8 540 | 1 102 |
| модули PyQt5 (`*.abi3.so`) | 8 604 | 8 620 | 8 604 |
| шрифты и кэш fontconfig | 7 876 | 7 240 | 810 |
| ICU | 2 564 | 2 564 | 254 |
| прочее | 20 444 | 17 420 | — |
| **ВСЕГО** | **166 904** | **101 876** | **60 991** |

Главный вывод: **35 % RSS — это Mesa и `libLLVM-16.so.1`** (45 МБ только LLVM).
Проверено, что на машине заказчика тот же стек: `glxinfo` на `:0` даёт
`Mesa Intel(R) Graphics (ARL)` 24.2.8, и `plasmashell` на `:0` тоже держит
`libLLVM-16.so.1` — в Mesa 24.x драйвер `iris` живёт внутри `libgallium.so`,
который слинкован с LLVM. То есть 58 МБ платятся при **любом** GL-контексте,
аппаратный он или нет. Изолированный стенд — тот же аппаратный GL (проверено
`glxinfo` внутри песочницы), поэтому замеры переносятся на машину заказчика.

Pss честнее RSS: своей памяти у процесса ~61 МБ, остальное — страницы библиотек,
общие с kwin/plasma. Но порог PRD A1 сформулирован в RSS, поэтому цель — RSS.

## Что проверено и **не** даёт эффекта

| приём | VmRSS, кБ | дельта |
|---|---:|---|
| как есть (базовая линия) | 167 740 | — |
| `MALLOC_ARENA_MAX=2` | 166 324 | −0,8 % (шум) |
| `malloc_trim(0)` через 8 с после старта | 167 088 → 166 940 | −0,1 % (шум) |
| `QT_QPA_PLATFORMTHEME=none` | 170 816 | 0 % |
| `QT_STYLE_OVERRIDE=Fusion` | 166 520 | −0,7 % (шум) |
| `QT_XCB_GL_INTEGRATION=xcb_egl` (EGL вместо GLX) | 170 376 | 0 % (Mesa всё равно грузится) |
| `QT_QUICK_BACKEND=software` **без** отключения GLX | 161 224 | −3,9 % (Mesa грузит сам XCB-плагин) |

Ленивых импортов чинить нечего: `python3 -X importtime` показывает только
`PyQt5.QtCore/QtGui/QtWidgets/QtQml/QtNetwork` и стандартную библиотеку —
**ни `numpy`, ни `requests`, ни `jsonschema`, ни `Xlib`, ни `onnxruntime`**
на старте не грузятся (`Xlib` уже под ленивым импортом в `platform/*.py`,
vendor в GUI не подключается). QML тоже чист: `QtGraphicalEffects` нигде нет,
а `QtQuick.Controls`, `QtQuick.Layouts` и `QtQuick.Shapes` используются по делу
(`ApplicationWindow`, `Switch`, `ComboBox`, `Button`, `RowLayout`, `ShapePath`) —
убирать нечего, лишних `import` в `Main.qml` нет.

## Единственный приём с эффектом ≥ 20 % — отказ от GL-контекста

Две переменные окружения **до импорта Qt** (в `scripts/astra-voice` и в
`bootstrap.py`, рядом с уже существующим `QT_QUICK_CONTROLS_STYLE`):

```sh
QT_QUICK_BACKEND="${QT_QUICK_BACKEND:-software}"
QT_XCB_GL_INTEGRATION="${QT_XCB_GL_INTEGRATION:-none}"
export QT_QUICK_BACKEND QT_XCB_GL_INTEGRATION
```

Обе нужны вместе: `QT_QUICK_BACKEND=software` сам по себе даёт лишь −3,9 %,
потому что Mesa грузит XCB-плагин Qt под GLX-интеграцию; `QT_XCB_GL_INTEGRATION=none`
без software-бэкенда оставит Qt Quick без контекста.

### Замер «после» (боевой лаунчер, та же методика)

| вариант | VmRSS, кБ | VmHWM, кБ | Pss, кБ | к порогу 122 880 |
|---|---:|---:|---:|---|
| **как есть (GL)** | **167 740** | **167 740** | 60 991 | +44 860 (превышение 36 %) |
| **software + без GLX** | **102 580** | **102 580** | 45 024 | −20 300 (запас 16,5 %) |

**Дельта: −65 160 кБ, −38,8 %.** Порог PRD A1 / DoD M1 пройден.
Дополнительно: `QGuiApplication` вместо `QApplication` снимает ещё 4,7 МБ
(97 180 кБ), но ломает путь-заглушку `_fallback_widget` (там `QLabel`) —
это правка поведения, отдельное решение.

### Цена: качество отрисовки и CPU

Кропы 300–400 % (`spikes/m1_live/out/rss_cmp_*.png`, полные окна `rss_gl.png` / `rss_sw.png`):
текст, знак, иконки `QtQuick.Shapes`, скругления, чип клавиши, сегмент, тумблеры,
фокус-кольцо и выпадающий список — **совпадают**. Расхождение по всему окну —
4,8 % пикселей, RMSE 4,5 %: это оттенки сглаживания на краях глифов и дуг,
на глаз при 100 % неразличимо.

CPU (тики по 10 мс, `utime+stime`, аппаратный GL в песочнице):

| сценарий | GL | software |
|---|---:|---:|
| покой, 10 с | 0 | 0 |
| непрерывное наведение на список разделов, 10 с | 63 | 76 |
| 10 переключений разделов (анимация), 6 с | 5 | 3 |

Наведение дороже на 13 тиков за 10 с — это +1,3 процентного пункта одного ядра
на время движения мышью; в покое разницы нет. Анимация переключения — не дороже.

### Побочный эффект, который надо закрыть

В software-режиме Qt печатает в stderr две строки при каждом старте:

```
QXcbIntegration: Cannot create platform OpenGL context, neither GLX nor EGL are enabled
Warning: fallback to QtQuick software backend.
```

Это шум в журнале, поведение не меняет; гасится обработчиком сообщений Qt
на эти две строки — микрозадача Developer.

## Итог

Порог 120 МБ **недостижим при любом GL-контексте**: Mesa+LLVM тянет 58 МБ,
всё остальное вместе даёт максимум 3 %. Либо software-рендер (102,6 МБ,
качество совпадает, +1,3 п.п. ядра при наведении), либо пересмотр порога A1
до ~170 МБ. Решение — за человеком (⛔ СТОП).
