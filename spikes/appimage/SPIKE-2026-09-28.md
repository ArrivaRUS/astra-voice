## 3. Замеры `--version` (мс, изоляция, временный HOME)

«Холодный» — после `posix_fadvise(DONTNEED)` по файлам (без root); кэш метаданных остаётся, поэтому после перезагрузки
реальный холодный старт будет медленнее. Разброс между прогонами ±40 мс.

| Режим | 1-й / холодный | тёплый (5 прогонов) |
|---|---|---|
| `.deb` `/usr/bin/astra-voice` (эталон) | — | 183–214 |
| Г: распакованный AppDir | 258–653 | 150–209 |
| Б: обычный запуск через FUSE | 805–998 | **724–946** |
| Б: только монтирование + AppRun, без Python | — | 18–24 |
| Б + `ASTRA_VOICE_SELFINSTALL=1`: самоустановка из FUSE | 1869–2252 | — |
| Б → уже установленная копия (запуск .AppImage) | — | 180–248 |
| А: установленная копия напрямую | 192–209 | 148–190 |
| В: `--appimage-extract-and-run` (+ самоустановка) | 1763–1984 | 1090–1465 |

Из замеров:
- Сам FUSE почти бесплатный: монтирование и AppRun занимают ~20 мс.
- Дорого чтение Python и библиотек через squashfuse: +600 мс уже на `--version`. При старте GUI (Qt 73 МБ, QML, ORT) разница
  будет больше. Это ещё не замерено — пункт проверки заказчика.
- Установленная копия стартует так же, как `.deb`.
- Повторный extract-and-run медленный (1,1–1,5 с): runtime каждый раз распаковывает всё заново. Поэтому основным путём
  его делать нельзя, только первым запуском.
- Движок: `onnxruntime` 1.24.4 из бандла загружает `silero_vad.onnx` за 57 мс, numpy 1.24.2.

## 4. FUSE на этой машине и самоустановка

Факт: при `enable_exec_on_fuse=N` запуск из FUSE **работает**. Так ведут себя и эталонный python-appimage, и наш
AppImage. `mountinfo` показывает `fuse.<имя> ro,nosuid,nodev`, `sys.executable` лежит в `/tmp/.mount_*`. Это совпадает
с одной из статей wiki Астры (#60358775): запрет действует только при включённом `astra-nochmodx-lock`, а здесь
`nochmodx=0`.

Что будет при настоящем запрете, проверить нельзя: нужен root (параметр ядра или nochmodx). Картина по коду runtime
20251108 (`strings`):
- монтирование пройдёт;
- `execv` нашего `AppRun` из монтирования упадёт;
- runtime напечатает `execv error: <причина>` и выйдет;
- автоматического отката нет.

Значит, **AppRun в этом случае не получит управления совсем**, и самоустановку изнутри образа не запустить. Рабочий
путь — первый запуск командой:

```
./Astra_Voice-0.1.0-x86_64.AppImage --appimage-extract-and-run
# или: APPIMAGE_EXTRACT_AND_RUN=1 ./Astra_Voice-0.1.0-x86_64.AppImage
```

Проверено здесь (режим В): runtime распаковывает образ в `$TMPDIR/appimage_extracted_<md5>`, а `AppRun` копирует себя в
`~/.local/share/astra-voice/app/<версия>-<build_id>/` и делает `exec` оттуда. Первый запуск занимает ~1,8 с.
При `noexec` на `/home` не поможет ничего (ожидаемо, см. ресёрч).

Как `AppRun` определяет режим. Пробный запуск бинаря не нужен: если `AppRun` вообще исполняется из монтирования,
значит исполнение разрешено.
- **А** — `HERE` совпадает с каталогом установки (`readlink -f`): обычный запуск.
- **Б** — задан `$APPIMAGE`, и самая длинная точка монтирования-префикс `HERE` в `/proc/self/mountinfo` имеет тип `fuse*`:
  - если есть целая установленная копия того же `KEY` → `exec` в неё;
  - если задан `ASTRA_VOICE_SELFINSTALL=1` → самоустановка;
  - иначе запуск прямо из монтирования.
- **В** — `basename HERE` = `appimage_extracted_*`: всегда самоустановка. После установки временная распаковка удаляется.
- **Г** — распакованный вручную `squashfs-root`: обычный запуск.

Самоустановка атомарна:
1. Блокировка `mkdir <корень>/.lock-<KEY>`.
2. `cp -a` во временный каталог рядом (`mktemp -d <корень>/.tmp-<KEY>.XXXXXX`).
3. Маркер `.installed-ok`.
4. `mv -T` (rename).

Повторные запуски сразу идут в установленную копию: проверены и прямой запуск (А), и запуск `.AppImage` (Б → А).

Особенности runtime, найденные в спайке:
1. Runtime перехватывает **любой** аргумент `--appimage-*` («… is not yet implemented»). Поэтому служебный флаг AppRun
   называется `--selfinstall-status`.
2. `--appimage-extract-and-run` у runtime 20251108 (и у runtime python-appimage) **не удаляет** свою распаковку: в
   `$TMPDIR` остаются ~270 МБ на каждую сборку. Теперь `AppRun` сам удаляет её после установки.
3. В одном из прогонов `measure.sh` FUSE-монтирование снялось с задержкой, и уборка упала на `rm`.
   Вручную не воспроизвелось (снятие ~0 мс во всех режимах). Сейчас `measure.sh` ждёт до 3 с и делает `fusermount -u`.
   После замеров висящих `.mount_` нет.

## 5. Библиотеки: что берётся с хоста

`ldd` по `libQt5Quick`, `libqxcb`, glx-интеграции, `QtDBus`, `onnxruntime_pybind11_state`, `python3.11`.
Итог: **ни одной реально отсутствующей библиотеки**.
- `libgfortran`/`libquadmath` в `numpy.libs` показываются «not found» только при `ldd` отдельного файла: внутри процесса их
  находит RPATH numpy, импорт и ORT работают.
- С хоста берутся:
  - glibc-семейство, `libstdc++`, `libgcc_s`, `libz`;
  - `libGL`/`GLX`/`GLdispatch`;
  - X11, xcb (+ icccm/image/keysyms/render-util/xinerama/xkb/…), `xkbcommon(-x11)`;
  - `fontconfig`, `freetype`, `png16`, `brotli`, `expat`;
  - `glib-2.0`, `pcre2`;
  - `libdbus-1` — тянет за собой **библиотеки Parsec** `libpdp`, `libparsec-base/aux`, а также `libsystemd`, `libcap`, `libaudit`, `libpam`;
  - Kerberos (`libgssapi_krb5`…) + **`libgost.so.2`** — это Qt Network.

  Всё это есть в замыкании `fly-all-main` (ресёрч §1.3); xcb-библиотеки сейчас берутся с хоста, а не из бандла.
- Утечек путей хоста нет:
  - `sys.path` — только бандл, `/usr/lib/python3` отсутствует;
  - строк `/usr/lib/python3` в не-`.py` файлах нет;
  - `LD_LIBRARY_PATH` не выставляется: у ELF свои RUNPATH.
- **Риск:** бандловый Python собран с **OpenSSL 1.1.1k** (RHEL 8, EOL), путь CA по умолчанию — `/etc/pki/tls/cert.pem`.
  `AppRun` ставит `SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt`. Наш `net/http.py` уже сам предпочитает этот файл,
  так что загрузка моделей и обновлений пойдёт с системными CA. Устаревший OpenSSL — вопрос для ИБ (T1):
  - собрать Python самим;
  - или взять python-appimage `manylinux2014`/другую сборку и проверить версию OpenSSL.

## 6. Что проверить заказчику руками с GUI

Запускать установленную копию или `.AppImage` из обычной сессии. `.deb`-версию на время проверки закрыть: общий lock не
даст второму экземпляру стартовать.
1. **Старт GUI:** время от запуска до значка в трее — `.AppImage` через FUSE, установленная копия, `.deb`.
2. **Трей** в KDE и Fly: значок, смена состояний, меню, уведомления с кнопками. QtDBus из pip-Qt 5.15.19 ходит в хостовый `libdbus`.
3. **Глобальная клавиша** и **вставка** в Kate, LibreOffice, терминал.
4. **Звук:** захват через хостовую `libpulse-simple`, регулировка микрофона (`pactl`), индикатор уровня.
5. **Тема:** светлая и тёмная из `kdeglobals`/`paletterc`; шрифты и HiDPI 1.25 на HDMI.

   Сверить скриншоты с `.deb`: Qt 5.15.19 против 5.15.8 и отсутствие platformtheme-плагина (диалоги в стиле Fusion).
6. **Распознавание фразы** (GigaAM v3) и загрузка модели/каталога по HTTPS (CA).
7. **Первый запуск** через `--appimage-extract-and-run` под пользователем без прав администратора.
8. **Стоковая ВМ ALSE 1.8:** то же при включённом `astra-nochmodx-lock`. Ожидаем `execv error`; записать точный текст.

## 7. Что придётся поменять в коде продукта

1. **Точка установки как основной путь.** Даже когда FUSE разрешён, запуск через squashfuse на ~0,6 с медленнее уже на
   `--version`. При запрете FUSE-исполнения `.AppImage` вообще не запускается повторно.

   Вывод: `.AppImage` — это «носитель + установщик», а меню и автозапуск указывают на установленную копию.
   - Стабильный путь — симлинк `~/.local/share/astra-voice/app/current` → `<версия>-<build_id>`, переключается атомарно.
   - Хранить две версии (текущую и предыдущую для отката), остальные удалять. Каждая копия занимает 267 МБ.
2. **`platform/autostart.py`.** `EXECUTABLE = "/usr/bin/astra-voice"` заменить на `…/app/current/AppRun`, если задан
   `ASTRA_VOICE_APPIMAGE_DIR` (AppRun его экспортирует). В записи — `TryExec` на тот же путь.
3. **Регистрация в меню** — пункт «Установить для себя»:
   - `~/.local/share/applications/astra-voice.desktop`;
   - значки `~/.local/share/icons/hicolor`;
   - снятие регистрации.

   Сейчас этого нет вовсе.
4. **`core/paths.py`.** Ресурсы уже берутся из `ASTRA_VOICE_RESOURCES`, AppRun её ставит. Без переменной
   `resource_root()` ушёл бы в запасной «корень репозитория» = `parents[3]` от `paths.py` = `<AppDir>/usr/lib`, где
   ресурсов нет. Держится всё только на переменной; нужна явная ветка «бандл» (от расположения `bootstrap.py`).
5. **Окружение дочерних процессов** (`pactl`, `gpgv`, `xdg-open`/браузер). `AppRun` не ставит `LD_LIBRARY_PATH` —
   главной утечки нет. Детям уходят только:
   - `APPIMAGE`, `APPDIR`, `ARGV0`, `OWD` — от runtime;
   - `SSL_CERT_FILE`, `ASTRA_VOICE_RESOURCES`, `ASTRA_VOICE_APPIMAGE_DIR`;
   - Qt-переменные из `bootstrap.py`.

   Для программ пользователя (`xdg-open`) нужен явный фильтр окружения.
6. **CA:** уже ок (`net/http.py` → `/etc/ssl/certs/ca-certificates.crt`, запасной `SSL_CERT_FILE`). Остаётся решение по OpenSSL 1.1.1k.
7. **Политика:** `/etc/astra-voice/policy.conf` читается с хоста как есть. `updates=admin/offline` должны выключать и
   самообновление AppImage-трека.
8. **Сосуществование с `.deb`:**
   - общий lock (`$XDG_RUNTIME_DIR/astra-voice/lock`) уже не даст двум экземплярам работать одновременно;
   - общие `~/.config/astra-voice` и модели;
   - desktop ID `astra-voice.desktop` в `~/.local/share/applications` перекроет системный — нужно правило (ресёрч §7, варианты а/б);
   - `~/.local/share/astra-voice/app/` живёт рядом с `data_dir()` продукта (модели, журналы). `data_dir()` ставит 0700 на
     родителя, `AppRun` создаёт его с `umask 077` — конфликта нет.
9. **Самообновление AppImage-трека** (ресёрч §5): скачать `.AppImage` и подпись → проверить → распаковать
   (`--appimage-extract` в `app/.tmp-*`) → `rename` → переключить `current`. Сам `.AppImage` после установки не нужен.
10. **Доводка `AppRun` (спайк → выпуск):**
    - зависшая блокировка `.lock-<KEY>` после убийства процесса — сейчас ждёт 30 с и падает; нужна проверка pid или `flock`;
    - сообщение пользователю при нехватке места (267 МБ);
    - `--version` без самоустановки в режиме В.
11. **CI:**
    - job `appimage`: `build.sh` + гейты `elf-audit --expect 157 --max-glibc 2.28`, SBOM, `check_qml`/`check_resources`,
      смоук `--appimage-extract-and-run --version`;
    - `lock.txt` → `packaging/appimage.lock`;
    - правки `.github/workflows` пушит заказчик.
