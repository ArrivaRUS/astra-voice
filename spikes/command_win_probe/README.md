# Ограниченный Win probe (S7, не приёмка)

Только отдельное окно и passive grab `Super_L` через существующий X11 backend.
Микрофон, модель, runtime, CoworkClient, буфер, настройки и службы не используются.
Дочерний процесс сам переводит обе D-Bus переменные в `/nonexistent`.
Без двух явных live-параметров запуск — dry-run, Qt/X11 не импортируются.

Первый операторский опыт: тап Win, удержание около секунды, отпускание, «Стоп».
Максимум 15 секунд от старта supervisor; после выхода отпустить клавиши и проверить
возвращение меню Win. Фокус при постановке — только собственное видимое окно.
Порог 300 мс выводит `would_record`, это не аудиозапись. Удержание дольше 5 секунд
закрывает пробник. Произвольные символы/коды клавиш и заголовки чужих окон не логируются.

**Раннее Win+key не исправлено:** наблюдённая другая клавиша до 300 мс даёт
`early_chord_FAIL_no_replay`, pending не запускает would_record. Передачи сочетания
обратно WM нет. Отсутствие такой строки не доказывает доставку сочетания в WM.
Не использовать пробник для проверки блокировки/крышки: он не подключает login1.
Не вводить пароли и не переключать фокус на рабочие окна во время опыта.

Команда для координатора **после проверки текущего DISPLAY и разрешения этого
конкретного опыта** (значение `:N` заменить наблюдённым локальным X11-сеансом):

```sh
/home/astra/.cache/astra-voice-dev/venv-a/bin/python \
  spikes/command_win_probe/probe.py \
  --live-display :N --confirm-live --duration 15
```

Это не команда для автоматического запуска из данного документа. Не использовать
угаданный `:0`. Допустимы только `:число[.экран]`; remote DISPLAY отвергается.
Не запускать через установленную Voice и не запускать полный runtime.
Кнопка «Стоп», закрытие окна или Ctrl+C в supervisor завершают ребёнка.
Supervisor по heartbeat 600 мс отправляет TERM и через 200 мс KILL только своему
Popen child; ждёт его завершения. Общий предел можно изменить явно, но не выше60с.
Linux PDEATHSIG=SIGKILL прекращает ребёнка при смерти supervisor; проверяется гонка
изменения parent PID. Оба процесса нужно оставить под наблюдением до `supervisor_closed`.
Если `grab_failed_stop` или `focus_not_ours_stop`, попытка завершена: не запускать
фоновый regrab, не останавливать других владельцев Win.

Проверки без GUI/X11/бусов/аудио:

```sh
DISPLAY= WAYLAND_DISPLAY= QT_QPA_PLATFORM=offscreen \
DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent \
DBUS_SYSTEM_BUS_ADDRESS=unix:path=/nonexistent \
/home/astra/.cache/astra-voice-dev/venv-a/bin/pytest \
  spikes/command_win_probe/test_probe.py -q -o addopts=
```

Crash/hang-тесты здесь затрагивают только искусственные дочерние процессы.
Нативное меню/освобождение Win пока не проверены. `XGrabKeyboard`, AnyKey,
синтетический ввод и изменения KWin отсутствуют. Поведение локера и полный S7
остаются за отдельно разрешёнными дальнейшими опытами.

Проверено 08.10: процессные тесты **10 PASS** (2,24 с в первом прогоне), Ruff PASS,
dry-run выводит `dry_run_no_X`. Повторный лог:
`/tmp/astra-command-win-probe-tests.log`. Это не native PASS.
Exit 0 — ребёнок завершился штатно; exit 2 — ограничитель/ошибка. Для различения
читать `supervisor_closed.reason` (`deadline`, `heartbeat_timeout`, `child_exit`),
а также дочерние коды `grab_failed_stop`/`focus_not_ours_stop`.
Срабатывание 15-секундного предела освобождает клавишу, но не принимает жесты за оператора.
