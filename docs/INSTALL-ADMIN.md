## 1. Что это и системные требования

Astra Voice — голосовой ввод. Пользователь зажимает горячую клавишу (по умолчанию `Ctrl+Space`),
говорит фразу, и текст появляется в активном окне. Распознаёт речь модель, которая лежит на диске этой же машины.
Считает процессор. Звук и текст никуда не передаются, сеть для диктовки не нужна.

### Что ставится

### Память: сколько нужно по моделям

Окно и индикаторы занимают ≈ 100 МБ в покое (программная отрисовка, замер M1). Модель работает
в отдельном фоновом процессе. Его объём — поле `min_ram_mb` встроенного каталога
(`/usr/share/astra-voice/data/catalog.json`). У всех моделей это **оценка**
(`ram_estimated: true`), а не замер на вашей машине.

| Модель (id в каталоге) | Язык | На диске | ОЗУ при работе | Отечественная |
|---|---|---|---|---|
| **GigaAM v3 RNN-T** (`gigaam-v3-e2e-rnnt-int8`) — рекомендуемая | ru, с пунктуацией | 216 МиБ | 419 МБ | да (Сбер) |
| GigaAM v3 CTC (`gigaam-v3-e2e-ctc-int8`) | ru, с пунктуацией | 214 МиБ | 417 МБ | да |
| GigaAM v3 RNN-T без пунктуации (`gigaam-v3-rnnt-int8`) | ru | 215 МиБ | 418 МБ | да |
| GigaAM v3 CTC без пунктуации (`gigaam-v3-ctc-int8`) | ru | 214 МиБ | 416 МБ | да |
| GigaAM Multilingual CTC (`gigaam-multilingual-ctc-int8`) | ru, en, kk, ky, uz | 214 МиБ | 416 МБ | да |
| GigaAM Multilingual Large CTC (`gigaam-multilingual-large-ctc-int8`) | ru, en, kk, ky, uz | 564 МиБ | 1095 МБ | да |
| T-one (`t-one-fp32`) | ru | 138 МиБ | 267 МБ | да (Т-Банк) |
| Vosk ru (`vosk-ru-int8`) | ru | 69 МиБ | 135 МБ | нет (Alpha Cephei) |
| Vosk small ru (`vosk-small-ru-int8`) | ru | 25 МиБ | 50 МБ | нет |
| Whisper small (`whisper-small-int8`) | многоязычная | 239 МиБ | 461 МБ | нет (OpenAI) |
| Whisper large-v3-turbo (`whisper-large-v3-turbo-int8`) | многоязычная | 1036 МиБ | 2007 МБ | нет |
| NeMo FastConformer ru (`nemo-fastconformer-ru-pc-ctc-int8`) | ru | 125 МиБ | 244 МБ | нет (NVIDIA) |

Как это проверяется в коде:
- при установке модели сравнивается `MemTotal` машины с `min_ram_mb` модели;
- при смене рабочей модели «на ходу» нужно `MemAvailable ≥ min_ram_mb + 200 МБ`. Если памяти меньше,
  программа предлагает «Переключить с паузой».

Для рекомендуемой модели ориентир ≈ 0,5 ГБ ОЗУ на пользователя в сумме (окно плюс фоновый процесс).
**[уточнить]** официального минимума ОЗУ для машины нет.

## 2. Получение и проверка пакета

### Что лежит в GitHub Release

Релиз собирает и подписывает CI (job `release` в `.github/workflows/ci.yml`, запускается по тегу `v*`
в защищённом Environment `release`). В релизе лежат:

| Файл | Что это |
|---|---|
| `astra-voice_<версия>_amd64.deb` | пакет |
| `sbom.cdx.json` | состав компонентов (CycloneDX) с sha256 трёх `.so` |
| `SHA256SUMS` | суммы `.deb`, `sbom.cdx.json`, `INSTALL-ADMIN.md`, `latest.json`, `release.gpg` |
| `SHA256SUMS.asc` | отсоединённая подпись `SHA256SUMS` (GPG, Ed25519) |
| `release.gpg` | публичная связка ключей подписи — та же, что в пакете; публикуется job `release` |
| `INSTALL-ADMIN.md` | эта инструкция для администратора |
| `latest.json` | указатель на пакет; формат — [`docs/contracts/latest.json.md`](contracts/latest.json.md) |

Публичных релизов на 26.09 нет.

### Откуда взять ключ и как ему поверить

Связка `release.gpg` лежит в GitHub Release отдельным файлом. Та же связка ставится пакетом в
`/usr/share/astra-voice/data/keys/release.gpg`. Доверие к ней держится на **отпечатке мастер-ключа**,
который публикуется в `README.md` репозитория и в этом разделе (ниже). Сверяйте отпечаток трижды:

1. **Опубликованный отпечаток** — из `README.md` и из этого раздела. Лучше взять его по независимому
   каналу, не с той же страницы, откуда скачан пакет.
2. **Файл `release.gpg` из Release** — его отпечаток должен совпасть с опубликованным.
3. **Файл из установленного пакета** — если на машине уже стоит Astra Voice (обновление) или есть
   эталонная машина. Его отпечаток тоже должен совпасть.

```sh
gpg --show-keys --fingerprint ./release.gpg                                   # из Release
gpg --show-keys --fingerprint /usr/share/astra-voice/data/keys/release.gpg    # из пакета
```

Расхождение хотя бы в одном месте — не ставить и сообщить по каналу из `SECURITY.md` §7.
Связку, извлечённую из того самого `.deb`, который вы проверяете, для первой проверки использовать
нельзя: подменивший пакет подменил бы и её.

> **Важно.** Мастер заказчика: `5F1F 7718 559F 8F57 FFE1  1780 55BB 1162 F17A 5CB0`,
> uid `Astra Voice Release <alekovalev@astralinux.ru>`; создан 26.09.2026.
> Он создан на рабочей машине заказчика; риск принят для v0.1, преемник M2 будет сгенерирован офлайн до v1.0 (см. `docs/SECURITY.md`).
> Подписывающие подключи `S1` (`7602 A029 F0E3 4CD2 344A  9CDA 657E D046 89FF 4D79`)
> и `S2` (`9053 EE0C 0085 683C E6C7  042E DC2E 5932 25D8 0428`) действуют до 26.09.2027.

### Проверка

```sh
# 0. Отпечаток связки сверен (см. выше)

# 1. Подпись файла сумм: нужна строка «Good signature»
gpgv --keyring ./release.gpg SHA256SUMS.asc SHA256SUMS
#    для обновления можно взять установленную связку:
# gpgv --keyring /usr/share/astra-voice/data/keys/release.gpg SHA256SUMS.asc SHA256SUMS

# 2. Суммы пакета и SBOM
sha256sum -c SHA256SUMS
```

Путь к связке указывайте с `./` или абсолютным. Имя без косой черты `gpgv` ищет в `~/.gnupg`.

Код программы проверяет подписи строже, чем `gpgv` по коду возврата. Он принимает подпись только
по строке `VALIDSIG`, отпечаток из которой должен быть в списке закреплённых и не должен быть в списке
отозванных (`src/astra_voice/security/verify.py`). Для ручной проверки администратором достаточно
команд выше и сверки отпечатка.

## 3. Установка

### Перед установкой: needrestart на рабочих станциях

На ALSE 1.8 стоит `needrestart` (3.6). После **любого** `apt install` он может показать синий диалог
«Демоны, использующие устаревшие библиотеки», в котором отмечен `user@<UID>.service`, то есть менеджер
сеанса пользователя. Если нажать «Ok», сеанс перезапустится: машина зависнет, и понадобится холодный
сброс. Так случилось при живой установке 16.09. Это поведение `needrestart`, а не пакета Astra Voice.

Постоянное решение для рабочих станций (применено у заказчика 16.09, с ним `0.1.0~m5.2` и следующие
версии ставятся без диалога):

```sh
sudo tee /etc/needrestart/conf.d/50-astra-desktop.conf >/dev/null <<'EOF'
# Рабочая станция: needrestart ничего не перезапускает сам, только перечисляет.
$nrconf{restart} = 'l';
# Пользовательские сеансы (user@UID.service) не трогать никогда.
$nrconf{blacklist_rc} = [ qr(^user@) ];
EOF
```

- `restart = 'l'` — только список, без вопросов и без перезапусков.
- `blacklist_rc` с `^user@` — сеансы пользователей в список не попадают вовсе. В стоковом конфиге
  3.6 этот список пуст, так что присваивание ничего не затирает.

Если конфиг не положен, а диалог уже появился: `Tab` → **«Отмена»** (`<Cancel>`).

Разовый вариант без конфига, по коду `needrestart` 3.6 (читает переменную `NEEDRESTART_MODE`):
`sudo env NEEDRESTART_MODE=l apt install ./astra-voice_<версия>_amd64.deb`.
**[уточнить]** на живой машине этот вариант не проверялся.

### Установка

```sh
sudo apt install ./astra-voice_<версия>_amd64.deb
```

Ставьте через `apt`, а не `dpkg -i`, чтобы зависимости подтянулись из репозиториев ОС. Сетевой доступ
при этом нужен только самому `apt` к вашим репозиториям, и только если зависимостей не хватает.

В закрытом контуре, без обращения к репозиториям:

```sh
sudo apt-get install --no-download --no-remove ./astra-voice_<версия>_amd64.deb
```

Если apt сообщит о недостающих пакетах, занесите их в контур обычным порядком.

### Проверка после установки

```sh
astra-voice --version                 # версия пакета
dpkg-query -W astra-voice             # то же средствами dpkg
stat -c '%U:%G %a' /var/lib/astra-voice/staging   # root:root 700
```

Запущенную у пользователя старую версию после установки нужно перезапустить (раздел 7).

## 4. Первый запуск пользователя

Программу запускают из меню («Astra Voice», категория «Утилиты») или командой `astra-voice`.
При первом запуске открывается мастер из пяти шагов. Его можно закрыть и вернуться позже.

1. **Язык и сеть.** Язык интерфейса и два тумблера: «Проверять обновления утилиты» и «Проверять
   обновления моделей». Оба **выключены** во всех профилях. **В v0.1 сами проверки ещё не реализованы
   (M7, v0.2):** тумблеры только сохраняют выбор. Если политика задала эти ключи, строки
   заблокированы с подписью «Задано администратором».
2. **Модель.** Два пути:
   - **Скачать.** Пользователь отмечает модели (по умолчанию предлагается GigaAM v3 RNN-T) и нажимает
     «Продолжить». Файлы идут с `huggingface.co` по HTTPS. Каждый файл сверяется по sha256 из
     подписанного встроенного каталога, после установки модель проходит пробное распознавание.
     Окно можно закрыть: загрузка продолжится, по готовности придёт уведомление. При запрете сети
     политикой кнопка скачивания отвечает «Задано администратором: работа без сети».
   - **Установить из папки** (кнопка «Установить из файла или папки…»). Сети не нужно;
     подходит для закрытого контура (см. ниже).
3. **Горячая клавиша.** По умолчанию `Ctrl+Space`, режим «удерживать, пока говорите» (`ptt`) или
   «нажать в начале и в конце» (`toggle`). Если комбинацию держит другая программа (например, Handy),
   мастер предупредит и предложит свободную (`Ctrl+Shift+Space`, `Ctrl+Alt+D`).
4. **Микрофон.** Проверка уровня работает без модели. Тестовая диктовка появляется, когда модель
   готова, и ничего не вставляет в другие окна.
5. **Готово.** Программа сворачивается в системный трей (значок слева от часов).

### Корпоративное зеркало моделей в v0.1

`corp_base` уже задаёт сетевое зеркало весов из встроенного подписанного каталога.
Собственный каталог (`catalog_url`, `catalog_pubkey`) появится в M10. Для доставки
модели без сети используйте установку из папки:

1. На эталонной машине скачайте модель штатно. Она окажется в
   `~/.local/share/astra-voice/models/<id>/<ревизия>/`. Например,
   `models/gigaam-v3-e2e-rnnt-int8/322c3b29492673eb7d0b434bfa9dfb8653e34d02/`.
2. Скопируйте **содержимое каталога ревизии** (сам каталог `<ревизия>/`, без соседнего
   `<ревизия>.json` и `current.json`) на общий ресурс, доступный пользователям на чтение.
3. Пользователь в мастере (шаг 2) или в разделе «Модели» нажимает «Установить из файла или папки…»
   и указывает этот каталог.

Что проверяет программа:
- в папке **ровно** файлы из каталога: лишний файл, подкаталог или символическая ссылка — отказ
  «лишние файлы»;
- каждый файл сверяется по sha256 при копировании;
- после установки идёт пробное распознавание;
- поддерживается только **папка**: архив отвергается с просьбой выбрать папку, хотя кнопка называется
  «из файла или папки».

**[уточнить]** По коду `0.1.0~m6.17` из папки ставится **рекомендуемая модель** (GigaAM v3 RNN-T).
Способа выбрать другую модель каталога для установки из папки в интерфейсе не найдено. Сценарий
с общим ресурсом на живой машине не прогонялся.

## 5. Политика парка: `/etc/astra-voice/policy.conf`

### Как файл читается (по коду `src/astra_voice/core/policy.py`)

- Файл читается **один раз при старте** программы пользователя. После правки пользователю нужно
  перезапустить программу: «Выход» в меню трея и запуск заново, либо перелогиниться.
- Формат INI (Python `configparser`, без интерполяции). Ключи пишутся в секции **`[astra-voice]`**.
  Если секции нет, берутся ключи из `[DEFAULT]`. Имена ключей к регистру не чувствительны.
- **Комментарии — только отдельной строкой**, начиная с `#` или `;`. Комментарий в конце строки
  становится частью значения: `offline = true  # ...` — уже не `true`.
- Повтор ключа в секции делает файл невалидным.
- Логические значения: `1 / true / yes / on` и `0 / false / no / off`, регистр не важен.
- **Каждый заданный ключ блокирует** свою строку в настройках, с подписью «Задано администратором».
  Пользователь её не меняет, а в его `settings.json` значение политики не записывается.
- Ключ `locked = ключ1, ключ2` блокирует строки, **не задавая** значения: остаётся значение по
  умолчанию или то, что выбрал пользователь.

Три состояния файла пишутся в журнал строкой `старт: версия=… сеанс=… политика=<состояние>`:

| Состояние | Когда | Что делает программа |
|---|---|---|
| `absent` | файла нет | значения по умолчанию, ничего не заблокировано, сеть по кнопкам пользователя |
| `ok` | файл разобран | значения и блокировки применены |
| `invalid` | ошибка синтаксиса, нет секции и ключей, дубликат ключа, негодное логическое значение, файл не читается пользователем (например, права 0600) | **сеть запрещена** («Не удалось проверить правила администратора: работа без сети»), остальные значения политики **не применяются и не блокируются** |

Права: `root:root`, **0644**. Файл должен читаться пользователем, потому что программа работает от его
имени. **[уточнить]** Проверка «владелец root и нет записи для группы и остальных» по коду v0.1
**не выполняется**: она запланирована в M7 (`docs/plans.md`, У16/У37). Пока права — ваша
ответственность.

```sh
sudo install -d -m 0755 -o root -g root /etc/astra-voice
sudo install -m 0644 -o root -g root policy.conf /etc/astra-voice/policy.conf
```

### Ключи, которые действуют в v0.1

| Ключ | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `profile` | строка | не задан | Пусто или `personal` — сеть по кнопкам пользователя. **Любое другое значение** (`secure`, `offline` и т. п.) запрещает сеть. В v0.1 `profile=secure` делает **только** это; остальные следствия из PRD (`updates=admin`, `domestic_only=true`) пока не реализованы |
| `offline` | логический | `false` | `true` — сеть запрещена: скачивание моделей недоступно, «Задано администратором: работа без сети». **Нераспознанное значение тоже запрещает сеть** (fail-closed) |
| `ca_bundle` | путь | не задан | Файл CA для HTTPS при скачивании моделей. Если файла нет, берётся `/etc/ssl/certs/ca-certificates.crt`, затем `SSL_CERT_FILE`. Проверка TLS не отключается никогда |
| `corp_base` | URL | не задан | HTTPS-адрес корпоративного зеркала файлов модели; оно опрашивается первым, затем публичные источники |
| `hotkey` | строка | `Ctrl+Space` | Горячая клавиша диктовки: модификатор (`Ctrl`, `Alt`, `Meta`/`Super`/`Win`) плюс одна клавиша, `Shift` — только дополнительно. Недопустимое значение не применяется (в журнале предупреждение), но строка **всё равно блокируется** со значением по умолчанию |
| `hotkey_mode` | строка | `ptt` | `ptt` — удерживать; `toggle` — нажать в начале и в конце. Иное значение → `ptt` |
| `pill_enabled` | логический | `true` | Плавающая «пилюля»-индикатор у края экрана |
| `check_app_updates` | логический | `false` | Тумблер «Проверять обновления утилиты» (в v0.1 проверок нет, ключ нужен для блокировки строки) |
| `check_model_updates` | логический | `false` | Тумблер «Проверять обновления моделей» (то же) |
| `language` | строка | `ru` | Язык интерфейса (`ru`, `en`) |
| `autostart` | логический | `true` | Строка «Автозапуск» в «Общих». **В v0.1 ярлык не создаётся** (раздел 6), значение только хранится |
| `model_id` | строка | не задан | Рабочая модель по id каталога. **[уточнить]** Через политику не проверялось и не рекомендуется |
| `locked` | список | пусто | Дополнительно заблокировать строки без задания значения |

Переменная окружения `HF_HUB_OFFLINE=1` в сеансе пользователя тоже запрещает сеть («Включена работа
без сети»). Прокси берётся из окружения сеанса (`https_proxy`/`HTTPS_PROXY`, `no_proxy`).

`corp_base` принимает только `https://` без логина, пароля, `?`, `#`, `%` и `\` в адресе.
Хост — только ASCII или punycode и совпадает точно, без поддоменов. Порт закреплён:
`https://mirror.example.local:8443` разрешает только `mirror.example.local:8443`.
Для файла строится `{corp_base}/{id}/{revision}/{path}`. Если зеркало не ответило,
загрузчик пробует `huggingface.co`, затем `github.com`; редирект с зеркала разрешён
только на тот же host:port. Некорректный `corp_base` не используется, в журнал
пишется предупреждение без адреса. Режима «только corp» и ключа `corp_only` в v0.1
нет: он запланирован на M10. `ca_bundle` заменяет системный набор CA **для всех**
хостов загрузки; если нужны публичные источники, добавьте в файл и их CA.

### Ключи из PRD, которые в v0.1 **не действуют**

Код v0.1 их не читает. Если записать их в файл, строки в интерфейсе ничего не изменят.

| Ключ | Назначение по PRD F14.3 / F15 | Когда |
|---|---|---|
| `catalog_url`, `catalog_pubkey` | корпоративный каталог со своей подписью | v1.0 (M10) |
| `updates_url` | корпоративный источник обновлений утилиты | v0.2 (M7) / v1.0 |

| `mic_volume_on_start` | поднимать громкость микрофона при запуске | v1.0 |

### Примеры

**Закрытый контур** — ни одного сетевого обращения, модели только из папки:

```ini
# /etc/astra-voice/policy.conf — закрытый контур
[astra-voice]
profile = secure
offline = true
# Тумблеры проверок — выключены и заблокированы
check_app_updates = false
check_model_updates = false
```

**Модель без сети в v0.1** — доставляется папкой (раздел 4):

```ini
[astra-voice]
offline = true
locked = check_app_updates, check_model_updates
```

**Сетевое зеркало весов в v0.1:**

```ini
[astra-voice]
corp_base = https://mirror.example.local/astra-voice
```

Для зеркала нужен тот же набор файлов и контрольных сумм, что во встроенном каталоге.
Публичные источники остаются запасными; `offline=true` запретит и это зеркало.

**Своя клавиша для парка** (например, если `Ctrl+Space` занят переключением раскладки):

```ini
[astra-voice]
hotkey = Ctrl+Alt+D
hotkey_mode = ptt
```

**Клавиша режима «Команда помощнику» — не действует до v1.0:**

```ini
# command_hotkey = ctrl+shift+space     ; или super, или off
```

Готовый пример `/usr/share/doc/astra-voice/examples/policy.conf` запланирован на v1.0 (M10);
в v0.1 его в пакете нет.

Для парка с Astra Cowork PRD (F14.3) рекомендует в `profile=secure` включить ключи политики **Cowork**:
«голос — только локальные умения» и «подтверждать необратимые действия для голосовых команд».
Эти ключи относятся к Cowork, а не к `policy.conf` Astra Voice. Реализуются вместе с режимом
«Команда помощнику» (v1.0).

## 6. Автозапуск

**В v0.1 штатного автозапуска нет.** Тумблер «Автозапуск» в «Общих» и на шаге 5 мастера сохраняет
значение, но ярлык в `~/.config/autostart/` не создаёт. Штатный автозапуск запланирован на M9 (v0.2):
программа сама будет вести `~/.config/autostart/astra-voice.desktop` с
`Exec=/usr/bin/astra-voice --hidden`.

Сейчас автозапуск делается ярлыком пользователя:

```ini
# ~/.config/autostart/astra-voice.desktop
[Desktop Entry]
Type=Application
Name=Astra Voice
Exec=/usr/bin/astra-voice --hidden
Icon=astravoice
Terminal=false
X-KDE-autostart-after=panel
```

`--hidden` запускает программу без окна, только со значком в трее. Второй запуск не создаёт копию, а
показывает окно уже работающей (`astra-voice --show`).

Замечания:
- **Для всего парка** ярлык можно положить в `/etc/xdg/autostart/`. **[уточнить]** Для KDE это
  стандартный путь, но во Fly не проверялось. План M9 отдельно предупреждает о риске, что автозапуск
  во Fly не стартует (фазы `X-KDE-autostart-phase`).
- Когда в M9 появится штатный автозапуск, ручной ярлык нужно убрать, иначе будет два запуска.
  Повторный запуск не страшен (он просто покажет окно), но это лишнее.
- На машине заказчика понадобилась обёртка с задержкой и запуском `pipewire-pulse.socket`, потому что
  сценарий входа гасил звуковой сокет. **[уточнить]** Нужна ли такая обёртка на стоковой ALSE, не
  проверено. В общем случае достаточно `Exec` выше.

## 7. Обновления

**В v0.1 обновление — только вручную:** скачать новую версию, проверить (раздел 2), поставить
тем же `apt install ./astra-voice_<новая>.deb` (раздел 3, с учётом needrestart).

- Настройки и модели пользователей при обновлении не трогаются.
- Уже запущенную у пользователя программу нужно перезапустить. Если старая программа встретит новый
  фоновый процесс, она сама скажет «Программа обновлена — перезапустите её».
- Откат: `sudo apt install ./astra-voice_<предыдущая>.deb` (apt попросит подтвердить понижение
  версии).

План дальше:
- **v0.2 (M7–M8), трек A:** проверка обновлений по тумблеру (не чаще раза в сутки) и установка из
  интерфейса. Установка идёт через один polkit-запрос (`auth_admin`, пароль администратора) к
  root-помощнику. Помощник повторно проверяет подпись и ставит пакет через `apt-get`. Служебный каталог
  `/var/lib/astra-voice/staging` используется именно им.
- **Трек B** — «Скачать пакет для администратора»: при включённой ЗПС, без прав администратора или
  по политике `updates=admin`. Пакет, суммы, подпись и эта инструкция складываются в папку, ставит
  администратор. Определение трека запланировано на v0.2, полный интерфейс — на v1.0 (M10).
  По плану M8 root-помощник сам читает `/etc/digsig/digsig_initramfs.conf` и `policy.conf` и при
  включённой ЗПС или `updates=admin` отказывается ставить пакет: обновление в таком контуре — только
  руками администратора.
- Тихой автоустановки нет и не будет ни в одном профиле.

## 8. Удаление

```sh
sudo apt remove astra-voice     # программа
sudo apt purge  astra-voice     # программа и системные файлы пакета
```

Что остаётся после `purge`:

| Что | Где | Кто удаляет |
|---|---|---|
| Файл политики | `/etc/astra-voice/policy.conf` | администратор (файл не принадлежит пакету) |
| Служебный каталог | `/var/lib/astra-voice/staging` (root) | **известная недоработка до M8.** 23.09 после `purge` у заказчика каталог остался; ИБ T2 (26.09, У86) считает, что пустой каталог dpkg удаляет сам. Исправление — `postrm purge` в M8 (T-114). Проверка и ручная очистка: `ls -la /var/lib/astra-voice && sudo rm -rf /var/lib/astra-voice` |
| Ярлык автозапуска, если его создавали | `~/.config/autostart/astra-voice.desktop` или `/etc/xdg/autostart/astra-voice.desktop` | администратор или пользователь |
| **Данные пользователя** | см. ниже | пользователь; пакет их не трогает |

Данные пользователя, в каждом домашнем каталоге (все каталоги 0700):

| Каталог | Что в нём |
|---|---|
| `~/.config/astra-voice/` | `settings.json` (0600) |
| `~/.local/share/astra-voice/` | `models/` (модели, основной объём), `logs/` (журнал), `measurements.json` (замеры скорости и памяти моделей) |
| `~/.local/state/astra-voice/` | `stats.json` (статистика без текста), `catalog-state.json` (защита каталога от отката, снимок отозванных версий) |
| `~/.cache/astra-voice/` | служебный конфиг клиента PulseAudio (запрет автозапуска звукового сервера) |
| `$XDG_RUNTIME_DIR/astra-voice/` | блокировка и локальный сокет, исчезают при выходе из сеанса |

Полная очистка у пользователя (после выхода из программы):

```sh
rm -rf ~/.config/astra-voice ~/.local/share/astra-voice ~/.local/state/astra-voice ~/.cache/astra-voice
```

## 9. Диагностика

### Журнал

`~/.local/share/astra-voice/logs/astra-voice.log`: ротация 5 файлов по 1 МБ (`astra-voice.log.1` … `.4`).
Ошибки уровня WARNING и выше дублируются в stderr.

Журнал лежит рядом с моделями (`core/paths.py`, `log_dir()`). В `~/.local/state/astra-voice/`
хранится состояние (статистика, состояние каталога моделей), а не журнал.

Что искать:

```sh
LOG=~/.local/share/astra-voice/logs/astra-voice.log
grep 'старт:' "$LOG" | tail -3        # версия, сеанс (KDE/FLY/OTHER), состояние политики
grep -i 'политик' "$LOG" | tail        # почему политика не разобрана
grep 'Запрос к' "$LOG" | tail          # к каким хостам шли запросы (только имя хоста)
grep -E 'WARNING|ERROR' "$LOG" | tail -20
```

В каждой строке есть вид сеанса `[KDE]`, `[FLY]` или `[OTHER]`.

**Чего в журнале нет:** распознанного текста, звука, содержимого буфера обмена. Фильтр журнала
вырезает поля `text`, `recognized_text` и `transcript` из любой записи. Итог вставки пишется без
самого текста (по нему видно, почему текст остался в буфере). Адреса URL в сообщениях об ошибках
сети не выводятся, только хост.

### Полезные команды

```sh
astra-voice --version          # версия
astra-voice --stats            # статистика скорости распознавания
astra-voice --debug            # подробный журнал (уровень DEBUG) и раздел «Отладка» в окне
ASTRA_VOICE_DEBUG=1 astra-voice   # то же через окружение
ASTRA_VOICE_RENDER=gl astra-voice # аппаратная отрисовка окна (по умолчанию программная: ≈ 100 МБ ОЗУ вместо ≈ 165 МБ)
```

### Раздел «Отладка»

Раздел скрыт. Он появляется при запуске с `--debug` или `ASTRA_VOICE_DEBUG=1`, а также открывается
кнопкой «подробности» на индикаторе при ошибке. В v0.1 в нём одна кнопка — «Перезапустить звуковую
службу» (помогает, если микрофон пропал после входа в систему). Полная «Отладка» появится в M11 (v1.0):
уровень журнала, «Открыть лог» и «Собрать диагностику» (архив без звука, текста и домашних путей).

### Частые случаи

| Симптом | Причина и что делать |
|---|---|
| Скачивание модели: «Задано администратором: работа без сети» | Так задумано: `offline`/`profile` в политике. Ставьте модель из папки |
| «Не удалось проверить правила администратора: работа без сети» | `policy.conf` невалиден или не читается пользователем. Проверьте журнал (`grep политик`) и права 0644 |
| «Нет доступа к huggingface.co. Можно установить модель из папки.» | Хост недоступен, прокси или межсетевой экран. См. раздел 10 и путь «из папки» |
| Предупреждение «комбинация занята» | Клавишу держит другая программа (Handy, переключатель раскладки). Выберите другую или задайте `hotkey` политикой |
| «Окно не приняло текст — он в буфере» | Окно-получатель не забрало текст за 1,5 с. Фраза осталась в буфере обмена, её можно вставить вручную |
| После `apt install` синий диалог needrestart | Раздел 3: «Отмена», затем конфиг `/etc/needrestart/conf.d/` |
| «Программа обновлена — перезапустите её» | Пакет обновлён при запущенной старой версии. Перезапустите программу |

## 10. Безопасность — для службы ИБ

Подробно:
- `/usr/share/doc/astra-voice/PRIVACY.md` (в репозитории `docs/PRIVACY.md`) — что уходит в сеть и что хранится;
- `/usr/share/doc/astra-voice/SECURITY.md` (`docs/SECURITY.md`) — ключи подписи, ротация, отзыв, канал
  сообщений об уязвимостях и сроки реакции (ФСТЭК № 239 п. 29.3.3);
- `docs/threat-model.md` в репозитории — модель угроз (границы доверия B1–B19, угрозы, принятые риски).
  В пакет не входит.

### Что программа делает в сети — по коду v0.1

| Действие | Когда | Куда | Реализовано в v0.1 |
|---|---|---|---|
| Скачивание файлов модели | **только** по кнопке пользователя (мастер, раздел «Модели», «Переустановить») | при `corp_base` сначала `mirror.example.local`, затем публичные `huggingface.co`/`hf.co` и `github.com`/`objects.githubusercontent.com` | **да** |
| Проверка обновлений моделей и каталога | по тумблеру, не чаще раза в сутки | GitHub / HF / `catalog_url` | нет — v0.2 (M7) |
| Проверка обновлений утилиты | по тумблеру, не чаще раза в сутки, или по кнопке | `api.github.com` / `updates_url` | нет — v0.2 (M7) |
| Скачивание пакета обновления | по согласию в окне обновления | GitHub Release / корпоративный адрес | нет — v0.2 (M8) |

Свойства сетевого клиента (`src/astra_voice/net/`):
- только HTTPS; публичные адреса — порт 443, у `corp_base` может быть закреплён другой порт; адреса с логином и паролем отвергаются;
- хост проверяется по белому списку на каждом шаге, включая до 5 перенаправлений: `github.com`,
  `api.github.com`, `objects.githubusercontent.com`, `huggingface.co` и `hf.co` с поддоменами;
- проверка TLS не отключается. Существующий файл `ca_bundle` заменяет системный набор CA
  для всех хостов; если файл не задан, берётся системный набор
  (`/etc/ssl/certs/ca-certificates.crt`), затем `SSL_CERT_FILE`;
- прокси — из окружения (`https_proxy`, `no_proxy`). Cookies не сохраняются, токенов и учётных
  записей нет. User-Agent: `astra-voice/<версия> (+https://github.com/ArrivaRUS/astra-voice)`;
- каждый файл модели сверяется по sha256 из **подписанного** каталога (`catalog.json` +
  `catalog.json.sig`, проверка `gpgv` с закреплённым отпечатком). Встроенный каталог
  подписан подключом `S1` мастера (раздел 2).

Не передаются никогда: звук, распознанный текст, содержимое буфера обмена, имена окон. Телеметрии,
отчётов о падениях и счётчиков запусков нет.

Для межсетевого экрана: если модели скачиваются из интернета, нужен исходящий HTTPS к
`huggingface.co` и `*.hf.co`. Если используется только путь «из папки», сеть не нужна вовсе.
Проверка: `sudo tcpdump -n -i any 'tcp port 443'` во время диктовки — соединений быть не должно.

### Что важно знать администратору (границы доверия)

- **Всё работает от имени пользователя.** В v0.1 у пакета нет привилегированных частей: нет
  root-помощника, polkit-действий, `setuid` и собственных maintainer-скриптов. Root нужен только
  для `apt install`. Root-помощник обновлений (polkit `auth_admin`, без кеширования пароля) появится
  в v0.2 (M8).
- **Сетевых портов программа не открывает.** Для единственного экземпляра используется локальный
  сокет в `$XDG_RUNTIME_DIR/astra-voice/` (каталог 0700, доступ только владельцу). Для связи с
  фоновым процессом распознавания — унаследованный дескриптор.
- **Запуск изолирован от окружения:** `python3 -I` не читает `PYTHONPATH` и пользовательские
  `site-packages`. Код в `/usr/lib/astra-voice` принадлежит root.
- **X11 не изолирует приложения друг от друга** (принятый риск П1). Любая программа того же
  пользователя видит нажатия клавиш и может прочитать буфер обмена. Для вставки фраза ненадолго
  кладётся в буфер обмена, до 1,5 с. Если окно её не забрало, фраза остаётся в буфере до следующего
  копирования (принятый риск П12). Фраза помечена как секретная: история Klipper её не сохраняет.
  **[уточнить]** Для менеджера буфера Fly это на живой системе не проверено.
- **Файлы пользователя** (`~/.config`, `~/.local`, модели) защищены правами 0700/0600, но программа
  другого процесса того же пользователя может их менять (граница B2). Модели проверяются по sha256
  только при установке.
- **Политика** доверяется как файл администратора. Пока код не проверяет владельца и права
  (раздел 5), держите файл `root:root 0644`.
- **Звук на диск не пишется**, распознанный текст — тоже. Данные в ОЗУ могут попасть в swap
  (принятый риск П4); шифрование swap — зона администратора ОС.
- **ЗПС (замкнутая программная среда).** При `DIGSIG_ELF_MODE=1` исполняемые объекты обязаны нести
  ГОСТ-подпись. Три собственных `.so` (onnxruntime, `/usr/lib/astra-voice/vendor/onnxruntime/capi/`)
  на сборке не подписаны. Их sha256 перечислены в `sbom.cdx.json`; подписывать их на месте —
  средствами организации (`bsign-integrator`, ключ организации). Подпись на сборке и приёмка на ВМ
  с ЗПС запланированы на v1.1. Если поверх ЗПС включена блокировка интерпретаторов, программа не работает:
  она написана на Python и запускается через `/usr/bin/python3`. **[уточнить]** В v0.1 работа с
  включённой ЗПС не проверялась.
- **Сообщения об уязвимостях:** GitHub Security Advisories репозитория `ArrivaRUS/astra-voice`,
  сроки — `SECURITY.md` §7. Резервный канал: `alekovalev@astralinux.ru`.

## Открытые вопросы (уточнить)

1. **Проверка владельца и прав `policy.conf`** в коде v0.1 отсутствует (план M7).
2. **`profile=secure` в v0.1** только запрещает сеть. `domestic_only`, `updates=admin` и прочие
   следствия из PRD F14.3 не реализованы.
3. **Установка из папки** — по коду только рекомендуемая модель, архивы не поддерживаются, сценарий
   общего ресурса на живой машине не прогонялся.
4. **Автозапуск:** тумблер ничего не создаёт до M9. `/etc/xdg/autostart/` для парка во Fly не
   проверялся. Нужна ли обёртка с задержкой на стоковой ALSE — неизвестно.
5. **`/var/lib/astra-voice/staging` после `purge`:** наблюдение 23.09 (каталог остался) расходится
   с анализом T2 (пустой dpkg удаляет сам). Исправление — M8 (T-114).
6. **Системные требования:** минимум ОЗУ машины и набор инструкций процессора не зафиксированы.
7. **Разовый `NEEDRESTART_MODE=l`** — по коду needrestart 3.6 работает, на живой машине не проверен.
8. **ЗПС в v0.1** не проверялась; поведение менеджера буфера Fly с пометкой «секретно» не проверено.
9. **`model_id` через политику** не проверялся.
