## 1. Что это и системные требования

Astra Voice — голосовой ввод. Пользователь зажимает горячую клавишу (по умолчанию `Ctrl+Space`),
говорит фразу, и текст появляется в активном окне. Распознаёт речь модель, которая лежит на диске этой же машины.
Считает процессор. Звук и текст никуда не передаются, сеть для диктовки не нужна.

### Память: сколько нужно по моделям

Окно и индикаторы занимают ≈ 100 МБ в покое (программная отрисовка, замер M1). Модель работает
в отдельном фоновом процессе. Его объём — поле `min_ram_mb` встроенного каталога
(`/usr/share/astra-voice/data/catalog.json`). У всех моделей это **оценка**
(`ram_estimated: true`), а не замер на вашей машине.

| Модель (id в каталоге) | Язык | На диске | ОЗУ при работе | Отечественная |
|---|---|---|---|---|
| **GigaAM v3 RNN-T** (`gigaam-v3-e2e-rnnt-int8`) — рекомендуемая | ru, с пунктуацией | 216 МиБ | 419 МБ | да (Сбер) |
| GigaAM v3 CTC (`gigaam-v3-e2e-ctc-int8`) | ru, с пунктуацией | 214 МиБ | 417 МБ | да |
| GigaAM v3 RNN-T без пунктуации (`gigaam-v3-rnnt-int8`) | ru | 215 МиБ | 418 МБ | да |
| GigaAM v3 CTC без пунктуации (`gigaam-v3-ctc-int8`) | ru | 214 МиБ | 416 МБ | да |
| GigaAM Multilingual CTC (`gigaam-multilingual-ctc-int8`) | ru, en, kk, ky, uz | 214 МиБ | 416 МБ | да |
| GigaAM Multilingual Large CTC (`gigaam-multilingual-large-ctc-int8`) | ru, en, kk, ky, uz | 564 МиБ | 1095 МБ | да |
| T-one (`t-one-fp32`) | ru | 138 МиБ | 267 МБ | да (Т-Банк) |
| Vosk ru (`vosk-ru-int8`) | ru | 69 МиБ | 135 МБ | нет (Alpha Cephei) |
| Vosk small ru (`vosk-small-ru-int8`) | ru | 25 МиБ | 50 МБ | нет |
| Whisper small (`whisper-small-int8`) | многоязычная | 239 МиБ | 461 МБ | нет (OpenAI) |
| Whisper large-v3-turbo (`whisper-large-v3-turbo-int8`) | многоязычная | 1036 МиБ | 2007 МБ | нет |
| NeMo FastConformer ru (`nemo-fastconformer-ru-pc-ctc-int8`) | ru | 125 МиБ | 244 МБ | нет (NVIDIA) |

Как это проверяется в коде:
- при установке модели сравнивается `MemTotal` машины с `min_ram_mb` модели;
- при смене рабочей модели «на ходу» нужно `MemAvailable ≥ min_ram_mb + 200 МБ`. Если памяти меньше,
  программа предлагает «Переключить с паузой».

Для рекомендуемой модели ориентир ≈ 0,5 ГБ ОЗУ на пользователя в сумме (окно плюс фоновый процесс).
Официального минимума ОЗУ для машины в v0.1 нет; рекомендуем оставлять под программу не меньше
`min_ram_mb` выбранной модели плюс ≈ 100 МБ на окно.

| Файл | Что это |

| `Astra_Voice-<версия>-x86_64.AppImage` | версия без прав администратора (раздел 3) |

Подписанные выпуски публикуются в GitHub Releases.

### Откуда взять ключ и как ему поверить

Связка `release.gpg` лежит в GitHub Release отдельным файлом. Та же связка ставится пакетом в
`/usr/share/astra-voice/data/keys/release.gpg`. Доверие к ней держится на **отпечатке мастер-ключа**:

```
5F1F 7718 559F 8F57 FFE1  1780 55BB 1162 F17A 5CB0
(без пробелов: 5F1F7718559F8F57FFE1178055BB1162F17A5CB0)
```

Отпечаток опубликован в `README.md` репозитория и в этом разделе, но **одного GitHub недостаточно**:
тот, кто смог подменить файлы релиза, может подменить и README. Поэтому отпечаток обязательно
сверяется **по второму каналу вне GitHub**:

- заказчик сообщает отпечаток пилотным администраторам письмом или в корпоративном чате до того, как
  они скачают релиз; при сомнении — запрос на резервный адрес из `SECURITY.md` §7
  (`alekovalev@astralinux.ru`);
- на машине, где Astra Voice уже стоит, отпечаток из установленной связки
  `/usr/share/astra-voice/data/keys/release.gpg` тоже должен совпасть.

Не совпало хотя бы в одном месте — не ставить и сообщить по каналу из `SECURITY.md` §7.
Связку, извлечённую из того самого `.deb`, который вы проверяете, для первой проверки использовать
нельзя: подменивший пакет подменил бы и её.

> **Важно.** Мастер: `5F1F 7718 559F 8F57 FFE1  1780 55BB 1162 F17A 5CB0`,
> uid `Astra Voice Release <alekovalev@astralinux.ru>`; создан 26.09.2026 в 17:09 UTC.
> Он создан на рабочей машине заказчика; риск принят для v0.1, преемник M2 будет сгенерирован офлайн до v1.0 (см. `docs/SECURITY.md`).
> Подписывающие подключи `S1` (`7602 A029 F0E3 4CD2 344A  9CDA 657E D046 89FF 4D79`)
> и `S2` (`9053 EE0C 0085 683C E6C7  042E DC2E 5932 25D8 0428`) действуют до 26.09.2027.

### Проверка

Доверяйте только релизу, чей `SHA256SUMS.asc` даёт `VALIDSIG` с отпечатком мастера. Релиз на GitHub
без такой подписи — не наш, даже если он отмечен как последний.

```sh
# Отпечаток мастера, полученный по второму каналу (без пробелов). Он должен совпасть с указанным
# в этом документе; сам документ лежит среди файлов релиза и подменяется вместе с ними, поэтому
# значение берите из второго канала, а не копируйте отсюда.
MASTER=<отпечаток из второго канала>

# 0. В связке ровно один первичный ключ, и это мастер
gpg --show-keys --with-colons ./release.gpg | grep -c '^pub:'
#    → должно быть 1
gpg --show-keys --with-colons ./release.gpg | awk -F: '$1=="pub"{p=1;next} p && $1=="fpr"{print $10; exit}'
#    → должно совпасть с $MASTER

# 1. Подпись файла сумм: ровно одна строка VALIDSIG, её последнее поле — отпечаток мастера
gpgv --status-fd 1 --keyring ./release.gpg SHA256SUMS.asc SHA256SUMS | grep '^\[GNUPG:\] VALIDSIG'
gpgv --status-fd 1 --keyring ./release.gpg SHA256SUMS.asc SHA256SUMS | awk '$2=="VALIDSIG"{print $NF}'
#    → должно совпасть с $MASTER
#    строка «[GNUPG:] REVKEYSIG» в выводе — ключ отозван: пакет НЕ ставить, сообщить по каналу SECURITY.md §7
#    для обновления можно взять установленную связку:
# gpgv --status-fd 1 --keyring /usr/share/astra-voice/data/keys/release.gpg SHA256SUMS.asc SHA256SUMS

# 2. Суммы скачанных файлов. --ignore-missing — если скачаны не все файлы выпуска
#    (например, только .deb или папка, которую подготовила программа, раздел 7)
#    ВАЖНО: в выводе обязательно строка «astra-voice_<версия>_amd64.deb: OK» (или «… .AppImage: OK»);
#    без неё пакет не проверен, даже если команда завершилась успешно.
sha256sum -c --ignore-missing SHA256SUMS
```

Путь к связке указывайте с `./` или абсолютным. Имя без косой черты `gpgv` ищет в `~/.gnupg`.

**Одного кода возврата `gpgv` и строки «Good signature» недостаточно.** `gpgv` доверяет всем первичным
ключам из переданной связки: если в скачанный `release.gpg` добавлен посторонний ключ, подпись им
тоже даст «Good signature», а отпечаток мастера в выводе `--fingerprint` останется на месте. Поэтому
шаг 0 проверяет, что первичный ключ ровно один, а шаг 1 — чья именно подпись (`VALIDSIG`).
Программа проверяет подписи так же: принимает только строку `VALIDSIG`, последнее поле которой —
закреплённый отпечаток, не входящий в список отозванных (`src/astra_voice/security/verify.py`);
связку перед выпуском проверяет `scripts/check_keyring.py`.

**Если дата на машине раньше 26.09.2026 17:10 UTC** (время создания подписывающих ключей), проверка подписи не пройдёт: и у `gpgv`, и в программе, включая встроенный список моделей
(программа сообщит, что подпись подтвердить не удалось). Выставьте верное время (NTP) и повторите.

## 3. Установка

### Перед установкой: needrestart на рабочих станциях

На ALSE 1.8 стоит `needrestart` (3.6). После **любого** `apt install` он может показать синий диалог
«Демоны, использующие устаревшие библиотеки», в котором отмечен `user@<UID>.service`, то есть менеджер
сеанса пользователя. Если нажать «Ok», сеанс перезапустится: машина зависнет, и понадобится холодный
сброс. Так случилось при живой установке 16.09. Это поведение `needrestart`, а не пакета Astra Voice.

Постоянное решение для рабочих станций (применено у заказчика 16.09, с ним `0.1.0~m5.2` и следующие
версии ставятся без диалога):

```sh
sudo tee /etc/needrestart/conf.d/50-astra-desktop.conf >/dev/null <<'EOF'
# Рабочая станция: needrestart ничего не перезапускает сам, только перечисляет.
$nrconf{restart} = 'l';
# Пользовательские сеансы (user@UID.service) не трогать никогда.
$nrconf{blacklist_rc} = [ qr(^user@) ];
EOF
```

- `restart = 'l'` — только список, без вопросов и без перезапусков.
- `blacklist_rc` с `^user@` — сеансы пользователей в список не попадают вовсе. В стоковом конфиге
  3.6 этот список пуст, так что присваивание ничего не затирает.

Если конфиг не положен, а диалог уже появился: `Tab` → **«Отмена»** (`<Cancel>`).

Разовый вариант без конфига, по коду `needrestart` 3.6 (читает переменную `NEEDRESTART_MODE`):
`sudo env NEEDRESTART_MODE=l apt install ./astra-voice_<версия>_amd64.deb`.
В v0.1 на живой машине этот вариант не проверялся; рекомендуем постоянный конфиг выше.

### Установка

```sh
sudo apt install ./astra-voice_<версия>_amd64.deb
```

Ставьте через `apt`, а не `dpkg -i`, чтобы зависимости подтянулись из репозиториев ОС. Сетевой доступ
при этом нужен только самому `apt` к вашим репозиториям, и только если зависимостей не хватает.

В закрытом контуре, без обращения к репозиториям:

```sh
sudo apt-get install --no-download --no-remove ./astra-voice_<версия>_amd64.deb
```

Если apt сообщит о недостающих пакетах, занесите их в контур обычным порядком.

### Проверка после установки

```sh
astra-voice --version                 # версия пакета
dpkg-query -W astra-voice             # то же средствами dpkg
stat -c '%U:%G %a' /var/lib/astra-voice/staging   # root:root 700
```

Запущенную у пользователя старую версию после установки нужно перезапустить (раздел 7).

### Установка без прав администратора: AppImage (с v0.2)

С версии 0.2 в выпуске есть второй файл — `Astra_Voice-<версия>-x86_64.AppImage`. Его запускает сам
пользователь, без `sudo`. При первом запуске программа копирует себя в
`~/.local/share/astra-voice/app/<версия>-<сборка>/`, переключает на эту копию ссылку `app/current`,
регистрирует меню и автозапуск на `app/current/AppRun` и дальше работает только из копии.

Во Fly пункт меню появляется в разделе «Инструменты»; при удалении убирается.

Для передачи через Telegram и другие каналы, которые не сохраняют исполняемые права,
используйте `Astra_Voice-<версия>-x86_64.AppImage.tar.gz`. Внутри находится только этот
AppImage с режимом `0755`; архив входит в `SHA256SUMS` выпуска. Проверьте подпись и
контрольные суммы по инструкции выше, затем распакуйте в отдельный каталог:

```sh
mkdir astra-voice-download
# --same-permissions сохраняет 0755 независимо от umask пользователя.
tar --extract --gzip --same-permissions --file=Astra_Voice-<версия>-x86_64.AppImage.tar.gz --directory=astra-voice-download
cd astra-voice-download
```

При распаковке архиватором проверьте, что он сохранил разрешение на запуск. Для
напрямую скачанного raw AppImage используйте `chmod +x`, как показано ниже.

**Первый запуск — через FUSE** (штатный путь; libfuse в Astra Linux SE 1.8 есть):

```sh
chmod +x Astra_Voice-<версия>-x86_64.AppImage
./Astra_Voice-<версия>-x86_64.AppImage
```

**Если FUSE недоступен**, пользователь запускает файл с личным временным каталогом:

```sh
TMPDIR="$HOME/.cache" ./Astra_Voice-<версия>-x86_64.AppImage --appimage-extract-and-run
```

Образ распаковывается в `~/.cache/appimage_extracted_<…>`, программа устанавливает себя так же, как из
FUSE, и удаляет распаковку. Без флага `--appimage-extract-and-run` сам на распаковку образ не переходит:
при неудачном монтировании он только сообщает об ошибке FUSE.

**Запуск без FUSE с распаковкой в общий `TMPDIR` (`/tmp`) не поддерживается** — это `--appimage-extract-and-run`
или `APPIMAGE_EXTRACT_AND_RUN=1` без `TMPDIR` в домашней папке. Модуль запуска AppImage распаковывает образ
в `/tmp/appimage_extracted_<сумма содержимого>`: имя одно для всех пользователей выпуска, уже существующий
каталог используется без проверки владельца, и файлы, подложенные туда другим пользователем, исполняются
раньше любых проверок программы (`docs/threat-model.md`, У101; решение заказчика 30.09 — вариант (б)).

- **Не от root.** Файл AppImage и установленную копию не запускайте через `sudo` и от root — ни для
  установки, ни для проверки версии: эта версия работает только под учётной записью пользователя.
- Путь к файлу и к домашней папке не должен содержать «:» — программа откажется запускаться.
- Запретить эту версию на компьютере можно ключом `appimage = deny` в `/etc/astra-voice/policy.conf`
  (формат — раздел 5): при запрете и файл, и уже установленная копия ничего не устанавливают и передают
  запуск пакету `.deb`, если он стоит, иначе завершаются с сообщением. Запрет совещательный: копия в домашней папке принадлежит
  пользователю, и средством защиты это не является.

## 4. Первый запуск пользователя

Программу запускают из меню («Astra Voice», категория «Утилиты») или командой `astra-voice`.
При первом запуске открывается мастер из пяти шагов. Его можно закрыть и вернуться позже.

1. **Язык и сеть.** Язык интерфейса и два тумблера: «Проверять обновления утилиты» и «Проверять
   обновления моделей». С 0.1.5 положение по умолчанию зависит от способа установки: в пакете
   `.deb` оба **выключены**, в AppImage оба **включены** (раздел 5, ключи `check_app_updates`
   и `check_model_updates`). С 0.1.1 первый тумблер включает автоматическую проверку новой версии
   программы (раз в сутки; `api.github.com`, при новой версии — ещё `github.com`, раздел 7); второй
   с 1.0 включает суточную проверку активной модели и подписанного каталога (раздел 5). Автоматическая проверка
   не запускается, пока пользователь не ушёл с этого шага. Если политика задала эти ключи
   или запретила сеть, строки заблокированы с подписью «Задано администратором».
2. **Модель.** Два пути:
   - **Скачать.** Пользователь отмечает модели (по умолчанию предлагается GigaAM v3 RNN-T) и нажимает
     «Продолжить». Файлы идут с `huggingface.co` по HTTPS. Каждый файл сверяется по sha256 из
     подписанного встроенного каталога, после установки модель проходит пробное распознавание.
     Окно можно закрыть: загрузка продолжится, по готовности придёт уведомление. При запрете сети
     политикой кнопка скачивания отвечает «Задано администратором: работа без сети».
   - **Установить из папки** (кнопка «Установить из файла или папки…»). Сети не нужно;
     подходит для закрытого контура (см. ниже).
3. **Горячая клавиша.** По умолчанию `Ctrl+Space`, режим «удерживать, пока говорите» (`ptt`) или
   «нажать в начале и в конце» (`toggle`). Если комбинацию держит другая программа (например, Handy),
   мастер предупредит и предложит свободную (`Ctrl+Shift+Space`, `Ctrl+Alt+D`).
4. **Микрофон.** Проверка уровня работает без модели. Тестовая диктовка появляется, когда модель
   готова, и ничего не вставляет в другие окна.
5. **Готово.** Программа сворачивается в системный трей (значок слева от часов). Если автозапуска
   ещё нет ни у пользователя, ни в системе и политика его не блокирует, мастер создаёт запись
   автозапуска (раздел 6). Отдельного переключателя в мастере нет — он в «Общих».

### Корпоративное зеркало и каталог моделей

`corp_base` уже задаёт сетевое зеркало весов из встроенного подписанного каталога.
С 1.0 `catalog_url` задаёт HTTPS-адрес каталога с подписью ключом выпусков,
тем же, что у встроенного каталога (раздел 5). Своя корпоративная связка
`catalog_pubkey` запланирована на v1.2 (M10-корп). Для доставки модели без сети
используйте установку из папки:

1. На эталонной машине скачайте модель штатно. Она окажется в
   `~/.local/share/astra-voice/models/<id>/<ревизия>/`. Например,
   `models/gigaam-v3-e2e-rnnt-int8/322c3b29492673eb7d0b434bfa9dfb8653e34d02/`.
2. Скопируйте **содержимое каталога ревизии** (сам каталог `<ревизия>/`, без соседнего
   `<ревизия>.json` и `current.json`) на общий ресурс, доступный пользователям на чтение.
3. Пользователь в мастере (шаг 2) или в разделе «Модели» нажимает «Установить из файла или папки…»
   и указывает этот каталог.

Что проверяет программа:
- в папке **ровно** файлы из каталога: лишний файл, подкаталог или символическая ссылка — отказ
  «лишние файлы»;
- каждый файл сверяется по sha256 при копировании;
- после установки идёт пробное распознавание;
- поддерживается только **папка**: архив отвергается с просьбой выбрать папку, хотя кнопка называется
  «из файла или папки».

По коду 0.1.0 (`ui/model_downloads.py`, `installFromPath`) из папки ставится только
**рекомендуемая модель** (GigaAM v3 RNN-T): содержимое папки сверяется с её записью в каталоге.
Другую модель каталога так поставить нельзя — её скачивают по сети или через `corp_base`.
Сценарий с общим ресурсом в v0.1 на живой машине не проверялся — рекомендуем один раз пройти его
на пилотной машине до раскатки.

## 5. Политика парка: `/etc/astra-voice/policy.conf`

### Как файл читается (по коду `src/astra_voice/core/policy.py`)

- Файл читается **один раз при старте** программы пользователя. После правки пользователю нужно
  перезапустить программу: «Выход» в меню трея и запуск заново, либо перелогиниться.
- Формат INI (Python `configparser`, без интерполяции). Ключи пишутся в секции **`[astra-voice]`**.
  Если секции нет, берутся ключи из `[DEFAULT]`. Имена ключей к регистру не чувствительны.
- **Комментарии — только отдельной строкой**, начиная с `#` или `;`. Комментарий в конце строки
  становится частью значения: `offline = true  # ...` — уже не `true`.
- Повтор ключа в секции делает файл невалидным.
- Логические значения: `1 / true / yes / on` и `0 / false / no / off`, регистр не важен.
- **Каждый заданный ключ блокирует** свою строку в настройках, с подписью «Задано администратором».
  Пользователь её не меняет, а в его `settings.json` значение политики не записывается.
- Ключ `locked = ключ1, ключ2` блокирует строки, **не задавая** значения: остаётся значение по
  умолчанию или то, что выбрал пользователь. Исключение — `check_app_updates` и
  `check_model_updates` (с 0.1.5): у них `locked` без значения закрепляет то, что уже записано
  в `settings.json` пользователя, а если записи нет (новая установка) — **выключено** на обоих
  способах установки, хотя в AppImage значение по умолчанию — «включено». Одноразовая миграция
  AppImage при переходе на 0.1.5 заблокированные строки тоже не меняет.

Три состояния файла пишутся в журнал строкой `старт: версия=… сеанс=… политика=<состояние>`:

| Состояние | Когда | Что делает программа |
|---|---|---|
| `absent` | файла нет | значения по умолчанию, ничего не заблокировано; сеть — по кнопкам пользователя, а в AppImage ещё автоматическая проверка обновлений (тумблер по умолчанию включён) |
| `ok` | файл разобран | значения и блокировки применены |
| `invalid` | ошибка синтаксиса, нет секции и ключей, дубликат ключа, негодное логическое значение, файл не читается пользователем (например, права 0600) | **сеть запрещена** («Не удалось проверить правила администратора: работа без сети»), остальные значения политики **не применяются и не блокируются**; только тумблеры проверок обновлений показаны выключенными и заблокированными (значения в `settings.json` не меняются) |

Права: `root:root`, **0644**. Файл должен читаться пользователем, потому что программа работает от его
имени. Проверка «владелец root и нет записи для группы и остальных» по коду v0.1
(`core/policy.py`) **не выполняется**: она запланирована в M7 (`docs/plans.md`, У16/У37). Пока права — ваша
ответственность.

```sh
sudo install -d -m 0755 -o root -g root /etc/astra-voice
sudo install -m 0644 -o root -g root policy.conf /etc/astra-voice/policy.conf
```

### Ключи, которые действуют

| Ключ | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `profile` | строка | не задан | Пусто или `personal` — сеть по кнопкам пользователя. **Любое другое значение** (`secure`, `offline` и т. п.) запрещает сеть. В v0.1 `profile=secure` делает **только** это; остальные следствия из PRD (`updates=admin`, `domestic_only=true`) пока не реализованы |
| `offline` | логический | `false` | `true` — сеть запрещена полностью: скачивание моделей, автоматическая и ручная проверка обновлений. У пользователя подпись «Задано администратором: работа без сети», переключатель «Офлайн-режим» в «Сеть и обновления» заблокирован. **Непонятное значение тоже означает офлайн** (в журнале предупреждение, остальная политика применяется). `false` ничего не блокирует — даже если `offline` указан в `locked`: пользователь может сам включить офлайн-режим. `locked = offline` без значения ключа блокирует переключатель «Офлайн-режим» в том положении, которое выбрал пользователь |
| `ca_bundle` | путь | не задан | Файл CA для HTTPS при скачивании моделей, проверке и скачивании обновлений программы. Если файла нет, берётся `/etc/ssl/certs/ca-certificates.crt`, затем `SSL_CERT_FILE`. Проверка TLS не отключается никогда |
| `corp_base` | URL | не задан | HTTPS-адрес корпоративного зеркала файлов модели; оно опрашивается первым, затем `huggingface.co` |
| `hotkey` | строка | `Ctrl+Space` | Горячая клавиша диктовки: модификатор (`Ctrl`, `Alt`, `Meta`/`Super`/`Win`) плюс одна клавиша, `Shift` — только дополнительно. Недопустимое значение не применяется (в журнале предупреждение), но строка **всё равно блокируется** со значением по умолчанию |
| `hotkey_mode` | строка | `ptt` | `ptt` — удерживать; `toggle` — нажать в начале и в конце. Иное значение → `ptt` |
| `pill_enabled` | логический | `true` | Плавающая «пилюля»-индикатор у края экрана |
| `check_app_updates` | логический | `.deb`: `false`; AppImage: `true` (с 0.1.5) | Тумблер «Проверять обновления утилиты»: автоматическая проверка новой версии программы не чаще раза в сутки — запрос к `api.github.com`, а если найдена версия новее — ещё загрузка подписанных сведений о ней (`SHA256SUMS`, `SHA256SUMS.asc`, `latest.json`) с `github.com` с перенаправлением на `release-assets.githubusercontent.com`. Без политики: в `.deb` выключена, в AppImage включена; при переходе AppImage с 0.1.4 и старше на 0.1.5 программа один раз включает оба тумблера проверок у пользователя, кроме строк, заданных политикой (значением или в `locked`), и кроме случая, когда политика запрещает сеть. Первая автоматическая проверка — не раньше, чем пользователь уйдёт с шага 1 мастера (раздел 4). `true` — проверка включена у всех, выключить её пользователь не может. `false` — выключена и заблокирована; недоступны и ручная «Проверить сейчас», и пункт «Проверить обновления» в меню значка. Без проверки программа не узнаёт о новой версии, поэтому кнопок скачивания и установки обновления нет (раздел 7). `offline=true` перекрывает `true`; пользовательский «Офлайн-режим» тоже перекрывает проверку, если `offline` не заблокирован политикой |
| `check_model_updates` | логический | `.deb`: `false`; AppImage: `true` (с 0.1.5) | Тумблер «Проверять обновления моделей» (мастер, шаг 1, и «Сеть и обновления»). Значение по умолчанию и миграция — как у `check_app_updates`. С 1.0 включает автоматическую проверку не чаще раза в сутки: refs активной модели на `huggingface.co` и подписанный каталог с `github.com` (подробнее ниже). «Проверить сейчас» и пункт «Проверить обновления» в меню значка тоже запускают проверку моделей; ручная проверка не ждёт суточного кэша 404 каталога. `false` запрещает оба обращения; `offline=true` запрещает всю сеть. Файлы обновления модели скачиваются и устанавливаются только по нажатию «Обновить» |
| `catalog_url` | URL | не задан | С 1.0 — HTTPS-адрес подписанного каталога на разрешённом публичном сервере; подпись берётся по тому же адресу с `.sig`. Пусто — не задано: берётся адрес из настроек пользователя, иначе адрес по умолчанию на `github.com`. Недопустимое значение (не HTTPS, логин/пароль, `?`, `#`, сегмент `..` и другие ошибки адреса) делает весь файл политики `invalid`, как ошибка разбора других ключей. Каталог проверяется той же связкой ключей выпусков, что встроенный; свою связку этот ключ не задаёт |
| `language` | строка | `ru` | Язык интерфейса. В v0.1 интерфейс только на русском; английский и французский — v1.0 (M11) |
| `autostart` | логический | `true` | Блокирует переключатель «Автозапуск при входе в систему» в «Общих»; мастер под политикой тоже ничего не создаёт. Файлы автозапуска программа под политикой не трогает: **при `true` запись не создаётся** (для запуска у всех нужна системная запись), при `false` уже созданные записи не удаляются. Расхождение пишется в журнал (раздел 6) |
| `model_id` | строка | не задан | **Не задавайте.** По коду (`core/model_source.py`) рабочая модель берётся из выбора пользователя в хранилище моделей; `model_id` учитывается, только если рабочая модель не выбрана, и лишь вместе с ревизией. Назначить модель парку этим ключом нельзя |
| `updates` | строка | не задан | Установка обновления AppImage из интерфейса («Установить и перезапустить»). Пусто, `allow`, `yes`, `on`, `true`, `1` — разрешена. `admin` — запрещена («Обновление запрещено администратором»); **любое другое значение**, в том числе `gui` из PRD, — тоже запрет («Обновление запрещено политикой сети»). С 1.0 значение `offline` (без учёта регистра и пробелов по краям) также запрещает автоматические и ручные проверки моделей. На проверку и скачивание обновлений программы ключ не влияет: скачанный AppImage остаётся в `~/.cache/astra-voice/updates/`, и пользователь может запустить его сам. На установку `.deb` не влияет — его программа не ставит. В инструкции к 0.1.0 ключ значился недействующим |
| `appimage` | строка | не задан | `deny` (или `false`, `0`, `no`, `off`) — совещательный запрет версии AppImage (раздел 3), в том числе установки её обновления из интерфейса («Запуск обновления запрещён администратором»). `allow`, логическая истина или ключ не задан — разрешено; непонятное значение — разрешено, в журнале предупреждение |
| `locked` | список | пусто | Дополнительно заблокировать строки без задания значения. Для `check_app_updates` и `check_model_updates` при новой установке закрепляет «выключено» и в AppImage (выше, «Как файл читается») |

Переменная окружения `HF_HUB_OFFLINE=1` в сеансе пользователя тоже запрещает сеть («Включена работа
без сети»). Прокси берётся из окружения сеанса (`https_proxy`/`HTTPS_PROXY`, `no_proxy`).

При `check_model_updates=true` проверка активной модели обращается к
`https://huggingface.co/api/models/<owner>/<name>/refs` методом GET. В пути — только
имя репозитория модели; заголовки — `Accept: application/json`, `User-Agent` с названием,
версией программы и ссылкой на её репозиторий, `Accept-Encoding: identity`,
`Connection: close`; при сохранённом ответе с ETag — ещё `If-None-Match`.
Данные пользователя не передаются. Каталог и подпись по умолчанию загружаются с
`https://github.com/ArrivaRUS/astra-voice/releases/latest/download/catalog-<S>.json`
и того же адреса с `.sig`, с перенаправлением на `release-assets.githubusercontent.com`.
`<S>` — первые 16 знаков SHA256 схемы каталога программы. При выключенном тумблере
или в офлайн-режиме этих запросов нет.

`corp_base` принимает только `https://` без логина, пароля, `?`, `#`, `%` и `\` в адресе.
Хост — только ASCII или punycode и совпадает точно, без поддоменов. Порт закреплён:
`https://mirror.example.local:8443` разрешает только `mirror.example.local:8443`.
Для файла строится `{corp_base}/{id}/{revision}/{path}`. Если зеркало не ответило,
загрузчик берёт файл из источника каталога — у всех 12 моделей это `huggingface.co`
(других источников во встроенном каталоге нет); редирект с зеркала разрешён
только на тот же host:port. Некорректный `corp_base` не используется, в журнал
пишется предупреждение без адреса. Режима «только corp» и ключа `corp_only` в v0.1
нет: он запланирован на M10. `ca_bundle` заменяет системный набор CA **для всех**
хостов загрузки; если нужны публичные источники, добавьте в файл и их CA.

### Ключи из PRD, которые пока **не действуют**

Эти ключи пока не управляют соответствующими функциями.

| Ключ | Назначение по PRD F14.3 / F15 | Когда |
|---|---|---|
| `catalog_pubkey` | своя связка ключей корпоративного каталога | v1.2 (M10-корп) |
| `updates_url` | корпоративный источник обновлений утилиты | не реализован: проверка и скачивание идут только на GitHub (`api.github.com`, `github.com`, `release-assets.githubusercontent.com`) |
| `zps=auto\|on\|off` | признак ЗПС | v0.2 (M8) / v1.0 |
| `domestic_only` | показывать только отечественные модели | v1.0 (M10) |
| `autostart_default` | автозапуск по умолчанию для парка | v1.0 (M10) |
| `insecure_http` | разрешить `http` для внутреннего зеркала | v1.0 (M10) |
| `mic_volume_on_start` | поднимать громкость микрофона при запуске | v1.0 |
| `meeting_*` (6 ключей) | запись встреч | v1.1 |

### Примеры

**Выключить проверки моделей**, сохранив остальные сетевые действия:

```ini
[astra-voice]
check_model_updates = false
locked = check_model_updates
```

Оба обращения — к refs и каталогу — запрещены. Альтернатива — `offline = true`:
он запрещает всю сеть, в том числе проверки программы и скачивание файлов.

**Свой адрес каталога с 1.0:**

```ini
[astra-voice]
catalog_url = https://github.com/example-org/voice-catalog/releases/latest/download/catalog.json
```

По этому адресу должна лежать пара `catalog.json` / `catalog.json.sig`, подписанная
ключом выпусков программы. Для проверок должен быть включён `check_model_updates`,
а сеть разрешена. Адрес в примере условный. Действует список разрешённых публичных
серверов (`net/hosts.py`); один `catalog_url` не разрешает произвольный корпоративный
хост. Своя связка `catalog_pubkey` — план v1.2 (M10-корп).

**Закрытый контур** — ни одного сетевого обращения, модели только из папки:

```ini
# /etc/astra-voice/policy.conf — закрытый контур
[astra-voice]
profile = secure
offline = true
# Тумблеры проверок — выключены и заблокированы
check_app_updates = false
check_model_updates = false
```

**Модель без сети в v0.1** — доставляется папкой (раздел 4):

```ini
[astra-voice]
offline = true
locked = check_app_updates, check_model_updates
```

**Новые версии ставит только администратор, без обращений за обновлениями** — отключены
проверки программы и моделей; модели по кнопке скачиваются как обычно (раздел 7):

```ini
[astra-voice]
check_app_updates = false
check_model_updates = false
locked = check_app_updates, check_model_updates
# Установка AppImage из интерфейса запрещена, даже если проверку потом разрешат
updates = admin
```

Для полного запрета сети задайте `offline = true`. Один `check_app_updates = false`
оставляет проверки моделей при включённом тумблере «Проверять обновления моделей».

**Сетевое зеркало весов в v0.1:**

```ini
[astra-voice]
corp_base = https://mirror.example.local/astra-voice
```

Для зеркала нужен тот же набор файлов и контрольных сумм, что во встроенном каталоге.
Запасной источник — `huggingface.co`; `offline=true` запретит и это зеркало.

**Своя клавиша для парка** (например, если `Ctrl+Space` занят переключением раскладки):

```ini
[astra-voice]
hotkey = Ctrl+Alt+D
hotkey_mode = ptt
```

Готовый пример `/usr/share/doc/astra-voice/examples/policy.conf` запланирован на v1.0 (M10);
в v0.1 его в пакете нет.

Для парка с Astra Cowork PRD (F14.3) рекомендует в `profile=secure` включить ключи политики **Cowork**:
«голос — только локальные умения» и «подтверждать необратимые действия для голосовых команд».
Эти ключи относятся к Cowork, а не к `policy.conf` Astra Voice. Реализуются вместе с режимом
«Команда помощнику» (v1.0).

Клавишу режима «Команда помощнику» политикой задать нельзя — её выбирает пользователь (решение 28.09.2026;
ключ `command_hotkey`, упомянутый в инструкции к 0.1.0, отменён, код 0.1.0 его не читал).
Выключить голосовые команды на всём парке можно на стороне Astra Cowork — настройкой или политикой приёма команд;
Astra Voice тогда получает отказ `policy_disabled` и сообщает пользователю, что приём выключен в Astra Cowork.

## 6. Автозапуск

Пользователь включает и выключает автозапуск переключателем «Автозапуск при входе в систему» в «Общих»
(группа «Запуск»). После входа в систему программа стартует без окна, только со значком в трее
(`--hidden`). Второй запуск не создаёт копию, а показывает окно уже работающей (`astra-voice --show`).

Автозапуск устроен по стандарту XDG autostart: окружение рабочего стола при входе читает файлы
`.desktop` из каталогов автозапуска.

### Какие файлы участвуют

| Запись | Путь | Кто пишет |
|---|---|---|
| Пользовательская | `$XDG_CONFIG_HOME/autostart/astra-voice.desktop`, обычно `~/.config/autostart/astra-voice.desktop` | программа (переключатель, мастер) или сам пользователь |
| Системная | `/etc/xdg/autostart/astra-voice.desktop`; если задан `XDG_CONFIG_DIRS` — первая найденная по его каталогам | только администратор. **Программа сюда никогда не пишет** |

Относительные пути в `XDG_CONFIG_HOME` и `XDG_CONFIG_DIRS` не учитываются: тогда берутся
`~/.config` и `/etc/xdg`.

По правилам XDG пользовательская запись с тем же именем перекрывает системную. Запись с `Hidden=true`
считается выключенной; `Hidden` читается как истина при значениях `true`, `1`, `yes`, `on` в любом
регистре.

**Источник правды — эти файлы, а не `settings.json`.** При старте программа читает, какая запись
действует, и показывает это в переключателе. Сами файлы автозапуска при старте не пишутся.

### Своя запись и чужая

Свою запись программа узнаёт **по строке `X-AstraVoice-Managed=true`**, а не по `Exec`. Файл без этой
строки считается чужим (ручным), даже если команда в нём та же.

Своя запись, которую создаёт программа:

```ini
[Desktop Entry]
Type=Application
Name=Astra Voice
Exec=/usr/bin/astra-voice --hidden
Icon=astravoice
NoDisplay=true
X-KDE-autostart-after=panel
X-AstraVoice-Managed=true
```

Чужая запись — например, ручная обёртка вида `Exec=sh -c "sleep 8; …; exec astra-voice --hidden"`:
- программа её никогда не переписывает и команду из неё не выполняет;
- выключение добавляет строку `Hidden=true` (или заменяет существующую строку `Hidden`), включение
  убирает только эту строку;
- остальное содержимое файла, включая `Exec`, остаётся байт в байт: сохраняются метка BOM в начале,
  концы строк `CRLF` и другие группы файла; права файла (например, 0600) тоже сохраняются.

### Что делает переключатель

| Что лежит сейчас | Переключатель показывает | Включить | Выключить |
|---|---|---|---|
| Записей нет | «выкл» | создаёт свою запись | — |
| Своя запись | «вкл» | — | удаляет её |
| Своя запись с `Hidden=true`, системной нет | «выкл» | убирает `Hidden=true` | — |
| Чужая запись | по строке `Hidden` | убирает `Hidden=true` | ставит `Hidden=true` |
| Только системная | «вкл» | — | создаёт пользовательскую копию с `Hidden=true`, она перекрывает системную |
| Системная и наша копия с `Hidden=true` | «выкл» | удаляет копию, снова действует системная | — |
| Системная сама с `Hidden=true` | «выкл» | создаёт свою пользовательскую запись | — |

Учитывается только `Hidden`. Строки `OnlyShowIn`, `NotShowIn` и `TryExec` программа не читает: если
системная запись ограничена, например, `OnlyShowIn=KDE;`, переключатель во Fly всё равно покажет «вкл».

### Мастер первого запуска

Отдельного переключателя автозапуска в мастере нет. После «Готово» мастер создаёт свою запись, только
если нет ни пользовательской, ни системной записи и политика не блокирует автозапуск. Если запись уже
скрыта (`Hidden=true`) пользователем или администратором, мастер её не трогает, а переключатель
показывает то, что записано в файлах. Если создать запись не удалось, мастер всё равно завершается,
в окне — «Не удалось изменить автозапуск». Дальше автозапуск меняют переключателем в «Общих».

### Если изменить не удалось

Программа читает только обычный файл не больше 64 КиБ. Изменить запись не получится, если:
- пользовательская запись — символьная ссылка (прочитать её можно, изменить нельзя);
- на месте записи каталог или другой не обычный файл либо файл больше 64 КиБ;
- файл пустой или в нём нет группы `[Desktop Entry]`: строку `Hidden` некуда поставить;
- нет прав на каталог `~/.config/autostart/`.

Тогда программа файл не трогает. В окне появляется «Не удалось изменить автозапуск», переключатель
возвращается в прежнее положение. После каждого изменения программа перечитывает записи: если итог не
совпал с нажатым, это тоже ошибка, а не тихий успех. Путь и подробности — только в журнале
`~/.local/share/astra-voice/logs/` (раздел 9).

Если запись при старте не читается (каталог, слишком большой файл), переключатель показывает последнее
сохранённое значение, причина — в журнале.

Если запись изменилась, а `settings.json` сохранить не удалось, в окне «Не удалось сохранить
настройки», переключатель показывает фактическое состояние записи.

Файл записывается целиком во временный файл рядом и подменяется одной операцией: при сбое остаётся
прежний файл. Каталог `~/.config/autostart/`, если его не было, создаётся с правами 0755, своя запись —
с правами 0644.

### Автозапуск для всего парка

Чтобы программа запускалась у всех пользователей машины, положите системную запись:

```ini
# /etc/xdg/autostart/astra-voice.desktop
[Desktop Entry]
Type=Application
Name=Astra Voice
Exec=/usr/bin/astra-voice --hidden
Icon=astravoice
Terminal=false
X-KDE-autostart-after=panel
```

```sh
sudo install -m 0644 -o root -g root astra-voice.desktop /etc/xdg/autostart/astra-voice.desktop
```

Пользователь при этом может выключить автозапуск у себя: программа создаст в его домашнем каталоге
копию с `Hidden=true`. Системный файл она не меняет.

### Политика

Строка `autostart = true|false` в `/etc/astra-voice/policy.conf` (или `autostart` в `locked = …`)
блокирует переключатель с подписью «Задано администратором». Под политикой программа **файлы
автозапуска не трогает** — ни переключатель, ни мастер. Если запись на диске расходится с политикой,
в журнал пишется предупреждение.

- **`autostart = true` запись не создаёт.** Переключатель покажет «вкл», но если записи нет, программа
  при входе не запустится. Чтобы она запускалась у всех, положите системную запись (выше).
- **`autostart = false` уже созданные записи не удаляет.** Переключатель покажет «выкл», но
  пользователь, у которого запись уже есть, продолжит получать автозапуск.

### Как отключить у всех

1. Уберите системную запись, если вы её клали: `sudo rm /etc/xdg/autostart/astra-voice.desktop`.
2. Задайте в политике `autostart = false`: мастер и переключатель перестанут создавать записи.
3. Уберите записи, которые уже есть у пользователей: `~/.config/autostart/astra-voice.desktop` в каждом
   домашнем каталоге. Если это ручной файл пользователя, достаточно добавить в него строку
   `Hidden=true`.

### Что проверено и что нет

- Поведение с файлами проверено автотестами на подставных каталогах.
- **KDE:** запуск после перелогина живьём ещё не проверен — проверит заказчик по чеклисту.
- **Fly: не проверено**, читает ли Fly `~/.config/autostart/` и `/etc/xdg/autostart/`. Пока проверки
  нет, считайте автозапуск во Fly непроверенным.
- На машине заказчика понадобилась обёртка с задержкой и запуском `pipewire-pulse.socket`, потому что
  сценарий входа гасил звуковой сокет. На стоковой ALSE это в v0.1 не проверялось; в общем случае
  достаточно `Exec` выше. Если после входа в систему программа не слышит микрофон, помогает
  «Перезапустить звуковую службу» в разделе «Отладка» (раздел 9).
- `apt remove` и `apt purge` пользовательские записи автозапуска не удаляют (раздел 8).

## 7. Обновления

Обновить программу можно двумя путями: администратор ставит новый пакет или пользователь обновляет
её из интерфейса. Встроенный обновлятор есть с 0.1.1, загрузка файлов выпуска работает с 0.1.2.
Ниже — по коду 0.1.4 (`src/astra_voice/updates/`, `ui/updates_bridge.py`, `app.py`).

### Администратор ставит пакет

Скачать новую версию, проверить (раздел 2), поставить тем же `apt install ./astra-voice_<новая>.deb`
(раздел 3, с учётом needrestart).

- Настройки и модели пользователей при обновлении не трогаются.
- Уже запущенную у пользователя программу нужно перезапустить. Если старая программа встретит новый
  фоновый процесс, она сама скажет «Программа обновлена — перезапустите её».
- Откат: `sudo apt install ./astra-voice_<предыдущая>.deb` (apt попросит подтвердить понижение
  версии).

### Обновление из интерфейса программы

1. **Проверка.** Автоматически не чаще раза в сутки, если включён тумблер «Проверять обновления
   утилиты» (по умолчанию: `.deb` — выключен, AppImage — включён с 0.1.5; раздел 5), или вручную —
   «Проверить сейчас» в верхнем блоке раздела «Сеть и обновления» и пункт «Проверить обновления»
   в меню значка; ручная проверка работает и при выключенном тумблере. В разделе «О программе»
   с 0.1.5 кнопки проверки нет, там показано только её состояние.
   Запрос к `api.github.com`. Если там версия новее установленной, программа скачивает подписанные
   сведения о выпуске (`SHA256SUMS`, `SHA256SUMS.asc`, `latest.json`) с `github.com` (перенаправление
   на `release-assets.githubusercontent.com`) и проверяет подпись закреплённым ключом (раздел 2).
   Только после этого в строке состояния появляется «Доступна версия X», а в разделе «Сеть
   и обновления» — панель с «Что нового».
2. **Скачивание — только по нажатию** «Скачать новую версию» (AppImage) или «Скачать пакет»
   (`.deb` и другие установки). Файл берётся с `github.com` (перенаправление на
   `release-assets.githubusercontent.com`) и кладётся в
   `~/.cache/astra-voice/updates/download-<…>/complete/` вместе с `SHA256SUMS`, `SHA256SUMS.asc`
   и `latest.json`. Размер и sha256 сверяются с подписанным `SHA256SUMS`; при несовпадении файл
   удаляется. «Отмена» и офлайн-режим прерывают загрузку. Скачанные комплекты программа не удаляет.
3. **Установка.**
   - **`.deb`** программа не ставит и не вызывает `apt`, `dpkg`, `pkexec`. Панель показывает
     «Открыть папку» и строку для администратора `sudo apt install ./astra-voice_<версия>_amd64.deb`.
     Файлы проверки лежат в той же папке: проверьте пакет по разделу 2 (`gpgv` с отпечатком
     мастера, `sha256sum -c --ignore-missing SHA256SUMS`) и ставьте как обычно.
   - **AppImage** — отдельной кнопкой «Установить и перезапустить», только после проверки и не во
     время диктовки или работы с моделями. Программа перепроверяет файл и подпись, штатно
     завершается и запускает новый файл (`--appimage-extract-and-run`, распаковка в
     `~/.cache/astra-voice/tmp/`). Новая версия копирует себя в
     `~/.local/share/astra-voice/app/<версия>-<сборка>/` и становится `current`; прежняя остаётся
     `previous`, более старые копии удаляются. Права администратора не нужны, `apt` и репозитории
     не участвуют. Модели и настройки не трогаются. Если новая версия не подтвердила запуск,
     панель покажет это при следующем запуске.
4. Тихой автоустановки нет и не будет ни в одном профиле: скачивание и установка — каждое
   отдельным нажатием пользователя.

Откат AppImage: `~/.local/share/astra-voice/app/previous/AppRun` запускает прежнюю копию (меню
и автозапуск по-прежнему ведут на `current`). Чтобы вернуть прежнюю версию насовсем, запустите
её файл AppImage, проверенный по разделу 2: запуск файла делает его версию текущей. Затем в панели
обновления — «Пропустить эту версию» для более новой.

### Как ограничить обновление из интерфейса

Ключи задаются в `/etc/astra-voice/policy.conf` (раздел 5).

| Цель | Что задать | Что остаётся возможным |
|---|---|---|
| Программа не проверяет, не скачивает и не ставит новые версии программы | `check_app_updates = false` | проверки моделей при включённом тумблере; скачивание моделей; ручное скачивание файлов с GitHub браузером — вне программы |
| Никаких обращений за обновлениями программы и моделей | `check_app_updates = false`, `check_model_updates = false`, `locked = check_app_updates, check_model_updates` | скачивание моделей по кнопке |
| Проверка и скачивание — да, установка AppImage из интерфейса — нет | `updates = admin` | скачанный AppImage пользователь может запустить сам — это обычная самоустановка (раздел 3) |
| Никаких сетевых обращений программы | `offline = true` или `profile = secure` | установка AppImage, уже скачанного и проверенного в этом сеансе программы: офлайн её не запрещает, нужен ещё `updates = admin` |
| Запретить версию AppImage на компьютере | `appimage = deny` | `.deb`; запрет совещательный (раздел 3) |

`locked = check_app_updates` без значения ключа проверку не запрещает, если пользователь уже включил
тумблер: для запрета задайте `check_app_updates = false`. Это важно для AppImage: там тумблер
включён по умолчанию, а при переходе с 0.1.4 и старше на 0.1.5 программа один раз включает его
сама. Значение по умолчанию для `.deb` («выключено») действует, только пока у пользователя нет
сохранённого значения: если он раньше работал с версией AppImage 0.1.5 и новее, его `settings.json`
сохраняет включённые проверки и после перехода на `.deb`. Чтобы гарантировать «выключено», задайте
ключ в политике. Проверки используют политику, прочитанную
при запуске программы. Запреты установки (`updates`, `appimage`) и запрет сети для начатого
скачивания программа перечитывает из файла при каждом действии. Хосты для межсетевого экрана —
раздел 10.

План дальше:
- **M8, трек A:** установка `.deb` из интерфейса через один polkit-запрос (`auth_admin`, пароль
  администратора) к root-помощнику. Помощник повторно проверяет подпись и ставит пакет через
  `apt-get`. Служебный каталог `/var/lib/astra-voice/staging` используется именно им. В 0.1.x
  помощника нет.
- **Трек B** — «Скачать пакет для администратора». Скачивание `.deb` с файлами проверки по кнопке
  уже есть (выше); ЗПС программа пока не определяет, полный интерфейс трека — v1.0 (M10).
  По плану M8 root-помощник сам читает `/etc/digsig/digsig_initramfs.conf` и `policy.conf` и при
  включённой ЗПС или `updates=admin` отказывается ставить пакет: обновление в таком контуре — только
  руками администратора.

## 8. Удаление

```sh
sudo apt remove astra-voice     # программа
sudo apt purge  astra-voice     # программа и системные файлы пакета
```

Что остаётся после `purge`:

| Что | Где | Кто удаляет |
|---|---|---|
| Файл политики | `/etc/astra-voice/policy.conf` | администратор (файл не принадлежит пакету) |
| Служебный каталог | `/var/lib/astra-voice/staging` (root) | **известная недоработка до M8.** 23.09 после `purge` у заказчика каталог остался; ИБ T2 (26.09, У86) считает, что пустой каталог dpkg удаляет сам. Исправление — `postrm purge` в M8 (T-114). Проверка и ручная очистка: `ls -la /var/lib/astra-voice && sudo rm -rf /var/lib/astra-voice` |
| Запись автозапуска | `~/.config/autostart/astra-voice.desktop` в домашнем каталоге — пакет её не удаляет ни при `remove`, ни при `purge`; после удаления программы запись указывает на несуществующий `/usr/bin/astra-voice`. `/etc/xdg/autostart/astra-voice.desktop` — если её клал администратор, пакету она не принадлежит | пользователь; системную — администратор |
| **Данные пользователя** | см. ниже | пользователь; пакет их не трогает |

Данные пользователя, в каждом домашнем каталоге (основные каталоги 0700;
`model-catalog-updates/` создаётся с правами по umask внутри каталога состояния 0700):

| Каталог | Что в нём |
|---|---|
| `~/.config/astra-voice/` | `settings.json` (0600) |
| `~/.local/share/astra-voice/` | `models/` (модели, основной объём), `logs/` (журнал), `measurements.json` (замеры скорости и памяти моделей); у версии AppImage — `app/` (копии программы `current` и `previous`) |
| `~/.local/state/astra-voice/` | `stats.json` (статистика без текста), `catalog-state.json` (состояние действующего каталога — встроенного или принятого: защита от отката, снимок отзывов, `<S>` схемы), `update-cache.json` (общий HTTP-кэш проверок), `update-state.json` (проверка обновлений программы), `model-update-state.json` (срок проверки моделей и уже показанные уведомления); файлы 0600 |
| `~/.local/state/astra-voice/model-catalog-updates/` | `catalog-snapshot.json` (каталог с подписью), `new-models.json` (отметки «Новое»), `http-state.json` (HTTP-кэш, если не передан общий; в штатном запуске — `update-cache.json` выше); файлы 0600, `<S>` — первые 16 знаков SHA256 схемы каталога |
| `~/.cache/astra-voice/` | служебный конфиг клиента PulseAudio (запрет автозапуска звукового сервера); `updates/` — проверенные сведения о выпусках и скачанные по кнопке новые версии программы с файлами проверки (программа их не удаляет); `tmp/` — распаковка новой версии AppImage при установке |
| `$XDG_RUNTIME_DIR/astra-voice/` | блокировка и локальный сокет, исчезают при выходе из сеанса |

Полная очистка у пользователя (после выхода из программы):

```sh
rm -rf ~/.config/astra-voice ~/.local/share/astra-voice ~/.local/state/astra-voice ~/.cache/astra-voice
```

Запись автозапуска удаляется отдельно: `rm -f ~/.config/autostart/astra-voice.desktop`.

### Удаление версии AppImage

Под учётной записью пользователя выполните:

```sh
~/.local/share/astra-voice/app/current/AppRun --uninstall
```

Команда удаляет установленные копии программы, её запись меню и принадлежащие ей
значки. Если установлен пакет `.deb`, собственная запись автозапуска переключается
на системную версию; иначе она удаляется. Чужие записи и значки сохраняются.
Модели, настройки, журналы и статистика остаются в каталогах из таблицы выше.

Если Astra Voice ещё работает, её копия сохраняется до корректного выхода. Завершите
программу через меню трея. Для старой версии без обработки отложенного удаления
может потребоваться повторная команда из исходного файла нового AppImage:

```sh
./Astra_Voice-<версия>-x86_64.AppImage --uninstall
```

При отсутствии FUSE применяются те же правила личного `TMPDIR`, что в разделе 3.
Команда удаления из исходного файла не устанавливает программу заново. Служебный
файл блокировки в `app/` может остаться: он согласует удаление с параллельной
установкой. Если остановка фонового процесса не подтверждена, программа сохраняет
копию, а следующая команда удаления завершается с сообщением об ошибке. Такое
состояние требует проверки перед удалением.

Администратор выполняет операцию от имени владельца профиля:

```sh
runuser -u <пользователь> -- /home/<пользователь>/.local/share/astra-voice/app/current/AppRun --uninstall
```

Запуск AppImage от root запрещён, в том числе для удаления.

## 9. Диагностика

### Журнал

`~/.local/share/astra-voice/logs/astra-voice.log`: ротация 5 файлов по 1 МБ (`astra-voice.log.1` … `.4`).
Ошибки уровня WARNING и выше дублируются в stderr.

Журнал лежит рядом с моделями (`core/paths.py`, `log_dir()`). В `~/.local/state/astra-voice/`
хранится состояние (статистика, состояние каталога моделей), а не журнал.

Что искать:

```sh
LOG=~/.local/share/astra-voice/logs/astra-voice.log
grep 'старт:' "$LOG" | tail -3        # версия, сеанс (KDE/FLY/OTHER), состояние политики
grep -i 'политик' "$LOG" | tail        # почему политика не разобрана
grep 'Запрос к' "$LOG" | tail          # к каким хостам шли запросы (только имя хоста)
grep -E 'WARNING|ERROR' "$LOG" | tail -20
```

В каждой строке есть вид сеанса `[KDE]`, `[FLY]` или `[OTHER]`.

**Чего в журнале нет:** распознанного текста, звука, содержимого буфера обмена. Фильтр журнала
вырезает поля `text`, `recognized_text` и `transcript` из любой записи. Итог вставки пишется без
самого текста (по нему видно, почему текст остался в буфере). Адреса URL в сообщениях об ошибках
сети не выводятся, только хост.

### Полезные команды

```sh
astra-voice --version          # версия
astra-voice --stats            # статистика скорости распознавания
astra-voice --debug            # подробный журнал (уровень DEBUG) и раздел «Отладка» в окне
ASTRA_VOICE_DEBUG=1 astra-voice   # то же через окружение
ASTRA_VOICE_RENDER=gl astra-voice # аппаратная отрисовка окна (по умолчанию программная: ≈ 100 МБ ОЗУ вместо ≈ 165 МБ)
ASTRA_VOICE_AUDIO_BACKEND=simple astra-voice  # запасной способ записи звука, если новый сбоит
```

Команда включает запасной способ записи только для этого запуска. Чтобы он работал всегда, задайте
`ASTRA_VOICE_AUDIO_BACKEND=simple` в окружении сеанса пользователя или в записи автозапуска Astra Voice.

### Раздел «Отладка»

Раздел скрыт. Он появляется при запуске с `--debug` или `ASTRA_VOICE_DEBUG=1`, а также открывается
кнопкой «подробности» на индикаторе при ошибке. В v0.1 в нём одна кнопка — «Перезапустить звуковую
службу» (помогает, если микрофон пропал после входа в систему). Полная «Отладка» появится в M11 (v1.0):
уровень журнала, «Открыть лог» и «Собрать диагностику» (архив без звука, текста и домашних путей).

### Частые случаи

| Симптом | Причина и что делать |
|---|---|
| Скачивание модели: «Задано администратором: работа без сети» | Так задумано: `offline`/`profile` в политике. Ставьте модель из папки |
| «Не удалось проверить правила администратора: работа без сети» | `policy.conf` невалиден или не читается пользователем. Проверьте журнал (`grep политик`) и права 0644 |
| «Нет доступа к huggingface.co. Можно установить модель из папки.» | Хост недоступен, прокси или межсетевой экран. См. раздел 10 и путь «из папки» |
| Предупреждение «комбинация занята» | Клавишу держит другая программа (Handy, переключатель раскладки). Выберите другую или задайте `hotkey` политикой |
| «Окно не приняло текст — он в буфере» | Окно-получатель не забрало текст за 1,5 с. Фраза осталась в буфере обмена, её можно вставить вручную |
| «Не удалось изменить автозапуск» | Запись автозапуска нельзя изменить: символьная ссылка, не обычный файл, файл больше 64 КиБ, пустой или без группы `[Desktop Entry]`, нет прав на `~/.config/autostart/`. Путь — в журнале. Раздел 6 |
| После `apt install` синий диалог needrestart | Раздел 3: «Отмена», затем конфиг `/etc/needrestart/conf.d/` |
| «Программа обновлена — перезапустите её» | Пакет обновлён при запущенной старой версии. Перезапустите программу |
| Подпись не подтверждается ни у пакета, ни у встроенного списка моделей | Часы машины отстают: дата раньше 26.09.2026. Выставьте время (NTP), раздел 2 |

## 10. Безопасность — для службы ИБ

Подробно:
- `/usr/share/doc/astra-voice/PRIVACY.md` (в репозитории `docs/PRIVACY.md`) — что уходит в сеть и что хранится;
- `/usr/share/doc/astra-voice/SECURITY.md` (`docs/SECURITY.md`) — ключи подписи, ротация, отзыв, канал
  сообщений об уязвимостях и сроки реакции (ФСТЭК № 239 п. 29.3.3);
- `docs/threat-model.md` в репозитории — модель угроз (границы доверия B1–B19, угрозы, принятые риски).
  В пакет не входит.

### Что программа делает в сети — по коду v0.1

| Действие | Когда | Куда | Реализовано в v0.1 |
|---|---|---|---|
| Скачивание файлов модели | **только** по действию пользователя: «Продолжить» на шаге модели в мастере; «Скачать выбранное», «Обновить», «Повторить», «Переустановить» в «Моделях» | при `corp_base` сначала `mirror.example.local`, затем `huggingface.co`; перенаправления — только на хосты белого списка `net/hosts.py`: `github.com`, `api.github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`, `huggingface.co` и `hf.co` (поддомены — только у двух последних) | **да** |
| Проверка обновлений моделей и каталога | при включённом тумблере — автоматически не чаще раза в сутки, а также вручную: «Проверить сейчас», пункт «Проверить обновления» в меню значка | GitHub / HF / `catalog_url` | нет — v1.0 (M7-модели); в 0.2 каталог только встроенный |
| Проверка обновлений утилиты | по тумблеру (по умолчанию: `.deb` — выкл., AppImage — вкл. с 0.1.5; не раньше ухода с шага 1 мастера), не чаще раза в сутки, или вручную: «Проверить сейчас», пункт «Проверить обновления» в меню значка | `api.github.com`; если версия новее — ещё `SHA256SUMS`, `SHA256SUMS.asc`, `latest.json` с `github.com` → `release-assets.githubusercontent.com` и проверка подписи | **да**, с 0.1.1; запрос к API ≤ 3 с, ответ кэшируется |
| Скачивание новой версии программы | **только** по нажатию «Скачать новую версию» / «Скачать пакет» после успешной проверки | `github.com` → `release-assets.githubusercontent.com`; корпоративного источника нет | **да**, с 0.1.1 (рабочее с 0.1.2); файл сверяется по sha256 из подписанного `SHA256SUMS` |
| Установка новой версии | AppImage — отдельным нажатием «Установить и перезапустить», в домашнюю папку пользователя; `.deb` программа не ставит | сеть не нужна | **да** для AppImage; установка `.deb` из интерфейса (root-помощник) — M8 |

Свойства сетевого клиента (`src/astra_voice/net/`):
- только HTTPS; публичные адреса — порт 443, у `corp_base` может быть закреплён другой порт; адреса с логином и паролем отвергаются;
- хост проверяется по белому списку на каждом шаге, включая до 5 перенаправлений: `github.com`,
  `api.github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`,
  `huggingface.co` и `hf.co` с поддоменами (`src/astra_voice/net/hosts.py`);
- проверка TLS не отключается. Существующий файл `ca_bundle` заменяет системный набор CA
  для всех хостов; если файл не задан, берётся системный набор
  (`/etc/ssl/certs/ca-certificates.crt`), затем `SSL_CERT_FILE`;
- прокси — из окружения (`https_proxy`, `no_proxy`). Cookies не сохраняются, токенов и учётных
  записей нет. User-Agent: `astra-voice/<версия> (+https://github.com/ArrivaRUS/astra-voice)`;
- каждый файл модели сверяется по sha256 из **подписанного** каталога (`catalog.json` +
  `catalog.json.sig`, проверка `gpgv` с закреплённым отпечатком). Встроенный каталог
  подписан подключом `S1` мастера (раздел 2);
- сведения о новой версии программы и скачанный файл обновления проверяются так же: подпись
  `SHA256SUMS.asc` закреплённым ключом (раздел 2), затем sha256 по `SHA256SUMS`.

Не передаются никогда: звук, распознанный текст, содержимое буфера обмена, имена окон. Телеметрии,
отчётов о падениях и счётчиков запусков нет.

Для межсетевого экрана: если модели скачиваются из интернета, нужен исходящий HTTPS к
`huggingface.co` и `*.hf.co`. Для обновления программы из интерфейса — к `api.github.com`,
`github.com` и `release-assets.githubusercontent.com` (на него GitHub перенаправляет файлы выпуска;
программа допускает его с 0.1.2; в белом списке есть и `objects.githubusercontent.com`). Проверки
моделей с 1.0 требуют `github.com` и `release-assets.githubusercontent.com` для каталога,
`huggingface.co` для refs. Чтобы полностью отключить обращения за обновлениями, задайте
`check_app_updates = false`, `check_model_updates = false` и
`locked = check_app_updates, check_model_updates` (раздел 7); `offline = true` запрещает всю сеть.
Один `check_app_updates = false` оставляет проверки моделей при включённом тумблере.
Версия AppImage без политики с 0.1.5 обращается
к `api.github.com` сама — раз в сутки (тумблер включён по умолчанию). Если используется только путь
«из папки» и проверки обновлений выключены, сеть не нужна вовсе.
Проверка: `sudo tcpdump -n -i any 'tcp port 443'` во время диктовки — соединений быть не должно
(при включённых автоматических проверках — кроме названных хостов GitHub и `huggingface.co`).

### Что важно знать администратору (границы доверия)

- **Всё работает от имени пользователя.** В v0.1 у пакета нет привилегированных частей: нет
  root-помощника, polkit-действий, `setuid` и собственных maintainer-скриптов. Root нужен только
  для `apt install`. Root-помощник обновлений (polkit `auth_admin`, без кеширования пароля)
  запланирован на M8; в 0.1.x его нет.
- **Самообновление AppImage.** Пользователь версии AppImage может сам заменить её новой — без
  администратора и вне управления конфигурацией (apt, репозитории): нажатием «Скачать новую
  версию», затем «Установить и перезапустить». Ставится только сборка с подписью закреплённого
  ключа и совпавшей суммой. Если версию программы на парке определяет администратор, задайте
  `check_app_updates = false` и `updates = admin` (раздел 7). Запрет совещательный: копия в домашней
  папке принадлежит пользователю (граница B2), и другой файл AppImage он может запустить сам.
- **Сетевых портов программа не открывает.** Для единственного экземпляра используется локальный
  сокет в `$XDG_RUNTIME_DIR/astra-voice/` (каталог 0700, доступ только владельцу). Для связи с
  фоновым процессом распознавания — унаследованный дескриптор.
- **Запуск изолирован от окружения:** `python3 -I` не читает `PYTHONPATH` и пользовательские
  `site-packages`. Код в `/usr/lib/astra-voice` принадлежит root.
- **X11 не изолирует приложения друг от друга** (принятый риск П1). Любая программа того же
  пользователя видит нажатия клавиш и может прочитать буфер обмена. Для вставки фраза ненадолго
  кладётся в буфер обмена, до 1,5 с. Если окно её не забрало, фраза остаётся в буфере до следующего
  копирования (принятый риск П12). Фраза помечена как секретная: история Klipper её не сохраняет.
  Для менеджера буфера Fly это в v0.1 на живой системе не проверено.
- **Файлы пользователя** (`~/.config`, `~/.local`, модели) защищены правами 0700/0600, но программа
  другого процесса того же пользователя может их менять (граница B2). Модели проверяются по sha256
  только при установке.
- **Политика** доверяется как файл администратора. Пока код не проверяет владельца и права
  (раздел 5), держите файл `root:root 0644`.
- **Звук на диск не пишется**, распознанный текст — тоже. Данные в ОЗУ могут попасть в swap
  (принятый риск П4); шифрование swap — зона администратора ОС.
- **ЗПС (замкнутая программная среда).** При `DIGSIG_ELF_MODE=1` исполняемые объекты обязаны нести
  ГОСТ-подпись. Три собственных `.so` (onnxruntime, `/usr/lib/astra-voice/vendor/onnxruntime/capi/`)
  на сборке не подписаны. Их sha256 перечислены в `sbom.cdx.json`; подписывать их на месте —
  средствами организации (`bsign-integrator`, ключ организации). Подпись на сборке и приёмка на ВМ
  с ЗПС запланированы на v1.1. Если поверх ЗПС включена блокировка интерпретаторов, программа не работает:
  она написана на Python и запускается через `/usr/bin/python3`. В v0.1 работа с
  включённой ЗПС не проверялась.
- **Сообщения об уязвимостях:** GitHub Security Advisories репозитория `ArrivaRUS/astra-voice`,
  сроки — `SECURITY.md` §7. Резервный канал: `alekovalev@astralinux.ru`.

## Что в v0.1 не проверено

По коду 0.1.0 известно: права `policy.conf` не проверяются (M7, раздел 5); `profile=secure`
в v0.1 только запрещает сеть (раздел 5); из папки ставится только рекомендуемая модель (раздел 4);
`model_id` через политику модель не назначает (раздел 5). На живых машинах в v0.1 не проверено:

1. **Установка из папки с общего ресурса.**
2. **Автозапуск после перелогина.** Во Fly не проверено, читает ли сеанс `~/.config/autostart/` и
   `/etc/xdg/autostart/` и стартует ли программа в трей. В KDE запуск после перелогина проверит заказчик
   по чеклисту. На стоковой ALSE не проверено, нужна ли обёртка с задержкой, как на машине заказчика
   (раздел 6).
3. **`/var/lib/astra-voice/staging` после `purge`:** наблюдение 23.09 (каталог остался) расходится
   с анализом ИБ (пустой каталог dpkg удаляет сам). Исправление — M8 (T-114); проверка и ручная
   очистка — раздел 8.
4. **Системные требования:** минимум ОЗУ машины и минимальный набор инструкций процессора.
5. **Разовый `NEEDRESTART_MODE=l`** — по коду needrestart 3.6 работает, на живой машине не запускался.
6. **ЗПС** и поведение менеджера буфера Fly с пометкой «секретно».

### Панель Fly: аварийная копия (US-8.6, бэкенд шага A)

Перед правкой `~/.fly/theme/current.themerc` бэкенд сохраняет исходные байты в `~/.local/share/astra-voice/backups/fly-theme/current.themerc.<UTC>.<hex>`: каталог `0700`, файл `0600`, не более пяти копий. `fly-tray.json` рядом с каталогом `backups` содержит только факт применения и вставленный фрагмент. Обычный откат удаляет только этот элемент, сохраняя поздние изменения темы.

Полную копию возвращают только вручную при аварии: завершите Astra Voice, сравните выбранную копию с текущим файлом и сохраните поздние изменения отдельно; восстановите нужные байты, сохранив владельца, группу, режим, ACL и метки текущего файла. Если действуют ограничения администратора/МКЦ, восстановление выполняет администратор. Перезапуск панели — отдельное действие в подходящем сеансе после сохранения документов; бэкенд файловой правки его не выполняет; контроллер настройки запускает отдельную ограниченную операцию. Копии и факт применения при удалении программы автоматически не удаляются.


### Приоритет значка Fly: ограничения администратора (US-8.6, шаг B)

Настройка `fly_tray_icon` по умолчанию True. Автоматическое применение возможно один раз за обычный запуск после завершённого мастера и только в простое. Вызов `/usr/bin/fly-wmfunc FLYWM_RESTART` выполняется вне GUI, с таймаутом 5 с, затем до 30 с проверяется новый владелец лотка. До команды снимаются глобальные клавиши; после наблюдения они восстанавливаются штатным механизмом. При неизвестном исходе второго вызова и автоматического отката файла нет.

Для полного запрета действий программы задайте в `/etc/astra-voice/policy.conf`:

```ini
[astra-voice]
fly_tray_icon=false
```

Заданная политика блокирует пользовательский переключатель и автоматические операции. Также программа уважает `TrayBlackList` с `astra-voice` (включая подстрочное совпадение), `NO_TRAY` для этого класса в `~/.fly/apprc`, `UseSystemTray=false`, административного владельца, запрет записи и ограничения ACL/МКЦ. При запрете списки и права не исправляются обходными средствами.

Защита от повторных перезапусков хранится отдельно от происхождения элемента: `~/.local/share/astra-voice/fly-tray-loop.json`, обычный файл своего uid `0600` под защищённой цепочкой каталогов. Четвёртое последовательное исчезновение ранее добавленного токена блокирует автоматику до явного переключения настройки. Признак `restart_in_progress` записывается до команды и снимается только после подтверждённого возврата панели: после неизвестного исхода или прерванного перезапуска автоматика заблокирована и в следующих запусках до явного переключения. Явное выключение доступно после окончания сторожа с обычными проверками и резервом простоя; пропавший токен очищает только сведения о происхождении без перезапуска. Регистрация, `--hidden` и управляемый запуск после обновления не выполняют автоматическую правку. Мастер не получает новых экранов.
