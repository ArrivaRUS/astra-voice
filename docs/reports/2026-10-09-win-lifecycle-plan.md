## Решение по обработке Win

Два независимых архитектурных взгляда (Astra/high и Sol6.1/high) согласны:
исходный Super можно вернуть WM через ReplayKeyboard, если XI2 slave raw видит
раннюю вторую клавишу до продвижения замороженного core-события Super.
Developer уже проверил competitor root grab на отдельном Xvfb. Replay второго
события после SyncKeyboard не является заменой этого механизма.

Выбран отдельный непривилегированный процесс-владелец командного X-соединения.
Он обслуживает короткий Sync deadline независимо от GUI, возвращает ранний
chord системе либо после 300мс принимает удержание и переводит grab в Async.
Другие клавиши за время подтверждённого удержания подавляются согласно F17.
Явный XGrabKeyboard не используется. Обычная текстовая диктовка остаётся на
прежнем backend.

GUI и helper обмениваются heartbeat; expiry/EOF/ошибка протокола отменяют жест,
освобождают захваты и требуют свежего физического нажатия. GUI должен завершить
и убрать зависший helper; helper — освободить X при зависшем GUI. Для watchdog
учитывать сон через CLOCK_BOOTTIME. Raw-коды посторонних клавиш не выходят из
helper и не журналируются. IPC частный, ограниченный и проверяемый; события
старого поколения не допускают команду. Запуск через существующий bootstrap -I.

## Меню KWin — следующий подэтап

Демо-настройка Meta= пока сохранена. Полноценная замена должна владеть только
этим ключом и возвращать его при отключении/выходе/крахе, сохраняя пользовательские
изменения. Рассматривается уникальный no-op D-Bus tuple вместо неоднозначного
empty и журнал для восстановления после сбоя. Выбран взаимный cleanup GUI/broker:
при отказе одного второй восстанавливает lease; при гибели обоих — recovery
на следующем старте. Security подтвердил допустимость этой ограниченной гарантии.
Отдельный автор реализует platform/kwin_command_lease.py; остаются проверка
на реальном KDE и независимый security review. Известное исходное состояние демо есть в
`../../demo/runtime-backup/kwin-meta-before.json`; продукт не должен считать
любое встреченное empty своим прежним изменением.

## Промежуточный контроль реализации (не приёмка)

- Разработчик сообщил isolated Xvfb smoke: ранний Win+L попал независимому
  WM root grab; реальное удержание подтвердилось через 300 мс; остановленный
  helper завершён родителем с потерей регистрации. Независимый тестировщик
  адаптирует прежнюю приёмку к отдельному процессу и реальному времени.
- Security предварительно потребовал отменять удержание при перезахвате
  mapping даже с прежним keycode и привязывать queued press к эпохе допуска
  регистрации. Координатор уточнил гонку эпохи во время blocking grab RPC.
  Эти замечания проверяются до финального ревью.
- Модуль KWin lease сохраняет отсутствие ключа отдельно от пустого значения,
  пишет журнал до изменения и восстанавливает только собственный уникальный
  tuple. Авторские тесты используют временные файлы и подменённые команды;
  фактическая настройка KWin в этом этапе не менялась.
- Независимые окончательные проверки, сборка и настоящие Win/сон/локер
  пока не завершены. Этот раздел не является отчётом о готовом выпуске.

- Дополнительная проверка координатора: реальные `/usr/bin/kreadconfig5` и
  `/usr/bin/kwriteconfig5` на шести временных конфигурациях успешно прошли
  acquire/release с absent, empty, custom, пробелами, ведущим `--`, обратным
  слешем и переводом строки. `qdbus reconfigure` подменён, DISPLAY снят,
  session bus недоступна: проверен CLI roundtrip, не поведение живого KWin.
  Воспроизводимый локальный пробник: `/tmp/astra-voice-kwin-cli-check.py`.

- Независимый tester (Sol 6.1/high) на промежуточном broker snapshot сообщил
  **29 unit + 57 isolated Xvfb PASS**: настоящие WM root grabs для
  Win+L/D/E/Tab (также Ctrl/Shift), peer SIGSTOP/KILL/EOF, отдельный Qt GUI
  SIGSTOP/KILL, same-keycode mapping change, stale confirmed press через эпоху
  блокировки. Финальные digest и повтор после интеграции lease ещё ожидаются.
- На промежуточном этапе ревьюер проверял гонку внешнего `kwriteconfig5`, пережившего владельца:
  поздняя запись после peer restore может оставить значение без журнала.
  До подтверждения и исправления этот механизм не готов к установке.

- P1 с пережившим владельца внешним writer подтверждён reviewer реальным
  `kwriteconfig5` на временном файле и исправлен автором lease: production
  subprocess наследует flock FD, журнал остаётся до завершения writer.
  61 unit PASS, включая subprocess regression; намеренное удаление передачи
  FD возвращает прежний failure. Модуль SHA-256
  `e594c003b6b0863b0f5d12a9981a3e6b03ebf4b736740cefdc22cfbec4b6b8e4`.
  Остановленный навсегда writer удерживает lock: восстановление откажет
  за ограниченное время и сохранит журнал до завершения этого процесса.
- При аварии между записью lease и передачей token новому broker второго
  готового наблюдателя ещё нет: восстановление обеспечивается журналом при
  следующем запуске. Немедленное восстановление любого этапа старта не заявлено.

### Ограничения для передачи на установку

- 600 мс — срок watchdog X11. KConfig операции имеют отдельные command
  timeouts; startup/acquire могут занимать несколько секунд. Возврат меню
  после ошибки конфигурации может потребовать следующего запуска по журналу.
- Для исходного меню ноутбука перед первым production lease нужен отдельный
  возврат известного демо-backup: фактический manual `Meta=` новая lease
  корректно сохраняет как baseline. Не удалять чужое значение без сравнения.
- Пакет не собран и не установлен в этом checkout. Установка, общая сборка
  с mouse UI и реальная проверка Win/локера/сна — в чате «Astra Voice».
  Fly и живая KWin modifier-only реакция пока не приняты.
