# Контракт интерфейса и логики (QML ↔ Python)

> **Зачем этот документ.** Окно Astra Voice нарисовано на QML, а всё остальное —
> настройки, сеть, модели, горячая клавиша — живёт в Python. Общаются они только
> через два объекта-моста, которые Python кладёт в контекст QML. Здесь записано,
> какие свойства и слоты у этих мостов есть **на самом деле**, что происходит при
> записи свойства и какие значения допустимы. Если вы правите QML — смотрите
> разделы 2–4; если правите Python — ещё и разделы 5–7.
>
> **Состояние на 2026-09-21.** Документ сверён с текущим кодом рабочего дерева.
> Раздел 5 честно перечисляет, чего в контракте ещё нет.
>
> Основные источники: `src/astra_voice/ui/bridges.py` и `src/astra_voice/ui/formatting.py`,
> сборка — `src/astra_voice/app.py`,
> исполнение — `src/astra_voice/runtime.py` и `src/astra_voice/core/dictation.py`,
> ожидаемое поведение — `tests/unit/test_bridges.py`, `tests/unit/test_qml_onboarding_static.py`,
> `tests/xvfb/test_onboarding.py`.

## 1. Как это работает в двух словах

* Мостов два: **`SettingsBridge`** (настройки) и **`OnboardingController`** (мастер
  первого запуска). Оба — `QObject` со свойствами `pyqtProperty` и слотами `pyqtSlot`.
* Общая служба **`ModelDownloads`** хранит каталог, выбор и очередь установок для
  обоих мостов. В `app.py` создаётся один экземпляр; отдельно в контекст QML он
  не передаётся. Очередь живёт независимо от окна мастера.
* QML **читает** свойства через биндинги и **пишет** их обычным присваиванием
  (`settingsBridge.pillEnabled = false`). Никаких «применить» и «сохранить» нет:
  каждая принятая запись изменяемой настройки сразу пишет `settings.json`
  (требование F11.7 PRD, сценарий S19).
* Обратно в QML приходят **сигналы `<имя>Changed`** — по ним пересчитываются биндинги.
  У выбора и сведений о текущей модели есть общие сигналы для нескольких
  свойств: `selectionChanged` и `activeModelChanged` (см. таблицы ниже).
* Мосты кладутся в контекст **после** `engine.load()`, а окно должно открываться и
  вовсе без Python (`qmlscene qml/Main.qml`). Поэтому **каждое** обращение к
  контекстному имени в QML обёрнуто проверкой:

  ```qml
  readonly property var bridge: (typeof onboarding !== "undefined" && onboarding !== null) ? onboarding : null
  ```

  Это не стиль, а проверяемое правило: `tests/unit/test_qml_onboarding_static.py::test_context_identifiers_are_guarded`
  роняет сборку, если хоть одна строка обращается к `onboarding`, `settingsBridge`
  или `showOnboarding` без такой защиты.

## 2. Контекстные свойства

Что именно Python отдаёт в QML (`app.py`, функции `_load_qml` и `main`):

| Имя | Объект Python | Когда появляется | Что это |
|---|---|---|---|
| `appInfo` | `AppInfo` (`app.py:_make_app_info`) | до `engine.load()` | Сведения о приложении: неизменяемые `version` (строка версии), `sessionKind` (`KDE`, `FLY` или `OTHER`), `policyStatus` (`absent`, `ok`, `invalid` — состояние `/etc/astra-voice/policy.conf`); свойство `debug` и сигнал перехода `showSection` описаны ниже |
| `themeSource` | `ThemeBridge` (`ui/theme_bridge.py`) | до `engine.load()` | Источник темы (светлая/тёмная, акцент). Кладётся ещё и в глобальный объект JS движка: `Theme.qml` — синглтон, а синглтоны контекстных свойств не видят |
| `showOnboarding` | `bool` | до `engine.load()` — `false`; сразу после сборки мостов — настоящее значение | Показывать мастер первого запуска вместо окна настроек. Пересчитывается по сигналу `doneChanged` контроллера |
| `settingsBridge` | `SettingsBridge` | после `engine.load()` | Настройки (раздел 3) |
| `onboarding` | `OnboardingController` | после `engine.load()`, **только если** `settings.extra["onboarding_done"] is not True` | Мастер первого запуска (раздел 4) |

У `AppInfo` есть свойство **`debug`** (`bool`, только чтение, сигнал
`debugChanged`). При запуске оно истинно, если передан `--debug` или переменная
`ASTRA_VOICE_DEBUG` равна `1`, `true` или `yes` без учёта регистра и пробелов
по краям. Все остальные значения означают ложь.
При `debug === true` в боковом меню появляется пункт «Отладка»; его содержимое
пока — страница-заглушка «Здесь будут сведения для поддержки».

Сигнал **`showSection(QString)`** передаёт ключ раздела в `Main.qml`:

| Ключ | Раздел | Переход через `showSection` |
|---|---|---|
| `general` | Общие | Переключает раздел |
| `models` | Модели | Переключает раздел |
| `output` | Вывод | Переключает на страницу-заглушку |
| `network` | Сеть и обновления | Переключает на страницу-заглушку |
| `advanced` | Продвинутые | Переключает на страницу-заглушку |
| `about` | О программе | Переключает раздел |
| `debug` | Отладка | Переключает на страницу-заглушку |

`Main.qml` выбирает экран по ключу раздела (`sectionPages`), а заголовок и
подзаголовок шапки берёт из описания раздела в `Sidebar.sections`
(`key`, `title`, `subtitle`). Переход между разделами — плавное появление.
`showSection` меняет выделение в боковом меню для любого ключа из таблицы;
для неизвестных ключей выделение не меняется. При любом ключе обработчик
показывает окно и запрашивает его активацию.
Python вызывает метод `show_section(name)`
(это не слот QML). При запросе `debug`, если раздел ещё скрыт, метод сначала
включает `debug` и отправляет `debugChanged`, затем — `showSection`.
Поэтому «Подробности» в уведомлении
открывают «Отладку» и без флага запуска. Кнопки «Выбрать микрофон» и «Выбрать
другую» открывают `general`. Эти обработчики сначала показывают окно.

Особенности, о которых легко забыть:

* Мосты передаются **после** загрузки QML, поэтому корневые объекты успевают
  создаться со значениями по умолчанию, а потом получают настоящие. Так и
  задумано: `tests/unit/test_bridges.py::test_qml_accepts_bridge_after_loading_and_observes_changes`
  проверяет, что биндинги пересчитываются после подстановки моста.
* Оба моста помечены `QQmlEngine.CppOwnership` — движок не имеет права их удалить,
  временем жизни распоряжается Python.
* Если QML не загрузился, `app.py` показывает виджет-заглушку. Тогда контекстных
  свойств нет вообще: `_set_context_property` для заглушки ничего не делает.
* Если онбординг пройден **до запуска приложения**, `onboarding` в контекст
  **не кладётся вовсе** — QML обязан работать, когда имя не определено.
  При завершении мастера в текущем сеансе меняется `showOnboarding`, сам мост остаётся.

## 3. Настройки — `settingsBridge`

`SettingsBridge` держит две копии настроек:

* **`settings`** — то, что пользователь выбрал; именно это пишется в `settings.json`;
* **`mirror`** — те же настройки с наложенной политикой администратора; из неё
  берутся значения для показа и ими пользуется рантайм.

Поэтому заблокированная администратором настройка показывает значение политики,
а в файле остаётся выбор пользователя — он вернётся, когда политику снимут
(`test_real_save_preserves_user_choices_under_policy`).

### 3.1 Свойства

| Свойство | Тип | Доступ | Что происходит при записи | Сигнал |
|---|---|---|---|---|
| `hotkey` | `string` | чтение и запись | Сначала пробное живое применение; при успехе — запись файла. При отказе возвращается прежняя комбинация, результат уходит в `hotkeyStatus` | `hotkeyChanged` |
| `hotkeyMode` | `string` | чтение и запись | Допустимы только `"ptt"` и `"toggle"`; иное — запись в журнал и полный отказ (файл не трогается, сигнала нет). Дальше — как у `hotkey` | `hotkeyModeChanged` |
| `pillEnabled` | `bool` | чтение и запись | Запись файла → `apply.pill_enabled()`: индикатор-пилюля и значок в трее переключаются сразу | `pillEnabledChanged` |
| `language` | `string` | чтение и запись | Допустимы только `"ru"` и `"en"`; иное отвергается. Только запись файла, живого применения нет | `languageChanged` |
| `checkAppUpdates` | `bool` | чтение и запись | Только запись файла | `checkAppUpdatesChanged` |
| `checkModelUpdates` | `bool` | чтение и запись | Только запись файла | `checkModelUpdatesChanged` |
| `autostart` | `bool` | чтение и запись | Только запись файла; ничего в системе пока не создаётся (см. раздел 5) | `autostartChanged` |
| `device` | `string` | чтение и запись | Пишется в `settings.extra["device"]` (пустая строка сохраняется как `null`) → `apply.device()`. Рантайм сбрасывает объявление микрофона; устройство читается перед следующей записью, текущая продолжается на прежнем | `deviceChanged` |
| `hotkeyStatus` | `string` | только чтение | Ставится из Python (`set_hotkey_status`) после каждой попытки захвата клавиши | `hotkeyStatusChanged` |
| `saveError` | `string` | только чтение | Пусто, если последняя запись удалась; иначе `«Не удалось сохранить настройки»` | `saveErrorChanged` |
| `modelSelfcheck` | `string` | только чтение | Ставится из Python (`set_model_selfcheck`); сейчас никто не вызывает (раздел 5) | `modelSelfcheckChanged` |
| `lockedSettings` | `QStringList` | только чтение, неизменно | Отсортированный список ключей, заданных администратором. Список — копия: `push`/`append` в QML ничего не меняет | нет (constant) |

Читаются и пишутся только первые восемь свойств; свойства моделей и общей
очереди из раздела 3.6 доступны только для чтения.
`tests/unit/test_bridges.py::test_defaults_and_readonly_properties`
сверяет по метаобъекту, что писать можно ровно восемь первых свойств, а у каждого
остального есть либо сигнал, либо пометка «неизменно».

### 3.2 Порядок действий при записи

1. Настройка заблокирована политикой → **ничего не меняем**, но сигнал
   `<имя>Changed` всё равно отправляем: биндинг в QML должен вернуть тумблер на место.
2. Значение не изменилось → выходим молча.
3. Значение недопустимо (`hotkeyMode`, `language`) → запись в журнал, выход без сигнала.
4. Для `hotkey` / `hotkeyMode`, если подключено живое применение, сначала пробуем
   новую комбинацию и режим. При отказе восстанавливаем прежние, публикуем
   `hotkeyStatus` и `<имя>Changed`, файл не трогаем.
5. Меняем `settings`, пишем файл атомарно (временный файл → `fsync` → `os.replace`, права `0600`).
6. Файл не записался (`OSError`) → **откат** значения, `saveError` заполняется,
   уходят оба сигнала. Для клавиши восстанавливаем прежний перехват; пилюлю
   и устройство не применяем.
7. Файл записался → обновляем `mirror`, чистим `saveError`, вызываем живое
   применение пилюли / устройства; для клавиши публикуем `hotkeyStatus: "ok"`.
   Отправляем `<имя>Changed`.

Для пилюли и устройства действует порядок «сначала на диск, потом в рантайм»
(`test_pill_and_device_apply_after_save`). Для клавиши предварительное применение
нужно, чтобы не сохранять комбинацию, которую не удалось захватить.

Объявления «Микрофон: ‹имя›» и «Микрофон сменился» учитываются по поколению
воркера. При первом `audio.ready` с именем устройства во время обычной записи
показывается «Микрофон: ‹имя›»; другое имя в том же поколении даёт «Микрофон
сменился», повтор того же имени молчит. Новое поколение воркера или успешный
выбор другого устройства в настройках сбрасывает объявление. Следующая запись
снова объявит микрофон как первый. Проверка и измерение уровня на шаге 4 этих уведомлений не создают.

### 3.3 Как QML узнаёт, что настройка заблокирована администратором

Двумя способами, оба рабочие:

* свойство **`lockedSettings`** — список ключей; так делает `qml/sections/General.qml`:

  ```qml
  function isLocked(name) {
      return settings && settings.lockedSettings ? settings.lockedSettings.indexOf(name) >= 0 : false
  }
  ```

* слот **`is_locked(name) -> bool`** — то же самое одним вызовом.

**Важно:** имена здесь — как в файле настроек и в `policy.conf`, не как в QML:
`hotkey`, `hotkey_mode`, `pill_enabled`, `language`, `check_app_updates`,
`check_model_updates`, `autostart`, `device`. `is_locked("pillEnabled")` вернёт
`false` — это проверяется тестом.

Показывать блокировку положено подписью, а не только серым цветом: строка
получает `locked: true` и `rowEnabled: false`, рядом — текст «Задано администратором»
(сквозное правило спецификации). В онбординге для этого есть готовые
`policyLocked` и `policyLockedText` (раздел 4.2).

### 3.4 Ошибка сохранения

Свойство `saveError` содержит готовую строку `«Не удалось сохранить настройки»`
и очищается при первой удачной записи. Подробности (путь, `errno`) в него **не
попадают** и в журнал тоже: тест `test_save_error_rolls_back_without_apply`
проверяет, что содержимое файла и путь не утекают в лог.

`General.qml` показывает непустой `saveError` в баннере ошибки над настройками.
В самом мастере первого запуска такого вывода пока нет (раздел 5).

### 3.5 Методы для Python, не для QML

Не помечены как слоты, из QML недоступны:

* `set_extra(key, value) -> bool` — сохранить служебный ключ в `settings.extra`
  (им пользуется онбординг); при отказе записи — откат и `saveError`;
* `reload()` — перечитать настройки и уведомить только об изменившихся свойствах;
* `set_hotkey_status(code)`, `set_model_selfcheck(state)` — публикация состояний из рантайма.

Кроме `is_locked` и `reinstallActiveModel()` (раздел 3.6), есть слот
**`retryHotkey()`**: повторная попытка захватить клавишу. Кнопки «Повторить» в `General.qml` нет
(решение заказчика 15.09.2026); рантайм повторяет попытку автоматически раз в
30 секунд. Запись `hotkey`/`hotkeyMode` применяет комбинацию отдельно, как описано
в разделе 3.2.

### 3.6 Модель и загрузки после мастера

Эти свойства доступны через тот же `SettingsBridge` и после завершения мастера.
Все — **только для чтения**: присваиванием нельзя выбрать рабочую модель или
изменить очередь, записи в `settings.json` здесь нет.

| Свойство | Тип | Значение | Сигнал |
|---|---|---|---|
| `activeModelName` | `string` | Имя записи каталога: сначала совпадающей с `current_ids()`, иначе первой с состоянием `ok` в хранилище, иначе первой, для которой есть любая запись в хранилище (в том числе сломанная); если ничего не найдено — пусто | `activeModelChanged` |
| `activeModelSize` | `string` | Размер записи, выбранной в том же порядке, что и для `activeModelName`, через `format_size`, например «226 МБ»; без записи — пусто | `activeModelChanged` |
| `activeModelState` | `string` | Состояние текущей модели, словарь — ниже | `activeModelStateChanged` |
| `downloadState` | `string` | Состояние общей очереди из раздела 4.3 | `downloadStateChanged` |
| `downloadProgress` | `real` | Доля общей загрузки от 0 до 1 | `downloadProgressChanged` |
| `activeModelMessage` | `string` | Готовая фраза отказа для текущей модели: «Файлы модели повреждены. Переустановите модель», «Не удалось загрузить модель», «Не хватает места на диске», «Не удалось проверить список моделей»; когда отказа нет — пусто | `activeModelStateChanged` |
| `canReinstall` | `bool` | Переустановка доступна: запись есть, очередь свободна, каталог читается | `activeModelStateChanged` |
| `canInstall` | `bool` | Установка рекомендованной модели доступна: модели нет, каталог читается, очередь свободна | `activeModelStateChanged` |
| `downloadTitle` | `string` | Готовый заголовок общей загрузки | `downloadTitleChanged` |
| `downloadDetail` | `string` | Уточнение к заголовку: «нужно ещё 126 МБ» при нехватке места, иначе пусто | `downloadDetailChanged` |
| `speed` | `string` | Готовая строка скорости общей очереди | `speedChanged` |
| `eta` | `string` | Готовая фраза оставшегося времени общей очереди | `etaChanged` |

| `activeModelState` | Когда возвращается |
|---|---|
| `none` | Каталог или общая служба недоступны либо в хранилище нет ни одной записи для записей каталога |
| `ok` | Запись в хранилище имеет состояние `ok`, и карточка не переопределяет его одним из четырёх состояний ниже |
| `broken` | Текущая запись есть, но её состояние в хранилище не `ok`, и нет переопределения карточкой |
| `downloading` | Карточка текущей модели скачивается |
| `verifying` | Карточка текущей модели проверяется или устанавливается |
| `failed` | Карточка текущей модели завершилась ошибкой |
| `no-space` | Для текущей модели не хватило места |
| `catalog-unavailable` | Каталог не читается: нет подписи, нет `gpgv`, хранилище непригодно. Имя модели при этом берётся из хранилища, если оно там есть; «Переустановить» недоступна |

Это состояние **текущей модели**, выбранной в указанном выше порядке, а не
любой модели в очереди. Неисправная запись и запись с пометкой `recheck`
теперь видны как `broken`, если выбраны и нет переопределения карточкой.
Они доступны через `active_entry()`, даже если не возвращаются через
`current_ids()`: `reinstall_active()` использует ту же запись, поэтому
«Переустановить» работает и для неисправной модели или записи с `recheck`.

Слот **`reinstallActiveModel()`** без аргументов ставит текущую запись в общую
очередь заново. Если записи нет, очередь уже занята, работает поток проверки
или приложение выходит, вызов ничего не делает.

Слот **`installRecommendedModel()`** ставит в очередь рекомендованную запись
каталога — для случая, когда модели нет вовсе (`activeModelState = none`).
Слот **`cancelDownloads()`** прерывает очередь: фоновая загрузка, начатая из
настроек, должна быть управляемой (ИБ, У66). Слот **`openModelsFolder()`**
открывает каталог моделей в файловом менеджере; путь в QML не передаётся.

`downloadState`, `downloadProgress`, `downloadTitle`, `speed` и `eta` показывают
**ту же очередь**, что и свойства `onboarding`, с теми же текстами и сигналами.
Если `SettingsBridge` создан без `ModelDownloads`, строковые свойства очереди
возвращают `""` (в том числе `downloadState`), а прогресс — `0.0`.

#### Каталог и выбор для раздела «Модели»

Раздел «Модели» окна настроек показывает тот же каталог и тот же выбор, что шаг 2
мастера: и `SettingsBridge`, и `OnboardingController` спрашивают **один и тот же**
`ModelDownloads`. Значения, тексты, сигналы и словари состояний — полностью как в
разделе 4.3, повторять их здесь незачем. Все свойства **только для чтения**.

| Свойство | Тип | Значение | Сигнал |
|---|---|---|---|
| `models` | `QVariantList` | Весь каталог; поля записи — таблица раздела 4.3 | `modelsChanged` |
| `selectionSummary` | `string` | «Будет скачано ‹размер›» для отмеченных записей; пусто при нулевой сумме | `selectionChanged` |
| `selectionFits` | `bool` | Хватит ли места для этой суммы | `selectionChanged` |
| `selectionMessage` | `string` | Пусто при `selectionFits == true`, иначе готовое сообщение о нехватке места | `selectionChanged` |
| `freeSpaceText` | `string` | Готовая фраза «свободно на диске 42,1 ГБ»; пусто, если узнать нельзя | `freeSpaceTextChanged` |
| `installedSummary` | `string` | Счётчик шапки раздела «Установлено 3 из 12 · 680 МБ на диске»; при нуле установленных — «Установлено 0 из 12», при пустом каталоге — пусто | `modelsChanged` |
| `installedCount` | `int` | Сколько записей каталога установлено — цифра значка у пункта «Модели» в сайдбаре; `0`, когда не установлено ничего, каталог пуст или моста каталога нет | `modelsChanged` |

Слот **`toggleModel(id)`** переключает отметку выбора у записи каталога,
**`startSelectedDownloads()`** ставит отмеченные записи в общую очередь,
**`retryModel(id)`** повторяет неудавшуюся запись, **`pickInstallPath()`**
спрашивает папку и ставит модель из неё (диалог задаётся аргументом
`dialog_factory`, как у мастера). Все четыре ничего не делают, если
`SettingsBridge` создан без `ModelDownloads`; тогда же `models` пуст,
`selectionFits` истинно, остальные строки пусты.

Кнопки установленной карточки (§5.4 спецификации, состояния 19–20 и 25) — ещё
три слота. Все три работают только при свободной очереди: пока идёт загрузка,
установка или перепроверка, вызов молча ничего не делает.

| Слот | Что делает |
|---|---|
| `makeModelCurrent(id)` | Делает установленную ревизию рабочей. Отказывает, если записи нет или её состояние не `ok`; при отказе хранилища карточка получает `message` «Модель установлена. Сделать её рабочей не удалось — попробуйте переустановить.» |
| `removeModel(id)` | Удаляет установленную ревизию из хранилища. Рабочую модель (`badge == "active"`) не трогает — сначала нужно выбрать другую; при отказе хранилища карточка получает `message` «Не удалось удалить модель. Попробуйте ещё раз.» |
| `updateModel(id)` | Ставит в общую очередь ревизию из каталога, когда установлена прежняя (`updateAvailable == true`). В остальных случаях ничего не делает |

Размер в `installedSummary` — сумма размеров установленных записей **по
каталогу**, те же цифры, что в строке «Занимает места» каждой карточки, а не
результат обхода диска. `installedCount` считает те же записи, что и первое
число `installedSummary`; сайдбар прячет значок, когда счёт нулевой.

`canContinueFromModel` у `SettingsBridge` **нет**: это подсказка кнопке
«Продолжить» в мастере, а не в настройках.

### 3.7 Громкость микрофона и звуковая служба (PRD 0.9 F6.6/F6.7, ступени 1–2)

Состояние выбранного источника записи читается у звуковой службы **без открытия
микрофона** (значок записи не загорается, §9.5). Само по себе ничего не
опрашивается: чтение происходит при открытии раздела «Общие»
(`refreshMicrophone()`), при смене микрофона в списке и после нажатия кнопки.
Системную настройку программа меняет **только** по нажатию человека.

| Свойство | Тип | Значение | Сигнал |
|---|---|---|---|
| `microphoneVolume` | `int` | Системная громкость выбранного микрофона в процентах; `-1` — узнать не удалось (звуковая служба не ответила или её нет) | `microphoneChanged` |
| `microphoneMuted` | `bool` | У выбранного источника стоит признак «звук выключен» | `microphoneChanged` |
| `canRaiseMicrophone` | `bool` | В системе есть чем менять громкость. **`false` — строку «Громкость микрофона» в «Общих» не показываем** | `microphoneChanged` |
| `canOpenSoundSettings` | `bool` | Есть чем открыть системную панель звука | `microphoneChanged` |
| `canRestartSoundService` | `bool` | Есть чем перезапустить звуковую службу сеанса. `false` — строки в «Отладке» нет | `microphoneChanged` |

| Слот | Что делает |
|---|---|
| `refreshMicrophone()` | Перечитать состояние источника. Вызывает `General.qml` при `Component.onCompleted`; чаще раза в секунду опрашивать запрещено (§8) |
| `raiseMicrophoneVolume()` | Включить звук выбранного микрофона и поставить громкость ровно 100 %. Выше 100 % не поднимаем; если громкость уже выше — только включаем звук. Другие источники, громкость воспроизведения, профиль и порты карты не трогаются. После действия состояние перечитывается |
| `openSoundSettings()` | Открыть системную панель звука отдельным окном. Ничего в системе не меняет; на машине без панели не делает ничего |
| `restartSoundService()` | Перезапустить звуковую службу сеанса (раздел «Отладка»). Только по нажатию; сама программа звуковую службу никогда не поднимает |

Все пять свойств — **только для чтения**; присваивание громкости мостом не
предусмотрено (ползунка нет, есть кнопка «Поднять»).

Без живого рантайма (`apply=None`) свойства отдают `-1`/`false`, а слоты ничего
не делают: экран настроек остаётся рабочим и без него.

**Уведомление при диктовке.** Когда воркер сообщил о тишине, рантайм уточняет
причину по тому же состоянию источника и один раз за сеанс на причину показывает
уведомление «Микрофон выключен» или «Микрофон почти не слышно» с кнопкой
«Открыть настройки звука». Причина сбрасывается успешным нажатием «Поднять» или
тем, что при следующей тишине состояние источника уже в порядке. В мост это не
выведено: уведомление — дело рантайма, QML о нём ничего не знает.

## 4. Онбординг — `onboarding`

`OnboardingController` — пять шагов мастера первого запуска. Настройки сам он не
сохраняет: **все записи настроек идут через `SettingsBridge`**, поэтому правила раздела 3
(мгновенное сохранение, откат, блокировка политикой) действуют и здесь.

### 4.1 Общие свойства

| Свойство | Тип | Доступ | Значение |
|---|---|---|---|
| `step` | `int` | только чтение | Текущий шаг, 1…5. Меняется слотами `next` / `back` / `skip`; при старте берётся из `settings.extra["onboarding_step"]`, всё, что не целое из 1…5, заменяется на 1 |
| `totalSteps` | `int` | только чтение, неизменно | Всегда 5 |
| `canFinish` | `bool` | только чтение | Можно ли нажать «Готово»: всегда равно `modelReady`; сигнал `canFinishChanged` |
| `modelReady` | `bool` | только чтение | Есть хотя бы одна запись хранилища со `state == "ok"` без пометки `recheck`; если сервиса моделей нет — `settings.extra["onboarding_model_ready"] is True`. Сигнал `modelReadyChanged` |
| `done` | `bool` | только чтение | Онбординг пройден (`settings.extra["onboarding_done"] is True`) |

Кнопка «Готово» на пятом шаге неактивна, пока `canFinish` ложно, — это проверяет
`test_qml_onboarding_static.py::test_finish_button_mentions_can_finish`.

### 4.2 Шаг 1 «Сеть»

| Свойство | Тип | Доступ | Значение |
|---|---|---|---|
| `language` | `string` | чтение и запись | `"ru"` / `"en"`. Запись отвергается, если язык заблокирован политикой; при удачной записи ставится отметка `onboarding_language_set`, чтобы автоопределение больше не срабатывало |
| `checkAppUpdates` | `bool` | чтение и запись | Проверять обновления программы. По умолчанию **выключено** — без явного действия программа в сеть не ходит |
| `checkModelUpdates` | `bool` | чтение и запись | Проверять обновления моделей. По умолчанию выключено |
| `policyLocked` | `bool` | только чтение | Истинно, если администратор задал `check_app_updates` **или** `check_model_updates` |
| `policyLockedText` | `string` | только чтение | `«Задано администратором»` либо пустая строка |

Язык при первом запуске определяется по переменной окружения `LANG`: начинается
с `ru` → `"ru"`, иначе `"en"`. Делается это один раз — пока в настройках нет ключа
`onboarding_language_set`.

### 4.3 Шаг 2 «Модель»

Новый контракт отдаёт весь доступный каталог через `models`. В `ModelService`
отозванные ревизии исключаются, рекомендованная запись идёт первой, остальные —
в порядке каталога. При отсутствии сервиса список пуст. Ниже все свойства —
**только для чтения**: присваивание не сохраняет выбор и не запускает загрузку.
Выбор меняется слотами и хранится в памяти `ModelDownloads`, не в `settings.json`.

| Свойство | Тип | Значение | Сигнал |
|---|---|---|---|
| `models` | `QVariantList` | Новый список объектов со всеми полями из таблицы ниже; изменение возвращённой записи не меняет очередь | `modelsChanged` |
| `selectionSummary` | `string` | «Будет скачано ‹размер›» для суммы выбранных записей без `badge`; пусто, если сумма равна нулю | `selectionChanged` |
| `selectionFits` | `bool` | Хватит ли места для этой суммы по `disk_ok`; при нулевой сумме — `true` | `selectionChanged` |
| `selectionMessage` | `string` | Пусто при `selectionFits == true`, иначе готовое сообщение о нехватке места | `selectionChanged` |
| `canContinueFromModel` | `bool` | Есть выбранные записи без `badge` **или** `modelReady`, и при этом `selectionFits == true` | `selectionChanged` |
| `downloadState` | `string` | Состояние общей очереди, словарь — ниже | `downloadStateChanged` |
| `downloadProgress` | `real` | Доля общей загрузки от 0 до 1, взвешенная по размерам моделей в байтах | `downloadProgressChanged` |
| `downloadTitle` | `string` | Готовый заголовок общей загрузки, точные тексты — ниже | `downloadTitleChanged` |
| `downloadDetail` | `string` | Уточнение к заголовку: «нужно ещё 126 МБ» при нехватке места, иначе пусто | `downloadDetailChanged` |
| `freeSpaceText` | `string` | Готовая фраза «свободно на диске 42,1 ГБ»; пусто, если узнать нельзя | `freeSpaceTextChanged` |
| `speed` | `string` | Готовая строка скорости, например «860 КБ/с» или «5,2 МБ/с» | `speedChanged` |
| `eta` | `string` | Готовая фраза оставшегося времени целиком, включая слово «осталось» | `etaChanged` |

Поля **каждой** записи `models`:

| Ключ | Тип | Значение |
|---|---|---|
| `id` | `string` | Идентификатор модели; передаётся в `toggleModel` и `retryModel` |
| `name` | `string` | Имя из каталога |
| `description` | `string` | Описание из каталога |
| `host` | `string` | Узел источника модели |
| `recommended` | `bool` | Признак рекомендованной записи каталога |
| `sizeBytes` | `int` | Размер записи каталога в байтах |
| `sizeText` | `string` | Размер через `format_size`, например «226 МБ» |
| `ramText` | `string` | Требуемая память из `min_ram_mb`, например «768 МБ» |
| `selected` | `bool` | Идентификатор есть в текущем выборе; после успешной установки тоже становится `true` |
| `badge` | `string` | `""`, `installed` или `active`, словарь — ниже |
| `state` | `string` | `available`, `queued`, `downloading`, `verifying`, `installed`, `failed` или `no-space` |
| `message` | `string` | Пояснение ошибки карточки; по умолчанию и при обычных переходах без ошибки — пусто |
| `progress` | `real` | Доля скачивания этой модели от 0 до 1; в остальных состояниях — 0 |
| `vendor` | `string` | Кто выпустил модель, например «Сбер (GigaChat Team)»; пусто, если каталог не сообщает |
| `domestic` | `bool` | Правообладатель отечественный; по этому полю работает фильтр «Только отечественные» в разделе «Модели» |
| `updateAvailable` | `bool` | В хранилище стоит другая — прежняя — ревизия этой модели, а каталог знает свежую; только тогда в карточке есть «Обновить» |
| `tags` | `QVariantList` | Готовые подписи карточки строками, словарь — ниже; пустой список, если каталог их не несёт |
| `metrics` | `QVariantList` | Ровно две полоски — «Качество» и «Скорость», поля — ниже |

Поля каждой записи `tags` — это **готовые строки**, интерфейс их не собирает и не
переводит. Порядок фиксирован, отсутствующие подписи пропускаются:

| Позиция | Значение | Когда есть |
|---|---|---|
| язык | «Только русский», «Русский и ещё четыре языка», «Русский и ещё много языков» | всегда, если каталог назвал язык |
| пунктуация | «с пунктуацией» | только если модель ставит знаки препинания |
| лицензия и вендор | «MIT · Сбер», «Apache-2.0 · Alpha Cephei» | если каталог назвал хотя бы одно из двух |
| происхождение | «отечественная» | только для отечественных правообладателей |

Поля каждой записи `metrics`. Список всегда из двух элементов в этом порядке:
«Качество» (доля ошибок в словах) и «Скорость». Цифр может не быть — тогда
`hasData` ложно, а карточка рисует дорожку пунктиром и ничего не пишет:

| Ключ | Тип | Значение |
|---|---|---|
| `label` | `string` | Подпись полоски: «Качество» или «Скорость» |
| `text` | `string` | Готовое значение: «WER 7,60 %» или «42,5× быстрее речи»; пусто при `hasData == false` |
| `fill` | `real` | Доля заливки от 0 до 1 **относительно лучшей модели каталога**: у лучшей — 1,0; 0 при `hasData == false` |
| `hasData` | `bool` | Есть ли опубликованная цифра по протоколу; выдумывать её нельзя |
| `measured` | `bool` | Замерено ли на этом компьютере. Пока всегда `false`: цифры взяты из опубликованного бенчмарка |

| `badge` | Значение |
|---|---|
| `""` | В хранилище нет записи с непустым состоянием ни для ревизии каталога, ни для прежней ревизии этой модели |
| `installed` | Запись есть, но она не является текущей исправной моделью; пометка возможна и для `broken` или `recheck` |
| `active` | Состояние записи `ok`, и её идентификатор и ревизия совпадают с `current_ids()` |

Пометку даёт **установленная ревизия этой модели**: сначала та, что названа в
каталоге, иначе любая другая из хранилища. Поэтому модель, установленная старой
версией, остаётся «Установлена» и получает `updateAvailable == true`, а не
выдаёт себя за незнакомую.

| `state` | Значение |
|---|---|
| `available` | Исходное состояние записи без `badge`; сюда же возвращаются отменённые задания. Выбор по-прежнему возможен только при пустом `badge` |
| `queued` | Запись поставлена в очередь, её задание ещё не началось |
| `downloading` | Скачиваются файлы, обновляется `progress` карточки |
| `verifying` | Проверка файлов, установка и пробное распознавание; также фоновая перепроверка `recheck` |
| `installed` | Установка завершилась успешно; это же начальное состояние карточки с непустым `badge` |
| `failed` | Установка или перепроверка завершилась ошибкой; пояснение — в `message` |
| `no-space` | Не хватило места; пояснение — в `message` |

Начальное `state` без отдельного состояния карточки равно `installed`, если
есть `badge`, иначе `available`. Поэтому ни `badge == "installed"`, ни начальное
`state == "installed"` **не заменяют** проверку `modelReady`.

Выбор изначально пуст, даже у рекомендованной модели. Записи с непустым `badge`
не переключаются и не входят в сумму скачивания. Если ничего не выбрано и нет
готовой модели, `selectionSummary` и `selectionMessage` пусты, `selectionFits`
истинно, `canContinueFromModel` ложно. Логические свойства пустыми не бывают.
Нехватка места даёт «На диске не хватает ‹размер›. Освободите место.»: сервис
считает дефицит с запасом 20%, округляет его вверх до целых МБ. Если точный
дефицит получить нельзя, текст — «Недостаточно места на диске для модели
‹размер›. Освободите место.»; для выбора здесь указан его суммарный размер.

`canContinueFromModel` — подсказка интерфейсу, не условие внутри `next()`:
переход шага сам по себе загрузку не запускает. Для запуска нужен
`startSelectedDownloads()`; все слоты перечислены в разделе 4.6.

#### Сквозной прогресс

| `downloadState` | Что происходит | Точный `downloadTitle` |
|---|---|---|
| `idle` | Очередь ещё не запускалась или отменена; также перепроверка без вердикта | Пустая строка |
| `downloading` | Скачивается текущая запись | «Загружается ‹имя›»; при нескольких записях — «Загружается ‹имя› · ‹номер› из ‹всего›» |
| `verifying` | Проверяются и устанавливаются файлы, выполняется пробное распознавание; также `recheck` | «Проверяю модель…» |
| `done` | Очередь закончилась хотя бы с одной успешной установкой либо успешно закончилась перепроверка | «Модель готова» |
| `failed` | Очередь без успешных установок закончилась ошибкой, кроме последнего отказа по месту; либо не прошла перепроверка | «Не получилось загрузить модель» |
| `no-space` | Успешных установок нет, последний отказ в очереди — нехватка места | «Не хватает места на диске» |

`downloadProgress` считает байты успешно установленных моделей плюс текущую
долю скачивания, делённые на общий размер исходной очереди. В начале и при
отмене — 0. При неудаче текущие байты в итог не входят: значение может
уменьшиться. `done` при частичном успехе не означает 100%; завершение установки
из папки тоже не измеряет время проверки этим прогрессом. Перепроверка
публикует `verifying` с прогрессом 0.

`speed` и `eta` — **готовые строки целиком** из `ui/formatting.py`: QML не
добавляет «осталось», единицы или вторую оценку секунд. Размеры и скорость
используют десятичные КБ/МБ. Скорость округляется до целых КБ/с или одного
знака МБ/с с запятой: «860 КБ/с», «5,2 МБ/с»; при неизвестной, нулевой,
отрицательной или неконечной скорости — пусто.

| Форма `eta` | Когда используется |
|---|---|
| «считаю…» | Первые 5 секунд, недостаточно устойчивая оценка или неизвестное/недопустимое оставшееся время |
| «осталось меньше минуты» | Известная оценка меньше 60 секунд |
| «осталось ~N мин» | От 60 секунд до часа; минуты округлены до ближайшего целого |
| «осталось ~N ч M мин» | От часа; минуты округлены до ближайшего целого с переносом 60 минут в следующий час |
| «осталось ~N ч» | Та же оценка от часа, если после округления минут получилось 0 |

Средняя скорость берётся из `SpeedTracker` с окном 8 секунд; для ненулевой
оценки нужен интервал хотя бы в секунду. Во время поступления прогресса
`speed` / `eta` пересчитываются **не чаще раза в секунду**, сигнал посылается
только при изменении строки. Это ограничение не относится к прогрессу и
немедленному сбросу строк при начале, отмене, завершении очереди и начале
перепроверки. До первого расчёта обе строки пусты; первый прогресс обычно
сразу даёт `eta == "считаю…"`. На стадии проверки последние оценки могут
оставаться до завершения: переход в `verifying` сам их не очищает.

`modelReady` не равно `downloadState == "done"`: достаточно хотя бы одной
исправной записи без `recheck`, в том числе установленной раньше. `canFinish`
всегда повторяет `modelReady`. Успех загрузки **не закрывает окно мастера**
и не вызывает `finish()`; пользователь завершает мастер сам. `finish()`
сохраняет отметку и скрывает окно, как описано в разделе 4.6.

#### Общая очередь `ModelDownloads`

Мастер, настройки и переустановка используют один объект из `app.py`.
Выбранные модели ставятся в порядке `entries()` — рекомендованная первой,
остальные в порядке каталога, а не нажатий пользователя. Задания исполняются
**строго по одному** в `QThread`; следующая модель запускается только после
выхода предыдущего потока. Повторный запуск очереди, изменение выбора и
переустановка во время занятой очереди или потока ничего не делают.

Сбой одной модели ставит её карточке `failed` или `no-space`, но **не
останавливает остальные**. Если хотя бы одна установка удалась, общий итог —
`done`, даже если другая карточка осталась с ошибкой. Без успехов итогом будет
последний вид отказа (`failed` / `no-space`). Успешно установленная модель
сохраняется. Если до начала очереди уже была текущая модель со статусом `ok`,
она остаётся рабочей, пока сохраняет `ok`; иначе рабочей остаётся
**первая успешно установленная**.
Последующие успешные установки не переключают рабочую модель на себя.

`cancelDownloads()` выставляет событие отмены для текущего задания, удаляет
ожидающие задания, возвращает их карточки и текущую карточку в `available`,
сбрасывает общий статус в `idle`, прогресс в 0, скорость и время в пустые
строки. Выбор сохраняется. Уже установленные модели не удаляются. Поток
заканчивает работу асинхронно, новый запуск до его выхода невозможен; если
он уже успел успешно установить текущую модель, её итог сохраняется как
`installed`. Отмена доступна и во время проверки/установки; скрытие окна
само по себе загрузку не отменяет.

#### Перепроверка записей `recheck`

`app.py` вызывает `start_recheck()` у общей службы при запуске. В список
попадают записи каталога, чьи ревизии в хранилище помечены `recheck == true`.
Они проверяются последовательно тем же механизмом потоков, после активной
очереди установок, без скачивания: сначала файлы, затем пробное распознавание.
Карточка и общий `downloadState` переходят в `verifying`.

| Исход | Что меняется |
|---|---|
| Успех | `mark_ok` снимает `recheck`, карточка `installed`, общий статус `done`; если текущей модели нет, проверенная становится текущей; отправляются сигналы готовности и сводки выбора |
| Подтверждённый отказ файлов или распознавания | `mark_broken` снимает `recheck`, карточка `failed` с безопасным пояснением, общий статус `failed`; отправляются сигналы готовности и сводки выбора |
| Отмена, выход или невозможность получить вердикт | Прежние значения карточки восстанавливаются, общий статус `idle`; пометка `recheck` сохраняется для следующего запуска, исправность модели не объявляется |

Отсутствие пробной записи, таймаут, сбой запуска воркера и исключение при
перепроверке не доказывают неисправность модели и относятся к третьему исходу.
Для пробного распознавания подтверждёнными отказами считаются только
`load-failed`, `no-match`, `transcribe-failed`. `cancelDownloads()` во время
перепроверки отменяет текущее задание и очищает оставшиеся перепроверки;
восстановление карточки публикуется после выхода потока.

#### Уведомления и строка трея

Когда очередь закончилась хотя бы с одной успешной установкой,
`OnboardingController` показывает уведомление **«Модель установлена»** с текстом
«Можно диктовать.», если окно не отмечено видимым и приложение не выходит.
Это уведомление о завершении очереди, а не о каждой карточке; перепроверка
его не посылает. При старте уже после пройденного мастера контроллер не
создаётся, поэтому у переустановки из одних настроек этого обработчика нет.

При подключённом рантайме под строкой состояния в меню трея появляется
неактивная строка «‹downloadTitle› — ‹процент›», процент округлён до целого.
Она скрыта для `idle` и `done`, видна для `downloading`, `verifying`, `failed`,
`no-space`. Сигналы заголовка, прогресса и состояния обновляют её и после
мастера; окно для этого открывать не требуется.

#### Разные тексты отказа распознавания

Ошибку запуска и F4.9 нельзя объединять в одно сообщение:

| Где и по какой причине | Что видит пользователь |
|---|---|
| Пробное распознавание при установке: `load-failed`, `worker-failed`, `no-wav`, `timeout` | «Не удалось запустить распознавание. Попробуйте переустановить модель» |
| Пробное распознавание при установке: `no-match`, `transcribe-failed` | F4.9: «Распознавание на этом компьютере не работает. Обратитесь к администратору» |
| Самопроверка рантайма завершилась отказом: `load-failed`, `worker-error`, `no-wav`, `timeout` | `notify_engine_failed()`: заголовок «Не удалось запустить распознавание», текст «Попробуйте переустановить модель.» |
| Самопроверка рантайма: другой окончательный отказ, в том числе `no-match` или повторная `cancelled` | `notify_selfcheck_failed()`, F4.9: заголовок «Распознавание на этом компьютере не работает», текст «Обратитесь к администратору.» |

При установке эти фразы приходят в `models[].message` и, для рекомендованной
модели, в старое `modelMessage`; системное уведомление о таком отказе сам мост
не посылает. Для прочих отказов, кроме нехватки места, сети и отзыва версии,
новая карточка получает «Модель не прошла проверку. Попробуйте скачать или
установить её заново.». Старое `modelMessage` может сохранить безопасную фразу
пробника «Модель не прошла пробное распознавание на этом компьютере».
Отзыв версии даёт «Издатель
больше не рекомендует эту версию модели. Не устанавливайте её — скачайте
свежую версию.», сетевой отказ в карточке — «Нет доступа к источнику модели.
Проверьте подключение или установите её из папки.».

В рантайме первая `timeout` или `cancelled` запускает одну автоматическую
повторную попытку с новым воркером, без окончательного уведомления. После
исчерпания повтора действует таблица выше; `ok` уведомления об отказе не даёт.
Ошибка события `transcribe.file`, кроме таймаута, превращается в `worker-error`;
несовпадение пробной фразы — в `no-match`. Оба уведомления критические, с кнопкой
«Подробности». Обычная ошибка первоначальной загрузки модели вне повторной
самопроверки идёт отдельно в индикацию ошибки загрузки; таблица описывает
именно окончательный результат самопроверки. Для фонового `recheck` действуют
три исхода из предыдущей таблицы, а не безусловное уведомление F4.9.

### 4.4 Шаг 3 «Горячая клавиша»

| Свойство | Тип | Доступ | Значение |
|---|---|---|---|
| `hotkey` | `string` | чтение и запись | Комбинация; пишется через `SettingsBridge` со всеми его правилами |
| `hotkeyMode` | `string` | чтение и запись | `"ptt"` (удерживать) или `"toggle"` (нажать-нажать) |
| `captureState` | `string` | только чтение | Состояние поля захвата, перечень — ниже |
| `captureMessage` | `string` | только чтение | Короткое пояснение для состояний `conflict`, `duplicate`, `not-grabbed`; в остальных — пусто |
| `pendingCombo` | `string` | только чтение | Комбинация, которую пользователь только что нажал и которая ещё не принята |
| `freeCandidates` | `QStringList` | только чтение | Свободные комбинации по живому опросу системы; заполняется слотом `refreshCandidates()` |

#### Допустимые значения `captureState`

Семь состояний, ровно как в `design/spec.md` §7:

| Значение | Что это на экране |
|---|---|
| `idle` | Поля захвата нет: чип с текущей комбинацией и кнопка «Изменить» |
| `capturing` | Поле активно, текст «Нажмите комбинацию…», справа «Esc — отмена» |
| `captured` | Комбинация нажата, показывается она, справа «Отпустите клавиши» |
| `success` | Зелёный баннер «Комбинация назначена» |
| `conflict` | Жёлтый баннер: комбинация занята другой программой. Это **предупреждение, а не запрет** — можно оставить её (`keepCombo()`) или выбрать другую |
| `duplicate` | Жёлтый баннер: комбинация уже назначена внутри самой программы |
| `not-grabbed` | Красный баннер: захватить не удалось, диктовка работать не будет, пока не выбрана другая |

Как код системного пробника превращается в состояние: `ok` → сохраняем и
`success`; `busy` → `conflict`; `duplicate` → `duplicate`; `bad-combo`,
`not-grabbed` и любая ошибка → `not-grabbed`. Тот же перечень кодов приходит в
`settingsBridge.hotkeyStatus`: `ok`, `busy`, `bad-combo`, `duplicate`, `not-grabbed`.

Про порядок: перехват клавиатуры снимается **до** любого пробника, сохранения или
применения — иначе сеанс останется с захваченной клавиатурой. Уход со шага,
скрытие или закрытие окна во время захвата тоже снимают его (для этого контроллер
ставится фильтром событий на корневое окно).

### 4.5 Шаг 4 «Микрофон»

| Свойство | Тип | Доступ | Значение |
|---|---|---|---|
| `devices` | `QVariantList` | только чтение | Список объектов с полями `id` и `name`. Первый — `{'id': '', 'name': 'Системный по умолчанию'}`; далее устройства из системного списка |
| `device` | `string` | чтение и запись | Идентификатор выбранного устройства, пустая строка — системный выбор. Читается и пишется через `SettingsBridge.device`, с сохранением и блокировкой политикой |
| `deviceResolved` | `string` | только чтение | Имя микрофона, который система открыла на самом деле; пустая строка, пока неизвестно |
| `levelState` | `string` | только чтение | Состояние отдельного измерения: `idle`, `listening`, `error`; сигнал `levelStateChanged` |
| `levelMessage` | `string` | только чтение | Пояснение измерения, пусто при штатных `idle` / `listening`; сигнал `levelMessageChanged` |
| `level` | `real` | только чтение | Уровень сигнала 0…1 из `peak_dbfs` при измерении (`listening`) или записи проверки (`recording`); при выходе из этих состояний — 0 |
| `peak` | `string` | только чтение | Последний пик строкой, например `«−18 дБ»`; до получения уровня и после сброса проверки — пусто |
| `testPhrase` | `string` | только чтение | Предложенная фраза: `«Сегодня хороший день для прогулки.»`. Это свойство, не слот |
| `testState` | `string` | только чтение | Состояние проверки, перечень — ниже |
| `testText` | `string` | только чтение | Распознанный текст после `done`; доступен только на шаге 4, пока онбординг не завершён, иначе пусто |
| `testDuration` | `string` | только чтение | Время распознавания после `done`, например `«0,31 с»`; в остальных состояниях — пусто |
| `testMessage` | `string` | только чтение | Готовое пояснение при `error` и `preparing`; также «Будет доступно после установки модели» при отказе `startTest()` без модели. Обычные обновления других состояний очищают строку |

`deviceResolved` приходит из события готовности звука воркера — того же, что
даёт уведомление «Микрофон: …» при обычной диктовке. Значение обновляется
при измерении уровня, проверке на шаге 4 и при обычной записи, сбрасывается в пустую строку при перезапуске воркера
и при смене устройства в настройках. Главный случай — выбран «Системный по
умолчанию», и интерфейс показывает, какой микрофон это на самом деле. При явно
выбранном устройстве имя тоже приходит; показывать его или нет — решает интерфейс.

#### Допустимые значения `testState`

Полный перечень: `idle | preparing | recording | processing | done | error`.

| Значение | Что это на экране |
|---|---|
| `idle` | Проверка не запускалась либо сброшена; результата нет |
| `preparing` | «Готовлю модель…» из `testMessage` показано подсказкой под индикатором уровня; поле результата скрыто. Рантайм ждёт загрузки модели, микрофон ещё не открыт; кнопка «Остановить» вызывает `stopTest()` и отменяет ожидание |
| `recording` | «Слушаю…»: модель готова, запущена запись проверки микрофона |
| `processing` | «Распознаю…» |
| `done` | Показаны распознанный текст и время; текст никуда не вставлен |
| `error` | Показано пояснение из `testMessage`, например «Не удалось распознать речь. Попробуйте ещё раз.» |

Ожидание модели в `preparing` ограничено 30 секундами, после чего состояние
становится `error` с пояснением о недоступности модели.

Список устройств собирается при создании контроллера. Даже если получить его
не удалось, остаётся «Системный по умолчанию»; наружу возвращается копия списка
и его объектов.

**Уровень сигнала доступен без модели.** `startLevelMonitor()` через хост и
`runtime.start_level_monitor()` открывает выбранный микрофон без загрузки модели
и распознавания. `MicrophoneLevelUpdate` в `core/dictation.py` содержит только
`state` (`idle` / `listening` / `error`), необязательный `peak_dbfs` и `message`;
речи в этом канале нет. Обновления питают общие `level` / `peak` и отдельные
`levelState` / `levelMessage`, **не меняя `testState`**.

| `levelState` | Что происходит |
|---|---|
| `idle` | Измерение ещё не запускалось либо микрофон освобождён после остановки. Если при этом `levelMessage` не пуст — проверку остановил сам мост по общему потолку эпизода (`LEVEL_TOTAL_LIMIT_S`, 180 с, ИБ У62); интерфейс показывает пояснение и кнопку «Проверить ещё раз», которая зовёт `startLevelMonitor()` заново |
| `listening` | Запущено измерение, события уровня обновляют индикатор |
| `error` | Измерение не удалось; пояснение в `levelMessage`, например «Не удалось проверить микрофон. Попробуйте ещё раз.» или «Сначала завершите текущую диктовку, затем попробуйте ещё раз.» |

Измерение запускается только на шаге 4 при наличии хоста, до завершения мастера
и выхода из приложения, если оно ещё не идёт и нет проверки в `preparing`,
`recording`, `processing`. Кроме того, мост отказывает, если окно **скрыто или
свёрнуто** в момент вызова: видимость читается у самого окна, а не по прошлому
событию. Эпизод измерения ограничен `LEVEL_TOTAL_LIMIT_S = 180` с — по
истечении мост сам останавливает микрофон и переходит в `idle` с пояснением. Рантайму нужен работающий воркер; занятая диктовка
или ожидающая проверка не допускает параллельного измерения. Индикация записи
включается до открытия микрофона. Простое открытие шага в Python измерение не
запускает: QML должен вызвать слот.

`stopLevelMonitor()` останавливает измерение без распознавания. Остановка
асинхронна: штатное `idle` приходит только после освобождения микрофона.
Оркестратор посылает `record.cancel`, при отсутствии ответа — `audio.close`,
затем при необходимости перезапускает воркер. Измерение также останавливается
при успешной смене шага (в том числе «Назад»), скрытии или закрытии окна,
сигнале `deviceChanged`, завершении мастера и выходе из приложения. Смена
устройства не запускает измерение автоматически заново. При явной остановке
последний `peak` может остаться; очистка проверки при уходе со шага, смене
устройства или закрытии окна сбрасывает его.

`startTest()` требует `modelReady`. Если модели нет, запись не начинается,
`testState` не меняется, а `testMessage` становится «Будет доступно после
установки модели». Если готовая модель есть и измерение ещё идёт, контроллер
сначала останавливает его и ждёт `idle`, а затем запускает проверку;
ошибка остановки этот отложенный запуск снимает. Установленной модели ещё
может потребоваться загрузка в воркер — тогда действует `preparing`.

Во время записи проверки уровень тоже обновляется из `peak_dbfs`.
При переходе к распознаванию `level` сбрасывается в 0, а последний `peak`
остаётся до сброса проверки. При `level <= 0,02` экран показывает «Пока тишина»,
при `level > 0,02` — «Слышим вас».

**Приватность (PRD S1-A5): распознанный текст проверки виден ТОЛЬКО на экране
шага 4.** Он не попадает в журнал, статистику, уведомления, буфер обмена или
вставку и не становится последней фразой для копирования из трея. Уход со шага,
скрытие или закрытие окна, сигнал смены устройства и завершение мастера очищают
результат и отменяют активную проверку. Запоздавший ответ не возвращает текст.

Это правило закреплено тестами: статическая проверка
`tests/unit/test_bridges.py::test_microphone_text_never_reaches_log_ast`
запрещает передавать речь проверки в журнал, в том числе через промежуточные
переменные. `test_microphone_privacy_ast_gate_detects_leaks` проверяет сам этот
запрет на примерах утечек. Полный цикл без вставки, статистики, уведомлений и
сохранения последней фразы проверяет
`tests/unit/test_dictation.py::test_microphone_test_cycle_is_private`.

### 4.6 Слоты, которые вызывает интерфейс

| Слот | Аргументы | Что делает |
|---|---|---|
| `next()` | — | Следующий шаг. Номер шага сначала сохраняется; если запись не удалась, шаг не меняется |
| `back()` | — | Предыдущий шаг, те же правила |
| `skip()` | — | То же, что `next()`: онбординг пропускается по экранам |
| `toggleModel(model_id)` | `string` | Переключить выбор карточки по `id`; неизвестный `id`, непустой `badge`, занятая очередь/поток или выход — ничего не менять |
| `startSelectedDownloads()` | — | Запустить выбранные записи без `badge` в порядке каталога; пустой выбор, отсутствие сервиса, занятая очередь/поток или выход — ничего не делать |
| `retryModel(model_id)` | `string` | Повторить только эту карточку в `failed` или `no-space`; для других состояний или неизвестного `id` — ничего. Общие ограничения запуска очереди сохраняются |
| `cancelDownloads()` | — | Отменить общую очередь или перепроверку, включая проверку/установку; подробности в разделе 4.3 |
| `installFromPath(path)` | `string` | Установить **рекомендованную** запись из локальной папки или файла через общую очередь. Принимает обычный путь, `file://…` и раскрывает `~`; пустой путь или отсутствие рекомендованной записи ничего не делают. Сеть не используется; занятая очередь/поток и выход блокируют запуск |
| `openModelsFolder()` | — | Открыть каталог моделей в файловом менеджере (`QDesktopServices`). Путь в QML не передаётся; если каталога нет, слот ничего не делает |
| `pickInstallPath()` | — | Открыть диалог выбора папки (`QFileDialog.getExistingDirectory`); непустой результат передать в `installFromPath(path)`. Отмена ничего не делает |
| `beginCapture()` | — | Начать назначение комбинации: захватить клавиатуру. Не удалось — состояние `not-grabbed` |
| `endCapture(combo)` | `string` | Завершить назначение нажатой комбинацией. Пустая строка = отказ, возвращает в `idle` |
| `cancelCapture()` | — | Отменить назначение, снять захват, вернуться в `idle` |
| `keepCombo()` | — | «Оставить» занятую комбинацию: работает только в состоянии `conflict` при непустом `pendingCombo` |
| `refreshCandidates()` | — | Обновить `freeCandidates` живым опросом системы |
| `startLevelMonitor()` | — | Начать измерение уровня без модели на шаге 4; не меняет `testState`, условия запуска — в разделе 4.5 |
| `stopLevelMonitor()` | — | Остановить измерение без распознавания и снять отложенный запуск проверки; штатный `idle` означает освобождение микрофона |
| `startTest()` | — | Начать проверку выбранного микрофона только при `modelReady`, на шаге 4 при наличии хоста, до выхода и завершения мастера, если проверка ещё не идёт. Без модели — только `testMessage = "Будет доступно после установки модели"`; активное измерение сначала останавливается |
| `stopTest()` | — | Остановить запись и перейти к распознаванию; если уже идёт распознавание — отменить его. Если проверка ещё ждёт загрузки модели — сбросить ожидание в `idle` |
| `finish()` | — | Завершить онбординг: сохранить отметку, очистить проверку, вызвать `reload_model()` хоста, показать уведомление с напоминанием комбинации и спрятать окно. Не сработает, пока `canFinish` ложно, мастер уже завершён или отметку не удалось сохранить |

После успешной записи `onboarding_done` контроллер вызывает
**`OnboardingHost.reload_model()`**. В `app.py` этот порт вызывает
`runtime.reload_model()`: если текущая модель уже загружена и успешно прошла
самопроверку, а загрузка не идёт, вызов ничего не делает. Воркер перезапускается
с ожиданием модели только если модель изменилась, не загружена, загрузка ещё
идёт или самопроверка не завершилась успехом. Если текущий запрос модели не
удалось определить, воркер также перезапускается. Модель работает без
перезапуска приложения; при перезапуске воркера обычная диктовка ждёт загрузки
модели. Ошибка вызова записывается в журнал, но не отменяет завершение мастера.

Метод `shutdown()` слотом не является — его зовёт `app.py` при выходе, чтобы
остановить измерение и отменить проверку. Собственную очередь контроллер
завершает сам; общую очередь `ModelDownloads` отдельно завершает `app.py`.
Поток установки ожидается не больше пяти секунд;
если он ещё занят, приложение продолжает выход с предупреждением в журнале.

устройство — через `SettingsBridge.device`.

| Ключ | Тип | Кто пишет |
|---|---|---|

### 4.8 Устарело, удалим после второй волны QML

`modelState`, `modelName`, `modelHost`, `modelSize`, `modelSizeBytes`, `modelRam`,
`modelMessage`, `progress`, `download()` и `cancelDownload()` оставлены лишь
ради нынешнего QML (`Step2Model.qml`, `OnboardingModelCard.qml`). Свойства
описывают **только рекомендованную модель**, а не весь каталог и не очередь.
`download()` тоже запускает только рекомендованную запись. Исключение по
действию: `cancelDownload()` теперь делегирует отмену **всей** общей очереди.

Для нового QML используйте `models` вместо одиночной карточки,
`downloadState` / `downloadProgress` / `downloadTitle` вместо состояния и
прогресса одной модели, `startSelectedDownloads()` / `cancelDownloads()`
вместо `download()` / `cancelDownload()`. Повтор отдельной карточки —
`retryModel(id)`. `speed` и `eta` остаются актуальными общими свойствами из
раздела 4.3 и уже возвращают готовые строки целиком.

| Свойство | Тип | Доступ | Значение |
|---|---|---|---|
| `modelState` | `string` | только чтение | Состояние рекомендованной модели для старой карточки, перечень — ниже |
| `modelName` | `string` | только чтение | Имя рекомендованной записи каталога; пусто, если каталога нет |
| `modelHost` | `string` | только чтение | Узел, откуда скачивается модель (для карточки и сообщений) |
| `modelSizeBytes` | `int` | только чтение | Размер в байтах |
| `modelSize` | `string` | только чтение | Тот же размер строкой, например `«226 МБ»` |
| `modelRam` | `string` | только чтение | Требуемая память из `min_ram_mb` записи каталога, например `«768 МБ»`; пусто, если записи нет |
| `progress` | `real` | только чтение | Доля загрузки от 0 до 1; нечисловые значения приводятся к 0 |
| `modelMessage` | `string` | только чтение | Готовая фраза для пользователя под карточкой |

#### Допустимые значения `modelState`

| Значение | Что это на экране | Текст в `modelMessage` |
|---|---|---|
| `absent` | Каталога моделей нет — скачивать нечего | «Каталог моделей недоступен. Попробуйте открыть приложение ещё раз.» |
| `downloadable` | Можно скачать: место есть, памяти хватает, сеть разрешена | «Модель будет скачана с ‹узел›, объём — ‹размер›.» |
| `downloading` | Идёт скачивание; работают `progress`, `speed`, `eta`, доступна отмена | «Скачиваю модель с ‹узел›…» |
| `verifying` | Проверяются контрольные суммы файлов; нынешняя карточка QML не показывает отмену, но общий слот её принимает | «Проверяю целостность файлов модели…» |
| `installing` | Перенос в хранилище и пробное распознавание | «Устанавливаю модель и проверяю пробное распознавание…» |
| `installed` | Рекомендованная модель готова; готовность мастера определяется отдельно через `modelReady` | «Модель установлена и готова к работе.» |
| `broken` | Модель не прошла проверку или установка не удалась; можно повторить | «Модель не прошла проверку. Попробуйте скачать или установить её заново.» либо безопасное пояснение самопроверки или отзыва версии (раздел 4.3) |
| `no-network` | Сети нет или она запрещена; предлагается установка из папки | «Нет доступа к ‹узел›. Можно установить модель из папки.» либо причина из политики |
| `no-space` | Не хватает места на диске | «На диске не хватает ‹столько-то›. Освободите место.» — точный дефицит, если хранилище умеет его посчитать; иначе общая фраза с размером модели |
| `no-ram` | Оперативной памяти может не хватить — **предупреждение, не запрет**: скачать по-прежнему можно | «Может не хватить оперативной памяти. Можно скачать и проверить модель.» |
| `cancelled` | Пользователь отменил загрузку; можно продолжить | «Загрузка отменена. Можно продолжить скачивание.» |

Ровно этот перечень (кроме `absent`) должен быть в `qml/components/OnboardingModelCard.qml` —
это сверяется тестом `test_component_state_names`, а `tests/xvfb/test_onboarding.py`
снимает эталонный снимок каждого состояния в светлой и тёмной теме.

Как считается начальное состояние: нет сервиса или рекомендованной записи →
`absent`; рекомендованная запись имеет `ok` → `installed`; та же запись имеет
`broken` → `broken`; сеть запрещена → `no-network`; мало места → `no-space`;
мало памяти → `no-ram`; иначе `downloadable`. Отметка `recheck` отдельно
учитывается в `modelReady`, даже если старое состояние уже `installed`.

Скачивание и установка идут в отдельном потоке `QThread`; интерфейс общается с
ним только сигналами, отмена — через событие. Итог публикуется **после** выхода
потока, чтобы повторная попытка сразу была возможна. Внутренние причины ошибок
наружу не выходят — только безопасные фразы из таблиц: распознанный текст или
ответ сервера могут содержать речь пользователя.

| Устаревший слот | Аргументы | Что делает сейчас |
|---|---|---|
| `download()` | — | Скачивает рекомендованную модель в состояниях `downloadable`, `no-ram`, `cancelled`, `broken`. Перед этим для `no-network`, `no-space`, `no-ram` заново вычисляет начальное состояние. Занятая очередь или поток и выход из приложения блокируют запуск |
| `cancelDownload()` | — | Делегирует `cancelDownloads()`: отменяет общую очередь или перепроверку, в том числе на стадии `verifying`; прежнее ограничение только состоянием `downloading` больше не действует |

## 5. Чего в контракте ещё нет

### 5.0 Отдано мостом на M6, ждёт QML

`models[].vendor`, `models[].tags` и `models[].metrics` мост считает по
подписанному каталогу из двенадцати записей (раздел 4.3), и оба экрана —
`qml/onboarding/Step2Model.qml` и `qml/sections/Models.qml` — берут их оттуда:
зашитые цифры рекомендованной записи убраны.

Ждёт QML слот перезапуска звуковой службы для баннера «Микрофон молчит»: он
появится вместе с поднятием громкости микрофона (PRD 0.9, F6.6–F6.8).


Честный список на 2026-09-21. Каждый пункт проверен по текущему коду.

Каталог `models`, выбор нескольких моделей и общая очередь, сквозной прогресс,
перепроверка `recheck`, измерение уровня без модели и свойства текущей модели
с переустановкой **уже есть в Python-контракте** (разделы 3.6, 4.3, 4.5).
Перенос экранов на эти свойства — отдельная вторая волна QML: нынешний шаг 2
ещё использует совместимость из раздела 4.8. Это не отсутствие слотов в мосте.

* **`conflictOwner`.** Имени программы или действия, занявшего комбинацию,
  в мосте нет. `Step3Hotkey.qml` по-прежнему передаёт `conflictOwner: ""`.
* **«Открыть папку» при нехватке места.** Обработчик `onOpenFolderRequested`
  в `Step2Model.qml` пуст, слота открытия хранилища нет. Это отдельное действие
  от работающего `pickInstallPath()`, который выбирает папку для установки.
* **Звук начала и конца записи.** Тумблер в `General.qml` начинается с
  `checked: false`, но к мосту не привязан: свойства для звука нет, выбор
  не сохраняется и не применяется.
* **Ошибка сохранения в мастере.** `saveError` уже виден в баннере «Общих»,
  но файлы `qml/onboarding/` его не читают. При отказе сохранения мастер
  оставляет прежнее значение или шаг, не показывая причину.
* **`modelSelfcheck` не связан с рантаймом.** `General.qml` уже показывает
  состояния `running` и `failed`, но `set_model_selfcheck` в рабочем коде никто
  не вызывает. Мост остаётся в `idle`; рантайм ведёт свою самопроверку и пишет
  её итог в локальную статистику. Значения `idle`, `running`, `ok`, `failed`
  проверяются тестом `test_runtime_status_setters`.
* **Запасной признак готовности.** `settings.extra["onboarding_model_ready"]`
  рабочий код только читает. Без сервиса моделей и заранее записанного `true`
  свойство `canFinish` остаётся ложным.
* **Автозапуск.** `autostart` сохраняется в файл, но не создаёт и не удаляет
  системную запись автозапуска.
* **Ограничения шага 3 в QML.** `CaptureField` собирает комбинации только
  с буквами A–Z, цифрами, Space и F1–F12; остальные основные клавиши не
  поддержаны. Комбинация передаётся по нажатию, ожидания отпускания нет.
  Прежние пробелы в подключении устранены: используются `endCapture(combo)`,
  `cancelCapture()`, `keepCombo()`, `refreshCandidates()`, а также
  `pendingCombo`, `captureMessage` и `freeCandidates`.

   контракта. Подключённые к QML значения сравниваются посимвольно. Список
   состояний нынешней карточки и поля
   захвата проверяет `tests/unit/test_qml_onboarding_static.py::test_component_state_names`;
   переименование без правки спецификации и теста ломает экран молча.
3. **Распознанный текст не выходит за пределы вставки.** Ни в журнал, ни в
   уведомления, ни в статистику, ни в подписи интерфейса. Сообщения об ошибках
   моста — фиксированные фразы из таблиц выше, а не текст исключения, ответа
   сервера или результата распознавания: в них может оказаться речь пользователя.
   На шаге «Микрофон» распознанная фраза видна только на экране шага 4:
   ни буфер обмена, ни вставка, ни другие каналы её не получают (раздел 4.5).
4. **Не оставлять несохранённое значение.** Пилюля и устройство применяются
   после удачной записи файла. Клавиша сначала проверяется живым применением;
   при отказе записи возвращается прежний перехват. Ошибка сохранения заполняет
   `saveError`, значение откатывается (раздел 3.2).
5. **Тексты — простым языком.** Ни путей, ни имён звуковых устройств, ни имён
   системных служб: `test_qml_onboarding_static.py::test_user_text_has_no_technical_words`
   ищет в подписях `/usr`, `/etc`, `~/`, `alsa`, `pipewire`, `systemctl`, `hw:` и
   подобное и роняет сборку. Технические подробности — только в «Отладке» и в
   документации.
6. **Цвета — только из `Theme`.** Шестнадцатеричные литералы и `Qt.rgba(...)` в
   файлах интерфейса запрещены тестом: страница обязана одинаково выглядеть в
   светлой и тёмной теме.
