# Заметки к выпуску: стиль и шаблон

Правило владельца от 13.10.2026, действует для всех выпусков начиная с 0.1.3.

Заметки к выпуску — это тело GitHub Release. Программа показывает его в панели «Что нового»
(`net/github.py` → `ui/updates_bridge.py:display_notes` → `qml/components/UpdatePanel.qml`).
Тот же текст видят на странице выпуска на GitHub. Пишет его changelog-writer. Подробный список
изменений остаётся в `packaging/debian/changelog` и в журнале решений, в тело выпуска он не идёт.

## Структура

1. **«Главное»** — 1–3 пункта о ключевых новых возможностях. Пишем человеческим языком
   и с пользой для пользователя. Пример: «Программа сама находит новые версии в интернете
   и обновляется в пару нажатий».
2. **«Также»** — одна-две обобщённые строки без подробностей: «Улучшения интерфейса»,
   «Исправления ошибок», «Повышена надёжность».
3. **«Для администратора»** — только если для выпуска действительно нужно действие администратора
   или есть важное о безопасности и совместимости (новая зависимость, смена ключа,
   нужна переустановка .deb). Если такого нет, раздела нет.

Если новых возможностей в выпуске нет (только исправления), «Главное» не нужно: тогда пишем
один раздел «Также».

## Чего в теле нет

- номеров PR и задач, кодов замечаний (UI-…, M-…), хешей коммитов;
- имён файлов кода, классов, внутренних терминов (QML, фокус-кольцо, ETag, S1 и т. п.);
- перечня мелких исправлений и описания того, «как было раньше»;
- списка файлов выпуска, отпечатка ключа и инструкций по проверке подписи. Отпечаток передаётся
  администраторам отдельно, по `docs/INSTALL-ADMIN.md` §«отпечаток мастер-ключа»: в теле выпуска,
  которое не подписано, он ничего не подтверждает.

## Формат: что умеет панель

Панель выводит тело **простым текстом** (`Text.PlainText`), разметку не обрабатывает:

| В теле | В панели |
|---|---|
| `- пункт` (также `*` и `+`) | пункт с точкой-маркером и висячим отступом |
| `## Заголовок` | обычная строка без решёток, не жирная. Строка «Что нового» пропускается |
| пустая строка | убирается |
| `**жирный**`, `_курсив_`, `[ссылка](…)`, `` `код` `` | **показываются как есть, вместе со звёздочками и скобками** — не использовать |
| таблицы, картинки, HTML | показываются как сырой текст — не использовать |

Поэтому пишем только заголовки `##` и пункты `- `. Заголовок с версией не нужен:
панель показывает версию сама, а на GitHub она есть в названии выпуска.
Ширина панели около 600–750 px: держим каждый пункт в пределах 1–3 строк, а всё тело —
не длиннее примерно 800 знаков. Жёсткий предел панели — 2000 знаков, дальше текст обрезается.

## Шаблон

```markdown
## Главное

- <Новая возможность: что теперь может пользователь и чем это ему полезно.>

## Также

- Улучшения интерфейса.
- Исправления ошибок.

## Для администратора

- <Только если нужно действие администратора или есть важное о безопасности; иначе раздел удалить.>
```

## Порядок при выпуске

1. changelog-writer кладёт тело в `dist/release-<версия>/release-notes.md` по этому шаблону.
2. CI создаёт Release с `--generate-notes` (`.github/workflows/ci.yml`). Сразу после этого тело
   заменяется: `gh release edit v<версия> --notes-file dist/release-<версия>/release-notes.md`.
   Это условие У-3 из ИБ-проверки выпуска.
3. Сверка: `gh release view v<версия> --json body` должен совпасть с файлом (ИБ-T3-013-2).

Тело выпуска не подписано и в проверку обновления не входит: обновление сверяется только по тегу,
версии и подписанным `SHA256SUMS` / `latest.json`. Поэтому тело уже опубликованного выпуска можно
исправить через `gh release edit`. Пользователь увидит новый текст при следующей проверке обновлений.
