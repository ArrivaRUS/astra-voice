# Подтверждения IPC для US-2.6/2.7

GUI отправляет команды через `WorkerSupervisor` процессу воркера; воркер подтверждает результат своей команды, а не последней команды GUI. ACK закрытия захвата фразы — ответ воркера с `request_type`, поставленным самим воркером, отправленный только после `capture.wait_stopped(utterance_id)` потока захвата этой фразы; `record.stopped` — отдельное уведомление о физическом закрытии, не подтверждение отмены задания распознавания. Супервизор коррелирует ожидания по `utterance_id` **и типу запроса** (по одному ожиданию на тип для одного id), сохраняет тип из ответа через `setdefault`, не перезаписывает его и сохраняет сроки ожиданий и маршрут независимых событий; уведомления продлевают сроки текущих стадий записи, но не срок отмены, поскольку не подтверждают её завершение. GUI не принимает поздний ответ другого поколения или ответ на другую команду за ACK отмены: индикатор и страж удерживаются до подтверждения закрытия либо завершения процесса при эскалации. Это относится также к измерению уровня. `PROTOCOL_MISMATCH` делает поколение терминальным: поздние события, таймеры, отложенные и новые жесты не запускают запись, пробуждение модели или воркер; каждый новый жест снова показывает «Программа обновлена — перезапустите её», трей остаётся ERROR. Перезахват клавиш продолжает обслуживаться, но не снимает эту ошибку. Терминальность снимает только явный `restart_worker` или перезапуск программы.

| Отправитель → получатель | Команда / событие | Подтверждение и действие |
|---|---|---|
| GUI → воркер | `record.start(uid)` | `record.started` сообщает о начале захвата; не подтверждает закрытие. |
| GUI → воркер | `record.stop(uid)`, `recognize(uid)` | Ответ сохраняет собственный `request_type`; любой `bad-state` при живом владельце захвата задерживается до `wait_stopped(uid)`. Ответ не погашает ожидание `record.cancel(uid)`. |
| GUI → воркер | `record.cancel(uid)` | `cancelled` или `bad-state` с типом `record.cancel` после `wait_stopped(uid)` подтверждают закрытие и отсутствие задания; GUI завершает очистку. |
| GUI → воркер | `audio.close` | `audio.closed` с типом `audio.close` после ожидания физического закрытия подтверждает закрытие источника, но не отмену задания распознавания. |
| Воркер → GUI | `record.stopped(uid)` | Отдельный маршрут уведомления после успешного физического закрытия; снимает только владение захватом. Ошибка закрытия запрещает уведомление и приводит к `CaptureStopTimeout` / завершению процесса. |
| Воркер → GUI | Незатребованный `error`, уведомления | Доставляются независимо от ожидания ответа; не получают тип другой команды и не становятся ACK её закрытия. |
| Супервизор → GUI | Таймаут / завершение процесса | Сохраняется корреляция конкретного ожидания; таймаут сам не доказывает закрытие. GUI выполняет эскалацию, завершение процесса закрывает микрофон средствами ОС. |
| GUI | Поздний / неожиданный ответ | Не меняет владельца захвата, не завершает чужое ожидание; терминальное поколение не оживляет. |

Версия протокола — **4**: типы в `cancelled`, `audio.closed` и `result`, а также барьер физического закрытия перед ACK являются частью контракта, а не необязательным расширением версии 3.

| GUI + воркер | Совместимость |
|---|---|
| Новый GUI (v4) + старый воркер (v3) | `hello protocol=3` → `PROTOCOL_MISMATCH` → терминальное поколение, «Программа обновлена — перезапустите её». Команды `record.*` не отправляются. |
| Старый GUI + новый воркер | При разборе кадров лишние поля отбрасываются. Это совместимость полей, а не версий: GUI с проверкой равенства версии отклоняет `hello protocol=4` и требует перезапуска. |
| Новый GUI (v4) + новый воркер (v4) | Подтверждения принимаются по типу, поставленному воркером, и только своим ожидающим контекстом. |

Ожидание `audio.closed` принадлежит контексту и поколению, успешно отправившим `audio.close`. Отказ отправки (в том числе уже ожидающий ответа глобальный `audio.close`) не создаёт ожидания: поздний ACK прошлого запроса не закрывает новый захват. Подтверждение физического закрытия само по себе не отменяет задание распознавания.

Таймаут отмены сохраняет таймер завершения фразы с отложенным исходом. После позднего ACK или подтверждённого выхода процесса завершающий tail переводит фазу в IDLE, восстанавливает трей и вызывает `on_idle` для выгрузки по простою и отложенной смены модели.

Отправка SIGKILL не подтверждает закрытие. Супервизор ждёт до 0,2 с, затем при живом процессе проверяет выход по таймеру неблокирующими wait/poll и повторяет SIGKILL не чаще раза в 2 с; до `poll() is not None` не меняет поколение и не отправляет события завершения, которые снимают страж и `_capture_open`. Новое поколение запускается после подтверждённого выхода прежнего процесса.

Переход фразы в IDLE после tail ещё не доказывает закрытие микрофона. Начало отложенной смены модели и продвижение готового кандидата ждут завершения `cleanup_pending`; отказ остановки прежнего воркера не разрешает замену супервизора. Это сохраняет страж и владение захватом при задержанном выходе процесса даже после завершения показа исхода фразы.

При ожидании потока захвата его собственный deadline фиксируется один раз. Сроки других живых потоков определяют лишь момент пробуждения для `check_stop_watchdog` и пересчитываются на каждой итерации; завершившийся сосед не сокращает срок владельца. Исключение в освобождении PulseAudio-дескриптора не приводит к повторному `free`: ссылка на дескриптор обнуляется до вызова освобождения.

Терминальность снимает только явный `restart_worker` (действие трея «Перепроверить») или перезапуск программы. Проверка микрофона, применение и смена модели терминальность не снимают: повторяют причину перезапуска, оставляют трей ERROR и не создают воркер.

**INFO: наследование срока.** Если `send` не получил явный timeout, запрос с тем же id, включая `record.cancel`, наследует timeout и абсолютный deadline соседнего ожидания. Наследование не начинает новый отсчёт; последующие уведомления не продлевают срок отмены.
