# Сигналы начала и конца записи

Узкое расширение IPC v3: `record.started {utterance_id}` и
`record.stopped {utterance_id}` — уведомления, не ответы на команды.
Супервизор добавляет поколение своего соединения; уведомления не закрывают
ожидание результата. `record.stopped` может прийти после `result`, `error`
или `cancelled`; поздние данные ASR при этом по-прежнему отбрасываются.

`AudioCapture` публикует started после успешного открытия/flush и проверки
флага продолжения, перед чтением PCM. stopped публикуется только после возврата
`source.close()`, если started было опубликовано. При неудачном открытии пары
нет; при зависшем/неудачном закрытии подтверждения stopped нет. `audio.ready`,
UI-фаза и отпускание клавиши не являются подтверждениями остановки источника.

Оркестратор допускает только зарегистрированные обычные диктовки и команды
Cowork; тест микрофона, level monitor и transcribe.file не регистрируются.
Ключ — `(generation, utterance_id)`, по одному callback на границу; не больше
восьми ожиданий позднего закрытия. Shutdown не озвучивается.

Настройка `sound_cues_enabled` — bool, по умолчанию false. Qt-контракт:
`soundCuesEnabled` (записываемое свойство, notify), `soundCuesStatus` (строка,
notify). Сохранение атомарно; неудача откатывает значение до применения.

Playback — один фоновый поток и не больше одного `/usr/bin/paplay`, фиксированный
argv, shell=False, close_fds=True, PCM через stdin. 110 мс, S16LE mono 48 kHz,
пик не выше −18 dBFS; восходящий/нисходящий chirp с плавными краями. Это уровень
цифрового сигнала, не обещание физической громкости колонок. Нет новых библиотек
или ресурсов и нет связи отказа playback с процессом ASR.

До проигрывания ничего не подключается к PulseAudio. Собственный запечатанный
Linux memfd (0600, write/grow/shrink/seal запрещены) содержит только
`autospawn = no`; чужие конфиги не включаются. Через pass_fds наследуется
только этот конфиг, PULSE_CLIENTCONFIG указывает на `/proc/self/fd/<fd>`.
Дескриптор остаётся доступным child даже при неудаче reap после закрытия
родительской копии; конфиг не может исчезнуть раньше проигрывателя. Окружение внешнего child очищается штатным clean_env, затем путь
конфига заменяется нашим; PULSE_SERVER/SINK/COOKIE сохраняются. `default-server`
только в чужом client.conf не переносится: административный endpoint для cues
следует задавать PULSE_SERVER. Устройство и громкость не меняются.

Очередь ограничена четырьмя элементами и сроком начала 350 мс. При stop удаляется
ещё не начавшийся start той же записи, повторы подавляются. Подтверждённая граница
не гарантирует звук при перегрузке или ошибке проигрывателя. communicate имеет
общий бюджет 1 с; затем terminate/wait/kill/wait (по 200 мс). Все ожидания child
выполняются вне GUI; shutdown запрещает задания и ожидает поток не более 600 мс.
Неубранный child или живой поток сохраняются для проверки app перед handoff.

Один ленивый SessionMonitor используется совместно с Cowork. Звуки требуют
known/active/unlocked, отсутствия lock_requested и preparing_for_sleep; supported
остаётся ограничением Cowork. `Active` читается из login1 GetAll как строгий bool; отсутствие или неправильный
тип делает сеанс неизвестным. Изменённый/инвалидированный `Active` вызывает полное
перечитывание с немедленным закрытием допуска. Общий snapshot содержит настоящее
active: существующий command guard также закрывается для неактивного сеанса.
Отдельный `cue_epoch` увеличивается при потере допуска звуков независимо от
supported, включая Fly known→unknown→known до доставки GUI-callback. Command
blocked_epoch и его контракт остаются отдельными.
Снимок, cue_epoch и sleep_epoch проверяются повторно в playback
thread без Qt-вызовов. Отключение, запрет сеанса и shutdown инвалидируют очередь.
Неизвестный сеанс отражается в статусе и не препятствует диктовке.

Проверки автора — только fake playback/capture/session и анализ PCM в памяти.
Фактическая слышимость KDE/Fly, задержка устройства вывода и акустическое попадание
стартового звука в микрофон требуют разрешённой живой проверки. Захват не
задерживается, первые кадры речи не отбрасываются. AppImage использует paplay
хоста: при отсутствии показывается недоступность, пакет автоматически не ставится.
