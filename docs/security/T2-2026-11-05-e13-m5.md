### Проверено — находок нет

- **Снос через dirfd (MJ-14, MN-6, T-433).**
  - `purge_deleted` берёт `.store.lock` корня и аренды всех писателей (`GUI`, `CAPTURE`, `TRANSCRIBE`, `DIAR`) с `LOCK_NB` — живой владелец даёт отказ, а не ожидание.
  - `_erase`: `lstat` → `open(O_DIRECTORY|O_NOFOLLOW)` → сверка `(st_dev, st_ino)` открытого с `lstat` → `list(scandir)` до удаления → рекурсия только через dirfd → повторный `lstat` перед `rmdir`. Чужой uid или другое `st_dev` — отказ.
  - Симлинк `.deleting-<id>` (на HOME) — удаляется сама ссылка, цель цела. Симлинк внутри — только `unlink`. Подмена файла каталогом между `lstat` и `unlink` даёт ошибку, не выход за корень. Перенос каталога наружу во время сноса — данные уходят из-под dirfd только у процесса того же uid (П26).
  - Глубокая вложенность — `RecursionError` ловится, надгробие остаётся.
  - Воскрешение исключено: `create`/`reserve` отказывают при `.deleting-<id>`; `list` скрывает `<id>` при наличии `.deleting-<id>`.
- **Надгробие и владельцы (Д12).** Любое состояние → DELETING разрешено напрямую, промежуточного TRANSCRIBING нет. Поколение +1 отсекает публикации роли. `_update` не пишет поверх DELETING, а при надгробии в памяти пишет только само надгробие. Пока надгробие не записано, события роли буферизуются и при отказе переигрываются; роль удерживается (`_advance`, `_handle_exits`). Выход — только подтверждённый: даже `restart-limit` при `purpose == "delete"` идёт в `_kill`. Допуск в очередь проверяет надгробие в своём завершении. Экспорт в полёте и открытый системный диалог держат освобождение (`_release_files`, `cardSaveFinished`).
- **Rename после выхода владельцев** (отклонение от arch §3.6): DELETING в `meeting.json` уже устойчивая отметка, поэтому переименование после выхода безопасно и не даёт роли писать в скрытый каталог. Согласен.
- **Сроки (Д6).** Звук — только при `DONE + SUCCEEDED + !cancelled`, по `finished_at + retain_days`, зафиксированному при успехе. Встречи — по `started_at`, не по имени каталога; RECORDING/PAUSED пропускаются. `cleanup_pending` пишется до `unlink`, после сбоя доводится без ASR, текст цел. Настройки: 0–365 и {0, 30, 90, 365}, `OverflowError` ловится. Во время прохода допуск расшифровок закрыт (`_schedule`).
- **Решение Юрки 04.11 (сроки вне гейта).** С позиции ПДн третьих лиц — правильно: срок — политика минимизации, заданная пользователем или администратором. Удалять встречи вручную можно и под запретом политики (`deleteEnabled` от политики не зависит). Подпись при выключении «Сохранённые встречи останутся…» формально верна. По умолчанию оба срока «никогда» (`meeting_retention_days = 0`), удаление по возрасту включает только явный выбор. Баннер не нужен. Риск ожиданий — строкой в `threat-model.md`.
- **Экспорт (MN-1, MN-3, MN-15).** Кроме I-1, каждое поле — один code span (фазз 476 случаев + 96 комбинаций у Sol). `|` в ячейке статистики экранируется и внутри code span (GFM). Предпросмотр ограничен (6/3 строки, 240/600 символов, 8 строк статистики), весь QML — `PlainText`.
- **Переименование (D3, MN-3, MN-12).** Отказ при надгробии, DELETING, RECORDING/PAUSED и во время сохранения записи. NFC; Cc/Cf/Cs (в т. ч. U+202E) → отказ до схлопывания пробелов; 1–120.
