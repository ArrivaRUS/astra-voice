  - `_check_dir`: realpath равен `<root>/<id>`; дальше все открытия через dirfd.
  - WAV читается по `check_private_file`. Разбор заголовка ограничен 4 КиБ, бесконечного цикла нет.
  - Совокупные пределы: 4 ч, 9000 реплик, кандидатов ≤ 4×ёмкости, стена 2×длительность + 10 мин, окно ASR 60 с. Кредиты ≤ 4096, выдача событий не растёт при неживом читателе.
  - Отмена: fence и подтверждение только без записи в полёте. Чекпойнт — только текст и числа (BL-3 для M4).
  - Запуск: `harden_process(strict)` + `RLIMIT_AS` + nice 19, stderr в `/dev/null`, журналов в роли нет.
- **Гейт политики.**
  - `_jobs_allowed` = `enabled() and policy_allowed()` на каждом тике. Под запретом:
    - допуск не стартует (`_schedule`, повторная проверка в `_admit`);
    - бегущее задание останавливается без отмены (`suspend`), резюм — после снятия запрета;
    - «Расшифровать» ничего не делает;
    - `recover`/`on_recorded` не ставят задания;
    - запись встречи останавливается с сохранением.
  - D1 включается только через диалог ответственности: `setSetting` отвергает `meetings_enabled`.
  - `ASTRA_VOICE_MEETING_CAPTURE_DEV` удалён полностью (grep).
- **M3: авто-продолжение.** Срабатывает только при причинах ⊆ {`lease`, `indicators`} и без `manual_resume_required`. Дополнительно требуются:
  - свежая аренда (< 5 с);
  - аттестация GUI `indicators_visible` (X11 `map_state == IsViewable` и пересечение с экраном, или подтверждённый SNI трея с иконкой встречи);
  - эпоха блокировки не менялась с начала паузы;
  - окно 1 с на собственных часах capture;
  - повторная проверка внутри нативного connect.
  - Устаревший или повторный keepalive (`seq`) аттестовать не может; потеря видимости во время авто-открытия закрывает поток.
  - Пауза ≥ 3600 с — терминальный стоп и в GUI, и в capture.
  - Блокировка экрана — по-прежнему только ручное продолжение (BL-5).
- **Утечки.**
  - Все новые записи журнала — константные коды.
  - Уведомления — постоянный текст, название встречи не передаётся (решение 03.11).
  - QML — `PlainText` везде. Единственный `RichText` (текст уведомления собеседникам в `MeetingNotice.qml:180`) экранирует `& < > "` до вставки. Копирование — только `text/plain`.
  - Подсказка трея — состояние, время и имя микрофона, без названия встречи.
- **Действия уведомлений.** «Продолжить» и «Продлить» из уведомления — нажатие человека через сервер уведомлений. QtDBus фильтрует `ActionInvoked` по владельцу `org.freedesktop.Notifications`. Подделать может только процесс того же uid, занявший это имя, — это принятый риск П1/П26 (под X11 тот же uid и так нажмёт кнопку через XTest).
