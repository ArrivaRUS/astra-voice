# Кнопка мыши для команды Cowork: порт runtime

Настройки, отдельный X11-бэкенд, мост и общий путь Command1 подключены в runtime.
Статус проверки и поставки конкретной ревизии — в отчёте
[2026-10-09-cowork-mouse.md](../reports/2026-10-09-cowork-mouse.md).

## Настройки и локальный выбор кнопки

- `command_mouse_enabled: bool = False`, `command_mouse_button: int = 2`.
- Сохраняется **логическая X11-кнопка**: средняя `2` или дополнительные `8…31`.
  Левая/правая `1/3`, прокрутка `4…7`, bool и неверный тип/диапазон запрещены.
  Некорректное сохранённое значение выключает только управление мышью;
  номер сбрасывается на 2, включение остаётся явным действием пользователя.
- `qt_button_to_logical(int(event.button))`: Qt MiddleButton `4 → 2`;
  дополнительная кнопка `1 << k → k + 5`, `k=3…26`. Комбинации битов
  отвергаются. Число Qt нельзя записывать как готовый номер X11.
- Карточка Cowork в существующих «Продвинутых» сохраняет выбор клавиши.
  Мышь — дополнительный независимый источник команды, не замена клавиатуры.
- Локальный выбор кнопки не использует глобальный захват. Перед открытием
  выбора runtime берёт общий capture lease и снимает регистрации команд.
  При уже начатом pending/recording/processing/preview или другом редакторе
  открытие отклоняется. Завершение, Esc, потеря фокуса и закрытие окна освобождают lease.
  Восстановление — только через общую проверку допуска и после отпускания
  кнопки выбора; нажатие для назначения не является командой.

## Автомат и публичный API

`MouseHoldManager(backend=None, *, allowed=lambda: False, clock=time.monotonic)`
не зависит от Qt, RawWinBroker, микрофона или транспорта. Default guard запрещает
захват, пока runtime явно не подключит допуск.

| API | Контракт |
| --- | --- |
| `arm(button) -> MouseGrabResult` | Сначала отменяет прошлый жест. Проверяет допуск и номер, устанавливает захваты. `held`/`not-grabbed` не означают готовность; допустим ограниченный retry только пока включена настройка и открыт допуск. |
| `fileno()` | Собственный fd, `-1` без соединения. Один QSocketNotifier и ровно один читатель. |
| `process_pending()` | Считывает очередь, учитывает поколение, вызывает callback только для выбранной кнопки. |
| `on_pending(generation)` | Нажатие допущено, запись ещё не началась. Runtime резервирует общий input owner или немедленно вызывает `cancel("owner-busy")`. |
| `deadline` | Монотонный срок: pending 300 мс либо потолок записи 120 с, `None` вне этих фаз. |
| `tick(generation=token)` | Таймер старого поколения ничего не делает. Сначала читает очередь, затем проверяет guard/удержание/срок. |
| `on_state(state, reason)` | Сообщает `RECORDING/hold`, `PROCESSING/release` или `/limit`, терминальный `IDLE` с причиной. PENDING приходит отдельным callback. |
| `cancel(reason)` | Инвалидирует поколение, очищает deadline/состояние, снимает пассивные регистрации и активный pointer grab, очищает очередь. |
| `done(generation)` | Принимает только завершение текущего PROCESSING. Возвращает IDLE, автоматически не перевооружает. |
| `close()` | Терминальная отмена и закрытие отдельного X-соединения. |

Переходы: `IDLE → PENDING → RECORDING → PROCESSING → IDLE`.
Отпускание до старта записи, включая уже стоящее в очереди при запоздалом
таймере, даёт `IDLE/tap`, без микрофона, toggle и отправки. Повторный press
не продлевает pending. При старте записи кнопка должна быть всё ещё зажата.
Успешно законченный жест снимает регистрации; после tap/cancel/done runtime
явно перевооружает менеджер при выполнении условий допуска.

Перед callback PROCESSING pointer grab уже освобождён. Даже при потерянном
release запись ограничена `RECORD_LIMIT_S=120`; runtime обязан обслуживать
deadline. Сам модуль не создаёт таймеры и не гарантирует сроки, если владелец
перестал обслуживать event loop. Исключение callback снимает ресурсы и
возвращает IDLE; runtime также обязан отменить уже созданную запись.

## Обязательства runtime

1. Хранить **одного владельца входа и общее поколение** для keyboard/mouse.
   Резервировать владельца уже в PENDING; другой источник не может начать,
   завершить или переключить его запись. Менеджер мыши имеет отдельное локальное
   поколение; оно не заменяет общее поколение оркестратора.
2. Guard проверяется перед arm, на press, перед RECORDING и перед release/limit:
   включены Cowork и мышь, профиль/сеанс поддержаны, сессия known/unlocked/active,
   нет sleep/lock request/capture lease, модель доверена и готова, владелец свободен
   или принадлежит текущему mouse gesture, оркестратор допускает соответствующую фазу.
3. `on_pending` резервирует owner и ставит single-shot на `deadline` с захваченным
   локальным и общим поколением. `on_state(RECORDING)` использует тот же путь
   Command1, что клавиатура, и ставит watchdog на новый deadline. Обновление
   настроек, shutdown, lock/sleep/unknown, исчезновение Cowork или потеря owner
   синхронно вызывают cancel; остановить нужно и внешний retry/timer/notifier.
4. В PROCESSING используется существующая оркестрация ASR/preview/Submit.
   Структура сообщений, guard Command1 и серверная проверка не меняются.
   Отмена input во время уже отправленного Submit не должна автоматически
   отменять исполнение Cowork: сохранить существующее различие preview/Submit.
5. После короткого клика/отмены/завершения перевооружать отложенно, с повторной
   проверкой допуска и состояния кнопки. Не восстанавливать автоматически
   старое PENDING/RECORDING. `held` требует отпускания и нового жеста.
6. Esc доставляется общим runtime-путём отмены. Бэкенд мыши не захватывает
   клавиатуру и не конкурирует с отдельным клавиатурным reader/broker.

## Границы X11 и освобождение ресурсов

`X11MouseBackend` владеет отдельным `X11Display`: передавать ему соединение
клавиатуры, вставки или поля выбора нельзя. XGrabButton ставится только для
выбранной кнопки с вариантами вычисленных Lock/NumLock/ScrollLock, base mask 0.
AnyButton, AnyModifier и явный XGrabPointer не используются. owner_events=False,
асинхронная обработка pointer/keyboard, только ButtonPress/Release.

При активации пассивного захвата X11 временно захватывает указатель. Поэтому
cancel снимает сохранённые пассивные маски **и** вызывает XUngrabPointer(CurrentTime)
с sync, даже если регистраций уже нет. При ошибке отмены закрывается собственное
соединение. Обычное закрытие процесса также освобождает его X-ресурсы.
SendEvent не принимается как жест. MappingNotify отменяет текущий жест и
старую очередь; следующий arm перечитывает lock masks. Перемаппинг не начинает
запись автоматически и не затрагивает соединение клавиатуры.

Для средней кнопки состояние читается через XQueryPointer. Для дополнительных
кнопок нужен XI2: core XQueryPointer представляет только кнопки 1…5.
XIQueryDevice используется только для поиска enabled master pointers.
Состояние каждого master читается через XIQueryPointer на том же собственном
соединении: бит N в возвращённой byte mask означает логическую кнопку N,
бит 0 зарезервирован. Состояния известных masters объединяются через OR;
ошибка, пустая/повреждённая/недостаточная маска или другой экран у любого
master дают неизвестное состояние и закрывают допуск.

Нельзя брать состояние из ButtonClass XIQueryDevice: на проверенном Xvfb после
перенумерации физической кнопки 8 в логическую 31 там остаётся бит физической 8,
хотя событие XGrabButton и XIQueryPointer сообщают логическую 31. Число физических
кнопок также не ограничивает логический номер. Регресс проверяется на настоящем
owned Xvfb, включая held-before-arm и начало записи после порога удержания.

В python-xlib нет XIQueryPointer, поэтому модуль определяет только этот
read-only запрос через `rq.ReplyRequest`: opcode 40, фиксированный ответ 56 байт,
`buttons_len` в единицах четырёх байт. Подписки на raw events, новое соединение
и связи с RawWinBroker не добавляются. Формат сверяется с
`/usr/include/X11/extensions/XI2proto.h` (`xXIQueryPointerReq/Reply`).

Проверки с настоящим X-сервером обязательны отдельно: BadAccess, активный
pointer grab у второго клиента, mapping, перенумерация кнопок, held-before-arm,
получение release и отсутствие старта коротким кликом. Unit-тесты с подменными
портами не принимают физическую мышь, KDE/Fly или работу установленного пакета.


## Мост настроек и локальный редактор (отдельный контракт, 2026-10-09)

Реализованы `ui/command_mouse_capture.py`, свойства/слоты `SettingsBridge` и
`SettingsBridge.attach_window(root)` в `app.py`; runtime предоставляет
общий input owner и порт ниже. При неполном или отсутствующем порте
редактор и включение недоступны; сохранённую включённую настройку можно выключить.
Наличие карточки и сохранённого выбора не доказывает реальный захват кнопки.

Точный порт `CommandMouseHost` (все методы, чтение свойств и уведомления —
в GUI-потоке; без вложенного event loop):

| Член | Обязательство runtime |
| --- | --- |
| `begin_command_mouse_capture() -> object\| None` | Атомарно получить **общий** input/capture owner до первого жеста и до стадирования пресета. Вернуть непрозрачный уникальный token; `None` — отказ, bool запрещён. Не начинать аудио. Отказать при записи, pending другого источника, processing, preview, другом редакторе и закрытом допуске сеанса. Снять command grabs, заблокировать начало диктовки. |
| `command_mouse_capture_valid(token) -> bool` | `True` только для текущего своего lease и действительного допуска сеанса/владельца. Повторно проверяется перед press/release, выбором и Apply. При отзыве token нельзя снова сделать действительным. |
| `end_command_mouse_capture(token) -> None` | Идемпотентно освободить только этот token. Старый token никогда не снимает новый lease. Восстановление command grabs — через общие guards, только после фактического отпускания кнопок; при отмене зажатого жеста ждать нового нажатия. |
| `reload_command_mouse() -> None` | Применить уже записанные настройки, прочитать реальный результат захвата и уведомить UI. Во время lease сохранять запрет захвата; освобождение lease затем выполняет отдельную проверку допуска. |
| `command_mouse_status: str` | Реальное `disabled / ready / busy / unavailable / suspended`; строка `ready` не выводится из настройки. `busy` означает внешний конфликт захвата. |
| `command_mouse_status_message: str` | Краткое пользовательское объяснение состояния, без технических/приватных данных. |
| `command_mouse_can_edit: bool` | Собственная запись/обработка/preview, чужой редактор и session blocked дают `False`. Внешний `busy` не запрещает переназначение. **Свой lease редактора** сохраняет `True`, иначе следующий Apply отменится. |
| `on_command_mouse_changed: Callable[[], None]\| None` | Мост устанавливает callback. Runtime обязан вызвать его при изменении статуса/допуска и отзыве lease, включая lock/sleep/unknown/shutdown. Уведомления старого подключения игнорируются по поколению. |

`bind_command_host(host)` подключает этот порт только при наличии всех методов,
типизированных свойств статуса/message/can-edit и возможности установить callback.
Неполный/отсутствующий порт закрывает допуск. Старый редактор отменяется перед
заменой host. Сам callback держит слабую ссылку; уничтожение Qt-объекта не
оставляет возможности вызвать сигнал удалённого объекта. Уничтожение родителя
контроллера освобождает lease через отдельный владелец ресурса, который не QObject.

Состояния локального редактора: `idle / capturing / pressed / ready / error`.
Кандидат — 0 либо логическая кнопка 2/8…31. В `pressed` кандидат ещё нельзя
сохранить: нужно совпадающее отпускание и `qtButtonsRemaining == 0`. Левая,
правая, wheel/NoButton, битовая комбинация и chord отклоняются; повтор возможен
после отпускания всех кнопок. Пресет также получает lease, стадирует кнопку и
требует отдельного Apply. Сохранение никогда не включает мышь автоматически.
8/9 подписаны «Дополнительная кнопка 1/2», номера выше — «Кнопка мыши N».

Apply использует политику сохранения моста: locked учитывается, при OSError
настройка откатывается, mirror и значения QML меняются только после успешной
записи. После ошибки остаются lease и готовый кандидат для повторного Apply
или отмены (до исходного таймаута). Повторный Apply той же кнопки допускает
повторную попытку реального захвата. Ошибка reload не подменяет реальный
статус готовностью и не отменяет факт уже успешной записи.

Отмена идемпотентна: Esc, уход QML из раздела, hide/close/deactivate/minimize,
уничтожение окна/родителя, 30 секунд с открытия (таймер GUI), отзыв lease,
замена host. Внутреннее поколение и срок исключают влияние старого уведомления
host или старого timeout на новый редактор. При заблокированном event loop
таймер срабатывает после его возобновления; runtime остаётся владельцем guards.
Не используются XGrabKeyboard/XGrabPointer, аудио, Submit или новый транспорт.
Редакторы текстовой/командной клавиатуры и мыши взаимно исключены, включая мастер.

Мост учитывает `command_mouse_enabled` и `command_mouse_button` в `lockedSettings`.
Выключение разрешено даже при собственной операции, кроме административного
замка самого enabled. Включение требует валидной кнопки, доступного редактирования
и отсутствия открытого capture. Статус выключенной настройки — `disabled`;
при включённой — состояние порта. Unit/offscreen проверки не принимают KDE/Fly,
физическую мышь или установленную сборку.

## Escape и завершение операции

На mouse PENDING runtime получает внешний Escape lease в существующем
текстовом HotkeyManager. Второй keyboard reader не создаётся. Неудача
регистрации Escape запрещает старт записи. Lease действует также в обработке
и предпросмотре; чужой или устаревший token не снимает текущую регистрацию.

Завершение сначала отменяет оставшийся mouse FSM и таймер, затем освобождает
общего владельца. Ошибки уведомления интерфейса изолированы от очистки.
Ошибка создания или открытия keyboard capture watchdog откатывает владельца;
ошибка его close не должна препятствовать освобождению.

## Уточнение 09.10.2026: временная пауза и настройка меню KDE

Обычная передача владения вводом клавиатура → мышь временно снимает X/Raw-захваты командной клавиши, сохраняя брокер, heartbeat и KWin menu lease. Возвращение к неизменённой клавише не должно вызывать освобождение и повторное получение этой lease: иначе каждый жест вызывает лишний `KWin.reconfigure`. Это отдельный ресурс от capture lease редакторов.

Окончательное снятие при отключении, исчезновении Cowork, блокировке/неизвестном состоянии сеанса, выходе, ошибке и смене клавиши по-прежнему освобождает menu lease — в том числе из паузы. Возобновление не переносит старый удержанный жест: требуется новое физическое нажатие. Журнал восстановления KWin не изменён. Изолированные проверки подтверждают вызовы и переходы; исчезновение физической вспышки экрана требует проверки в живом KDE.
