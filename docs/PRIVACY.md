# Что уходит из Astra Voice в сеть

Коротко: **ни звук, ни распознанный текст никуда не передаются.** Распознавание
идёт на процессоре той же машины, моделью, которая лежит на диске. Отключите сеть —
диктовка продолжит работать.

В сеть утилита обращается ровно в четырёх случаях, все — по явному действию
пользователя или по расписанию проверки обновлений, и все отключаются политикой
администратора (`policy.conf`, `offline=true` или `profile=secure` — тогда
соединений нет вовсе).

## 1. Каталог моделей

**Когда:** при открытии раздела «Модели» и не чаще раза в сутки при запуске.
**Куда:** за подписанным `catalog.json` — на хост, указанный в сборке (по умолчанию
GitHub Releases проекта), либо на корпоративный адрес из `policy.conf: catalog_url`.
**Что отправляется:** обычный HTTPS-запрос — адрес файла, User-Agent вида
`astra-voice/<версия>`. Идентификаторов пользователя и машины нет; учётных записей
и токенов у утилиты нет вовсе.
**Что приходит:** JSON с описанием моделей и его подпись. Каталог с неверной или
чужой подписью отвергается.

## 2. Скачивание весов модели

**Когда:** только по нажатию «Скачать» на карточке модели.
**Куда:** `huggingface.co` и её CDN для файлов (`cdn-lfs*.hf.co`), либо
`github.com` / `objects.githubusercontent.com`, если каталог указывает на
GitHub Release, либо корпоративное зеркало из `policy.conf: corp_base`.
**Что отправляется:** запрос файла по пути из подписанного каталога. Токен доступа
не используется.
**Что приходит:** файлы модели; каждый сверяется по sha256 из каталога.

Модель можно поставить и без сети — из локального файла или каталога (трек B).

## 3. Проверка обновлений самой утилиты

**Когда:** при запуске, не чаще раза в сутки, и по кнопке «Проверить».
**Куда:** `api.github.com` (список релизов) либо адрес из `policy.conf: updates_url`.
**Что отправляется:** запрос списка релизов и версия утилиты в User-Agent.
**Что приходит:** номер версии, `SHA256SUMS` и подпись.

## 4. Скачивание пакета обновления

**Когда:** только после явного согласия в окне обновления.
**Куда:** `github.com` / `objects.githubusercontent.com` (ассеты релиза) либо
корпоративный адрес.
**Что приходит:** `.deb`, `SHA256SUMS`, `SHA256SUMS.asc`. Пакет ставится только
после проверки подписи и суммы; проверка выполняется до установки, root-помощником.

## Отдельно: установка пакета через apt

Установка обновления — это `apt-get install ./astra-voice_*.deb`. Если в системе
не хватает зависимостей (например, Qt-модулей), **apt сам обратится к репозиториям
операционной системы**, настроенным администратором. Это стадия системы, а не
утилиты: список источников, прокси и учётные данные — те же, что у остальных
пакетов. В офлайн-режиме apt вызывается с `--no-download`, и при нехватке
зависимостей выдаётся сообщение «передайте пакет администратору».

## Чего не делает утилита

- не отправляет аудио, распознанный текст, содержимое буфера обмена и имена окон;
- не собирает телеметрию, счётчики запусков и отчёты о падениях;
- не создаёт учётных записей и не хранит токенов;
- не обращается к сторонним аналитическим или рекламным сервисам;
- не пишет распознанный текст в журнал (фильтр логгера вырезает поле `text`),
  а «Собрать диагностику» формирует архив без аудио, текста и домашних путей.

## Что хранится на машине

`~/.config/astra-voice/settings.json` (настройки, права 0600),
`~/.local/share/astra-voice/` (модели), `~/.local/state/astra-voice/`
(журнал, состояние каталога). Удаление пакета (`apt remove`) эти файлы **не трогает** —
их удаляет пользователь, пути показаны в разделе «О программе».

## Проверить самому

Сетевые обращения видны обычными средствами системы, например:

```sh
sudo tcpdump -n -i any 'tcp port 443' &
astra-voice          # подиктуйте несколько фраз, не открывая раздел «Модели»
```

Во время диктовки соединений быть не должно.
